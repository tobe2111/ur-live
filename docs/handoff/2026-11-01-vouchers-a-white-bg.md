## 6. 후속 — CI 가 "가드가 지키는 척만 한다"로 잡은 것 (같은 PR, 2026-11-01)

PR #2066 의 `Verify` 가 **가드 주입 검증**에서 빨간불이 났다(run `41286191380`):

```
🖼️ 앱이 배너 시드를 안 읽는다 — 서버 배너가 사라졌다 다시 나타난다:
   결함을 심었는데 vouchers-hero-banner-ssr-2026-10-18.test.tsx 가 **통과**
```

🔎 **원인은 픽스처가 아니라 그 결함이 더 이상 결함이 아니라는 것**이었다. 주입은
`useHomeBanners.ts` 의 `const full = readBannersSeed()` **호출**을 지우는데, A안으로 머리에 배너가
없어지면서 워커가 `__SSR_INITIAL_BANNERS__` 를 **아예 안 싣는다**(주입처 전수 0 — 실측).
그러면 그 리더는 **늘 `undefined`** 를 내므로 지워도 **행동이 안 변한다.**
그리고 시험은 리더 **정의**(`getElementById('__SSR_INITIAL_BANNERS__')`)를 앵커로 잡고 있어서
호출이 사라져도 통과했다 — **계산과 사용은 다른 자리다**(2026-08-02 `goneStatus` 교훈의 재현).

**처방 — 가드 재조준이 아니라 죽은 가지 제거:**

| 자리 | 조치 |
|---|---|
| `components/home/useHomeBanners.ts` | `readBannersSeed()` 정의·호출 **제거**(주입처 0 = 도달 불가) |
| `scripts/mutations/vouchers-hero-banner-ssr-2026-10-18.mjs` | 그 주입 **삭제** + 왜 다시 만들면 안 되는지 묘비 주석 |
| 같은 매니페스트 | **반대 방향** 주입 신설 — `🖼️ 홈이 섹션 시드로 첫 배너를 안 세운다` |
| 시험 ② | *"앱이 그 시드를 읽는다"* → *"BANNERS 는 주입처도 리더도 없다"* + *"홈 strip 경로는 남아 있다"* |
| 낡은 주석 2곳 | `worker/index.ts:760`(`교환권=BANNERS`) · `shared/home-strip-banners.ts` |

🔴 **새 단언 하나엔 주입이 없다(의도).** 리더를 되살려도 행동이 안 변하므로 **출력으로 판정할 수
없다** — 행동 가드가 아니라 **근거 정확성** 가드다(선례 `blog-dates-honest-2026-10-12`).
주입을 다시 만들려 하지 말 것. 되살아나는 방향은 기존 주입
`🖼️ 교환권이 다시 배너 보조 시드를 받는다` 가 잡는다.

🔴 **중복 잠금을 피했다.** 홈 strip 시드의 *쌍*(서버 마크업 ↔ `placeholderData`)은
`home-strip-banner-ssr-2026-10-14` 가 주인이다. 그쪽은 `placeholderData: seeded,` 를 앵커하고
여기선 **계산 쪽**(`stripBannersOf(raw)`)만 본다 — 전수 확인 결과 그 줄을 보는 시험은 여기뿐이다.

**검증**: tsc 0 · 관련 유닛 3파일 40건 pass · 낡은 앵커 0(4,995건) ·
주입 3건(`머리에 배너가 되살아난다` · `다시 배너 보조 시드를 받는다` · `홈이 섹션 시드로 안 세운다`)
**되돌려-검증 전부 빨간불 확인**.

⚠️ **교훈**: 기능을 걷을 때는 **그 기능을 지키던 주입도 함께 판정**할 것. 결함이 결함이 아니게
되면 그 주입은 가드를 *헛돌게* 만들고, CI 는 "가드가 거짓이다"로 읽어 빨간불을 낸다(옳은 동작).

### 6-2. 같은 클래스가 **두 번** 터졌다 — 그리고 전수로 끝냈다

1차 수리를 푸시했더니 `Verify` 가 **또** 같은 단계에서 빨간불(run `41289919534`):

```
🎟️ 배너 카드 높이가 예약 판과 갈린다: 결함을 심었는데
   vouchers-first-screen-2026-10-14.test.tsx 가 **통과**
```

그 불변식은 **쌍**이었다 — `HERO_CARD_CLS` 의 `!h-[196px]` ↔ 교환권 첫 화면이 예약한 판 196px.
A안이 그 판을 없앴으니 카드 높이는 **맞출 상대가 없다**: `hero` 변형은 사용처가 0(`BannerHeroRail`
포함)이라 180 으로 바꿔도 **아무 화면도 안 변한다** ⇒ 주입 **제거 + 묘비 주석**.

🩸 **제가 1차 때 그 자리를 보고도 틀리게 판단했다.** 같은 매니페스트 머리말에 제 손으로
*"③ 배너 카드 높이 = 예약 판 높이 — **홈이 계속 쓴다**. 그대로 둔다"* 고 적어 뒀다. 홈이 쓰는 건
**다른 변형**(strip)이고 `hero` 는 사용처 0 이 됐다 — **변형 이름이 같다고 같은 코드가 아니다.**

⚠️ **왜 로컬에서 미리 못 잡았나**: `pre-push` 게이트는 이 주입 검증을 **일부러 제외**한다
(전수 80분+). 그래서 이 클래스는 **CI 에서만** 드러나고, 한 건씩 고치면 회차마다 ~70분이 날아간다
(실제로 두 번 날렸다).

⇒ **처방: CI 와 같은 범위를 로컬에서 직접 돌렸다.**

```
node scripts/check-guard-mutations.mjs --changed     # 이 브랜치가 바꾼 33파일에 걸린 210건
→ 통과 209 · 실패 1 (위 그 건뿐)
```

🧭 **다음 세션이 기능을 걷을 때 할 일**: `--changed` 를 **푸시 전에 한 번** 돌려라. 느리지만
CI 회차보다 싸다. 특히 *무언가를 제거하는 PR* 은 그 기능을 지키던 주입이 **같이 무의미해지므로**
반드시 돌릴 것.

🩸 **그리고 측정에서 두 번 헛짚었다**: ① `pgrep -f 'check-guard-mutations'` 가 **내 감시 명령의
명령줄 자체**를 잡아 끝난 작업을 30분간 "RUNNING" 으로 읽었다(자기 자신 매칭) ② 그걸 치우려고 쓴
`pkill -f "while pgrep -f"` 가 **내 셸을 같이 죽였다**(exit 144). 끝났는지는 **프로세스가 아니라
로그 꼬리**로 판정할 것. ③ 주입이 돌는 중에 `check-stale-mutation-anchors` 를 돌려 **거짓 빨간불**을
받았다(그 순간 소스가 일시 변형 상태였다) — CLAUDE.md 가 경고한 그 자리다.

### 6-3. 3차 CI — **버그가 아니라 개선을 안 잠근 것**

```
❌ surface-budgets: vouchers 190.4 → 184.5 KB 로 줄었다
   — 개선을 잠그라(--rebaseline). 안 잠그면 그 여유가 다음 기능에 조용히 먹힌다
```

배너를 걷어서 그 화면 봉투에서 **배너 캐러셀 + hero 변형이 빠졌다(-5.9KB)**. 이 래칫은 **양방향**이라
줄어든 것도 잠가야 통과한다. 🔑 **로컬 측정이 CI 와 정확히 같았다(184.5)** — brotli 바이트라
결정적이고, 그래서 로컬 `--rebaseline` 값을 그대로 믿을 수 있다(`exec-cost` 와 다른 점이다).

⚠️ **`--rebaseline` 은 27개 화면을 전부 다시 쓴다.** 이 PR 이 바꾼 건 교환권 하나인데 다른 26개가
±0.2KB 씩 같이 기록된다(main 머지분). 그대로 커밋하면 **다음 PR 의 허용오차가 그만큼 헐거워지고**
diff 가 시끄러워 진짜 회귀를 가린다 ⇒ **`vouchers` 항목만 새 값으로 두고 나머지는 커밋된 값 그대로**
되돌렸다(이 파일 `history` 에 2026-10-26·11-01 선례가 있다: *"다른 화면은 로컬 측정 편차라 손대지 않았다"*).
`_doc` 의 *"손으로 고치지 말 것"* 은 **숫자를 꾸미지 말라**는 뜻이고, 커밋된 값으로 되돌리는 것은
그 반대다 — 그래도 되돌릴 땐 스크립트를 다시 돌려 **27개 전부 예산 안**인지 확인할 것(했다).

📌 `npm run build` 는 `route-chunk-map.ts`(**커밋 대상 아님** → `git checkout`)와
`critical-css.ts`(**커밋 대상**)를 재생성한다 — 이번엔 전자만 바뀌어 되돌렸다.

### 6-4. 4차 CI — **래칫은 둘이다**(바이트 + 실행비용)

3차에서 무게(brotli)만 잠그고 푸시했더니 4차가 터졌다:

```
❌ exec-cost: 교환권 실행된 JS 281.7 → 264 KB 로 줄었다 — 개선을 잠그라
```

🩸 **화면이 가벼워지면 잠글 래칫이 둘이다** — `check-surface-budgets`(받는 바이트)와
`check-exec-cost`(**실제로 돌는 JS**, V8 커버리지). 배너 캐러셀·hero 변형이 빠지며 둘 다 줄었는데
하나만 잠가서 회차를 한 번 더 태웠다(~70분). **다음에 무언가를 걷을 때는 둘을 같이 재라.**

🔬 **측정 일관성 확인**: 교환권 로컬 `264.2` / `263.7`(두 번) ↔ CI `264.0` — 0.5KB 안이다.
CLAUDE.md 가 경고한 *"첫 CI 는 크로미움 판 차이로 어긋날 수 있다"* 는 이번엔 해당 없었다.
⚠️ 다만 **에이전시 콘솔은 로컬만 +4.7(허용 4 초과)** 이고 CI 는 +3.1 로 통과했다 — main #2060 의
에이전시 화면 추가분이고 **이 PR 과 무관**하다. 그래서 **손대지 않았다**(로컬 초과를 근거로
남의 화면 기준을 올리면 그 화면의 진짜 회귀를 가린다).

⇒ `surface-budgets` 와 같은 방식으로 **교환권 항목만** 새 값, 나머지 9개는 커밋된 값 그대로.

| 회차 | CI 가 막은 것 | 성격 |
|---|---|---|
| 1 | 배너 시드 주입이 헛돌음 | 🔧 결함 |
| 2 | 배너 카드 높이 주입이 헛돌음 | 🔧 결함 |
| — | GitHub 쪽 충돌(main 이 움직임) | 🔧 병합 |
| 3 | 교환권 **바이트** −5.9KB | ✅ 개선 잠금 |
| 4 | 교환권 **실행 JS** −17.7KB | ✅ 개선 잠금 |

📈 4차에서 **주입 검증 단계를 통과**했다 — 1·2차 수리가 먹었다는 뜻이다.
