### 사진 비율: 실측이 가정을 뒤집었다
대표 *"네이버에서 가져오는 사진들 비율 중 가장 많은 비율로. 그루폰은 세로가 짧잖아"* →
라이브 네이버 사진 **70장을 직접 쟀다**:

| 세로가 더 김 | 정사각 | 4:3 | 3:2 | 16:9 |
|---|---|---|---|---|
| **37%** | 21% | 23% | 11% | 7% |

**중앙값 정확히 1:1.** "가장 많은 비율"은 넓은 게 아니라 정사각~세로다 — 16:9 로 가면 열 중 여섯이 잘린다.
⇒ **답은 프레임이 아니라 자를 위치였다.** 프레임 3:2 고정 + `gravity=auto`(Cloudflare 스마트 크롭).
라이브 실측으로 동작 확인(center 대비 결과 바이트가 다름 = 실제로 다른 곳을 자름) + 세로 사진
육안 비교로 피사체 보존 확인. `cf-image.ts` 잠금 해제는 CLAUDE.md audit log 에 기록.

### 버튼이 따로 놀던 진짜 이유
처리가 **넷 다 달랐다**: 뒤로/공유=검정 반투명 원 · 찜=원 없는 맨 하트 · **핀=흰 원 + 이모지 ➕**.
선 아이콘 사이의 이모지 하나가 가장 튄다. 흰 원 + 잉크 선 아이콘으로 통일(숙소 뒤로가기도 같이).

🐛 그 과정에서 `KakaoShareButton` 원형 아이콘 색이 `#fff` 로 박힌 걸 발견 — 흰 원 위에서 **빈 원**으로
보였다. `currentColor` 로 고치니 **PC 섹션 탭의 공유 버튼도 같이 고쳐졌다**(밝은 배경이라 원래 안 보였다).

### 이번에 밟은 함정 (다음 세션 주의)
1. **`check-file-size --changed-only` 는 커밋된 diff 만 본다.** 작업트리 변경은 "대상 없음(skip)" 초록.
   ⇒ 크기 판정은 **커밋 후**.

4. **가드를 값에 앵커하지 말 것.** `padding: '20px 18px 0'` 에 걸어 둔 검사가 **디자인 변경만으로** 빨간불.
5. 파이썬 편집 스크립트는 **중간에 assert 로 죽으면 파일을 안 쓴다** — 앞의 성공한 편집까지 통째로 유실된다.

대상 = `slug LIKE 'demo-stay-%'` **그리고** `description LIKE '%—%'`(조립문의 지문).
- 슬러그 한정이 빠지면 관리자 수기 문구를 덮는다
- 줄표 조건이 빠지면 멱등이 깨진다(새 desc 는 줄표를 안 쓰므로 두 번 돌려도 무해)

`descHealed` / `amenityHealed` 를 응답에 실었다 — `amenityHealed` 는 그간 **계산만 하고 버려서**
"돌았는데 0건"과 "안 돌았음"을 구분할 수 없었다.

**대표가 할 일**: 어드민에서 숙소 데모 시드 1회 실행 → 응답의 `descHealed` 가 고친 건수다.

## 2026-08-31 후속 ② — 이미지 이관 cron 이 넉 달간 죽어 있었다

대표: *"내가 할 것 미루고 다른 것 할 건 없어?"* → 숙소 커버가 **46건 전부 남의 서버**인 걸 재다가
진짜 원인을 찾았다.

**실측 근거 사슬**
```
데모 숙소 46건 커버   R2 0 · 외부 46 (카카오맵 36 · 네이버 블로그 10)   ← 이용권은 100건 중 R2 72
이관 대기 큐          338건, 전부 img_rehost_tries = 0  ← 한 번도 시도된 적이 없다
하트비트              ok:true · "reconditioned=3 migrated=0 images=0 done=0"  ← D1 은 되고 R2 만 안 됨
/api/media 서빙       200 (캐시 우회 ?cb= 로도 200 → Pages 쪽엔 바인딩이 있다)
wrangler.toml         [[r2_buckets]] MEDIA_BUCKET 이 **주석 처리**돼 있었다
```

🔑 **배포가 둘이고 바인딩 출처가 다르다.**
- Pages(요청 처리) ← 대시보드 바인딩 → `/api/media` 정상
- **Workers(cron) ← `wrangler.toml` 만** → MEDIA_BUCKET 없음 → `if (!MEDIA_BUCKET) return` 으로 매 5분 조기 반환

⚠️ **에러가 안 난다.** cron 은 성공으로 기록되고 큐만 안 줄어든다. `migrated=0` 이 "옮길 게 없었다"와
"옮길 수 없었다" **양쪽으로 읽혀서** 아무도 못 봤다.

**수리**: ① `wrangler.toml` 주석 해제(이 파일이 worker-deploy 트리거 경로에 있어 머지 시 자동 재배포)
② 두 cron(`demo-image-rehost`·`r2-orphan-cleanup`)이 못 돈 사유를 `skipped:'NO_MEDIA_BUCKET'` 로 남김
③ 가드 `cron-bindings.test.ts` — **조기반환 게이트가 걸린** 바인딩은 wrangler.toml 에 있어야 한다
   (한 홉 별칭 `const bucket = env.MEDIA_BUCKET` 까지 추적) + 못 돈 사유를 남기는지.

⚠️ **가드를 일부러 좁혔다.** 처음엔 cron 이 참조하는 모든 `*_BUCKET`/`*_KV` 를 검사했더니
`RATE_LIMIT_KV` 3건이 걸렸다. 그건 **폴백이 있고**(`getFeatureFlags(KV, env.DB)`) KV id 가 대시보드에만
있어 **내가 못 고치는 것으로 CI 를 막는 꼴**이 된다. ⇒ "없으면 통째로 건너뛰는" 것만 대상으로.

**남은 판정(다음 세션 첫 액션)**: 머지·배포 후
```
curl -s .../api/admin/cron-heartbeats  → demo-image-rehost 의 result 에 migrated>0 이 찍히는지
```
안 찍히고 `skipped=NO_MEDIA_BUCKET` 이 보이면 **버킷 이름이 다른 것**이다(레포 문서 3곳이 모두
`ur-live-media` 라 그대로 썼지만, 이 세션의 CF 토큰엔 R2 읽기 스코프가 없어 이름을 직접 확인 못 했다).
그때는 대표에게 대시보드 R2 버킷 실명을 물어 `bucket_name` 만 고치면 된다.

### 2026-08-31 후속 ③ — "모두 영구적으로" (대표 지시)

②를 보고하며 **영구가 아닌 세 칸**을 정직하게 남겼는데, 대표가 *"계속 해. 모두 영구적으로"* 라고
해서 셋 다 닫았다. 닫는 과정에서 **CF Pages API 로 실제 바인딩을 읽은 것**이 결정적이었다:

```
Pages 프로덕션 바인딩 (2026-08-31 실측)
  MEDIA_BUCKET  → ur-live-media                          ← ②에서 "확인 못 했다"고 남긴 것. 맞았다
  RATE_LIMIT_KV → bf9d3b4e6a314004aaa58fc38c3b5837
  CACHE_KV      → 25aef97917074251aa482f0988be8283       ← 네임스페이스 *이름*은 `ur-cashe`
```
🔑 `CACHE_KV` 가 이름이 아니라 id 로 매칭된다는 wrangler.toml 의 경고가 사실이었다 —
**이름으로 고르면 안 된다.** RATE_LIMIT_KV 도 그래서 Pages 가 가리키는 id 를 그대로 옮겼다.

| 남았던 칸 | 어떻게 닫았나 |
|---|---|
| ① 대시보드(Pages) 바인딩을 레포가 못 본다 | `check-live-contracts` 에 R2 프로브. `/api/media/:key` 가 **404(객체 없음)와 503(바인딩 없음)을 다른 코드로** 준다 → **없어도 되는 키**를 두드린다(특정 사진에 안 매임·자격증명 불필요). 라이브 실측 404 ✓ |
| ② 폴백 있는 바인딩(RATE_LIMIT_KV)은 가드 밖 | id 를 실측으로 얻어 `wrangler.toml` 에 선언. cron 5곳의 **디스코드 경고 중복제거**가 이제 실제로 동작한다(그전엔 같은 경고가 매시간 도배될 수 있었다) |
| ③ "돌긴 했는데 아무것도 못 함" 일반형 | `cron-stale-watch` 에 두 번째 판정 추가 — `skipped` 를 실은 비트를 골라 `blocked:{name}` 키로 알린다. 정상 회차는 그 필드를 안 실으므로 **오탐이 구조적으로 0**, 앞으로 만들 cron 도 관례만 따르면 공짜로 감시된다 |

⚠️ **그래도 못 보는 것**(다음 세션이 과신하지 않게): 바인딩이 **엉뚱한 버킷/네임스페이스**를 가리키는
경우. 200/404 로는 구분이 안 된다 — 그건 위 표처럼 **CF API 로 실측**해야 보인다(정기 점검엔 토큰이
없다). `CACHE_KV → ur-cashe` 가 정확히 그 모양이고, 그건 의도된 것이라 두었다.
