## 무엇을 만들었나
`src/components/deal/DetailBreadcrumb.tsx` — 사진 **위** 한 줄. 두 상세가 같은 컴포넌트를 쓴다.

| 페이지 | 경로 | 단계 |
|---|---|---|
| 이용권/공구 상세 | `홈 / 식사 이용권` | 2 |
| 숙소 상세 | `홈 / 숙소 / 호텔` | 3 (`/stays` 가 실재하는 중간 목록이라) |

**단계 수가 다른 건 의도다.** 우리 분류는 그루폰보다 얕아(이용권 카테고리 4종이 전부) 없는 중간
단계를 지어내면 `홈 / 이용권` 처럼 **같은 곳으로 가는 크럼 두 개**가 된다. 그건 길이 아니라 장식이다.

**여백은 컴포넌트가 정한다**(`overlayHeader` prop). 공구 상세는 헤더가 `fixed` 로 사진 위에 떠 있어
56px 만큼 비켜 줘야 하고, 숙소는 그런 헤더가 없다. 페이지마다 손으로 적으면 두 상세가 갈린다.

**함께 뺀 것** — 빵부스러기가 카테고리를 말하기 시작하면서 중복이 된 배지 둘:
공구 사진 위 카테고리 칩(게다가 **자체 라벨 맵**을 들고 있어 명칭 SSOT 와 어긋났다 —
'뷰티'/'숙박'/'액티비티' vs SSOT 미용/숙소/기타) · 숙소 유형 배지('호텔').
안 뺐으면 내가 방금 없앤 "같은 말 두 번" 을 새로 만드는 셈이었다.

## 후속 — 그루폰 요소 전수 대조 (2026-08-31)
대표 *"카테고리바 뿐 아니라 그루폰처럼 웬만한 요소 다 넣었어?"* → **아니었다.** 스크린샷과 하나씩
대조해 빠진 것을 찾았고, 대표가 항목을 골라 줬다(프로모 배너는 "지금은 안 한다").

| 넣은 것 | 근거 |
|---|---|
| **모바일 로고** | 상세 상단바에 브랜드 표식이 **하나도 없었다**. 공유 링크로 바로 들어온 사람이 "여기가 어디인지" 알 방법이 없다(PC 는 전역 상단바가 담당). 스크롤하면 제목에 자리를 내준다 |
| **찜 하트** | 홈 카드엔 있는데 상세엔 없어서 **상세까지 들어온 사람이 오히려 찜을 못 했다** |
| **거리** | 주소 옆 `1km`. ⚠️ **새로 권한을 묻지 않는다** — 지도 홈이 저장한 `ur_last_loc_v1` 만 읽고, 없으면 자리를 비운다 |
| **판매 수량** | `group_buy_current > 0` 일 때만 "이미 N명이 구매했어요". 데이터는 이미 응답에 있었는데 **공유 문구에만 쓰고 화면에선 버리고 있었다** |
| **매장 줄 정리** | 대표 *"와고숯불구이 정식 등록 매장 저 부분도 AI가 만든 것 같아"* — 맞다. `· 정식 등록 매장`이 **조건 없이 모든 매장에 붙고**(승인 여부를 보지도 않는다) 로즈로 칠해져 이름이 라벨처럼 읽혔다. 이름만 잉크로 |
