## 🩸 내보내기가 화면 필터를 **통째로 무시**하고 있었다 (수리)

```
파트너: listCompanyLeads(DB, { limit: 5000, includeHeld: true })   ← 필터 인자가 아예 없다
매장  : listProspects(DB, { includeClosed: false, limit: 2000 })    ← 〃
```

화면에서 *"이메일 있음 + 대행사 + 서울"* 로 좁혀도 파일은 **무필터 상위 N행**이었다.
- 파트너: 이메일 보유가 12%뿐이라 5,000행 중 실제 발송 가능분 **~600건** + **보류(active=0) 혼입**
- 매장: 95%가 학원이라 *"카페 + 전화 보유"* 로 좁혀도 파일은 **사실상 전부 학원** ⇒ 대표 우선업종은
  **내보내기로 도달 자체가 불가능**했다

> 🔑 이 DB 의 성공 지표는 총 인원이 아니라 **"제안 보낼 수 있는 리드 수"** 다(CLAUDE.md 방향).
> 화면은 그 정의로 세는데 내보내기가 안 따르면 **지표가 화면에만 있고 손에는 안 잡힌다.**

**수리**: 두 내보내기가 목록과 **같은 필터**를 읽는다. 화면도 조립을 `buildQuery()` 로 추출해
목록과 파일이 한 곳에서 나온다(두 벌이면 반드시 갈라진다 — 이번이 그 결과다).
상한에 닿으면 **파일 마지막 줄에 잘렸다고 적는다**(무음 캡 금지).
공용 모듈 `pool-export.ts` 신설 — 파일크기 래칫(600줄)을 `[SKIP_SIZE]` 로 우회하지 않고 분리했다.

⚠️ **가드가 리팩토링 직후 낡은 지도가 됐다** — 파싱을 모듈로 옮기자 라우트 본문을 앵커하던 시험 3개가
깨졌다. 지켜야 할 것은 **위치가 아니라 "같은 키를 읽고 실제로 넘긴다"** 라, 그 의미로 다시 잡았다.

## 🧭 새 수집 루트 후보 — 기준: "이메일이 공시 항목인 공적 등록부"

| 후보 | 왜 유망한가 | 상태 |
|---|---|---|
| **인허가(localdata) 부활** | 대표 우선업종 4종이 **전부 여기 있다**. 이미 코드·게이트·업종 16종 완비 | 🔴 주소 불일치 — **요청주소 한 줄이면 즉시 부활** |
| **공정위 가맹 부활** | 프랜차이즈 본사 = 대량 매장 한 번에 | 🔴 〃 |
| **나라장터 부활** | 조달 등록 = 사업자 연락처 공시 | 🔴 〃 |
| **카카오 로컬 확대** | 지금 유일하게 우선업종을 캔다 · 중복 0 · 키/레인 완비 | 🟡 회차를 거의 못 받음 + CPU 사망 |
| 관광사업자 등록(문체부) | **숙박**이 우선업종. 등록 의무 + 연락처 공시 | ⚪ 미조사 |
| 유튜브 확대 | 이메일 수율 **34%** — 전 루트 최고 | 🟡 `ADS_YT_SEARCH_BUDGET` 로 조절 가능 |
| 네이버 카페·티스토리 | 3,520건인데 **이메일 0** | ⚠️ 수율 0 — 늘려도 리드가 안 는다 |

**⇒ 결론: 새 루트를 뚫는 것보다 죽은 3개를 살리는 게 압도적으로 크다.** 세 개 다 원인이 같고
(주소 불일치), 대표 우선업종이 전부 거기 있고, 코드는 이미 다 있다.
