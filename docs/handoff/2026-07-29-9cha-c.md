### 수집 — 키워드 회전이 교착돼 있었다 (대표 "수집 관련하여 더 개선점")

`found 332 → saved 3`(99% 중복)의 원인은 발굴 코드가 아니라 **키워드 포트폴리오 교착**이었다.

| 실측(라이브 키워드 API) | 값 |
|---|---|
| 활성 키워드 | **210** — 상한(`MAX_ACTIVE_KEYWORDS`) 200을 **초과** |
| 구성 | seed 190 · auto 20 |
| 활성 중 누적 저장 0건 | 66 |
| 최근 승격 | **`promoted: []`** |

승격 자리가 `room = max(0, 200 − 활성전체)` 인데 **활성이 210이라 room 이 영구 0** → 신규 키워드가
아무리 발굴돼도 들어올 자리가 없다. 시드만으로 상한에 닿는다(일반 ~90 + **지역그리드 100** + 방배 11)
— 즉 **지역 그리드가 추가된 시점부터 auto 승격이 죽어 있었다.**

시드를 줄이는 건 답이 아니다(코드 주석의 기존 결정: *"시드는 대표가 고른 지역/업종 축이라 비활성화하면
커버리지에 구멍"*). 진짜 문제는 **쿨다운과 room 이 서로 다른 것을 센다**는 점 — 쿨다운은 *검색 슬롯*
점유를 막지만 room 은 *활성 행 수*를 세서, 쿨다운된 시드도 room 을 0 으로 눌렀다.
→ **두 관심사 분리**: 시드=커버리지(대표가 정함, 무제한) · auto=발굴(자기 쿼터 `MAX_AUTO_KEYWORDS=60`).
`autoPromotionRoom(활성auto)` 로 계산 → 시드가 몇 개든 발굴 자리가 남는다. 불모 auto 는 기존 규칙
(`barren_streak >= 8`)이 회수하므로 쿼터가 계속 재활용된다.
관측: 스냅샷에 **`kw_auto {active, room, cap}`** 추가 — `promoted: []` 가 "후보가 없어서"인지
**"자리가 없어서"**인지 화면에서 갈린다(이 값이 없어서 몇 세션 동안 못 봤다).

   ("뷰티 공구"는 뷰티 리뷰어보다 공구 셀러에 가깝다).
3. **`PRIORITY_CATEGORIES` 편입** — 시드만 늘리면 희소한 YT 검색 슬롯이 균등 순환에 묻힌다.

> ⚠️ **이 축의 진짜 위험은 동음이의어다.** 한국어 '공구'는 工具(전동공구·공구상가·공구함)와 겹쳐서
> 맨 단어로 매칭하면 하드웨어 리뷰어가 대량 유입된다(사람이 발송 큐에서 걸러야 함 = 이 세션이 줄이려는
> 바로 그 시간). 반드시 **공동구매 문맥이 붙은 형태만** 잡는다. bare `공구`·bare `라방` 금지.
> 확장하다 실제로 한 번 뚫렸다 — `공구\s*중` 이 **'공구 중고거래'**를 삼켜서, 부정전방탐색 `(?!고)` 로 막고
> 유닛에 케이스를 박았다(회귀 주입으로 실제로 잡히는 것 확인).
