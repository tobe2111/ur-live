## 1. "허술하다"를 세어 봤다 — 인상이 아니라 숫자였다

앞 PR(#1567)이 목록 **문법**을 하나로 만들었는데도 대표가 다시 *"별로"* 라고 했다.
그래서 이번엔 고치기 전에 **셌다**:

| 재 본 것 | 값 |
|---|---|
| 글자 크기 종류 | **17단계** — `9 · 10 · 10.5 · 11 · 11.5 · 12 · 12.5 · 13 · 13.5 · 14 · 15 · 16 · 17 · 18 · 25 · 28 · 30px` |
| 격자 밖 간격(반쪽 값) | **115건** — `mt-0.5`(2px) · `px-3.5`(14px) · `py-3.5` · `mb-1.5`(6px) … |
| 아이콘 | lucide **35** · 유어딜 아이콘 **0** |

**12 와 12.5 와 13 이 한 화면에 같이 있으면 어느 두 줄도 서로 동의하지 않는다.**
개별 결함이 아니라 그 자체가 *"덜 만든 화면"* 의 인상을 만든다 — 대표가 두 번 지적한 그 인상이
색이나 부품이 아니라 **여기서** 나왔다. 대기업 앱은 대개 5~6단계로 끝낸다.

🔑 그리고 이게 왜 계속 자랐는지가 더 중요하다: **단계 하나가 반쪽 값으로 새도 빌드는 초록이고
화면도 안 깨진다.** 사람 눈으로는 12 와 12.5 를 못 고른다 ⇒ 가드가 세야 한다.

## 2. 무엇을 했나

### ① 타입 스케일 여섯 단계 (28 / 24 / 17 / 15 / 13 / 12)

| px | 자리 |
|---|---|
| **28** | 큰 숫자(오늘 매출) — 규칙 ③ *숫자가 주인공* |
| **24** | 구역 제목(파는 쪽에만 · 규칙 ⑦) |
| **17** | 사람 이름 · 시트 제목 · 중간 숫자 |
| **15** | 목록 행 제목 · 블록 라벨 · 주 버튼 |
| **13** | 설명 · 보조 문장 |
| **12** | 그룹 라벨 · 미세 라벨 — **바닥**(이보다 작은 글자를 새로 만들지 않는다) |

9·10·10.5·11px 이 전부 사라졌다. 마이에서 가장 흔했던 크기가 **10px**(읽으라고 만든 글자인데
읽히지 않는 크기)였다는 게 이 화면의 문제를 요약한다.

### ② 간격은 4의 배수만 — 단, 음수는 예외

반쪽 값 115건을 격자로 올렸다(`px-3.5`→`px-4` · `mt-0.5`→`mt-1` · `gap-x-2.5`→`gap-x-3` …).
**음수 광학 보정(`-mt-0.5`)은 그대로 둔다** — 그건 리듬이 아니라 아이콘 하나를 눈으로 맞추는
일이라 격자 밖이 맞다(시험도 앞 글자가 `-` 면 안 세도록 짰다).

### ③ 강조색 면을 하나로 (표면 규칙 ②) — 대표 지적 ①

`오늘` 카드가 `TicketCard`(파란 머리 띠)였고 **바로 아래** `이용권 사용처리` 파란 바가 있어
파란 면이 연속 둘이었다. 규칙 ②는 *"강조색 하나, 자리 셋"* 이고 시안(코레일톡)도 파랑 하나다.

**띠를 없애는 쪽으로 풀었다** — 규칙 ④(티켓 은유)는 **산 권**의 문법이고, 오늘 매출은 권이 아니다.
`TicketCard` 를 여기 쓴 것 자체가 부품 오용이었다. 하루에 가장 많이 누르는 버튼(사용처리)을
죽이는 쪽으로 풀었다면 화면에서 강조가 아예 사라졌을 것이다.

### ④ 고아 바 입양 — 대표 지적 ②

잔액 0 일 때 뜨는 *"딜을 모으면 더 싸게…"* 바가 어느 그룹에도 안 속한 채 떠 있었다.
**숨기지 않고** `<GroupLabel>내 딜</GroupLabel>` 을 달았다 — 숨기면 마이에서 딜 버는 길이 사라진다.

### ⑤ 헤더의 회색 알약 제거

`프로필 편집` 알약이 이름 옆에 떠 있었다. 목록 문법이 이미 *"줄 전체가 눌린다 + 오른쪽 화살표"*
인데 헤더만 다른 문법을 쓰고 있었다 ⇒ **프로필 블록 전체를 누르는 줄**로 만들고 화살표를 붙였다.

### ⑥ 블록/아코디언 라벨 13 → 15px

`내가 산 것`·`돈 버는 법`·`설정` 이 본문 설명(13)과 같은 무게라 구분이 안 됐다.

## 6. lucide 36종 → 유어딜 24종 + 조작 10종

**문제**: 탭 다섯은 우리 아이콘으로 바꿔 놓고 **그 바로 아래 본문은 통째로 lucide** 였다.
마이 한 화면에 lucide **36종 · 87건**, 유어딜 아이콘 **0종**. 획이 2 와 1.6 으로 갈리는데
**같은 열에 나란히** 서 있어서 그 차이가 그대로 보인다.

**경계를 "뜻이냐 조작이냐" 로 그었다**:
- **뜻**(내 이용권 · 찜 · 정산 · 설정 · 가게 …) → 유어딜. 우리 물건의 이름이라 남의 세트에 맞는 그림이 없다.
- **조작**(화살표 · 닫기 · 검색 · 확인 · 더하기 · 로딩) → lucide 그대로. 어느 앱에서나 같아서 직접 그릴 값이 없다.

**결과**: 뜻 아이콘 **0개**가 lucide 에 남았다. 유어딜 아이콘 **24종 · 41건**.

**새로 그린 18종** (`urdeal-icons.tsx`, 255 → 461줄 · cap 600):
쿠폰 · 찜 · 단골(별) · 알림(종) · 주문상자 · 배송지핀 · 리뷰(풍선+별) · 제안(풍선+`+`) ·
사람들 · 가게등록(차양+`+`) · 주문(클립보드) · 분석(축+추세선) · 메시지(풍선+글) ·
설정(톱니) · 스캔(QR 틀) · 로그아웃(문+화살표) · 메일 · 메달

그리면서 판단한 것 몇 가지(전부 18px 로 그려 보고 정했다):
- **막대 그래프를 버렸다** — 1.6 획에서 막대인지 선인지 구분이 안 된다 ⇒ 축 + 추세선.
- **톱니는 이를 여섯**으로 — 열둘이면 18px 에서 테두리가 원으로 뭉친다.
- **같은 말풍선을 셋이 쓴다**(리뷰·제안·메시지) — 내용물(별 / `+` / 글 두 줄)이 이름표다.
- **`내 가게 등록`은 장바구니였다** — 그건 *사는 행위*로 읽힌다. 실제 뜻은 가게를 내는 것이라 차양 + `+`.
- `AccountPcPane` 의 `BookOpen` 은 **참조 0인 죽은 import** 였다. 함께 걷었다.

## 12. UI② 상태색 — **색 이름은 남고 색은 사라져 있었다** (2026-09-29)

### 무엇이 진짜 문제였나 (내가 처음 잡은 프레임이 틀렸다)
대표에게 *"체계 밖 색 198건"* 이라고 보고했는데, **틀린 프레임이었다.**
`tailwind.config.js` 는 2026-06-19 대표 지시("아예 흑백, 기능 빨강만 유지")로 장식 색조 16개를
**전부 잉크 스케일로 리맵**한다. 그래서 그 198건은 *잘못된 색*이 아니라 **이미 회색**이다.

```
실측 (tailwind.config.js 를 직접 불러 값 비교)
 50 단계: rose = emerald = amber = blue = green = #F8F7FC
600 단계: rose = emerald = amber = blue = green = #55534F
red 만 리맵 대상이 아니다 (= 대표가 유지하라고 한 '기능 빨강')
```

⇒ 문제는 색이 틀린 게 아니라 **의미가 조용히 사라진 것**이다. 코드에 `text-emerald-600` 이라고
적힌 자리를 사람은 "초록 = 성공" 으로 읽는데 화면엔 회색이 뜬다. 빌드도 화면도 안 깨져서
**아무도 신고하지 않는다.**

### 🩸 그리고 이걸 막으라고 만든 가드가 **소비자 화면을 한 건도 못 보고 있었다**
`check-status-tone`(2026-09-03 신설, 정확히 이 사고를 막으려고 만든 것)의 판정이
`\{[^{}]*label…[^{}]*cls…\}` 였다. `[^{}]` 가 중괄호를 금지하는데 **CLAUDE.md 는 모든 UI 문자열에
`t(키, { defaultValue: '한글' })` 을 강제한다** ⇒ 소비자 상태표는 라벨 안에 중괄호가 **항상** 있어
매칭이 거기서 끊긴다.

```
{ label: t('…', { defaultValue: '취소/환불' }), cls: 'text-rose-600' }   → 매치 0  ❌
{ label: '취소/환불',                            cls: 'text-rose-600' }   → 매치 1  ✅
```

`entries: []` 라 **초록불로 "0건"** 이 떠 있었다. 중괄호 균형 파싱으로 바꾸자 **즉시 7파일 16건**.

### 고친 것 (실제로 화면에서 구별이 안 됐던 자리)
| 화면 | 그때 | 지금 |

| 마이 주문내역 목록 | 취소/환불·구매완료·배송중·준비중 **넷 다 같은 회색** | tone-bad/ok/info/warn |
| 주문 상세 배지 | 같은 주문인데 넷 중 셋이 구별 안 됨 | 목록과 **같은 배정**(열었을 때 색이 달라지면 더 나쁘다) |
| 🔴 **매장 이용권 스캐너** | 성공=회색 / 실패=빨강 — **되돌릴 수 없는 동작인데 한쪽만 읽혔다** | tone-ok / tone-bad 쌍 |

### ① glob 이 최상위 파일을 통째로 건너뛴다
가드와 코드모드가 둘 다 `git ls-files 'src/pages/**/*.tsx'` 로 대상을 골랐다.
git pathspec 의 `**` 는 **`FNM_PATHNAME`** 이라 **디렉터리를 최소 하나 요구한다** —

```
git ls-files 'src/pages/**/*.tsx' | grep -c '^src/pages/[^/]*\.tsx$'   → 0
git ls-files 'src/pages/*.tsx'    | wc -l                              → 734
```

그래서 `src/pages/AffiliatePage.tsx` 의 `text-xs`·`text-sm` 이 **그대로 남은 채 초록불**이었다.
검사가 459개를 돌아 "통과" 라고 말하니 지키는 것처럼 보였다.

- **어떻게 잡혔나**: 주입 앵커를 재조준하다가 `AffiliatePage` 의 `find: 'text-xs'` 가 소스와
  맞는 걸 보고 "코드모드가 왜 이 파일을 안 건드렸지?" 를 되짚었다. 가드를 의심한 게 아니라
  **모순을 하나 발견하고 끝까지 따라간 것**이 시작이었다.
- **수리**: 최상위·하위를 둘 다 명시 + 검사 대상 수 하한(`seen > 3000` / `> 7000`)을 둬서
  같은 회귀가 다시 나면 "0건이라 통과" 가 아니라 **빨간불**이 되게 했다.
- **주입**: `🕳️ 최상위 페이지가 다시 검사 밖으로 나간다` — 되돌려-검증 빨간불 확인.
- 🔎 **다음 세션이 볼 것**: 같은 모양의 glob 을 쓰는 가드가 더 있는지.
  `grep -rn "ls-files '.*\*\*/" scripts/ src/tests/` 로 1분이면 센다.

### ③ 주입 재조준에서 `replace` 까지 고쳐 결함을 지울 뻔했다
낡은 앵커 24건을 재조준하며 스크립트로 `find` 와 `replace` 를 **같이** 변환했다.
`replace` 는 **주입할 결함 그 자체**라, 정본 값으로 바꾸면 결함이 사라진다:

```
replace: 'text-[12.5px]'  →  'text-[12px]'    ← 결함이 정본이 됐다(주입이 헛돈다)
replace: 'py-3.5'         →  'py-4'           ← 〃
```

앵커 검사는 `find` 만 보므로 **초록불이 떴을 것**이다. 커밋 전에 diff 를 적대적으로 다시 읽다가
잡았다. ⇒ **재조준은 `find` 만.** `replace` 는 문맥 토큰(결함이 아닌 주변 클래스)만 따라간다.
