# 발송 실패한 교환권을 숫자에서 뺀다 — 보이되 세지 않는다

**대표 결정(2026-09-04)**: *"모두 다 해 · 재발송은 안해도 돼"* — 발송 실패분을 개수·금액에서 제외.
재발송(데이터 조치)은 **하지 않기로 확정**.

## 배경

`/api/vouchers/my` 의 KT 병합은 **발송 실패**를 이렇게 실어 보낸다(2026-06-17 — 카드가 실패 UI 를
그려 *"결제됐는데 안 왔다"* 를 알리라고):

```ts
status: (vo.status === 'sent' || vo.status === 'failed') ? 'unused' : 'processing',
kt_status: vo.status,
```

그래서 **`status` 만 보는 곳은 전부 문자조차 못 받은 것을 '사용 가능'으로 셌다.**
대표 계정(`voucher_orders` id 1 · 아메리카노 · `sent_at` NULL)이 실제로 그 상태다.

| 자리 | 배포 전 | 배포 후 |
|---|---|---|
| 마이 "내 교환권" | 1 | **0** |
| 교환권 지갑 "사용 가능 N장" | 실패분 포함 | 실패분 제외 |
| 교환권 지갑 상단 딜 합계 | 실패분 금액 포함 | 제외 |
| 실패 카드 자체 | 보임 | **그대로 보임** (새 '발송 실패' 그룹, 맨 위) |

## 원칙 — 숨기는 게 아니라 안 세는 것

카드를 지우면 *"결제됐는데 안 왔다"* 를 알 방법이 사라진다. 그래서 **화면에서는 맨 위**(발송 중보다도
앞), **숫자에서는 0**. 카드 안 가격(4,500딜)도 남긴다 — 실제로 결제한 금액이고 그게 있어야 문의가 된다.

## 고친 것

1. `shared/voucher-wallet.ts` — `isFailedGifticon(v)` = `kt_status === 'failed'` (판정 SSOT 한 곳).
2. `useMyCounts.ts` — `gifticon` 카운트에서 실패분 제외.
3. `MyGifticonsPage.tsx` — `owned`(=실패 제외)로 그룹·통계·합계를 계산, `failed` 는 자기 그룹으로.
4. `voucher.status.sendFailed` 6개 언어.

## 검증

`tsc 0` · 신규 **8건 pass**(지갑 페이지는 실제 렌더, 카운트는 `renderHook` — 대표 계정 실측 행을 픽스처로) ·
**주입 2건 각각 되돌려-검증 빨간불 확인** · guard-registry 124 · theme OK · file-size OK.

## 🩸 되돌려-검증이 구멍을 잡았다 (이게 이 작업에서 제일 값지다)

처음엔 지갑 페이지만 테스트했다. 그 상태에서 **`useMyCounts` 의 필터를 옛날로 되돌렸는데 5건이 전부
초록**이었다 — 대표가 지목한 "내 교환권 1" 이 정확히 그 값인데도. 훅 테스트 3건을 추가하고서야 빨갛게 됐다.
**가드는 깨뜨려 봐야 가드인지 안다.** (같은 파일에서 어설션도 두 번 틀렸다: 라벨이 히어로·카드에도 있어
`getByText` 가 늘 중복 매치였고, "카드 가격도 없어야 한다"는 잘못된 단정이었다 — 둘 다 테스트가 잡았다.)

## 이 수정이 못 막는 것

서버가 `kt_status` 를 **안 보내면** 실패분이 옛날처럼 '사용 가능'으로 돌아온다. 판정 근거가 그 필드
하나뿐이라 클라에서는 방법이 없다. 서버 계약이 바뀌면 여기도 같이 봐야 한다.
