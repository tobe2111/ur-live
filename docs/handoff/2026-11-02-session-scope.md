# [E2] 세션 = 작업 하나 — 남의 작업을 이어받지 않게 (2026-11-02)

대표: *"세션별로 분리를 하고 싶어도 계속 세션별 작업 분리가 안되는데? 다른 세션에서 기존 세션에서 작업하던 걸 가져오고 그래."*

## 원인 (실측)
- CLAUDE.md 가 *"새 세션 시작 시 반드시 `ls docs/handoff/ | sort -r | head -5` 로 최근 인계를 찾아 1~3건 열기"* 를 지시했다.
- 인계마다 *"다음 세션의 첫 액션"* 이 적혀 있다(최근 30건에 40회). 검사 메시지(`check-current-work-sync.mjs`)도 그렇게 쓰라고 가르쳤다.
- 세션이 동시에 여러 개 도는 지금 **최신 인계 = 다른 세션이 하던 일**이다 → 새 세션이 주제와 무관한 남의 할 일을 받아 실행.
- 예약 작업(점검 알림 4건 + 주간 보고)은 원인이 아니다 — 전부 **자기 세션**만 깨운다(`persistent_session_id` 실측).

## 바꾼 것
- CLAUDE.md 인계 절에 🧱 "세션 = 작업 하나" 4줄: 주제로 찾기(grep) · 남의 "첫 액션" 실행 금지(대표가 이름을 대서 시킬 때만) · 남의 브랜치·PR 손대지 않기 · 겹치면 세 줄 보고.
- 칸 이름 "다음 세션의 첫 액션" → **"이어받는 세션의 첫 액션"** (CLAUDE.md · 검사 메시지).
- `docs/CURRENT_WORK.md` 의 최신순 명령 → 주제 grep.
- `.claude/agents/dev.md` — 남의 PR·인계 루틴은 dev 역할 루틴 세션만.
- 가드 `src/tests/unit/session-scope-2026-11-02.test.ts`(4건) + 주입 `scripts/mutations/session-scope-2026-11-02.mjs` 5건 전부 빨간불 확인.

## 이어받는 세션의 첫 액션 (대표가 이 작업을 이어서 하라고 했을 때만)
- 판정(E4 에 해당): 머지 뒤 새 세션을 하나 열어 아무 작업이나 시키고, 그 세션이 **다른 주제의 인계를 실행하지 않는지** 본다. 레포는 행동을 못 본다.

## 틀렸던 판단
- 처음엔 예약 작업이 남의 세션을 깨우는 것을 의심했다 — 실측하니 전부 자기 세션 고정이었다.

## 못 하는 것 / 남은 것

- 옛 인계 파일의 "다음 세션의 첫 액션" 문장은 기록이라 고치지 않았다(🧱 절이 무력화한다).
