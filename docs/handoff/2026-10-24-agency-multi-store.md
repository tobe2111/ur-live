- 신규 `agency_products(product_id PK, seller_id, agency_id, created_by_staff_id)` — 행이 없으면 사장님 이용권.
- 신규 `src/worker/utils/agency-product-scope.ts` — 에이전시 좌석은 **기본 차단**, 허용목록(목록·등록·수수료 안내·매장 컨텍스트·사진 업로드 +
  자기 이용권 하나의 GET/PUT/DELETE·하위 화면)만 통과. 판정은 서명 claim 으로(DB 흔들려도 차단 유지). `storeSeatGuard` 에 배선.
- 가드가 건너뛰는 경로 셋도 막음: `/my-stores/summary` → `agencySummary`(자기 이용권 숫자) · 매장 알림 → 에이전시엔 빈 목록.

- 화면: 에이전시 판 = [오늘 · 우리 이용권] + [이용권 등록 · 관리] 하나(사용처리·주문·정산·전체 도구 제거, 딥링크도 허용 화면만).
  `SellerGroupBuyPage` 는 에이전시면 이번 달 매출·정산 대신 "우리가 맡은 이용권 · 판매 N". 사장님 `AgencyLinkCard` = 에이전시 목록(상태·맡은 이용권 수·끊기) + 한 곳 더 맡기기.

## 이번에 틀렸던/주의할 판단
- 처음엔 *"셀러 API 를 하나씩 에이전시 몫으로 고치자"* 로 생각했는데 수백 개라 하나만 빠져도 남의 매출이 보이고 에러가 안 난다 ⇒ **기본 차단 + 허용목록**으로 뒤집었다.
- `storeSeatGuard` 가 **건너뛰는** 경로(`/my-stores/*`)가 있어서 가드만 믿으면 요약 숫자가 매장 전체로 샜다 — 따로 막았다. 새 셀러 경로를 가드 스킵 목록에 넣을 땐 에이전시 분기를 같이 볼 것.
- 매장 알림(`dashboard_notifications`)은 에이전시별로 나눌 수 없어서 숨겼다(빈 목록). 지어내지 않는다.
