## ① 1차 측정이 헛돈 원인 (확정)

하네스의 **catch-all 이 `{ data: [] }`** 를 돌려줘서 일곱 화면이 전부 **빈 목록**으로 떴다.
빈 목록은 당연히 가로스크롤 0 · 잘린 글자 0 이므로 **"🟢 깨끗" 여섯 개**가 나왔다.

신설 `--trace-api` 가 그걸 한 줄로 보여 준다 — **정산 화면 하나가 `/api/*` 를 18곳 부르는데
하네스가 답하던 건 셋뿐이었다.**

## ④ 🔴 그 과정에서 찾은 실제 결함 — 정산 화면이 통째로 죽었다

`/seller/settlements` 만 ErrorBoundary 로 떨어졌다. 프로덕션은 `drop_console: true` 라 원인이
안 남는데, **`vite.config.ts` 의 그 한 줄을 잠깐 끄고 빌드하니** 바로 떴다:

```
TypeError: Cannot read properties of undefined (reading 'toLocaleString')
```

`DealBalanceCard` 가 `balance.total.toLocaleString()` 처럼 **응답 필드에 직접** 포매팅을 불렀다.
`if (!balance) return null` 가드는 **`null` 만** 막는다 — 빈 객체·배열·필드 누락은 통과하고,
그 순간 **카드 하나가 아니라 정산 화면 전체**가 날아간다.

CLAUDE.md 가 이미 금지한 패턴이다(2026-05-17 ₩NaN 사고에서 나온 룰) → `formatNumber` 로 교체.
뺄셈은 `safeMinus` 로(한쪽만 비어도 NaN 이 되지 않게). **유효한 숫자에서는 출력이 종전과 같다.**

> ⚠️ **라이브에서 터지는 것은 못 봤다.** 재현은 하네스이고 거기선 스텁이 `{ data: [] }` 를 줘서
> `balance` 가 배열이 된다. 라이브 API 는 제대로 된 객체를 준다 — 고친 것은 **깨지기 쉬움**이다.

### 결재문이 남긴 질문에도 답이 나왔다

*"목록 API 하나가 실패하면 정산 화면 전체가 날아가는가?"* → **아니다.**
`useApiQuery` 에 `throwOnError`/suspense 가 없다. 그래서 이건 쿼리 실패가 아니라 **렌더 예외**였다.
