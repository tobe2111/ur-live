# 딜을 얼마나 쓸지 고른다 — 2026-09-13

대표 신고(같은 문장 안의 두 번째 절): *"딜을 쓰고 결제할지, 딜 일부만 쓰고 결제할지 등 선택도 안돼."*
앞 절(토스 결제 실패)은 **PR #1418 로 먼저** 처리했다(대표 확정 *"결제 수리 먼저, 선택 UI 는 이어서"*).

## 종전에 무슨 일이 일어나고 있었나

부분결제는 **이미 켜져 있었다** — 라이브 `platform_settings.voucher_partial_deal_enabled = true`.
그리고 서버는 **말없이 가진 딜을 최대한** 카드 청구액에서 뺐다. 사용자는

- 고를 수 없었고,
- 그 사실을 **결제창에 가서야** 알았다(16,500원짜리를 눌렀는데 5,300원이 떠 있다).

고를 수 없는 것도 문제지만 **말 안 하고 내 돈을 쓰는 것**이 더 문제다.
서버 `resolvePartialDealPlan` 은 `requested` 를 **이미 받고 있었다**. 없던 것은
**고르는 화면과 그 값을 보내는 배선**뿐이다.

## 무엇을 했나

| 층 | 변경 |
|---|---|
| 서버 `/join` | body 에 `deal_use?: number\|null` → `resolvePartialDealPlan(..., { requested: deal_use })`. **안 보내면 종전과 byte-동일**(최대한) |
| 서버 신규 | `GET /api/group-buy/deal-plan/:productId?qty=N` — 읽기 전용. 잔액·상한·총액·게이트 상태를 준다 |
| 화면 | `DealUseChooser` — 접힌 한 줄 `딜 N · 카드 M원` + `변경`. 펼치면 [최대로 쓰기 / 직접 입력 / 안 쓰기] |
| 배치 | 모바일 고정 바 **CTA 위** · PC `DealPurchaseBox` 도 같은 슬롯(`dealSlot`) |

**숫자는 전부 서버가 준 것만 쓴다.** 2026-09-04 audit log 가 이미 값을 치른 규칙이다 —
*"화면이 잔액으로 추정하면 게이트가 꺼진 순간 그 안내가 거짓말이 된다."*
게이트가 꺼져 있으면 `enabled=false` 가 와서 **블록이 통째로 안 뜬다**.

## 🩸 내가 처음에 틀린 것 두 가지 (다음 세션이 같은 걸 밟지 말라고)

1. **고르는 자리를 구매 버튼 *아래*에 뒀다.** 순서가 거꾸로이고, 모바일 결제 바는
   `fixed bottom-0` 이라 **딜이 없는 사람에게도 영구히 130px** 를 먹는다.
   ⇒ 접힌 한 줄(≈30px)로 바꾸고 CTA **위**로 올렸다. 접혀 있어도 그 한 줄이
   무슨 일이 일어날지 말하므로 "말 안 하고 쓰는" 문제는 펼치지 않아도 사라진다.
2. **PC 를 통째로 잊었다.** PC(lg+)는 하단 바가 아니라 `DealPurchaseBox` 를 쓴다.
   그대로 뒀으면 **PC 사용자는 종전대로 말없이 딜이 빠지는 상태**로 남았고, 에러가 안 나서
   아무도 몰랐을 것이다. ⇒ `dealSlot` prop 신설.

그리고 **내가 쓴 순서 검사 자체가 헛돌았다** — `page.indexOf('<DealUseChooser plan=')` 가
**PC 박스를 먼저** 잡아서, 모바일에서 위아래가 뒤집혀도 초록이 떴다.
모바일 고정 바 구간(`fixed bottom-0 inset-x-0`)을 잘라 그 안에서만 순서를 보도록 고쳤다.
주입 하나도 처음엔 `hidden` 속성을 심었는데 **순서 검사는 그걸 못 본다** — 실제 결함 클래스
(요약 줄이 숫자를 안 말함)로 재조준했다.
