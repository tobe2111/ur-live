# 이용권을 딜로도 살 수 있게 — 그리고 이미 열려 있던 문을 닫는다

**대표 방향** (2026-08-31): *"현금으로 정산받을 땐 수수료 10%이고, 딜로 교환권, 이용권은 공짜로."*
+ *"계속 진행해줘."*

## 🔑 이 변경의 정체는 "기능 추가"가 아니다

`group-buy.routes` join 의 상품 조회가 **`voucher 카테고리 OR deal_only=1`** 를 함께 매칭한다.
그래서 **서버는 원래부터 이용권에도 `payment_method:'deal'` 을 받고 있었다** — 화면이 안 내놨을
뿐, 직접 POST 하면 통했다. 정산·원장·환불 대칭도 이미 전부 붙어 있다.

⇒ 이 PR 이 넣은 게이트는 **기능을 여는 스위치인 동시에 그 열린 문을 닫는다.**
기본 OFF 라 머지되는 순간 이용권 딜 결제가 서버에서 400 으로 거절된다.

## 무엇을 넣었나

| | |
|---|---|
| 서버 게이트 | `platform_settings.voucher_deal_payment_enabled === 'true'` (기본 OFF). `deal_only !== 1` 일 때만 적용 → **교환권 무영향** |
| 클라 플래그 | `VOUCHER_DEAL_PAYMENT_ENABLED = false` (`GB_ENGINE_ENABLED` 선례의 2겹 게이트) |
| 화면 | 상세 하단에 보조 버튼 `딜로 결제 (보유 N딜)` — **플래그 + 로그인 + 잔액 ≥ 금액** 일 때만. 기본 결제수단은 그대로 카드 |
| 운영 | `OPS_GATES` 등록 + `platform-settings-validation` 화이트리스트 + 스테이징 **S9** |

## 🐛 타입체커가 잡은 진짜 버그

`handleJoin(payWithDeal = false)` 로 바꾸자 `onClick={handleJoin}` 이 타입 에러를 냈다.
그대로 뒀으면 **MouseEvent 가 `payWithDeal` 로 들어가 truthy** 가 되어
**모든 이용권 구매가 딜 경로로** 갔을 것이다. `() => handleJoin()` 으로 두 자리를 감쌌고,
테스트가 `onClick={handleJoin}` 패턴 자체를 금지한다.

## ▶ 활성 순서 (셋을 벌리지 말 것)

1. `/admin/kt-alpha` → 소비자 마진 **20 → 0** + "기존 상품 가격 재계산" (**PR #1268 배포 선행**)
2. `/admin/commission-settings` → 딜 보너스 **20 → 0** + 현금 정산 수수료 (**PR #1269**)
3. `voucher_deal_payment_enabled = true` + 클라 플래그 `true` (배포)

🔴 **2번 없이 3번을 켜면 안 된다.** 보너스 20% 가 이용권 마진(5~10%)보다 커서
**팔릴수록 유어딜이 건당 8~14원 적자**다. 교환권은 소비자 마크업 20% 가 보너스를 상쇄해
괜찮았고, 이용권엔 그 상쇄가 없다.
