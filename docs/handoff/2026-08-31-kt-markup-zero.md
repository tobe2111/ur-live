# 교환권을 원가(정가)로 — 마진 0% 를 삼키던 `|| 20` 수리

**대표 지시** (2026-08-31): *"원가로 그냥 너가 되돌려줘. 다 정가로."* + *"딜 보너스는 일단 0으로 가자."*

## 무엇을 발견했나 (라이브 실측)

교환권 소비자 판매가 = `gift_catalog.real_price × (1 + kt_alpha_consumer_markup_pct/100)`, 마진 20%.
그런데 **KT 가 주는 할인이 사실상 0** 이었다.

| | 실측 |
|---|---|
| 판매가 / KT원가 | 1.20 (설정값 그대로) |
| KT원가 / 정가 | **0.9918** — 할인 없음 |
| **판매가 / 정가** | **1.19** |
| 정가보다 비싼 활성 상품 | **2,257 / 2,260** |
| KT 할인율 분포 | 2,065개 **0%** · 195개 평균 9.5% |
| 교환권 누적 발송 | **3건 / 5,400원** |

5,000원 쿠팡캐시 교환권이 **6,000딜**이었다. 안 팔린 게 아니라 팔릴 수 없는 가격이었다.

## 🔴 그리고 마진을 0 으로 내릴 수가 없었다

세 자리가 `Number(x) || N` 이라 **`0` 이 falsy 로 삼켜졌다**. 저장(PATCH)은 `Number.isFinite`
검증이라 0 을 **통과시킨다** → **저장은 되는데 아무도 안 읽는** 조용한 실패.
에러가 없어서 "슬라이더를 0으로 내렸는데 가격이 그대로"로만 보인다.

| 자리 | 삼킨 결과 |
|---|---|
| `admin-kt-alpha/settings.ts:112` 재계산 | 0 저장해도 **20% 로 재계산** |
| `admin-kt-alpha/catalog.ts:77` 상품 담기 | 새로 담는 상품에 20% |
| `seller-settlements.routes.ts:404,486` 셀러 축 | 0 저장해도 5% — ⚠️ **이 PR 에서 못 고쳤다**(아래) |

⚠️ **정정**: 처음엔 `AdminKtAlphaPage.tsx:122` 도 깨졌다고 봤는데 **아니다**. D1 은
`platform_settings.value` 를 TEXT 로 주므로 값이 문자열 `'0'` 이고, JS 에서 `'0'` 은 truthy 라
`|| '20'` 을 통과한다. 화면은 멀쩡했다.

## 고친 것

- 신규 SSOT `src/shared/kt-alpha-markup.ts` — `resolveMarkupPct(raw, default)` +
  소비자(20)/셀러(5) 래퍼 + `consumerPriceMultiplier`. **0 은 유효값**, 미설정·오염만 기본값, 범위 clamp.
- 호출부 4곳을 헬퍼 경유로. 현행값(20·5)에서는 **동작 byte-동일** — 0 을 넣었을 때만 달라진다.
- `src/tests/unit/kt-alpha-markup-zero.test.ts` 18건.
  R1 0 유효 / R2 기본값 보존 / **R3 호출부가 헬퍼를 쓰는지** / **R4 `|| 숫자` 재유입 차단**.
  R3·R4 는 주석을 지우고 검사한다(2026-08-01 "주석에만 남아도 통과" 교훈).
- `check-guard-mutations.mjs` 주입 2건 등록. **되돌려-검증 완료** — settings.ts 를 `|| 20` 으로
  되돌리니 R3·R4 두 건이 빨간불, 복원하니 18/18 초록.

검증: tsc 0 · `npm run build` 0 · 단위 18 pass · 주입 지도 594건 성함.

## ⚠️ 셀러 축은 이 PR 에서 뺐다 (CI 가 막았다)

같은 `Number(x) || 5` 결함이 `seller-settlements.routes.ts` 에도 있어 함께 고쳤는데,
**파일크기 래칫이 차단했다** — 그 파일이 baseline 1,076줄에 동결돼 있어 임포트 한 줄과
주석 두 줄(+3)도 못 늘린다. 처방은 리베이스라인이 아니라 **분리**이고, 그건 이 PR 의 범위 밖이다.

**현재 저장값이 5 라 라이브 영향은 0** 이다. 다만 **그 축을 0 으로 내리려는 순간 조용히 5 로
튕긴다** — 소비자 축에서 방금 겪은 것과 똑같은 사고다. SSOT 에 `resolveSellerMarkupPct` 는
남겨 뒀고(배선만 안 됨), 함수 주석과 테스트 SITES 주석에 그 사실을 적어 뒀다.

⇒ **별도 작업**: `seller-settlements.routes.ts` 를 분리해 줄이고, 그때 두 자리를
`resolveSellerMarkupPct` 로 배선 + 테스트 SITES 에 추가.

## ▶ 다음 세션의 첫 액션 — 배포 후 대표 또는 세션이 할 것

이 PR 이 **머지·배포된 뒤에야** 마진 0 이 실제로 먹는다. 순서를 지킬 것:

1. 어드민 `/admin/kt-alpha` → 소비자 마진 **20 → 0** 저장
2. 같은 화면 **"기존 상품 가격 재계산"** → 2,260개가 `real_price × 1.00` 으로
   (판정: 5,000원 쿠팡캐시 교환권이 **5,000딜**)
3. **곧바로** `influencer_deal_bonus_pct` **20 → 0**

⚠️ **2번과 3번 사이를 벌리지 말 것.** 두 개의 20% 가 서로를 상쇄해 유어딜 손익 0 을 만들고 있다.
한쪽만 내리면 커미션 100원 의무에 120원을 지출한다. 지금 미사용 딜이 4명 17,350딜뿐이라
최악이 3천원 수준이지만, 구조로는 그게 이용권에서 발견한 것과 같은 구멍이다.

## 이번에 틀렸던 판단

1. **"마크업 20% 는 KT 도매 할인에서 나온다"** 고 전제하고 대표에게 *"딜 보너스 20% ↔ 마크업 20%
   가 상쇄되어 유어딜 손익 0"* 이라고 보고했다. 유어딜 장부로는 맞지만, **인플루언서 구매력
   기준으로는 +20% 가 통째로 사라진다**(120딜로 정가 100원어치). 제안서 08번에 "20%가 더
   붙습니다"로 이미 나가 있다 — 정책 확정 후 반드시 고칠 것.
2. 클라이언트도 깨졌다고 보고했다가 정정했다(위 ⚠️). 문자열 `'0'` 은 truthy 다.

## ✅ 2026-09-02 21:44 KST — 라이브 적용 완료 (그런데 이 PR 로 간 게 아니다)

**수리는 다른 세션의 PR #1317 (`claude/kt-alpha-markup-zero`) 로 머지·배포됐다.** 같은 결함을

`resolveKtConsumerMarkupPct`)은 이 PR 과 **동작이 같다** — 미설정·비숫자만 기본 20, `0` 은 0, 0~100 clamp.

### 라이브에서 버그를 재현했다 (문서상 추정이 아니다)

`Number('0') || 20` 이 삼키는 그 자리다. 21:41 배포(main `325f91e11`, #1317 포함) 후

### 순서를 붙인 이유

마크업 20% 와 딜 보너스 20% 가 상쇄돼 유어딜 손익이 0이었다. **한쪽만 내리면 양방향 모두 손해**다 —
마크업만 0이면 커미션 100원 의무에 120원어치를 내주고, 보너스만 0이면 인플루언서가 정가의 83%만
산다. 그래서 재계산이 1.00 을 찍은 것을 확인한 **직후 같은 분에** 보너스를 내렸다.
