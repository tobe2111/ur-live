## 🐛 배포 후 실측에서 드러난 것 — "더보기"의 진짜 원인 (2026-08-27, PR #1221 머지 뒤)

`6ba98cd` 배포 직후 라이브를 재 보니 **"지금 인기 이용권" 더보기 버튼이 아예 안 보였다.**
`/api/sections` 실측:

```
 2  지금 인기 이용권   more_href='/?sort=popular'   ← 버튼 없음
 4  주말에 떠나는 숙소  more_href='/stays'          ← 정상
```

**원인**: `safeInternalPath()` 는 경로 검증기이면서 **쿼리 제거기**다(2026-05-01, `?error=…` 누적 차단).
`ref`/`aff`/`invite` 만 화이트리스트로 살리고 나머지는 버린다. 그래서 `/?sort=popular` → `/`.

⚠️ **이번에 틀렸던 판단 (제일 값진 부분)**
2026-08-19 에 같은 신고("더보기 눌러도 반응 없음")를 받고 *"정규화는 경로에만 하고 쿼리를 다시 붙인다"*
고 고쳤는데, **`safeInternalPath` 의 결과에서** 쿼리를 찾았다 — 이미 버려진 뒤라 붙일 게 없었다.
**그 수정은 한 번도 동작한 적이 없고, 소스만 고쳐진 것처럼 보였다.** 그 위에 08-27 세션이
"죽은 링크(`/`)는 숨긴다"를 얹자 납작해진 `/` 가 그 규칙에 걸려 **버튼이 통째로 사라졌다.**

⇒ 교훈: **문자열이 소스에 있는지로는 이 클래스를 못 잡는다.** 세 번 다 "고친 코드가 거기 있다"로는
통과했을 것이다. 그래서 순수 함수(`src/components/home/section-more-href.ts`)로 빼고
**실제 입력 → 출력**을 테스트로 고정했다(`src/tests/unit/section-more-href.test.ts` 7건).
08-19 버그를 그대로 재현하면 3건이 빨간불이 된다(확인함).

**수정**: 순서를 뒤집는다 — ① 먼저 `?`/`#` 로 쪼개고 ② 경로만 `safeInternalPath` + `resolveConsumerAlias`
③ 쿼리는 따로 소독(`SAFE_QUERY_RE`)해 다시 붙인다. 외부 URL·`/login`·`/auth/*` 차단은 그대로.
가드 2건 등록(493개, 되돌려-검증 빨간불 확인).
