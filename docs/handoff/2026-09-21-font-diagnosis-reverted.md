# 2026-09-21 — 로더 워드마크: 내 진단이 틀렸고, 고쳤다던 것을 되돌렸다

대표 신고: *"로딩 중에 urdeal 로고도 안보이고"* → *"셀러대시보드에서 로더가 문제 있는거야"*

## 무슨 일이 있었나

1. **오진**: 로더에 브랜드 점만 뜨는 것을 **웹폰트 FOIT** 로 봤다. 근거는 대표 스크린샷에서
   점이 정중앙이 아니라 **+69px** 오른쪽이라는 것 — "글자가 자리는 차지하는데 안 칠해졌다".
2. `display=swap` → `optional` 한 단어를 바꿔 배포했다 (PR #1527, 머지 `25d3866`).
3. **배포 후 판정하려고 재 봤더니 전제가 통째로 틀렸다.**

## 전제를 뒤집은 측정

폰트를 영영 안 오게 막아 두고 워드마크 박스의 **칠해진 픽셀**을 셌다(Chromium):

```
대기(ms)    20    50    80   110   150   250   500
swap      1626  1626  1626  1626  1626  1626  1626   (38.3%)
optional  1626  1626  1626  1626  1626  1626  1626   (38.3%)
```

**모든 시점에서 완전히 동일하다.** `swap` 의 블록 구간은 명세상 "extremely small" 이고
Chrome 실측 ~0 이라 **폴백 글자가 즉시 그려진다** — 그게 `swap` 의 존재 이유(anti-FOIT)다.

⇒ **폰트는 대표가 본 증상의 원인이 아니다.**

## 되돌린 이유

근거가 없어졌고, `optional` 은 폰트가 늦으면 **그 로드에서는 아예 안 쓴다**(다음 로드용으로만 받는다).
로더는 1초쯤 떠 있으므로 첫 방문자가 로고를 Poppins 로 거의 못 보게 된다 — 얻는 것 없이 잃는다.
잠금 파일이므로 승인된 상태(`swap`)로 환원했다.

## ❌ 원인은 아직 못 찾았다 — 코드로 배제한 후보 넷 (다시 파지 말 것)

| # | 후보 | 왜 아닌가 |
|---|---|---|
| ① | App.tsx Suspense 폴백이 흰 글자 | `/seller\|admin\|ads` 는 `DashboardLoader`(**forceLight**) → 잉크 `#16181C` on `#F4F5F7` |
| ② | `seller-light-theme` 안에서 `dark:` 가 이김 | `tailwind.config` darkMode 변형이 `:not(.seller-light-theme *)` 로 **이미 차단** |
| ③ | 워커 `#root` 정적 로더 | 대시보드는 `needsRootBlank` → `#F4F5F7` 빈 오버레이뿐, **워드마크 자체가 없다** |
| ④ | `BrandLoader` 소비자 기본값 | `fsBg`(`bg-white dark:bg-[#11141C]`)와 글자색이 **같은 방향** → 대비 안 깨짐 |

## 다음 세션의 첫 액션

대표에게 물을 것 — **(a)** 정확히 어느 화면·URL 인가 **(b)** 그때 테마가 다크였나
**(c)** 가능하면 새 스크린샷.

⚠️ **이 컨테이너 브라우저로는 재현 못 한다**: 라이브 자산을 못 받아 청크 자가복구가 발동하고
`chrome-error://chromewebdata/?__cb=…` 로 튄다(`urdeal.kr` HTML 자체는 200 이다). TLS 는
`ignoreHTTPSErrors: true` 로 넘어가지만 그 다음 단계에서 막힌다.

## 같은 PR 에서 살아남은 것

**저장 버튼을 편집 화면 위로**(`SellerProductEditPage`)는 그대로 유효하다 — 대표의 명시 요청이고

*"칠해졌는가"* 는 **전혀 구분하지 못한다**(투명해도 자리는 그대로다).
