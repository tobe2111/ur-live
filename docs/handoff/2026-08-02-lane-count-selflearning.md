# 회차당 레인 수를 스스로 잰다 — 손으로 잰 상수의 마지막 자리 (2026-08-02)

## 다음 세션의 첫 액션

배포 뒤 **한 시간만 기다렸다가** 어드민에서 두 값을 본다. 이 두 줄이 이번 변경의 유일한 판정이다.

```bash
# 1) 학습기가 실제로 자리를 옮겼는가
curl -sS "https://live.ur-team.com/api/admin/cron-heartbeats" -H "Authorization: Bearer $TOK" -H "User-Agent: $UA"
#    → ads:* 중 err=Worker exceeded CPU time limit 가 몇 건인가.  기대: 회차가 지날수록 0 으로 수렴
```
```sql
-- 2) platform_settings 두 키 (어드민 D1 조회 권한이 있으면)
SELECT key, value FROM platform_settings WHERE key IN ('ads_lanes_learned','ads_tick_history');
--    ads_lanes_learned  = {"cap":N,"clean":c,"pinned":p}   ← N 이 6 에서 내려갔으면 학습이 돌고 있다
--    ads_tick_history   = 회차별 [ran,n,ok,fail,miss,off]  ← fail·miss 가 줄어드는지
```

**판정**: `cap` 이 4~5 로 내려가고 `fail+miss` 가 0 에 가까워지면 성공.
`cap` 이 6 그대로면 → 회차 요약이 안 쌓이는 것(부모가 flush 전에 죽음)이니
`ads_tick_history` 가 비었는지부터 본다. **비어 있으면 학습기 문제가 아니라 관측 문제다.**

### 그리고 이것부터 봐라 — 인플루언서 **수집이 10시간째 0건**이다 (08-02 23:07 KST 실측)

```
                  22:45 KST → 23:07 KST (22분)
  nb_unmeasured      21,733 →   21,661   −72     ← 보강(측정)은 살아 있다
  with_contact        6,624 →    6,651   +27     ← 연락처도 나오고 있다
  total              43,597 →   43,597    +0     ← 🔴 수집은 완전히 멈췄다
  run.last_run   2026-08-02 04:02:17 UTC = 13:02 KST  (10시간 전, total_runs 254 고정)
```
`ads:collect` 하트비트는 **22:00 KST 에 `started=true`, ms=0** 인데 `last_run`·`total_runs` 가 안 움직였다
= **시작만 하고 아무것도 못 남기고 끝났다.** 같은 창(14:00~18:01 KST)에 CPU 사망 4건이 있었다.

⇒ 이 PR 의 학습기가 겨냥하는 바로 그 증상이다. 배포 후 **`total` 이 다시 오르는지**가 진짜 판정이고,
안 오르면 원인이 레인 수가 아니라 `collect` 자체에 있다(그때는 `/__ads/collect` 를 수동 POST 해
반환값을 직접 본다 — 그게 이 환경에서 얻을 수 있는 유일한 예외 원문이다).

> ⚠️ **보강 팬아웃의 자기 차단은 별건이고, 지금은 치명적이지 않다.**
> `ads:enrich-influencer-fanout` 이 `prev_landed=false`(*"직전 팬아웃 이후 레인 스냅샷이 그대로다"*)로
> 스스로를 막고 있는데, **DO 알람 레인이 대신 보강을 돌리고 있다**(위 −72 가 그 증거).
> 다만 *"직전이 착지 안 하면 다음도 안 띄운다"* 는 규칙은 원리상 **자기 잠금**이 될 수 있다 —
> cron 경로가 유일한 실행자가 되는 순간(알람이 멈추면) 영영 안 풀린다. 다음 세션의 검토 대상.

## 무엇을 왜 고쳤나

### 발견 — 손으로 잰 상수가 **또** 낡아 있었다

`FREE_LANES_PER_TICK` 는 사람이 "한 정각의 `ok=true` 개수"를 세어 넣는 값이다.
08-01 에 8 이었고 08-02 에 6 으로 내렸는데, **내린 그날 라이브가 이렇다**(KST, 어드민 `cron-heartbeats`):

```
  14:00  collect-neis              err=Worker exceeded CPU time limit
  16:01  reclassify-company        err=Worker exceeded CPU time limit
  17:01  maintenance?phase=quality  err=…
  18:01  collect-company           err=…
```

같은 창에서 **인플루언서 수집도 멈춰 있었다** — `ads:collect` 하트비트는 22:00 에 `started=true` 인데
`run.last_run` 은 **13:02 에 멈춰** 있다(9.7시간). 오늘 누적 3,077건이 대부분 13:02 이전에 들어왔다는 뜻이다.
즉 CPU 붕괴가 *값을 만드는 레인까지* 같이 끌고 갔다.

⇒ **사람이 재는 한 항상 한 발 늦는다.** 풀은 계속 커지고 레인은 계속 무거워지는데, 측정은 누가
이상을 눈치챈 날에만 일어난다. 죽은 레인의 그 회차 일은 통째로 버려지는데 **알림은 아무 데도 안 간다.**

### 그리고 유료 전환에서 같은 상수가 **더 크게** 틀린다

`PAID_LANES_PER_TICK = 64` 에는 *"사실상 상한 없음"* 이라고 적혀 있었다. 그런데 이 축의 한도는
요금제가 아니라 **인보케이션당 CPU** 이고 **유료 기본값도 30초**다(`limits.cpu_ms` 를 따로 올려야 한다).
서비스 바인딩 피호출자의 CPU 는 호출자 몫이라 부모 비용은 `동시 레인 수 × 각자의 CPU` 로 쌓인다.
⇒ **요금제만 바꾸면 첫 정각에 64 로 뛰어 그대로 무너진다.** 대표 요구사항("유료 전환 시 자동으로
이상적으로")의 정반대가 코드에 박혀 있었던 셈이다.

### 수정 — AIMD 제어 루프 (`src/worker-ads/lane-aimd.ts`)

```
  해로운 회차(죽음·기록없음)  →  ×0.75, 최소 1 은 반드시 줄인다   ← 빠르게 물러난다
  깨끗한 회차 2연속           →  +1 (천장까지)                    ← 천천히 되찾는다
```
- 입력은 **#969 이 만든 회차 요약**(`ads_tick_history`)이다. 관측을 먼저 만들어 둔 게 여기서 쓰인다.
- 우선순위 **명시 env > 학습값 > 요금제 기본값** — `ADS_LANES_PER_TICK` 이 학습을 통째로 이긴다(= 킬 스위치).
- 🔑 **요금제는 천장만 바꾼다. 시작값은 안 바꾼다.** 유료로 전환해도 배운 자리(예: 6)에서 이어
  올라가 하루~이틀에 걸쳐 *그 계정에서 실제로 가능한* 지점을 스스로 찾는다. 붕괴 없이.
- 총량만 정한다 — 도메인 비율(`DOMAIN_SHARE`)·측정 몫(`MEASURE_SHARE`)은 대표가 정하는 값이라 무접촉.

## 이번에 틀렸던 판단 / 함정

1. **`ads:sweep-kakao-phone` 이 4.3일 정지 — 기아인 줄 알았다. 아니다.**
   `/__ads/sweep-kakao-phone` 은 **수동 HTTP 라우트**이고 스케줄러가 띄우는 건
   `/__ads/sweep-kakao-chain` 이다. 07-29 의 수동 실행 기록이 남아 있을 뿐인데
   하트비트 화면이 `stale: true` 로 칠해 **정지처럼 보인다.**
   ⚠️ 이 화면은 "스케줄된 레인"과 "수동으로 한 번 눌린 라우트"를 구분하지 않는다 —
   다음 세션이 또 여기서 오진할 수 있다.

2. **`off`(예산 밖 하트비트)를 해로 세면 학습기가 영원히 바닥에 눌린다.**
   DO 알람·우회 레인이 자기 하트비트를 따로 남기므로 라이브에서 실제로 `띄운 7 · 기록 9` 가 나온다.
   테스트로 못박아 뒀다(`ads-lane-aimd.test.ts`).

3. **주입 하네스를 2분 타임아웃으로 돌리다 중단시켰다.** 종료 훅이 복원해 줬지만,
   중단 직후 스냅샷에는 주입된 코드가 남아 있었다 — **중단했으면 반드시 `git diff` 로 확인할 것.**
   (하네스 전체는 2분을 넘는다. 백그라운드로 돌려라.)
