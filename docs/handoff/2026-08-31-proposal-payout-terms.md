배포된다. 대외 문서라 틀리면 곤란하고, 방향이 **실제보다 나쁘게 읽히는** 쪽이었다.

## 코드에서 확인한 사실 (문서가 아니라 코드·라이브 D1)

| | 현금 수령 | 딜 수령 |
|---|---|---|
| 지급 문턱 | `available_amount >= 100,000` | **`> 0` (1원부터)** |
| 원천징수 | 사업 3.3% / 기타 8.8% | **없음** |
| 보너스 | 없음 | **+20%** |

- 문턱: `cron/influencer-payout.ts:94` `AND (payout_method = 'deal' OR available_amount >= ?)`
- 딜 적립: `marketing.routes.ts:772~786` — `influencer_deal_bonus_pct` 적용 후 `creditFreePoints`
  (무상 버킷. 유상으로 두면 [현금정산 → 딜 → 재출금] 세탁 루프가 열린다는 2026-07-05 주석)
- 라이브 실측: `influencer_deal_bonus_pct = 20` · `influencer_payout_min = 100000`

## ⚠️ 다음 세션이 알아야 할 구조 문제

**덱의 편집 원본이 repo 에 없다.** 슬라이드 본문(`bodies/*.html`)·셸 CSS·빌더는 세션 스크래치
(`/tmp/urdeal-proposal/`)에만 있고 repo 에는 **빌드 산출물 1개**(255KB, 캡처가 base64 로 박힌 HTML)만
있다. 이 세션에서는 스크래치가 살아 있어 원본을 고쳐 재빌드했지만, 다음 세션은 그 HTML 을 직접
고쳐야 한다(텍스트는 평범한 HTML 이라 가능하다. base64 는 `<img src>` 안에만 있어 방해하지 않는다).

⇒ 덱을 또 손볼 일이 있으면 **빌드 원본을 repo 에 넣는 것을 먼저 검토**할 것. 오늘 하루에만
세 번 고쳤다(#1248 잉크 · #1244 디자인 개편 · #1252 정산 조건).
