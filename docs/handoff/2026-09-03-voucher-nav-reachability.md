# 이용권 관리로 가는 길이 없었다 (2026-09-03)

## 대표 신고
- *"이용권 관리가 되어야 할 것 같은데?"*
- *"이용권 관리에 대한 통합 페이지가 따로 없어보여. 셀러 대시보드 왼쪽 카테고리에도 없지 않아? 분석해봐"*
- *"이용권 수정도 안되는구나?"*
- (상품 상세 스크린샷) *"이거 아이디? @store_mt9rvbhg1i6 이건 보여줄 필요가 없을 것 같은데?"*

## 결론 — 페이지는 있었다. 닿을 수가 없었다.

`/seller/group-buy`(목록·발행현황·매장 PIN·**수정 진입**)가 곧 이용권 관리 통합 페이지다.
세 신고가 **한 뿌리**에서 나왔다:

1. **그룹 전체가 `mode: 'store'`** → `isStoreOwner` 가 아닌 셀러에겐 통째로 숨김.
   그런데 **이용권 *등록*은 `common`**(2026-08-23 대표 지시) → **만들 수는 있는데 그 뒤가 없는** 상태.
   라이브 실측(D1 읽기): 대표 개인 셀러 2개(`tobe2111`·`tobe211111831`)가 **둘 다 `influencer`**,
   `store_owner` 는 홍대돈까스(id 14) 하나뿐. 즉 대표가 개인 계정으로 보면 **정말로 메뉴가 없다.**
2. **수정 버튼은 그 페이지 안에만 있다.** 상품 목록(`/seller/products`)은 `SELLER_STORE_ONLY_MODE`
   로 nav 에서 빠져 있어, 관리 페이지가 숨으면 **이용권을 수정할 화면 경로가 0** 이 된다.
3. 매장 단독 셀러의 심플 nav 에선 보이긴 했는데 이름이 **"내 딜"** — 찾는 단어가 아니다.
4. 덤: 이용권 하나를 운영하는 일이 **세 화면에 흩어져** 있었다(목록 / 사용처리 / 후기 인증).

## 고친 것
- `seller-nav.ts`: 그룹 `seller.layout.groupbuy` → **`seller.layout.vouchers`(🎟️ 이용권)**.
  **이용권 등록 + 이용권 관리** 두 항목(대표 *"이용권 등록이랑 같이 이용권 통합 관리 페이지"*) —
  등록을 홈 그룹에서 이 묶음으로 옮겼다. 둘 다 `common`.
  대행 등록 승인·숙소는 `store` 유지(숙소는 원래 매장 전용).
- **`SellerVoucherTabs`(신규)**: 목록 / 사용처리(QR) / 후기 인증을 **한 페이지처럼** 묶는다.
  nav 는 '이용권 관리' 하나, 페이지 안에서 탭 이동(`SellerProductTabs` 와 같은 방식) — 라우트는 그대로라
  딥링크가 안 깨진다.
  🔴 **`/seller/voucher-orders` 는 여기 안 들어간다** — 이름이 비슷해 처음에 넣었다가 되돌렸다.
  그건 **KT 교환권(기프티콘) 발송 이력**이고 교환권 ≠ 이용권(명칭 SSOT). 대표에게도 정정 보고함.
- `SellerLayout.tsx` `GROUP_ORDER`: 이용권 그룹을 **홈 바로 다음**으로(등록과 관리가 붙어 있어야 찾는다).
- `SellerSimpleNav.tsx`: **"내 딜" → "이용권 관리"**, 등록 바로 다음 자리, `also` 에 `/seller/products/`
  추가(수정 화면에서도 이 메뉴가 켜진다).
- **`src/shared/seller-handle.ts`(신규 SSOT)**: 서버 자동 발급 아이디(`store_<base36>` ·
  어드민 수기 `store_<전화번호>`)만 가린다. 사람이 고른 아이디는 그대로 — 그게 그 셀러를 부르는 이름이다.
  적용: `GroupBuyDetailPage` 셀러 줄 · `ProductCard` 폴백. ⚠️ 프로필 버튼의
  `navigate('/profile/{username}')` 는 **표시가 아니라 경로**라 그대로 둔다.
- 6개 언어 라벨 추가(`seller.layout.vouchers` · `seller.nav.voucherManage` · `seller.voucherTabs.*`).

### 통폐합(대대적 리팩토링)은 **아직 안 했다** — 다음 세션 몫
검색은 *"못 찾는다"* 를 즉시 완화하지만 *"페이지가 너무 많다"* 를 풀지는 않는다. 통폐합은 화면을
지우는 일이라 **대표 확인 없이 진행하면 안 된다**(무엇을 남길지가 곧 운영 정책이다).
제안 순서: ① 위 28개 중 실사용 13개를 어디로 접을지 표로 만들어 대표 승인 →
② 탭 통합(이용권처럼) → ③ 라우트는 남기고 nav 에서만 제거(가역).
