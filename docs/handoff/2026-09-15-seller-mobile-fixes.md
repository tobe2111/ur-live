## 무엇이 달라졌나 (사용자 관점)

- 폰 셀러 홈에서 **내 매장이 다시 보이고, 거기서 매장을 추가**할 수 있습니다.
- 내 매장 카드에서 **매장 관리(위임·삭제·이관)** 로 바로 갈 수 있습니다.
- 내 매장 목록이 **먼저 오는 대로 바로** 뜹니다. 종전엔 다른 조회가 끝날 때까지 기다렸습니다.
- 이용권 화면에서 **상담 버튼과 등록 버튼이 겹치지 않습니다.** 이용권이 없을 때 등록 버튼이 둘 뜨던 것도 하나로.

## ① 로딩 — 두 요청이 서로를 기다리고 있었다

```js
// 종전
const [storesR, ctxR] = await Promise.allSettled([my-stores, stores/context])
if (storesR …) setStores(…)          // ← 둘 다 끝나야 여기 온다
```

`loading = stores === null` 인데 `setStores` 가 **둘 다 끝난 뒤**에 돌았다. 매장 목록이 이미 손에 있어도
좌석 프리필(`stores/context`)이 느리면 그동안 계속 스피너다. axios timeout 이 15초라 최악 15초.

**수정**: 각 요청이 자기 결과만 따로 반영한다. 그리고 `loading` 은 목록이 없거나 **등록 매장이 0인데
좌석 판정이 아직일 때만** 참이다 — 등록 매장이 이미 있으면 게이트가 어차피 false 라 기다릴 이유가 없다.

곁다리로 `seatReady` 가 `null` 하나로 **'판정 중'과 '판정 실패'를 뭉개고** 있었다(fail-open 이 조기 발동해
STEP 1 게이트가 떴다 사라질 수 있다) → `undefined`(판정 중) / `null`(실패) / boolean 셋으로 분리.

⚠️ **무한 루프는 아니었다**(`onGateChange` 는 `useCallback([])` 로 안정). 처음에 그쪽을 의심했는데 아니었다.

## ④ 버튼 겹침 — 전역 FAB 과 페이지 바가 같은 띠를 썼다

```
하단 탭 60px │ 하단 고정 바 60~124px │ 상담 FAB 96~136px   ← 정면 충돌
```

FAB 은 `SellerLayout` 의 전역이고 바는 페이지별이라, 페이지마다 손으로 맞추면 다음 페이지에서 또 겹친다.
⇒ 신규 부품 `SellerBottomBar` 가 **스페이서 + 바 + `body.seller-has-bottom-bar` 신호**를 함께 맡고,
FAB 은 `index.css` 에서 그 신호를 보고 비켜 준다. FAB 의 Tailwind `bottom-24`(96px 고정, safe-area 무시) 제거.

🔢 **CSS 와 TS 에 같은 숫자가 둘 있다**(60 = `SELLER_TABBAR_H`, 64 = `SELLER_BOTTOM_BAR_H`). 이 레포가 반복해
당한 클래스라 **테스트가 세 값의 일치를 고정**한다 — 한쪽만 바꾸면 에러 없이 조용히 다시 겹친다.

덤: 이용권이 0건이면 고정 바를 안 그린다. 그때는 빈 상태 카드가 이미 같은 버튼을 세워 **한 화면에 둘**이었다.
