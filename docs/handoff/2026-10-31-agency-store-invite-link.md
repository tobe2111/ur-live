# 매장 영입 링크 — 늘 보이는 버튼 · 카톡 카드 · 링크로 가입하면 바로 연결 (2026-10-31)

대표: *"매장 영입 링크 만들기 이렇게 버튼 필요하지 않을까? 카카오톡으로 보면 예쁘게 보이게끔 하거나. 매장이 있어도 계속 초대가 필요해"*
· *"그 링크로 들어와서 가입하면 바로 에이전시와 매장이 연동되게 하면 되잖아."*

## 1. 다음 세션의 첫 액션 (E4 — 배포 후)
1. 카톡 스크래퍼 길: `curl -sS -A 'facebookexternalhit/1.1; kakaotalk-scrap/1.0' https://urdeal.kr/store/agency/$(printf 'a%.0s' {1..64}) | grep -o '<title>[^<]*</title>\|name="robots" content="[^"]*"'`
   → 제목 `에이전시가 매장 운영을 맡겠다고 해요 - 유어딜` + `noindex`. (배포 전 실측: 유어딜 홈 제목 + `index, follow`)
2. 실제 카톡방에서 [카카오톡으로 보내기] 카드 — 에이전시 이름·[매장 맡기기] 버튼이 뜨는지(카드는 카카오가 그린다 — **대표만** 판정).
3. 매장 없는 카카오 계정으로 링크 → [매장 등록하고 맡기기] → 등록 → 마이에서 "○○ 에이전시에 매장을 맡겼어요" 토스트, 에이전시 화면 '맡은 매장'에 바로 뜨는지.

## 2. 완료분
- `AgencyStoresPanel` — 판 위에 늘 [매장 영입 링크 보내기](관리자만). 종전엔 매장 0곳일 때만 빈 화면에 있고 한 곳이라도 생기면 에이전시 줄 맨 끝.
  대신 등록은 별도 줄·시트(`매장 대신 등록`)로 분리.
- `agency-stores-model` — `canManage` 첫 값을 캐시된 역할로(버튼이 응답 뒤 끼어들어 판을 밀지 않게).
- `AgencyInviteLinkCard` — 살아 있는 링크가 없으면 열자마자 생성 · [카카오톡으로 보내기](feed 카드, 에이전시 이름) → 기기 공유 → 복사 폴백.
- `shared/agency-store-invite.ts` — 카드 문구·토큰 규칙·쿼리 이름 SSOT. 워커가 `registerDynamicSurfaceSeo` 로 초대 주소에 초대 카드 + **noindex**(동적 표면 타입에 `noindex` 추가).
- `StoreAgencyInvitePage` — 매장 없는 사장님은 `/store/new?agency_invite=<토큰>` 으로. 목록이 있어도 [새로 등록하고 맡기기].
- `StoreClaimPage` — 토큰 검증 후 "○○ 에이전시가 보낸 링크" 안내 · 등록 직후 같은 맡기기 API(`/api/store-agency-invite/accept`) 호출. 중개 등록(주인 아님)은 그 전에 빠진다.
- 가드 `agency-invite-link-2026-10-31.test.tsx` 12건 + 주입 9건 전부 빨간불 확인.

## 3. 이번에 틀렸던 판단
- 처음 "버튼은 이미 있다(새로 만들 필요 없다)" 고 답했다 — 코드상 존재는 맞았지만 **대표 계정은 에이전시가 아니라 마이에 구역 자체가 안 보인다**는 점, 매장이 생기면 사실상 숨는다는 점을 가볍게 봤다.
- 카톡에 주소를 붙이는 길이 홈 카드 + `index, follow` 였다는 것은 라이브를 찔러 보고서야 알았다(코드만 봤으면 몰랐다).

## 4. 남은 결정
- 마이 '에이전시' 구역은 **에이전시 계정에만** 뜬다(이 브라우저에 에이전시 로그인이 있거나, 카카오 계정이 에이전시와 이어져 있을 때). 손님 마이에 "에이전시 만들기" 입구를 둘지는 대표 판단.
- 매장에서 말로 불러 줄 6자리 코드는 안 만들었다(사장님 입력 자리가 새로 필요 — 필요하면 별건).
