## 원인 — 히어로가 아니라 그 다음 단계

React 는 `createRoot`(비-hydrate)라 마운트 시 `#root` 를 비운다. 그 순간 상세 페이지 **청크는 아직
오는 중**이라 `App.tsx` 의 `<Suspense fallback>` 이 먼저 그려지는데, 그 폴백이
`BrandLoader fullScreen` = **`fixed inset-0` 불투명 오버레이**다. 2026-07-18 에 대표가
*"로딩 순간 유어딜 로더 말고도 보임"* 이라고 신고해서 **일부러 불투명하게 만든** 바로 그것이,
이번엔 방금 도착한 사진을 덮었다. 대표가 2026-07-01 에 금지한 **"로딩 화면 2~3개"**.

> 🧭 **교훈**: 전날 고친 것은 [서버 → React] 한 단계였고, 실제 경로는 **[서버 → 폴백 → 페이지]
> 세 단계**였다. 단계를 하나 빼먹고 "이어진다"고 판단했다. 프레임 캡처가 아니었으면 몰랐다.

## 무엇을 했나 — 같은 HTML 을 다시 만들지 않는다. **같은 노드를 들고 있는다**

1. 워커 첫 화면을 `<div id="ur-first-screen">` 로 감싼다 (`worker/utils/detail-ssr-body.ts`).
2. `main.tsx` 가 **`createRoot` 직전에** 그 DOM 노드를 참조로 잡는다 (신규 `src/lib/boot-first-screen.ts`).
3. 소비자 폴백 `PageLoader` → `BootFirstScreenLoader`(`components/brand/BrandLoader.tsx`) — 노드가
   있으면 `appendChild` 로 **그 노드 그대로** 도로 붙이고, 그 아래에만 인라인 로더(34dvh, FCP 위상동기).

⇒ 재파싱 0 · 재다운로드 0 · **픽셀 차이가 구조적으로 0**. 문자열을 다시 조립하면 두 벌이 갈린다.

### 두 가지 함정 (다음에 비슷한 걸 만들 때)

- 🩸 **노드를 미리 `remove()` 하면 안 된다.** 떼면 [떼어냄 → React 커밋] 사이에 페인트가 끼어 한
  프레임 사라질 수 있다 — `root.render()` 는 즉시 커밋을 보장하지 않는다. React 의 컨테이너
  비우기와 폴백 삽입은 **같은 커밋**이라 그 사이엔 페인트가 없다. (주입 매니페스트가 이걸 고정한다.)
- 🩸 **`useEffect` 가 아니라 `ref` 콜백으로 붙인다.** effect 면 첫 프레임이 빈 채로 그려질 수 있다.

### `App.tsx` 는 줄 수가 안 늘었다 (1112 동결)

import 줄에 named export 를 얹고(`import BrandLoader, { BootFirstScreenLoader } from …`)
`PageLoader` 본문 1줄을 교체했다 — **+0줄**. 래칫을 리베이스라인하지 않았다.
