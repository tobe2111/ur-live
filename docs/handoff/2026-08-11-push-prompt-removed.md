# 웹푸시 권유 팝업 제거 (2026-08-11)

대표: **"알림을 켜시겠어요? 팝업 삭제해줘"**

## 무엇을 지웠나

로그인 10초 뒤 화면 하단에 뜨던 웹푸시 권유 배너(soft prompt) — `PushNotificationSetup.tsx`.
그 배너가 이 컴포넌트의 **유일한 UI** 였으므로 컴포넌트는 이제 headless 다(`return null`).

## 무엇을 **안** 지웠나 (중요)

컴포넌트 자체는 남겼다. 배너는 *"새로 켜자"* 는 권유일 뿐이고, 나머지 코드는
**이미 알림을 켠 사람의 구독을 살려 두는 자가치유**다:

```
Notification.permission === 'granted'  →  8초 뒤 getSubscription → /api/push/subscribe 재전송
```

브라우저가 push endpoint 를 교체하거나 서버가 410 으로 구독행을 지웠을 때 이게 다시 붙인다.
같이 지우면 **어드민 시스템 경보 푸시**(`/admin/system-monitoring`)가 조용히 두절된다 —
2026-07-01 에 정확히 그 사고를 고치면서 넣은 코드다.

`requestPermission()` 호출도 함께 제거했다. 배너가 없어져 **제스처 진입점이 사라졌는데**,
제스처 없는 `requestPermission` 은 Safari 가 무시하고 Chrome 이 quiet-UI 로 강등하는 최악 패턴이라
되살리면 안 된다(2026-06-12 에 그 이유로 soft-prompt 로 바꿨던 것).

⇒ 지금 새로 알림을 켜려는 사용자는 **브라우저 주소창의 사이트 설정**에서 허용하면 된다.
그러면 위 자가치유가 다음 방문에 구독을 붙인다.

## 복원

배너 JSX 는 파일 하단에 **주석으로 통째 남겨 뒀고** i18n 키(`push.prompt*`, 6개 언어)도 안 지웠다.
되살리려면 그 블록을 컴포넌트 안으로 되돌리고 `showBanner` state · `snooze()` ·
`subscribe(fromGesture)` 인자를 함께 복원한다. (문구를 지우면 복원할 때 문안을 다시 짜게 된다.)
