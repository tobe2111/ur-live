## 🔴 다음 세션이 알아야 할 것

### 트래픽/페이로드가 이 변경의 핵심 리스크였다
카드 50개 × 갤러리를 그냥 실으면 첫 화면 요청도, 응답 크기도 몇 배가 된다. 그래서 **두 겹**으로 막았다:
- **클라**: 커버만 즉시 로드, 사용자가 **실제로 넘긴 장면**만 `<img>` 생성(`seen` 집합). hover 만으로는 아무것도 더 안 받는다.
- **서버**: 커버 중복 제거 후 **최대 3장**(`CARD_GALLERY_MAX`). materialized cron 도 **저장 시점에** 같은 규칙 — 안 자르면 캐시 row 가 원본 전량을 안고 그 크기를 캐시 hit 마다 파싱한다.

⚠️ **배포 후 실측 필요**(이 환경에선 못 잰다): `/api/group-buy/products` 응답 크기 · 홈 첫 화면 이미지 요청 수.

### 이번에 틀렸던 판단
- 위임 가드를 `/GroupBuyFeedCard/` 로 썼더니 **import 줄 때문에** 카드를 `<div>` 로 바꿔도 초록이 떴다.
  → `<GroupBuyFeedCard\b`(JSX 렌더)로 교정. **"파일에 이름이 있다"는 배선 증거가 아니다** — 이 레포가 반복해 당한 클래스.
- `mapped` 에 반환 타입을 안 붙였더니 TS 가 유니온으로 좁혀 `p.id` 접근이 깨졌다 → `: Record<string, unknown>` 명시.

## (2차) PC 메인 잉크 색면 — 대표 확정 결정

대표가 그루폰 홈 전체 스크린샷을 주며 *"PC 메인을 이 그루폰과 거의 유사하게. 특히 배경 초록색이
마음에 드는데 우리만의 색으로 덮으면 될듯. 혼자 판단하지 말고 결정할 건 나에게 얘기해"*.

**결정 방식**: 색을 글로 묻지 않고 **라이브 홈에 4색을 실제로 입혀 스크린샷**(Playwright CSS 주입)해
비교하게 드렸다 — A 로즈풀 / B 딥로즈 / C 잉크 / D 웜틴트.

| 항목 | 대표 확정 |
|---|---|
| 배경색 | **C. 잉크 `#1A2C42`**(브랜드 딥네이비) |
| 범위 | **PC 메인만** (다른 페이지·모바일 불변) |
| 추가 요소 | 섹션 흰 패널 · 큰 카피 히어로 · 카드 우상단 찜 하트 (3개 모두) |
| 모션 | *"버튼 나타날 때 그라데이션·페이드 같은 효과"* → 등장 페이드+스케일, hover lift, 찜 pop |

**구현**
- `index.css` 토큰 4종 — `.ur-home-panel`(색면 위 흰 패널) · `.ur-lift`(카드 부양) ·
  `.ur-appear`(컨트롤 등장 페이드+스케일) · `.ur-pop`(찜 피드백). 전부 `prefers-reduced-motion` 존중.
- `PcHomePage` 루트 배경 잉크 + [상단 헤더] [딜 그리드] 를 패널로. `HomeSections` 섹션도 같은 패널.
- `HomeHeroDefault` — 바탕을 색면과 같은 잉크로, 카피 34→46px, **하단 페이드**로 색면과 이어지게.
- `WishlistHeart`(신규) — 기존 `useWishlist` 훅 재사용(카드 50개여도 네트워크 1회), 낙관적 토글 +
  실패 롤백, 비로그인은 `/login?returnUrl`. **`<Link>` 안이라 preventDefault 필수**(캐러셀과 같은 함정).
- ⚠️ 색면 위에서 **자체 배경 없는 블록은 글자가 묻힌다** — `RegionLinkGrid`(gray-900 제목)를 흰 밴드로.
  `PcHomeAppBand`(자체 다크 배경)·`SiteFooter`(흰 배경)는 그대로 둬도 무방함을 코드로 확인.

## 범위 밖(의도적)
- **숙소 상세**(`StayDetailPage`)는 손대지 않았다 — 이미 16:10 와이드 히어로 + 스와이프 갤러리라
  그루폰과 크게 어긋나지 않는다. 2단으로 펼 가치가 있는지는 대표 판단(객실 사진은 객실 카드에도 있다).
- **교환권 상세**(`/vouchers/:id`)도 그대로 — KT 기프티콘은 대개 사진 1장이라 2단이 빈 칸을 만든다.
