## 2. 🗺️ 지도 바텀시트 — 얼어붙는 제스처 + 당겨서-새로고침

대표: ***"지도 페이지에서 스크롤 올리고 내리는게 편하지 않아. 새로고침으로 적용되거나.."***

**셋이 겹쳐 있었고 셋 다 조용하다.**

1. **위임이 죽었다(가장 큼).** 모바일에서 핀을 고르면 시트가 **통째로 언마운트**되고
   (`{(!selected || isLgViewport) && …}`), 닫으면 React 가 **새 DOM 노드**를 만든다. 그런데 터치
   위임 effect 의 deps 가 전부 불변(ref 객체 · `useCallback`)이라 **다시 돌지 않았다** → 리스너가
   떨어져 나간 옛 노드에 남았다. 비-full 스냅은 `touch-action:none` 이라 네이티브도 없어서
   **리스트가 통째로 얼었다.** ⇒ *"핀 한 번 눌렀다 닫으면 그 뒤로 시트가 안 움직인다."*
   **수정**: `sheetRef` 를 콜백 ref 로 바꿔 노드를 state 로 들고, 두 위임 effect 가 그 노드에 의존.
2. **얼어붙는 분기가 하나 더.** 종전 조건 `(위로 && 비-full) || (아래로 && scrollTop<=0)` 의 나머지는
   `mode='scroll'`(네이티브 위임)인데 비-full 엔 그 네이티브가 꺼져 있다 → 손가락이 움직여도 아무 일 없음.
   ⇒ 비-full 에서는 **방향 무관** 시트가 받는다(당근/네이버지도와 같다).
3. **당겨서-새로고침.** `overscroll-behavior` 가 리스트에만 `contain` 이라, 리스트 **밖**(필터 바 ·
   핸들 여백)에서 아래로 당기면 문서까지 올라가 브라우저가 새로고침했다.
   ⇒ 지도가 떠 있는 동안만 `html` 에 `overscroll-behavior-y: none`(언마운트 시 복원).

덤: **시트 몸통 아무 데나 잡아도 끌린다**(종전엔 28px 핸들 하나뿐). 탭은 6px 문턱을 못 넘어 버튼이
그대로 눌리고, `|dy| > |dx|` 라 카테고리 칩의 가로 스크롤을 안 가로챈다.

가드 `map-sheet-gesture-2026-09-30.test.tsx` 14건 + 주입 7건 **전부 빨간불 확인**.

## 3. 🔎 검색 제안 — 덮지 않고 대신한다

대표: ***"검색하는데 연관검색? 처럼 나오는거 별로야"*** + 레퍼런스 화면 → ***"이런 식으로 나오는거 좋다"***

**둘이 겹쳤다.**
- **떠 있는 카드가 결과를 가렸다** — 대표 스크린샷에서 제안 하나가 첫 결과를 통째로 덮고 있었다.
- **제안이 결과의 복사본이었다** — 서버(`/suggestions` 별칭)가 `products.name` **통짜**만 줘서
  "돈가스" → *"홍대 돈가스 버크셔 프리미엄 돈가스 1인 세트"* 이고 바로 아래 첫 결과가 같은 문자열.

**수정**: 서버는 **인기 검색어 → 매장명 → 상품명** 순으로 짧은 검색어를 준다(매장명이 핵심 —
제안이 결과와 다른 일을 한다). 클라는 떠 있는 드롭다운을 없애고 **결과 자리**에 전체폭 행 목록
(`SearchSuggestPanel`, 친 글자 굵게)을 넣는다.

🔒 **눌러서 0건이 나오면 안 된다** — 매장명 제안은 `SEARCH_COLUMNS` 에 `restaurant_name` 이 있어야
성립한다(짝을 가드가 검사). 세 쿼리가 **같은 이용권 스코프**를 쓴다.
🔒 **blur 로 닫지 않는다** — 모바일에서 행을 탭하면 blur 가 click 보다 먼저 나서 아무 일도 안 일어난다
(자동완성 최다 버그). 닫는 건 *선택·제출·지움* 셋뿐이고, 덮지 않으니 닫을 이유도 없다.

가드 `search-suggest-panel-2026-09-30.test.tsx` 10건 + 주입 8건 **전부 빨간불 확인**.

## 🩸 이번에 틀렸던 판단 — **전부 픽스처였다. 주입 러너가 세 번 잡았다**

1. **`setSheetSnap={() => {}}` 인라인**이 `finish` 의 identity 를 매 렌더 바꿔, 위임 effect 가 매 렌더
   다시 붙었다 → **재마운트 결함이 저절로 가려졌다.** 실제 페이지는 `useState` 세터라 안정적이다.
   ⇒ 픽스처를 모듈 스코프 상수로. **"페이지와 같은 안정성"을 픽스처가 흉내 내야 같은 것을 잰다.**
2. **가로 제스처 시험의 dy 가 4px** 이라 6px 문턱에서 걸러져 **축 판정에 닿지도 않았다**.
3. **"인기 검색어를 낸다" 를 테이블 이름으로만** 검사해서 `WHERE 0` 으로 무력화해도 통과했다
   → **술어(`WHERE keyword LIKE ?`)와 바인딩까지** 본다.

그리고 슬라이스 앵커 함정 하나 더: `card.indexOf('  return (')`(2칸)은 **조기반환의 `    return (`
안에도 매치**돼 slice 가 뒤집혀 빈 문자열이 됐다. 끝 앵커는 `'\n  return ('`.

# 🔎 후속 — "검색기능도 지금 완벽한지 확인해줘" (같은 날, 라이브 실측)

대표 지시로 검색을 **끝에서 끝까지** 재 봤다. 위 3번을 고친 뒤에도 **구멍이 셋 더** 있었고,
셋 다 에러를 안 낸다. 전부 라이브 D1/API 실측으로 확인했다.

## ① 제안 범위가 결과 범위와 **반대**였다 (교환권 검색이 통째로 빈다)

검색은 어디서 왔느냐에 따라 범위가 **정반대**다(`SearchPage` 의 `?scope=`):
- 기본 → **이용권만** (2026-07-16 대표 *"검색은 무조건 이용권만"*)
- `scope=exchange` → **교환권만** (2026-08-08 대표 — `/vouchers` 의 검색 버튼이 붙여 보낸다)

그런데 제안 엔드포인트는 **이용권 스코프를 하드코딩**하고 있었다. ⇒ 교환권 검색창에서는
제안이 **항상 비거나**, 뜨더라도 눌러서 **0건**이다. 실측:
```
GET /api/search/suggestions?q=스타벅스 → []      ← 교환권 2,260건이 통째로 빠져 있다
GET /api/search/suggestions?q=부산     → []
```
⇒ `scope` 를 **클라 → 라우트 → 빌더**로 잇고, 두 분기가 결과 화면의 분기를 미러한다.
⚠️ exchange 분기엔 카테고리 `?` 자리가 없으므로 **바인딩도 안 넘긴다**(개수가 어긋나면 D1 이
거절하고 catch 가 삼켜 조용히 빈 제안이 된다).

## ② `popular_searches` 테이블이 **라이브에 없다** — 세 기능이 조용히 죽어 있었다

```
D1: SELECT COUNT(*) FROM popular_searches → no such table: popular_searches (SQLITE_ERROR)
GET https://urdeal.kr/api/search/popular  → {"success":true,"data":[]}
```
migration `0273_search_logs_popular.sql` 이 **정의해 두고도 적용되지 않았고**(이 레포의 알려진
D1 마이그레이션 부채), `repair-schema` 에도 없어 **아무도 만들지 않았다.** 죽어 있던 것:
- `/api/search/popular` → 검색 빈 화면·결과 하단의 **"인기 검색어" 가 영영 안 뜸**
- 자동완성의 인기 검색어 소스 → 항상 빈 배열
- 0건일 때 **오타 보정**(`suggested_query`) 후보 source → 비어 있음
- 쓰기(`ProductRepository.logSearch`)도 try/catch 라 **에러 없이** 계속 실패

⇒ `repair-schema` 에 두 테이블 + 인덱스 3개 추가(migration 0273 과 동등, `IF NOT EXISTS`).
⚠️ **배포 후 `/api/_internal/repair-schema` 를 한 번 태워야 생긴다.** 그 전까지 ①의 인기 소스는
계속 빈 배열이고(다른 소스로 동작), 생긴 뒤에는 검색할수록 쌓인다.

## ③ 키 입력마다 요청 — 디바운스가 없었다

제안 로드가 `inputValue` effect 에서 **바로** 나갔다. 한글 IME 는 자모마다 입력 이벤트를 내고
제안 한 번이 **D1 쿼리 셋**이라, "돈가스" 다섯 타에 15 쿼리다. 이 레포는 이미 D1 일일 읽기
한도에 닿아 소비자 API 가 전부 500 난 적이 있다(2026-09-02). ⇒ **180ms 디바운스**.
패널 열림/닫힘은 **디바운스 밖**이다 — 글자를 지웠는데 목록이 남아 있으면 안 된다.

## 📏 왜 제안 소스 순서가 이런가 (라이브 실측 2026-09-30)

| | 건수 | 매장명 보유 |
|---|---|---|
| 이용권(기본 스코프) | 359 | **359 (100%)** |
| 교환권(exchange) | 2,260 | **0** |

기본 스코프에서는 **매장명이 주력**이고(모든 상품이 갖고 있다), 교환권에서는 자연히 비어
**상품명**이 답이다. 인기 검색어는 ②가 풀리기 전까지 어느 쪽에서도 안 나온다.

## ✅ 확인했고 **멀쩡한 것** (다시 파지 말 것)

- 검색이 `restaurant_name` 을 실제로 찾는다(`SEARCH_COLUMNS`) → 매장명 제안이 0건을 안 만든다.
- 결과 스코프 필터(`deal_only` 1차 가드 + `isVoucherCategory`)는 category 누락 응답에도 견딘다.
- 최근 검색은 localStorage(`recent_searches_v1`, 최대 10)라 테이블과 무관 — 정상 동작.
- 무한 스크롤(`useInfiniteQuery` + IntersectionObserver)·정렬 4종·0건 화면 — 이상 없음.

## 남은 것 (안 한 것)
- **오타 보정**(`suggested_query`)은 ②가 풀려 데이터가 쌓여야 의미가 생긴다. 그전엔 항상 null.
- 검색 **빈 입력** 화면은 종전 칩 목록 그대로(대표 레퍼런스는 행 목록) — 이번 신고 범위 밖.

# 🕸️ 그 뒤 CI 가 잡은 것 — **로컬 그물이 시험 뿌리 하나를 통째로 못 보고 있었다**

위 검색 변경을 푸시한 뒤 CI 가 `TypeError: onPanelChange is not a function` 으로 빨간불.
`SearchHeader` 에 필수 prop 을 더했는데 그것을 렌더하는 시험이 있었다 —
**`tests/unit/components/search/SearchHeader.test.tsx`**.

## 왜 로컬에서 못 봤나 (구멍이 **둘** 겹쳤다)

1. **시험 뿌리가 둘인데 그물은 하나만 봤다.** `vitest.config` 의
   `include: ['tests/**', 'src/tests/**']` 인데 `pre-push-tests.mjs` 는 `src/tests` 만 grep 했다.
   ⇒ `tests/` 아래 시험은 **로컬에서 한 번도 안 돌았다.**
2. **별칭 import 는 검색어에 안 걸렸다.** 그 시험은 경로를 문자열로 안 들고
   `import SearchHeader from '@/components/search/SearchHeader'` 로만 쓴다(확장자 없음).
   `pre-push-search-terms.mjs` 머리말이 이 한계를 *"못 잡는 것"* 으로 **적어 두고 있었다** —
   적어 두는 것만으로는 안 막힌다.
3. **tsc 도 못 봤다**: `tsconfig.json` 의 `include` 가 `src/**/*` 라 `tests/` 는 타입체크 밖이다.

## 옛 시험을 지우지 않고 **옮겨 적었다**

# 🩸 세 번째 CI 왕복 — 그리고 그물의 남은 눈먼 자리 둘

위 교훈("못 보는 것을 적지 말고 막아라")을 적은 **바로 그 푸시가 또 CI 에서 빨간불**이 났다.
같은 클래스인데 원인이 다르다. 둘 다 막았다.

## ① 새 부품이 4px 격자를 어겼다 — 검색어로는 **원리상** 못 고른다

`SearchSuggestPanel.tsx`(신규)에 `py-2.5` 를 썼다. 아이콘 원이 36px 라 행이 56px 가 되는데
그 10px 가 `#1568` 이 세운 격자 밖이다. 잡은 건 `consumer-type-scale-2026-09-29.test.ts` —
**`src/components/**` 를 글롭으로 훑는** 가드다.

🔑 **그 시험은 본문에 내 파일 이름을 안 들고 있다.** 새 파일이면 더더욱(아직 아무도 그 이름을
모른다). 검색어 매칭으로는 **영원히** 못 고른다 — 이건 튜닝 문제가 아니라 원리 문제다.
그리고 이 한계는 `pre-push-tests.mjs` 머리말이 *"그건 CI 담당"* 이라고 **적어 두었던** 것이다.

**처방(규칙 6)**: `src/` 가 하나라도 바뀌면 **트리를 읽는 시험 전부**를 합친다
(`scansTree` — `globSync`·`readdirSync`·`ls-files … src/`).

| | 실측 |
|---|---|
| 트리를 훑는 시험 | **48개 / 29초** |
| 합친 뒤 pre-push 시험 | 64 → **101개 / 50초** (게이트 전체 ~70초) |
| 되돌려-검증 | `py-2.5` 를 다시 넣으니 **로컬 50초에 빨간불** (직전엔 CI 6분) |

⚠️ **일부러 과하게 고른다.** 글롭 대상이 `src/` 인지 가리려면 파싱이 필요한데
`readdirSync(SOME_DIR)` 처럼 변수를 쓰는 시험이 많아 그 파싱은 **조용히 적게** 고른다 —
이 그물이 반복해 당한 실패 모드가 정확히 그거다. ⚠️ `src/` 변경이 없으면 안 돌린다
(문서만 고친 푸시에 29초를 물릴 이유가 없다 — 그쪽은 규칙 ② 가 이미 고른다).

## ② `.d.mts` 가 낡아 커밋이 막혔다 — 그리고 **오진을 유발했다**

①을 고치며 `scansTree` 를 더했더니 pre-commit tsc 가 `TS2305: has no exported member` 로 막았다.
`allowJs` 가 꺼져 있어 **tsc 는 `.mjs` 를 아예 안 읽고** 손으로 쓴 `scripts/*.d.mts` 만 읽는다.

🩸 **한참 헤맸다**: 파일에서 **나중에** 선언된 `searchTermsFor` 는 멀쩡히 잡히고 **앞에** 있는
새 export 둘만 안 잡혀서, *"TS 가 파일을 중간부터 못 읽나"* 로 오진했다. 실제로는 읽는 파일
자체가 달랐다. ⇒ 가드를 하나 더: **`scripts/*.d.mts` 는 형제 `.mjs` 의 export 를 빠짐없이 선언한다.**

⚠️ 그 가드의 첫 판이 `declare` 를 **필수**로 봐서 멀쩡한 두 파일을 위반이라고 신고했다
(`.d.mts` 에서 `declare` 는 선택이다). **정상 코드에 빨간불을 내는 가드는 결국 꺼진다** —
이 레포가 `check-input-text-color` 로 두 달 겪은 길이라, 헛도는 가드만큼 위험하다.

## 🩸 내 tsc 확인이 헛돌았다

`npx tsc --noEmit | tail -5; echo "tsc exit=$?"` 로 **초록을 봤다고 믿었다**. `$?` 는 `tail` 의
종료코드다 — tsc 가 뭘 하든 0 이다. 실제 로그엔 그때 이미 `TS2305` 가 있었다.
⇒ **파이프 뒤의 `$?` 를 판정에 쓰지 말 것**(`PIPESTATUS[0]`, 또는 파이프 없이 파일로).

## 무엇이 달라졌나

| 무엇 | 파일 |
|---|---|
| 행 여백 `py-2.5` → `py-3` (60px, 격자 위 · 엄지 표적) | `SearchSuggestPanel.tsx` |
| 규칙 6 — `scansTree` + `TREE_SCAN_PATTERN`(판정은 순수 모듈) | `scripts/pre-push-search-terms.mjs` |
| `src/` 변경 때 트리 시험을 검색어 결과에 합침 | `scripts/pre-push-tests.mjs` |
| 새 export 2개 선언 | `scripts/pre-push-search-terms.d.mts` |
| 트리 판정 4건 + `.d.mts` 계약 2건 (+ 뿌리 시험 **재조준**) | `pre-push-roots-2026-09-30.test.ts` |
| 주입 5건 추가 · 낡은 앵커 1건 재조준 | `scripts/mutations/pre-push-gate.mjs` |

**뿌리 시험 재조준**: grep 이 둘이 되면서 *"파일 어딘가에 `'tests'` 가 있는가"* 판정이 헛돌게 됐다
(한쪽만 좁혀도 다른 줄 때문에 초록). ⇒ **grep 호출 하나하나**가 모든 뿌리를 보는지 검사한다.
