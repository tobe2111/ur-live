# 판정: 빈자리 9 → 0, cap 2 → 12(무료 천장). 그리고 하루치 첫 정직한 숫자

**2026-08-08 23:23 KST** · #1090(잠정 회차) 배포 후 판정 · 대표 질문 *"무료로 안정적으로 하루 몇 건?"*

## 1. 수리 판정 — 문제가 재발하지 않았다

```
이력 24회차(08-08 00:00~23:00 KST, 밤 포함 만 하루)
  빈자리 0 · fail 0 · miss 0 · 잠정(p:1) 0
  cap 12  ← FREE_LANES_CEILING(무료 천장)

수리 전 같은 밤 구간: 빈자리 9회차, cap 6 → 2(바닥)
```

⚠️ **정확히 말하면 "안전망이 작동했다"가 아니라 "안전망이 필요 없었다"다.**
`p:1` 이 0 이라는 건 **꼬리가 한 번도 안 죽었다**는 뜻이다(죽었으면 잠정 항목이 남는다).
즉 이 하루로 증명된 것은 *"문제가 재발하지 않았다"* 이지 *"안전망이 실제로 받아냈다"* 가 아니다.
안전망의 실효는 **다음 꼬리 사망 때** 처음 확인된다.

⚠️ **왜 꼬리가 더는 안 죽는지는 설명 못 한다.** cap 이 2 → 12 로 올라 부하는 오히려 늘었는데도
죽지 않았다. 배포로 인한 재시작 효과인지, 다른 축(8/5 의 CPU 수리들)이 누적된 것인지 미확정.
⇒ **"고쳤으니 안 죽는다"고 단정하지 말 것.** 관측을 계속하는 게 맞다.

## 2. 하루치 수집량 — 첫 정직한 숫자

```
24시간(08-08)   인플루언서 6,257 + B2B 16,804 = 23,061건
```
| | 24h 합 | 패턴 |
|---|---|---|
| 인플루언서 | 6,257 | 시간당 122~366 으로 **평탄**(DO 알람) |
| B2B | 16,804 | **홀수시 덩어리** 1,6xx · 짝수시 10~100 (공공 API 벌크) |

⚠️ **"영구 하루 23,061건" 이라고 말하지 말 것.** 3주 일별이 17배로 요동쳤다(07-21 12,533 ~ 07-30 1건).
정직한 표현: *"정상 상태로 돈 하루는 23,061건. 유지되는지는 며칠 더 봐야 한다."*

📌 참고 — 이전 관측치와의 비교(둘 다 불안정 구간이었다):
  8/5 인플루언서 5,583/일 · B2B 14,663/일 → 합 ≈ 20,246
  이번(안정 구간) 23,061 = **약 +14%**

## 3. 새로 알게 된 것 — cap 이 무료 천장에 닿았다

`cap 12 = FREE_LANES_CEILING`. 학습기가 무료에서 갈 수 있는 **끝까지 올라갔다.**
⇒ 이 축(회차당 레인 수)으로는 **무료에서 더 못 늘린다.** 앞으로 발굴량을 늘리려면
다른 축(키워드 활성화·유료 전환)이어야 하고, 그 둘은 아직 아무도 안 쟀다.

2. 며칠치 일별 수집량을 더 모아야 "23,061 이 유지되는 값인가"에 답할 수 있다
