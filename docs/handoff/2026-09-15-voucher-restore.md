# 삭제한 이용권을 되돌리는 길 (2026-09-15)

대표: *"수정 및 삭제 버튼은 보여. 삭제도 되네."* → *"계속 해줘"*

## 대표가 눌러 본 덕에 드러난 구멍

전날 붙인 삭제 버튼(#1430)을 대표가 시험 삼아 눌렀다. **잘 지워졌다 — 그리고 되돌릴 방법이 없었다.**
라이브 실측(그 직후, D1):

```
2888 홍대돈까스   is_active=0 · status='DELETED' · 2026-09-15 11:10 KST
셀러 소유 활성 이용권  0건      ← 라이브의 유일한 실제 매장 상품이었다
```

되돌릴 경로를 전부 따라가 봤다:

| | |
|---|---|
| 어드민 `PATCH /api/admin/products/:id` | `is_active`·`sold_count`·`stock`·`referral_*` 만 받는다. **`status` 가 없다** |
| 셀러 목록 `GET /api/seller/products` | `AND COALESCE(p.status,'ACTIVE') != 'DELETED'` — 화면에 안 뜬다 |
| 셀러 `PUT /api/seller/products/:id` | `ALLOWED_STATUS` 에 `'ACTIVE'` 가 있다 — **쓰기 경로는 있는데 도달할 화면이 없었다** |
| 소비자 피드 | `p.is_active = 1` 만 본다 |

⇒ 어드민이 `is_active` 만 켜면 **소비자에겐 다시 보이는데 셀러는 여전히 관리 못 하는 어긋난 절반 복구**가 된다.
그래서 일회성 SQL 대신 화면을 붙였다.

> 같은 파일의 2026-07-02 주석이 *비활성화*에 대해 정확히 이 문제를 고쳐 놓고("비활성화 즉시 목록에서
> 사라져 재활성화 경로가 0이었음") *삭제*는 그대로 뒀다. 그때는 삭제 버튼이 없어 **도달할 수 없는**
> 구멍이었고, 버튼이 생긴 날 살아났다.

## 🩸 그러다 더 오래된 것을 찾았다 — 목록이 화면에 필요한 필드를 안 준다

이용권 화면은 `group_buy_current`·`restaurant_phone`·`store_owner_token`·`original_price` 를 읽는데
`GET /api/seller/products` 의 SELECT 에 **그 컬럼들이 없었다.** 에러가 아니라 `undefined` 라 조용하다:

- 판매 **0건** · 매출 **₩0** · 예상 정산액 **₩0** (모든 이용권, 언제나)
- 연락처가 등록돼 있어도 **"식당 연락처 미등록"** 배너 (라이브 2888 은 `restaurant_phone` 이 있다)
- '사장님 링크 복사' 가 **토큰 없는 링크**를 준다
- 정가 취소선이 절대 안 뜬다 · '종료' 세그먼트가 영원히 비어 있다

#1429 가 만든 게 아니다 — 재설계 **전** 화면도 같은 필드를 읽고 있었다(`git show 3247d923d`).
판매가 0건이라 숫자가 우연히 맞아 보였을 뿐이고, **첫 판매가 나는 순간 틀린 숫자가 됐을 것**이다.

## 🔒 머니 경로가 아니다

`status`·`is_active` 는 **판매 노출**만 정한다. 청구액은 `price`/공구 특가가 정하고(#1430 handoff §머니 경로),
복구는 어제까지도 서버가 받고 있던 PUT 을 그대로 부른다. 삭제도 soft delete 라 **발급된 이용권은 내내 살아 있었다.**

## 이번에 틀렸던 판단

1. **#1430 에서 "홍대돈까스는 연락처가 있어 수정 버튼이 안 떴다" 고 보고했는데, 그 설명은 틀렸다.**
   목록 API 가 `restaurant_phone` 을 **아예 안 주므로** 그 배너는 언제나 떠 있었고 수정 링크도 늘 렌더됐다
   (10px 밑줄 글씨였을 뿐이다). 고친 것(조건 없는 편집 버튼)은 여전히 옳지만 **이유를 잘못 말했다** —
   DB 에 값이 있다는 것과 API 가 그 값을 준다는 것은 다른 사실이고, 나는 전자를 보고 후자를 단정했다.
2. `--only "🗑️"` 로 돌려 "전부 빨간불" 을 받았는데 **내 주입은 한 건도 안 돌았다** — 그 이모지는 파일 헤더에만
   있고 주입 이름은 `🕳️` 로 시작한다. 부분일치라 **남의 8건**이 돌고 초록이 떴다.
   ⇒ 이름 목록을 뽑아 **한 건씩** 돌렸다.
3. **파일을 잘라 내다 178줄을 날릴 뻔했다.** 추출하면서 `s.index('    // COALESCE로 신/구 컬럼 모두 대응')`
   을 시작 앵커로 썼는데 **그 주석이 파일 안에 여러 번 있었다** — 첫 번째가 다른 핸들러라 슬라이스가
   그 사이를 통째로 먹었다(결과물이 `data: orders.results` 를 반환하고 있었다). 되돌리고,
   **핸들러 경계를 먼저 잡은 뒤 그 창 안에서만** 치환하도록 다시 했다. 긴 주석은 앵커로 쓰면 안 된다
   (2026-09-03 에 같은 이유로 174줄이 날아간 기록이 CLAUDE.md 에 있다 — **두 번째다**).
4. **한 건씩 돌리니 내 테스트 하나가 헛돌고 있었다** — 복구 호출을 `toMatch(/setSale\(true,/)` 로만 봐서
   `undefined && setSale(true, …)` 로 막아도 초록이었다. #1430 에서 세 번 밟은 것과 **같은 클래스**다
   (이름이 있는가 ≠ 동작하는가). `onClick={() => setSale(true,` 로 **모양**을 보게 바꿨다.
