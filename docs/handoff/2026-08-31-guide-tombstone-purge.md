# 중단된 라이브 기능의 묘비 철거 (2026-08-31)

## 대표 지시

> "셀러 라이브 방송 이런건 왜 있는거지? 라이브커머스 이제 안하는데"

## 왜 남아 있었나

#1270 에서 라이브 관련 4개 절을 **'종료됨' 한 줄로 덮었다.** 지우지 않은 이유는
**재시드가 삭제를 안 하기 때문**이다(가이드는 운영자가 큐레이션하는 문서라 그렇게 설계됐다) —
시드에서 빼면 라이브 DB 에는 **옛 OBS 설정법이 그대로 남는다.** 덮는 것이 그때 할 수 있는 최선이었다.

그 결과 목록에 묘비가 넷 섰고, 대표가 그걸 보고 "아직 하는 건가?" 를 다시 물었다.
**고쳐진 문서가 여전히 질문을 만들면 덜 고쳐진 것이다.**

## 무엇을 했나

| | |
|---|---|
| 철거 | `PURGE_ONCE` 4키 `DELETE` + 마커 `guide_tombstone_purge_2026_08_31` (1회) |
| 시드에서도 제거 | `guide-seed-seller.ts` 에서 그 4개 항목 삭제 |
| 제목 현행화 | `식권 사용 처리 — "선물하기" 모델` → `이용권 사용 처리 — 미리 사둔 메뉴를 내드리는 것` |

`GUIDE_SEED_VERSION` 22 → 23.

🔑 **시드에서 빼는 것이 필수다.** 철거 블록은 시드 루프 **앞**에서 돌기 때문에, 키가 시드에 남아
있으면 같은 실행 안에서 `INSERT OR IGNORE` 가 되살려 **삭제가 영원히 무효**가 된다. 가드로 고정했다.

⚠️ 제목의 `식권`은 은퇴한 말이고 `선물하기`는 **중단된 기능 이름**이라, 살아 있는 절 제목에 쓰면
같은 혼동을 만든다. 본문의 *"카카오 선물하기 패턴과 동일"* 은 외부 비유라 그대로 뒀다.

## 다음 세션의 첫 액션 — 배포 후 라이브 판정

```
어드민 토큰 → GET /api/guides/seller
```
- 셀러 섹션 수가 **36 → 32** 인가 (묘비 4개 사라짐)
- '라이브'·'선물하기'가 제목에 **0건**
- `seller-voucher-gift-model-2026-05` 제목이 '이용권 사용 처리 — …' 인가

안 걸렸으면 `GUIDE_SEED_VERSION`(23) vs DB 값 + `platform_settings.guide_tombstone_purge_2026_08_31` 마커.

## 이번에 틀렸던 판단

가드 단언을 파일 전체에 걸었더니 **관리자 강제 리셋**(`POST /:type/reseed` — 설계상 그 역할의
가이드를 통째로 지운다)이 위반으로 잡혔다. 정당한 코드다 → 철거 블록으로 범위를 좁혔다.

## ⚠️ 컨테이너 재시작 함정 (이 세션에서 실제로 당했다)

세션 중 컨테이너가 재시작되면서 로컬 `origin/main` 이 **몇 시간 전 커밋에 멈춰 있었다.**
그걸 모르고 브랜치를 파니 `GUIDE_SEED_VERSION` 이 22 가 아니라 **18** 로 보였고,
하마터면 이미 머지된 작업을 없애는 커밋을 만들 뻔했다.
⇒ **브랜치를 파기 전에 `git fetch origin main` 하고 `git ls-remote origin refs/heads/main` 과 대조할 것.**
