## ① 이용권 관리 페이지가 "없던" 진짜 이유 — 만들 수는 있는데 관리할 수 없었다

대표: *"이용권 관리에 대한 통합 페이지가 따로 없어보여. 셀러 대시보드 왼쪽 카테고리에도 없지 않아?"*

페이지는 **있었다**(`/seller/group-buy`). 안 보였을 뿐이다. `SellerLayout` 의 항목 필터가
`mode: 'store'` 인 줄을 `influencer` 타입 셀러에게 **통째로 숨기는데**, 그 형제인 "이용권 등록"은
`common` 이었다. ⇒ **등록은 되는데 관리가 안 보이는** 상태. 라이브 D1 실측: 셀러 12명 중 **5명이
`influencer`** 다. 대표 계정도 그중 하나였다.

**수정**: 사이드바 36줄 → 8묶음 13줄. 묶음의 첫 탭이 랜딩이고 나머지는 그 페이지 안의 탭으로 접힌다.
SSOT `src/components/seller/seller-tab-groups.ts` 하나에서 사이드바 항목(`also`)·인페이지 탭·⌘K
모두를 **파생**시킨다 — 셋을 따로 적으면 반드시 갈린다.

⚠️ 탭은 **레이아웃에서** 그린다(`SellerLayout` 안 `<SellerGroupTabs/>`). 헤더 부품에 넣으면 안 된다 —
대상 24페이지 중 **6개가 `DashboardPageHeader` 를 안 쓴다**(`/seller/stores` 같은 묶음 랜딩 포함).

## ② 인기 이용권 — 데모가 실제 매장 위에 있으면 안 된다

대표: *"무엇보다 데모가 아닌 실제 이용권이 무조건 인기 이용권 순위 위로 올라야 해."*

`section-rules.ts` 의 정렬에서 **데모-후순위를 첫 번째 키**로 올렸다:
`ORDER BY CASE WHEN <demo slug> THEN 1 ELSE 0 END, <점수>`. 점수가 아무리 높아도 데모는 못 올라온다.
배포 전에 라이브 D1 로 예상 순서를 계산해 두고 배포 후 실제 응답과 대조 — **일치**.

## ③ 뒤로가기 — 목록이 아니라 홈으로 가던 것

대표: *"이용권 페이지 들어갔다가 뒤로가기를 하면 무조건 메인페이지로 돌아가는 것 같아."*

원인은 **필터가 히스토리를 쌓고 있었다.** 브라우저로 재현: `/vouchers` 진입 → 브랜드 칩 1회 →
`history.length` 2 → 3. 칩을 서너 번 누르고 상세에 들어가면 목록 밖으로 나가는 데 네다섯 번을
눌러야 하는데 그 사이 화면은 계속 **같은 목록**이라 사용자는 계속 누른다 → 히스토리 맨 앞(홈).
"무조건 메인으로 간다"는 체감은 이 누적의 결과다.

**규칙**: 필터·정렬은 이동이 아니라 그 화면의 **상태** → `replace`.
같은 파일 안에서 이미 갈려 있었다 — 정렬·검색어는 replace, 칩 둘만 push.

가드는 **파일 목록을 손으로 안 적는다**. `src/pages` 의 소비자 화면을 훑어 URL 쓰는 파일을 스스로
찾는다(현재 7개). 대시보드는 제외 — 거기서 `?tab=` 은 사이드바 이동을 대신하는 **진짜 이동**이라
뒤로가기 한 칸이 생기는 게 맞다(`WholesaleDashboardPage.goTab`). 예외는 `back-nav-push-ok`.

## 이번에 틀렸던 판단 (제일 값진 부분)

- **`node scripts/check-file-size.mjs --changed-only -s` 는 아무것도 안 잰다.** "대상 없음 (skip)"
  이 뜨는데 그걸 통과로 읽었고 CI 가 **두 번** 막았다. `-s`(staged) 없이 `--changed-only` 로 돌릴 것.
  그리고 막혔을 때 `[SKIP_SIZE]` 로 넘기지 않고 실제로 줄였다(설명 주석을 테스트 헤더로 옮김 —
  어차피 중복이었다).
- **`sed` 로 되돌려-검증 주입을 했다가 이스케이프 때문에 조용히 no-op** 났고 "통과"로 보였다.
  주입은 python + `assert` 로 — 주입이 실패하면 크게 소리내야 한다.
- 가드가 자기 **주석 속 문자열**을 세서 가짜 초록/빨강이 났다(두 번). 판정 전에 주석을 벗길 것.
- `check-orphan-routes.mjs --rebaseline` 은 baseline 의 `_why`/`triage` 설명을 **지운다**. 되돌렸다.
- 🔴 **이 환경에서 GitHub REST 를 `curl` 로 치면 403** 이다("GitHub access is not enabled for this
  session"). CI 를 지켜보려고 curl 기반 모니터를 걸었는데 **아무것도 못 보면서 "진행 중"처럼 보였다** —
  이 레포가 반복해 당한 "검사가 실패할 수 없음" 을 감시 장치로 또 만든 셈이다.
  ⇒ GitHub 조회는 **`mcp__github__*` 툴로만.** (라이브 도메인 `urdeal.kr` curl 은 정상이다.)
- 판정용 playwright 프로브를 레포 루트에 복사했다가 작업 트리를 더럽혔다. 파일을 남기지 말고
  `node --input-type=module -e "$(cat <스크래치패드/스크립트>)"` 로 레포 루트에서 실행할 것.
