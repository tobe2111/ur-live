# 로그인하면 보던 링크로 안 돌아오던 것 (2026-10-01)

**[E2]** 작성·검증됨(유닛 25건 · 주입 6건 되돌려-검증 빨간불). 배포 전.

대표 신고: *"로그인이 안된 상태에서 해당 링크를 보고, 로그인을 하면 그 링크로 돌아가야 하는데
메인페이지로 돌아가고 있어."* (P17 실결제 안내 중 `/pass/2916` 에서 발견)

---

## 1. 무엇이 틀렸나 — **쓰는 사람만 있고 읽는 사람이 없었다**

로그인 벽을 치는 화면들은 돌아갈 곳을 `localStorage.loginReturnUrl` 에 적어 두고 `/login` 으로
보낸다. 실측 **9개 파일**(이용권 상세·상품 상세 4곳·교환권 상세·찜 버튼·찜 목록·쿠폰 수령·
딜 결제 오류·401 인터셉터). 그런데 **`LoginPage` 는 그 키를 한 번도 읽지 않았다.**

```
/pass/2916 → localStorage.loginReturnUrl='/pass/2916' → navigate('/login')   ← 쿼리 없이
           → LoginPage: 쿼리✗ 세션✗ → '/'
           → /auth/kakao/start?redirect=/
           → 콜백 safeInternalPath(state='/', stored='/pass/2916') → **'/' 가 이긴다**
           → 홈
```

마지막 줄이 고약하다 — `LoginPage` 가 만들어 낸 `'/'` 가 **저장된 값을 적극적으로 눌렀다.**
그래서 두 경로(SPA 콜백·서버 리다이렉트) 어느 쪽으로도 복귀가 안 됐다.

**에러도 로그도 없다.** 화면은 멀쩡히 홈을 보여 준다. 화면마다 "로그인하면 돌아온다" 고 믿고
`loginReturnUrl` 을 적은 세션이 아홉 번 있었는데 **아홉 번 다 아무 일도 안 했다.**

## 2. 수정 — 읽는 쪽을 고친다

신규 SSOT `src/utils/login-return.ts`:
`resolveLoginReturnUrl(쿼리값)` = **쿼리 `?returnUrl=` → `sessionStorage.returnUrl` →
`localStorage.loginReturnUrl` → `/`**, 전부 `safeInternalPath` 통과.

🔑 **화면 아홉 곳을 각각 고치지 않았다** — 그 길은 다음에 생길 열 번째를 못 막는다. 읽는 쪽
한 곳을 고치니 기존 writer 가 전부 한 번에 살아난다.

`LoginPage` 두 자리(마운트 시 / 카카오로 보낼 때)가 **같은** 함수를 쓰고, 복귀 후 `clearLoginReturnUrl()`.

⚠️ **`'/'` 는 후보로 치지 않는다** — "못 골랐다" 와 구분이 안 되고, 바로 그 혼동이 결함의 마지막
고리였다. 앞 후보가 `/` 로 떨어지면 다음 후보를 본다.

⚠️ **`safeInternalPath` 는 한 글자도 안 바꿨다**(2026-04-29 오픈 리다이렉트 SSOT). 이 파일은 **고르기만** 한다.

## 3. 가드

`src/tests/unit/login-return-url-2026-10-01.test.ts` 25건 — 실제로 함수를 **실행**해 우선순위·
`'/'` 처리·오픈 리다이렉트 차단·private mode 를 보고, `LoginPage` 배선과 **writer 9곳이 같은 키를
쓰는지**까지 본다. 주입 6건 **전부 빨간불 확인**.

🩸 **작성 중 겪은 것**: private-mode 스텁에 `clear` 를 안 넣어서 **단언이 아니라 공용 setup 의
`afterEach` 뒷정리에서** 깨졌다 — 실패 메시지가 테스트 내용과 무관해 보여 한 번 헛짚을 뻔했다.

⚠️ 이 가드가 **못** 보는 것: 실제 브라우저의 카카오 왕복, 화면이 **어느 시점에** 값을 적는지,
그리고 `safeInternalPath` 가 **쿼리를 버리는** 것(복귀 주소에 쿼리가 필요한 화면이 생기면 그 화면이
`?returnUrl=` 로 명시해야 한다 — 결제 콜백이 2026-09-13 에 `safePaymentReturnPath` 로 따로 간 이유와 같다).
