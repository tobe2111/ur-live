# 2026-08-27 — 대행사 매장이 5%가 아니라 10%를 내고 있었다

대표 확정 모델(본인 말): *"10%는 유어딜에 매장이 직접 입점하고 이용권을 판매할 때 내는 수수료야.
매장이 직접 입점하지 않고 대행사로 가입하면 5%인거고."* → *"응 그렇게 해줘."*

---

## 🩸 이 세션에서 **내가 두 번 틀렸다.** 그게 이 문서에서 제일 값진 부분이다

**1차 보고 (틀림)**: *"직접 입점 매장한테도 5%만 떼고 있습니다."*
→ `getSellerCommissionRate` 의 폴백 체인(`sellers.commission_rate` → GMV 티어 → 기본 5%)을 **읽기만 하고**
   실제 데이터를 안 봤다. 1번에서 이미 끝난다는 걸 몰랐다.

**2차 실측 (정정)**: DB 조회 →
```
활성 매장 7곳 전부  sellers.commission_rate = 10   →  실제로는 모두 10% 를 낸다
채널이 기록된 매장 1곳뿐 — 홍대돈까스(id 14) = brokered  →  10% 를 내고 있다(5% 여야 함)
컬럼 기본값은 5.00 · tier cron 표는 3/4/5 → 10 은 **아무도 의도하지 않은 잔재**
```
⇒ 틀린 쪽은 **대행사**였고, **매장이 손해 보는 방향**이었다(내가 1차에 말한 것의 정반대).

> **교훈**: 폴백 체인을 코드로 읽으면 "마지막 값"이 결론처럼 보인다. 하지만 폴백은 **앞 단계가
> 비어 있을 때만** 도달한다 — 앞 단계에 뭐가 들어 있는지는 **데이터를 봐야** 안다.
> `CLAUDE.md` 의 "추측 금지 · 진단 먼저" 가 정확히 이 실수를 막으려고 있는 규칙이다.

## 🔑 그리고 스위치를 켜도 안 고쳐지는 상태였다

`channelPlatformRate` 는 `direct` 가 아니면 **전부 `undefined`** 를 돌려 "종전 경로"로 보냈다.
주석은 *"모르면 낮은 쪽(5%)으로 떨어진다"* 고 적혀 있었는데, 그건
**"종전 경로가 마침 5% 다"** 라는 전제였고 **그 전제가 데이터에서 깨져 있었다**(전부 10).

> 폴백은 "아무 값"이 아니라 *특정 값*을 전제한다. 그 전제를 코드가 아니라 데이터가 정하게 두면
> 조용히 어긋난다 — 에러도 로그도 없다.

## 수리 3가지

**① 대행사도 자기 키에서 요율을 받는다** (`ledger-commission-policy.ts`)
채널이 `direct` / `brokered` 로 **확정된** 매장은 두 방향 모두 이 함수가 값을 정한다
(`platform_fee_pct_direct` / 신설 `platform_fee_pct_brokered`). **미지정만** 종전 경로.

**② 채널이 `sellers.commission_rate` 보다 위로** (`group-buy/api/helpers.ts` — 이용권 판매가 부르는 함수)
순서: **채널 → 매장별 값 → GMV 등급 → 기본값.**
⚠️ **왜 위인가가 이 수정의 핵심이다**: `sellers.commission_rate` 는 **쓰는 주체가 셋**이다 —
어드민 수동, `seller-tier-eval` **cron**(GMV 등급으로 3~5% 를 덮어쓴다), 과거 잔재.
채널을 그 아래에 두면 **cron 이 돌 때마다 채널 요율이 조용히 지워진다.**

**③ 어드민이 채널을 지정할 수 있게** (신규 `admin-store-channel.routes.ts`)
그전엔 **매장 소유자만** 바꿀 수 있었다(`POST /api/seller/stores/:id/channel`). 그래서 7곳 중 6곳이
미기록이었고, **값을 넣을 길이 없으면 규칙은 규칙이 아니다.** 감사 로그 + 게이트 상태를 응답에 실어
"채널만 찍고 적용됐겠지" 하는 오해를 막는다.

## ⚠️ 게이트는 여전히 OFF — 이 커밋은 라이브 동작을 안 바꾼다

`fee_channel_rates_enabled` 미설정 = 전부 종전과 byte-동일. 켜기 전 **staging 실결제**(S7) 필수.

1. **폴백 체인을 데이터 없이 읽고 결론을 냈다** (위 참조). 두 번 연속 방향을 틀렸다.

   주입 검증은 **커밋 후에** 하거나, 되돌릴 때 파일 단위 checkout 을 쓰지 말 것.

   (`channel-platform-rate` · `shopping-channel-rate`). 하나는 빨간불로 잡혔지만, 다른 상황이었으면
   **폴백을 타고 초록**이 됐을 수 있다. SQL 모양을 바꿀 때는 fake 도 같이 본다.
