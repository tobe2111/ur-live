# 2026-11-11 — 결제 귀속 체계화: 소개 링크 우선 + 무엇을 보고 샀나

대표: *"인플루언서 링크를 통해서 들어와선 유어쇼츠를 볼 수도 있잖아. 24시간 내에. 그럼 인플루언서 성과로 안잡히면 안되지.
이런 케이스들을 체계적으로 잡아줘"* · 결재 기록 `docs/decisions/2026-11-11-attribution-influencer-first.md`.
서비스: 유어딜(소비자). **머니 경로 접촉: 있음**(소개 귀속 → 매장이 정한 소개비). 롤백은 결재 파일 참조.

## 규칙 (SSOT `src/worker/utils/order-touch.ts`)
① 소개 링크(24시간 · 마지막 링크 · 자기 링크 제외) 있으면 **인플루언서** — 유어쇼츠·콘텐츠를 봤어도
② 없으면 24시간 안 유어쇼츠 '구매' → **유어쇼츠** ③ 상세 영상·블로그 열기 → **다녀온 사람들** ④ 그 밖 → **유어딜**

- 홈·유어쇼츠·지도 등으로 들어온 `?ref=` 가 구매 귀속에 저장 안 되던 것 → `captureLandingRef`(App.tsx). `/store`·`/seller`·

- 클라 `utils/touch-store.ts`(24h) → 모든 요청 `X-Ur-Via` → 결제 확정 3곳(딜 /join · 카드 /confirm-toss · 장바구니)이

## 이어받는 세션의 첫 액션
- 배포 후 첫 결제가 생기면 메인 D1 `SELECT bucket, via_kind, COUNT(*) FROM order_touch GROUP BY 1,2` — 행이 생기는지.
- 0 이면: 결제 확정 응답이 정상인지, `X-Ur-Via` 가 요청에 실리는지(브라우저 개발자도구) 순서로 본다.
