## 3. 이번에 틀렸던 판단
1. **줄 하나로 "떠 있나"를 판정하면 틀린다.** 지갑 지도 위 가로 카드는 `absolute` 가 **부모** 줄에 있어서
   첫 판이 흐름 속 판으로 보고 걷었다(지도 위에서 흰 면이 없으면 글자가 안 읽힌다). diff 를 읽다 잡았다 →
   `KEEP_LINE` 에 `snap-start shrink-0` 추가 + 주입 1건. **같은 클래스(부모가 떠 있는 자식)가 더 있을 수 있다.**
2. 줄 판정의 `h-1x` 규칙(입력창 높이)이 **내 딜 버튼 줄**(`h-11`)까지 남겼다 — 같은 카드의 세 상태 중 둘만 판이 남는
   모순. `h-1x items-center justify-center`(버튼 모양)로 좁혔다.
3. 마이의 공용 판(`LIST_PLATE_CLS`·`MyStats`)은 **소스에서 걷으면 안 됐다** — 폰 `.ur-my-flat` 의 선택자가
   `shadow-lift` 를 잡아 -16px 블리드를 주는데, 클래스를 빼면 그 선택자가 안 잡혀 줄이 16px 안으로 밀린다.
   그 둘은 CSS 가 이미 평면화하므로 남겼다(이유가 코드모드 `KEEP_FILES` 에 있다). `ListPlate` 부품(유어샵 관리·내 정산)만 평면.

## 4. 남은 것 / 결정 대기
- **흐름 속 판을 걷은 자리의 여백 정렬은 지갑만 손으로 맞췄다**(`-mx-4`). 다른 화면(정산·견적·쿠폰 등)은 판 안 여백
  (p-4/p-5)이 그대로라 글자가 제목보다 16~20px 안으로 들어갈 수 있다. 대표가 보시고 거슬리면 화면별로 `-mx-4`.
- `DealRow` 의 `surface='card'` 는 이제 판이 없다(여백·모서리만). `plain` 과 거의 같아졌으니 하나로 합칠지 후속 판단.
- 사장님 쪽(사용 처리 `VoucherVerifyPage`·`VoucherScanner`, 매장 통계, 생활 프로)은 범위 밖이라 그대로다.
