## 2. 검증 방법 — 라이브 브라우저는 못 쓴다

```
로컬 빌드 + Chromium (실측)
  몰 /test                액자=false  유어딜레일=false   ← 고쳐짐
  유어딜 /my-vouchers      액자=true   유어딜레일=true    ← 정상(대조군)
  유어딜 /wishlist         액자=true   유어딜레일=true    ← 정상(대조군)
```

⚠️ **첫 대조군을 `/vouchers` 로 잡았다가 둘 다 false 가 나왔다** — 그 페이지는 원래 풀너비
(`isFullBleedPcPath`)라 대조군이 못 된다. **측정 대상이 0 이면 통과처럼 보인다**는 이 레포의
단골 함정을 그대로 밟을 뻔했다. 액자를 쓰는 페이지로 다시 잡아야 판정이 성립한다.

⚠️ **라이브 URL 로는 브라우저 검증 불가**: `urdeal.kr` 은 curl 로는 되는데
**headless Chromium 은 프록시에서 `ERR_CONNECTION_RESET`** 이다(`*.pages.dev` 프리뷰는 CONNECT 403).
⇒ 시각 회귀는 **로컬 빌드 + 실브라우저**로 보고, 라이브는 curl(상태/메타)로만 본다.

### 판정 신호를 무엇으로 했나 — 그리고 그 한계

`shared/mall/origin.ts` 는 원래 *"몰 상품 판정에 쓰지 말 것"* 이라고 못 박혀 있었다.
여기서는 **상품이 아니라 "유어딜이 지금 영업해도 되는 자리인가"** 를 판정하고, 틀렸을 때
손해가 **한 방향으로만** 난다:

| 오판 | 결과 |
|---|---|
| 거짓 양성(몰만 지나친 본진 구매) | 영업 배너 1회 미노출 — 손해 ≈ 0 |
| 거짓 음성(몰 손님인데 노출) | **운영자 손님을 유어딜이 데려간다** |

비대칭이 명확하므로 **모르면 끄는 쪽**을 택했고, 그 근거를 `isFromMallSession` 주석에 박았다.

⚠️ **한계(다음 세션)**: 이건 클라 세션 신호라 새 탭·오래된 세션에서는 없다. 정확히 하려면
**주문에 실린 상품의 `mall_id`**(서버)를 봐야 하고, 그러려면 결제 완료 응답에 몰 정보를 실어야 한다
— 그 화면이 Toss 잠금이라 **대표 승인이 선행**이다.

### 🐛 내 가드가 또 헛돌았다 (되돌려-검증에서 잡음)

`ContinueShoppingLink` 를 화면에서 **통째로 들어내도 초록**이었다 — 판정이 `/ContinueShoppingLink/`
라 **import 문이 남아 통과**했다. `readMallOrigin` 호출을 지웠을 때도 같은 이유로 통과.
⇒ **import 줄을 벗기고**(`noImports`) JSX 사용(`<Comp`)·호출 결과 대입(`= fn()`)을 본다.
오늘만 같은 클래스를 세 번 만났다: **주석에만 남아도 통과 · 파일 절반만 읽음 · import 만 남아도 통과.**
공통 교훈은 하나 — **"언급이 있다"와 "실제로 쓴다"는 다르다.**

되돌려-검증 5건 전부 빨강 확인 후 복원(넛지 억제 제거 · 억제를 조기 return 밖으로 ·
장바구니 홈 환원 · 흔적 미조회 · 폴백 제거).
