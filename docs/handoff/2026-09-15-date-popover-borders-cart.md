## ① 날짜 팝오버 — 원인이 CSS 한 줄이 아니라 **부모가 sticky 인 것**이었다

세로 제한이 `max-h-[52vh] lg:max-h-none` 이라 PC 에서만 풀려 있었다. 보통은 넘쳐도 페이지를 스크롤해
볼 수 있어서 괜찮은데, 이 팝오버의 부모 아사이드는 `lg:sticky lg:top-[116px]` 다 — **sticky 는 뷰포트에
고정되므로 패널이 스크롤을 따라와서 잘린 부분에 영영 도달할 수 없다.** "넘치면 스크롤" 이라는 평소의
안전판이 이 자리에서만 없었다.

⇒ 트리거 아래 남은 공간을 실제로 재서 상한으로 쓴다. 달력만 안에서 스크롤하고 헤더·푸터는 늘 보인다.

🧭 **바닥값을 화면폭으로 갈랐다** — 모바일은 흐름 안이라 넘쳐도 스크롤로 닿는다. PC 규칙(260px)을 그대로
쓰면 팝오버가 **종전(52vh)보다 짧아진다**(고치려던 것과 반대). 실측으로 모바일 렌더 높이가 종전과
동일(429px)임을 확인했다.

## ② 테두리 — 15곳이 다 같은 위반이 아니었다

세어 보니 성격이 셋이다: **카드 4**(규칙 위반, 이것만 쟁점) / **구분선 7**(규칙이 허용 — `--rule` 이
있는 이유) / **outline 컨트롤 4**(남기되 토큰을 `--gbd-line2`→`--rule-strong`).
⇒ "전부 걷는다" 로 접근했으면 멀쩡한 11곳을 건드릴 뻔했다.

⚠️ **다크가 라이트보다 나쁘다** — `--line`(#2C2F35)이 카드(#1D1F29)보다 **밝아서** 테두리가 더 도드라진다.
⚠️ 안 2(들림)는 다크에 `--lift: none` 이라 실제로는 "라이트 들림·다크 면"이다.

## ③ 장바구니 — 설계 전체를 정한 실측 한 줄

> **`INSERT INTO vouchers` 가 소비자 `orders` 레일엔 0건이다.**

그래서 기존 `/checkout` 으로 태우면 **결제는 되고 이용권은 안 나온다.** 발급을 그쪽으로 옮기려면 Toss
감사-잠금 파일을 열어야 하는데, 그 자리의 규칙 열 가지가 이미 공구 레일에 산다 ⇒ **반대로 갔다.**
장바구니도 공구 레일에서 결제하고 규칙을 줄마다 그대로 돌린다. **잠긴 파일 무접촉**(helper 호출만).

🔒 **품목은 서버가 기억한다**(`gb_cart_intents`). 복귀 URL 로 돌려받으면 금액 검증을 통과하면서
**총액이 같은 다른 상품으로 바꿔치기**가 된다 — 우리 돈은 안 새지만 A 매장은 판 적 없는 매출을,
B 매장은 판 줄 모르는 매출을 갖는다. 확정 요청 본문엔 `items` 가 **아예 없다**(타입에서 지웠다).

상세: `docs/design/voucher-cart-2026-09.md`

## 이번에 틀렸던 판단 (제일 값진 부분)

### ⓐ 하네스를 실제 조건으로 안 맞춰 놓고 "고쳤다" 할 뻔했다
첫 하네스는 아사이드에 모드 탭 줄이 없어 카드가 **57px 높이** 앉았고, 그래서 vh 865(대표 화면)에서
**종전 코드도 통과**했다. 실제 배치를 재현한 뒤에야 760·640 에서 빨간불이 떴다.
⇒ **되돌려-검증이 초록이면 수리를 의심하기 전에 하네스를 의심하라.**

### ⓑ Tailwind content 글롭 밖에서는 내 하네스 클래스가 생성되지 않는다
스크래치 `.preview-stay.tsx` 의 `grid-cols-[1fr_360px]` 가 통째로 무시돼 레이아웃이 깨졌다(스크린샷으로
발견). 하네스는 **인라인 스타일**로 짜라.

### ⓒ 내가 쓴 시험 셋이 헛돌았다 — 전부 정규식 때문
| | |
|---|---|
| `/\n\s+continue\b/` | 주입의 `if (!p) continue` 는 앞이 `) ` 라 매치 실패 |
| `[^}]*` 로 거절 개수 | 템플릿 리터럴 `${p.name}` 의 중괄호에서 끊겨 6건 중 3건만 |
| 결제창 이름 길이만 검사 | 자르면서 `외 N건` 이 사라지는 걸 못 봤다(길이는 통과) |

세 번째는 **실제 결함**이었다 — 상품명이 길면 결제창이 나머지 품목을 감춘다. 자기 시험이 잡았다.

### ⓓ 코드를 옮기면 **남의 주입도 낡는다** (또 겪었다 — 지난 세션 교훈 그대로)
하단 바를 `DealBottomBar` 로 분리하니 `deal-use-chooser` 의 주입 하나와 그 짝 테스트가 대상을 잃었다.
지우지 않고 **재조준**했다(성질은 그대로 유효하다).
⚠️ 러너의 "복원 실패 의심" 경고가 이때 뜬다 — 진짜 주입 잔존과 구분이 안 되니 **반드시 `git diff` 로 확인**.

### ⓔ `worker/index.ts` 가 동결선에 붙어 있어 라우트를 못 붙였다
마운트 3줄이 baseline 을 넘겼다. `groupBuyRoutes.route('/', cartCheckoutRoutes)` 로 **공구 라우터 안에서**
붙여 index.ts 를 원상 복구했다(같은 접두사라 동작 동일).
