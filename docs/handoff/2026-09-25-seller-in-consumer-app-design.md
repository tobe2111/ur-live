## 이번에 틀렸던 판단 (제일 값진 것)

대표 질문에 처음 답하면서 **"진짜 벽은 인증 축이다 — 셀러 API 28개 모듈이 별도 JWT 를 요구하니
그걸 다 고쳐야 한다"** 고 말했다. **측정해 보니 틀렸다.** 다리는 이미 라이브에서 돌고 있다:

```
resolveActorUserId(c)                          ← 소비자 세션 쿠키를 직접 읽는다
  → canOperateStore(DB, userId, sellerId)      ← owner(linked_user_id) | operator(seller_operators)
    → POST /api/seller/stores/:sellerId/token  ← 그 좌석의 셀러 JWT
GET /api/seller/my-stores                      ← 소비자 세션만으로 좌석 목록
```

⚠️ **왜 틀렸나**: 파일 개수(`seller_token` 138파일 · `requireSeller()` 38곳 · `/api/seller` 28모듈)를
보고 규모를 말했는데, 그 숫자들은 **전부 한 함수로 수렴**한다(`requireUserType` · `getSellerIdFromToken`).
그리고 *이미 만들어진 우회로*(좌석 토큰)를 안 보고 답했다.
**교훈: "몇 곳에 있나" 가 아니라 "몇 곳에서 결정되나" 를 세라.**

## 결정

**이식이 아니라 재구성.** 경계 한 줄:
> **폰에서 한 손으로 하는 일 = 소비자 앱 / 앉아서 하는 일 = 셀러 대시보드.**

- 위치 = **마이**(`/user/profile` → `/sell/*`). 유어샵(`/u/{handle}`)은 **손님 진열대**라 안 쓴다 —
  거기에 주문·정산을 얹으면 §5.5 소유권 단일화(CI 가드) 가 흐려진다.
- `/seller/*` 는 **살려 둔다**. 301 하지 않는다(운영 도구 40여 개 + 이미 공유된 URL).
- 신규 화면은 **다크를 지원**한다. `light-island` 로 흰 섬을 만들지 않는다.
- 단계: 1 판매 카드 → 2 `/sell` 홈+좌석 → 3 주문 → 4 이용권 → **5 정산(🔴 머니 · 단독 세션 + staging)**

## 시안을 그리다 잡은 결함

판매 홈 '이번 주' 를 `[매출|수수료|받을 돈]` 3열로 그렸더니 **6자리 금액 셋이 붙었다**
(`1,240,00062,0001,178,000`). 430px 에서 각 열이 ~130px 인데 23px 숫자로는 안 들어간다.
2026-08-31 홈 카드의 *"6자리 가격에서 할인 pill 이 다음 줄로 밀린다"* 와 **같은 클래스**.
⇒ 구현 규칙: **판매 모드에서 금액 3개를 한 행에 균등 배치하지 않는다.** 3열은 *개수*에만.

## 대표 확정 (같은 날)

> *"디자인이 마음에 안들긴 해. 정산까지도 다 해주고, 주인 연결도 같이 가줘"*

- **정산 포함 · 주인 연결 동반** — 둘 다 범위 안. 그런데 재 보니 **둘 다 이미 만들어져 있다**:
  출금은 `POST /api/seller/account/withdraw`(+`withdraw-check`), 승계는 `store-codes`(`owner_claim`) ·
  `/store-claims` 4라우트 · `/store/find` · 어드민 `AdminStoreOwnerPage`. **기능이 아니라 자리가 없었다.**
  주인 연결은 **단계 2에 얹는다**(좌석 목록이 이미 `owner_claim_code` 를 내려준다 — 신규 API 0).
- **1차 디자인 반려** → 방향 3안 재작업. 갈리는 축은 *무엇이 주인공인가*:
  **A 숫자**(오늘 한 장) · **B 물건**(티켓 지갑 뒤집기) · **C 할 일**(큐).
  시안 `assets/seller-in-consumer-app-directions.html` · 렌더 `seller-directions-{light,dark}.png`.

### 1차 시안에서 내가 어긴 것

- **강조색 자리가 여덟이었다** — 규칙은 「강조색 하나, **자리 셋**」. 파란 게 많으면 아무것도 안 강조된다.
- 판매 홈에 **주인공이 없었다**(같은 무게 카드 4장 스택).
- 주문·이용권·정산이 **서로 구별이 안 됐다**(전부 흰 카드 + 리스트 행).
- **소비자 앱 같지 않았다** — 작은 대시보드로 보인다.

### 🩸 3안 시안이 또 하나 잡았다

`안 A/B/C` 태그를 `background: var(--ink); color: #fff` 로 그렸더니 다크에서 `--ink` 가 `#F5F3F1`
(거의 흰색)이라 **흰 면 위 흰 글자**가 됐다. `check-dark-contrast` 가 존재하는 바로 그 클래스.
⇒ **면 색이 토큰이면 글자도 토큰으로**(`--pagefg` 면에는 `--page` 글자). `#fff` 를 박으면 한쪽 테마가 깨진다.

## 🔴 대표 화면 실측 — 내 시안이 틀린 두 곳

대표가 실제 마이 스크린샷을 보내며 *"지금은 어떤 링크를 들어가는 구조잖어"* 라고 물었고,
그 화면이 둘을 바로잡았다.

1. **소비자 하단 탭은 5개다** — 홈 · 교환권 · **이용권(`/my-vouchers`)** · 유어샵 · 마이.
   내 1차·3안 시안의 마이 화면은 `이용권` 을 빠뜨리고 **4개**로 그렸다.
   ⚠️ `seller-in-consumer-app-mock.html`·`…-directions.html` 에 그 오류가 남아 있다(`seller-where-in-my.html` 만 교정).
   **그 그림을 치수 근거로 쓰지 말 것.**
2. **판매 진입점이 이미 있다** — `SellerSwitchInline`(123줄)이 프로필 이름 옆 칩으로 살아 있고
   셀러가 아니면 `내 가게 등록` 을 띄운다. ⇒ 단계 1은 *"새 카드를 만든다"* 가 아니라 **"그 칩이 자란다"**.
   새 자리를 만들면 진입점이 둘이 된다.

> 🧭 **교훈**: 화면을 코드로만 읽고 **한 번도 안 봤다.** `/user/profile` 은 `ProtectedRoute` 라 이 컨테이너에서
> 못 여는데, 그걸 "못 본다" 로 넘기고 소스에서 추론했다. **못 보면 대표에게 스크린샷을 먼저 청했어야** 했다.

  **마이가 켜져 있다.** 판매 안 이동은 **상단 알약**. ⚠️ **셀러 전용 하단 탭을 만들지 말 것**

## 🔴 착수 전 실측 3건 (설계 §15) — 단계 1 이 반드시 들고 가는 것

대표 *"지금 형태가 가장 이상적인 형태야?"* → 재 보고 답하다 나왔다. 상세는 설계 §15.

1. **저장 모델은 이상적이지 않다. 그래도 지금 안 고친다.**
   `sellers` **100/100 컬럼**(D1 한도에 정확히 닿음) · 11행 중 **10이 매장** · 가짜 이메일 **9** ·
   `seller_meta` 21키 111행. 이 어긋남이 이미 두 번 터졌다(09-02 두 번째 매장 등록 100% 실패 ·
   09-20 등록증이 meta 에만 들어가 어드민이 못 봄). **쪼개지 않는 이유**: `seller_id` 가
   주문·원장·정산·커미션·payout·토큰 전부에 박혀 있다 — 등급 C 를 한꺼번에 여는 일이고 화면 작업과 못 섞는다.
2. **`switch-to-seller` 는 라이브 9좌석을 못 본다.** 그 길은 `linked_user_id`(UNIQUE 1인1행) 한 행만
   보는데, `POST /store/new` 는 설계상 그 칸을 **비우고** `seller_operators` 로만 권한을 준다.
   ⇒ **새 판매 화면의 좌석 출처는 `GET /my-stores` 하나.** `switch-to-seller` 는 호환 경로로만 남긴다.
3. **🔴 좌석 토큰 ↔ 인라인 작업 충돌 — 단계 1 에서 막는다.** 좌석 토큰은 JWT 안에 `seller_id` 가
   박혀 있어 **가게를 바꾸면 토큰이 통째로 바뀐다.** 종전엔 전환이 곧 페이지 교체라 틈이 없었는데,
   §14 가 작업을 마이 안 인라인으로 옮기는 순간 *"A 의 목록을 펼쳐 둔 채 B 로 전환 → A 행에서 확인"* 이
   생긴다. 규칙 셋: ① 전환하면 열린 시트를 닫고 재조회 ② 화면이 든 `seller_id` ≠ 토큰 `seller_id` 면
   **보내지 않고 재조회** ③ 판매 화면은 `seller_id` 를 URL·localStorage 에서 읽어 API 에 넘기지 않는다.

## 단계 1 — 지은 것 (같은 날, 코드)

신규 `src/lib/seller-seat.ts`(좌석 SSOT) · `user-profile/useMyStores.ts` · `SellerSection.tsx` ·

`bumpSeatGeneration()` 이 그 일을 하고 구독자가 스스로 다시 부른다.

🕳️ **가드가 곧바로 하나 잡았다(교훈)**: `seller-seat.ts` 는 `/src/lib/` catch-all 로
`app-utils`(첫 페인트 **안**)에 떨어지는데, 거기서 `@/utils/enter-store`(첫 페인트 **밖**
