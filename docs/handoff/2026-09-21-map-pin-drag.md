## 무엇이 없었나

매장 등록 지도(`KakaoMapPicker`)는 **검색으로 찾은 장소만** 고를 수 있었다. 핀을 손으로 옮길
방법도, 좌표에서 주소를 되찾을 방법도 없었다(실측: `draggable`·`coord2Address` 참조 0).

그래서 상가 안쪽·신축·지번만 있는 곳은 검색이 집어 준 좌표에서 더 정확히 만들 길이 없었다.

## 무엇을 했나

`KakaoMapPicker` 에 **옵셔널** prop `onPinMove` 를 추가했다. 넘기는 화면에서만:

- 선택된 자리에 **드래그 가능한 핀**이 선다(검색 결과 마커와 별개 객체).
- 지도를 눌러도 핀이 그 자리로 간다.
- 놓는 순간 카카오 SDK 의 `services.Geocoder.coord2Address` 로 **주소를 되찾는다**.
  SDK 를 이미 `libraries=services` 로 싣고 있어 **서버 왕복이 0**이다(새 엔드포인트 없음).
- 지도 위에 흰 안내 띠(`light-island`) — 6개 언어.

**넘기지 않는 화면은 리스너조차 안 달려 종전과 byte 동일**이다.

## 🔴 가장 중요한 결정 — `onSelect` 와 갈라 놓았다

합치고 싶은 유혹이 있었는데, 합쳤으면 조용한 손실이 생긴다.

| | 뜻 | 바꾸는 것 |
|---|---|---|
| `onSelect`(기존) | **다른 매장을 골랐다** | 이름·주소·전화·좌표·place id 전부 |
| `onPinMove`(신규) | **같은 매장의 위치를 더 정확히** | 주소·좌표 **둘만** |

기존 `selectPlace` 는 `restaurant_phone: place.phone || ''` 로 **빈 값이면 전화를 지운다**.
핀 이동을 그 경로에 태웠다면 핀을 조금 끌었다는 이유로 방금 채운 전화번호가 사라졌을 것이다.
에러가 안 나서 아무도 신고하지 않는 종류다.

규칙 SSOT: `src/shared/pin-move.ts` `applyPinMove()`.

## 실패했을 때의 규칙 (둘이 방향이 반대다)

- **주소를 못 되찾으면 기존 주소를 지킨다** — 빈 문자열로 덮으면 맞게 들어가 있던 주소가 사라진다.
- **좌표는 실패해도 반드시 반영한다** — 핀은 옮겨졌는데 저장값이 그대로면 사용자는 고쳤다고
  믿고 넘어가고, 실제론 안 고쳐진 어긋남이 남는다.
