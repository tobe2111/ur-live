# 2026-10-15 지도 속도 — SDK 미리 데우기 · 타일 한 벌 · GTM 을 load 뒤로

대표 *"지도 부분 다시 확인해봐 속도"*.

## 실측 (느린 4G 1.6Mbps · 지연 150ms · CPU 4배 · iPhone 13, 라이브 urdeal.kr)

**홈 지도 알약 → 지도 (손님 대부분의 경로, SPA 이동)**
- 알약 탭 → 화면 코드 ~1.0초 → sdk.js(1.0→2.1~2.5초) → kakao.js(→2.6~3.8초) → services.js(→3.0~4.0초) → **타일 출발 3.0~4.2초** → 타일 전부 7.6~8.8초.
- 세 SDK 파일은 합쳐 ~38KB 인데 서로를 줄줄이 기다려 2~3초를 먹는다(바이트가 아니라 왕복이 비용).
- SDK 를 미리 받아 둔 상태로 같은 측정: **타일 출발 1.1~1.2초 · 타일 전부 5.8~6.1초**(약 2.5초 단축).
  - 단 그 상태에서 타일이 **24장**(12장 두 벌) — 지도가 목록보다 먼저 만들어져 기본 중심 타일을 받고, 목록 도착 후 초기 맞춤이 또 받는다. ⇒ 생성을 첫 목록 뒤로 미룸(⑤).

**`/map` 직접 하드로드**
- 지도 생성 ~4.2초(화면 코드 3.7초 + kakao.js 실행이 메인 스레드에 밀림) · 타일 4.3→9~11초 · LCP 8.9~10.9초. LCP 요소 = 지도 타일.
- GTM(gtag 153KB)이 **5.0초**에 출발 — 타일 다운로드 한복판. `requestIdleCallback` 만으로는 "첫 화면 뒤" 가 아니다(2026-10-12 센트리와 같은 클래스).
- 실사용자 vitals `LCP:/map` p75: 10-12 10.4초(n=4) · 10-13 7.7초(n=2) · 10-14 10.9초(n=3). 표본이 너무 적다.

## 바꾼 것
1. `src/pages/mobile-home/map-warmup.ts` + `MapPill.tsx` — 홈이 다 뜬 뒤(`runAfterLoad`) 카카오 지도 SDK 를 동적 import 로 미리 받는다. 데이터 절약 모드면 안 받는다. 알약을 누르는 순간 `mts.kakaocdn.net` 에 preconnect(crossorigin 없음).
2. `useKakaoMap.ts` — `dataReady`(첫 목록 도착) 전엔 지도를 만들지 않는다. 4초 지나면 그냥 만든다. 페이지가 `dataReady: !loading` 을 넘긴다.
3. `main.tsx` — GTM 을 `runAfterLoad(…, 10000)` + 20초 백스톱으로. `/map` 에선 load 가 타일 뒤에 오므로 타일과 회선을 안 나눈다(다른 화면도 같은 효과).

가드: `src/tests/unit/map-speed-warmup-2026-10-15.test.ts` + 주입 `scripts/mutations/map-speed-warmup-2026-10-15.mjs` 5건(전부 빨간불 확인).

## 하지 않은 것 (이유)
- **시트에 가려진 타일**: 지도 칸이 화면 전체라 시트 아래 타일(iPhone 12장 중 3장, Pixel 15장 중 6장)도 받는다. 칸을 줄이면 선택 카드 모드·드래그·중심 보정(`centerOffsetForSheet`)·뷰포트 목록이 전부 같이 움직여 위험이 커서 보류.
- **지도 화면 코드 미리받기**: 홈에서 지도 페이지를 동적 import 하면 묶음기(`surface-chunks.mjs`)가 지도 모듈 봉투를 다시 짠다(별건).
- **화질 낮추기**: 이미 느린 회선에서만 일반 화질(2026-10-14 #1773). 빠른 회선 화질은 대표 판단 사항이라 그대로.
- ⚠️ 카카오 지도 API 일 쿼터가 SDK 로드 단위로 세어진다면 홈 방문마다 1건 늘어난다(지금 규모에선 무관). 확인 안 함.

## 🆕 2차 — 대표 *"1, 2 둘 다 진행하고 저화질도 되돌려줘"* (2026-10-15)
화질은 낮추지 않는다는 전제로 세 가지를 했다. 로컬 빌드를 라이브 API 에 붙여 같은 하네스로 쟀다(`scratchpad/map/hidden.mjs` · `pill.mjs`).

1. **저화질 타일 되돌림** — `kakao-sdk.ts` 의 `prefersLowResMapTiles`/`disableHD` 제거. 가드 `map-tile-quality-2026-10-14.test.ts` 를 **반전**: 소스 어디에도 `disableHD(` 가 없고, 데이터 절약·3G 여도 SDK 준비가 화질을 안 내린다(실행으로 판정). 주입 3건.
2. **시트에 가려진 타일 안 받기** — 모바일 첫 화면은 지도 칸 아래를 `peek − 모서리 반경`(216px)만큼 줄여 만든다(`useKakaoMap` `hiddenBottomPx`, DOM 스타일 직접). 이용권을 골라 카드가 뜨면 칸을 화면 끝까지 펴고 **중심을 늘어난 높이의 절반만큼 내려 위쪽이 안 움직인다**. 페이지 ResizeObserver 는 이미 맞춘 높이면 다시 relayout 하지 않는다(카드 pan 애니메이션 보호).
   - 실측(첫 화면 타일 · 시트 밑 타일): 아이폰13 **12 → 9 · 3 → 0** · 갤럭시S9+ **12 → 9 · 3 → 0** · 픽셀7 **15 → 12 · 3 → 0**.
   - 카드 모드 화면은 라이브와 **픽셀 동일**(스크린샷 대조). 첫 시도는 시트 둥근 모서리 뒤가 회색으로 비쳐 24px 겹치게 고쳤다.
   - 부수 효과: 첫 화면의 중심(내 위치·첫 딜)이 화면 가운데가 아니라 **시트 위 보이는 영역 가운데**에 온다(종전엔 시트에 가까웠다).
3. **지도 화면 코드 미리받기** — `lib/route-preload.ts` 등록부. 동적 import 는 **App.tsx 의 lazy 한 곳**에만 두고(`loadMapPage`), 홈은 이름으로 부른다 → 묶음기 봉투 불변(surface-budgets 14 · critical-chunks 14 · 순환 0 그대로). SDK 를 받은 **다음에** 받고(같은 회선 동시 사용 X), 알약을 누르는 순간에도 한 번 부른다(한 번만, 실패하면 다음 기회에 재시도). 데이터 절약이면 미리 안 받는다.
   - 실측(느린 4G·CPU 4배, 홈 → 알약): 탭 뒤 청크 **5 → 0** · 시트 표시 **1.0~1.7 → 0.7~0.9초** · 타일 출발 1.5~2.2 → 1.3~1.5초.
   - `--no-idle` 하네스(exec-cost·surface-chunk-runtime)에서는 미리받기가 안 돈다 — 첫 화면 실행 비용 무변.
