# 2026-09-06 — 홈에서 같은 이용권 사진이 두 번 나오던 것

> 대표: *"메인에서 보면 이용권의 똑같은 사진이 두번 나오는 경우가 있는데 확인해볼래?"*

## 데이터가 아니라 편성이었다

먼저 의심한 것(서로 다른 상품이 같은 사진을 씀)은 **실측으로 기각**했다:

```sql
-- 활성 이용권 중 커버 사진이 같은 그룹 → 0건
SELECT image_url, COUNT(*) FROM products
WHERE is_active=1 AND group_buy_status='active' AND image_url != ''
GROUP BY image_url HAVING COUNT(*)>1
```

진짜 원인은 **홈 섹션이 서로 겹치는지 아무도 안 봤다**는 것이다. 라이브 `/api/sections` 실측:

```
[지금 인기 이용권]   2888, 2712, 2765, 2725
[주말에 떠나는 숙소]       2712, 2764, 2765, 2725   ← 4개 중 3개가 같다
```

두 섹션은 화면에서 **바로 위아래로 붙어 있다.** 사용자에겐 같은 사진이 두 번이다.

왜 겹치나 — '지금 인기'는 규칙(인기 점수순), '주말에 떠나는 숙소'도 규칙(숙소 카테고리)이다.
활성 이용권 338개 중 숙소가 51개인데 **인기 상위를 숙소가 차지**해서, 두 질의가 거의 같은
목록을 낸다. 각 섹션은 `resolveSectionProducts` 를 독립으로 호출했고 서로를 몰랐다.

## 고친 방식 — 한 상품은 한 화면에 한 번

- `resolveSectionProducts` 에 `excludeIds` 추가 → 본문 WHERE 에 `AND p.id NOT IN (…)`.
- 라우트가 **렌더 순서대로** 돌며 이미 나온 id 를 누적해 다음 섹션에 넘긴다.
- **수동 큐레이션이 규칙을 이긴다.** manual 섹션이 자기 몫을 **먼저 확정**하고, 규칙 섹션이
  그 바깥에서 채운다. 어드민이 직접 고른 상품이 위 규칙 섹션에 밀려 사라지면 안 된다.
- `LIMIT` 은 그대로라 **줄이 짧아지지 않는다** — 다음 후보가 자리를 메운다(숙소 후보 51개, 4자리).

### ⚠️ 아래 딜 피드와의 겹침은 **일부러 안 고쳤다**
`2888` 은 인기 섹션과 아래 '가까운 동네 딜' 피드에 동시에 나온다. 그 피드는 **전체 목록**이라
거기서 상품을 빼면 목록이 거짓말이 된다. 큐레이션한 것이 전체 목록에도 있는 건 정상이고
(쿠팡·배민도 그렇다), 두 블록은 제목과 간격으로 분리돼 있다. 테스트가 이 결정을 고정한다.

## 🩸 바인드 위치가 이 변경의 진짜 위험이었다

`NOT IN` 은 SQL 에서 인기 점수의 CROSS JOIN 분모 **뒤**에 온다. 바인드를 앞에 끼우면
카테고리와 id 가 어긋나 **SQL 은 통과하고 결과만 조용히 틀린다.** 문자열 검사로는 못 잡는다.
⇒ 진짜 SQLite 에 상품을 넣고 리졸버를 **실행**하는 테스트로 고정했고, 주입
(`binds.push` → `binds.unshift`)으로 빨간불을 확인했다.

`popular` 의 정규화 **분모(mx)에서는 배제하지 않는다** — 분모는 카탈로그 전체의 최대값이고,
어느 섹션이 먼저 그려지느냐에 따라 점수가 흔들리면 순위가 화면 순서에 의존하게 된다.

## 다음 세션의 첫 액션 — 배포 후 판정

```bash
curl -s 'https://urdeal.kr/api/sections' | python3 -c "
import sys,json
sec=json.load(sys.stdin)['data']
seen=set(); dup=[]
for s in sec:
    for p in s['products']:
        if p['id'] in seen: dup.append((s['title'],p['id'],p['name']))
        seen.add(p['id'])
print('겹침', len(dup), dup)"
```
**`겹침 0` 이어야 한다.** 배포 전 기준선은 **3건**(2712·2765·2725).
그리고 각 섹션이 여전히 4개씩 차는지(짧아지지 않았는지) 함께 볼 것.

⚠️ `/api/sections` 는 **TTL 120초 캐시**다. 배포 직후 바로 재면 옛 값이 나올 수 있다.

## 이번에 틀렸던 판단
- 테스트에서 `rest.length` 를 `all.length - 2` 로 썼다. **배제는 자리를 비우는 게 아니라 미룬다** —
  후보가 남아 있으면 `LIMIT` 은 그대로 채워진다.
- "딜 피드는 안 건드린다" 검사를 원문으로 짰는데 **그 사실을 설명하는 내 주석**이 경로를 적고
  있어 빨간불이 떴다. 이 레포가 기록해 둔 함정인데 같은 날 두 번 밟았다(핑크 수리 때도).
