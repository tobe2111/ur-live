# 2026-09-21 — 주문관리가 이용권을 택배로 그리던 것 (+ 결제 복구 E4 통과)

## 🎉 먼저: 결제 복구가 라이브에서 판정됐다 (E4)

2026-09-19 PR #1498(깨진 외래키 수리)이 머지·배포된 뒤, **대표가 직접 이용권을 결제했다.**

```
orders    88 → 89   id 89 · GB-3-1789611467065 · PAID · 1,000원 · 2026-09-21 10:36:10 KST
vouchers   1 → 2    UR-LUBA-RCP5 · unused · order_id 89
deal_used 900 + 카드 100        ← 부분결제도 정상 동작
payments/tax_invoices → REFERENCES orders(order_number)   ← 수리 모듈이 재빌드한 흔적(테이블명 따옴표)
```

3개월 만에(마지막 주문 2026-06-26) 주문이 다시 만들어졌다. **E4 통과.**

> 🩸 **판정 근거를 한 번 잘못 짚을 뻔했다.** `pragma_foreign_key_check('orders')` 가 0행인 걸 증거로
> 쓰려 했는데, 깨진 스키마를 로컬에 재현해 보니 **그 검사는 깨진 상태에서도 통과한다.**
> 실제로 갈리는 건 `INSERT … RETURNING` 뿐이다. 판정 근거는 pragma 가 아니라 **DDL 원문**이다.

## 🧾 이번 작업 — 대표 신고

> *"이거 지금 이용권 결제인데 배송이고, 지금 셀러대시보드고 어드민대시보드고 주문관리 페이지가 알맞지 않아."*
> *"제품 배송이 아니라 이용권 구매잖아."*

대표가 `/seller/orders` 에서 주문 89를 연 화면:
배송 정보에 **빈 칸 셋**(받는 사람·연락처·주소) · 주문 상품 **0원** · 결제상태 raw `pending` ·
상태 변경 버튼 **"준비중"(으)로 변경**.

### 원인이 넷이었다

| | 무엇 | 실측 |
|---|---|---|
| ① | `delivery_kind` 는 **죽은 컬럼** | 값은 `'shipping'` 이지만 **코드 어디서도 읽지도 쓰지도 않는다**(스키마 기본값뿐). 화면이 배송으로 보이는 건 이 컬럼 때문이 아니다 |
| ② | 두 주문관리가 **모든 주문을 택배로 가정** | 운송장·택배사·배송지·CSV 주소 칸, 상태 전이 `PAID → PREPARING → SHIPPING → DELIVERED` |
| ③ | 어드민 '종류' 칸 **판정이 틀렸다** | `isVoucherCategory(category)` 하나로 갈라 `meal_voucher` 를 **"교환권"** 이라 찍었다. 그건 이용권이다(`deal_only=0`, 카드) |
| ④ | 상품 금액이 **항상 0원** (별개 버그) | 서버 enrich 가 `unit_price` 만 보내는데 화면은 `item.price` 를 읽는다 → `undefined*n → NaN → "0"`. **이용권만이 아니라 모든 주문**. 2026-08-02 enrich 추출 때 컬럼이 갈렸다 |

### 고친 방식 — 판정을 새로 만들지 않았다

대표 선택: **"한 화면에서 분기"**(별도 탭 아님).

판정은 **이미 있는 `getNoShippingKind()`**(`product-flow.ts`)를 쓴다. 그 함수는 2026-09-01 에
*"배송비·배송지 판정의 단일 진실원천"* 으로 만들어졌고, 주문관리가 묻는 질문
(*"이 주문에 배송이 있나"*)이 정확히 같은 질문이다.

- **신규 `src/shared/order-kind.ts`** — `orderKindOfItems` / `orderKindOf` / `ORDER_KIND_META`
  - 🔒 **모르면 배송이다** — 라인이 비거나 배송 상품이 섞이면 `'shipping'`.
    이용권을 배송으로 그리면 화면이 이상할 뿐이지만, 배송 주문에서 운송장 칸을 지우면
    **셀러가 송장을 넣을 방법이 없어진다.**
  - ⚠️ `group_buy_status` 로 분류하지 않는다(migration 0146 이 전 상품을 DEFAULT `'active'` 로 만들었다).
- **서버** `order-list-enrich.ts` — `order_kind` 부여 + SELECT 에 `price` 추가(④ 수리). fail-soft.
- **어드민 API** — `first_item_deal_only` 추가(카테고리만으론 이용권↔교환권이 **구조적으로 안 갈린다**).
- **화면** — 셀러 상세: 배송 없는 주문이면 배송 정보 섹션 → 종류 배지 + 한 줄 안내 + `/seller/scan` 링크,
  운송장 폼·배송 상태 전이 숨김. 목록: 주문자 칸이 배송 없는 주문에선 계정 정보로 떨어진다(빈 칸 방지).
  어드민: `orderKind` 를 SSOT 로 교체 — 이용권/교환권/상품 3종.
