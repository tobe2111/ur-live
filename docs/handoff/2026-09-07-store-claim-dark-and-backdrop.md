# `/store/new` 매장 등록 — 다크 흰 글자 · 배경 클릭 이탈 (2026-09-07)

대표가 PC 다크모드에서 `/store/new` 를 직접 열어 보고 **두 가지**를 신고했다. 둘 다 실재하는 결함이었다.

> *"그리고 글자도 지금 흰색이라 보이지 않아."*
> *"그리고 흰 섹션 바깥쪽을 클릭하니까 페이지가 꺼져."*

## ① 흰 판 위 흰 글자 — 이 레포 **세 번째** 재발

`StoreRegisterModal` 의 패널은 `bg-white` 뿐이라 **테마와 무관하게 늘 흰색**이다. 그런데 이 모달은
셀러 대시보드뿐 아니라 **소비자 라우트 `/store/new`(StoreClaimPage)** 에서도 열린다. 다크에서는
안쪽 `dark:` 유틸이 살아 있어 검색 입력의 `dark:text-white` 가 적용되고, 그 위에 전역
`.dark input:not(...)`(특이도 **0,5,1**)이 `text-gray-900`(**0,1,0**)을 이긴다.
⇒ **클래스 유틸로는 구조적으로 못 이긴다.**

**브라우저 실측 (컴파일된 CSS + Chromium, 계산된 색):**

| | 글자 | 패널 | 대비 |
|---|---|---|---|
| 수정 전 | `rgb(255,255,255)` | `rgb(255,255,255)` | **1.00:1** (글자가 없는 것과 같다) |
| 수정 후 | `rgb(22,24,28)` | `rgb(255,255,255)` | **17.77:1** |

**처방**: 패널에 `light-island`. tailwind `darkMode` variant 가 안쪽 `dark:` 를 통째로 끄고,
`index.css` 의 `.light-island input` 규칙이 `!important` 로 전역 다크 입력 규칙을 무력화한다.

⚠️ **`light-fixed` 는 주석이라 런타임엔 아무 일도 안 한다** — 가드 면제용 부표일 뿐이다.
2026-09-03 지도 검색창이 정확히 그 착각으로 깨졌고, 이번 것도 같은 클래스다.

⚠️ **왜 기존 가드가 못 잡았나**: `check-theme-consistency`·`check-input-text-color` 는 셋 다 초록이었다.
전자는 "라이트 토큰에 `dark:` 가 있나"를 보는데 이 입력은 `dark:text-white` 를 **갖고 있어서** 통과했고,
후자는 같은 className 의 base 토큰만 본다. **특이도 싸움의 승자는 브라우저만 안다** —
그래서 `check-dark-contrast.mjs`(실제 렌더 측정)가 있는 것인데, 그 경로 목록에 `/store/new` 가 없다
(로그인이 필요한 페이지라 넣어도 리다이렉트된다). **남은 사각지대다.**

## ② 배경 클릭이 폼을 통째로 날린다

`/store/new` 는 **모달이 곧 페이지**다(`StoreClaimPage` 의 내용이 이 모달 하나뿐). 배경 뒤에 아무것도
없는데 배경 클릭이 `onClose → navigate(-1)` 이었다. 사업자등록증까지 올린 폼이 스치는 클릭 하나에
사라지고 화면을 떠난다.

**같은 컴포넌트라도 겹쳐 뜬 것과 페이지인 것은 닫기의 의미가 다르다** — 대시보드에선 뒤에 목록이
보이니 바깥 클릭 닫기가 맞다. ⇒ `dismissOnBackdrop` prop(기본 `true`)을 두고 페이지에서만 `false`.

**곁다리로 드러난 것**: `onClose={() => navigate(-1)}` 는 이 페이지에서 원래 위태로웠다. 이 페이지의
존재 이유가 *"푸터·소개 페이지·카톡 링크 어디서나 도달하는 하나의 주소"* 인데, **직접 주소로 열면
돌아갈 이력이 없다.** 그때 `-1` 은 아무 일도 안 하거나 앱 밖으로 나간다 ⇒ 이력 없으면 홈으로.
