## 이번에 틀렸던 판단
- **숙박 만료를 "자동 환불" 로 고쳤다가 대표가 바로잡았다**: *"숙소는 시간 지나면 자동환불이 아니라 사용 완료로 환불이 안되는건데"*. 코드가 환불을 시도하다 실패하고 있었기에 "환불이 의도" 라고 읽었다. 의도한 규칙은 코드가 아니라 대표의 말에서 확인할 것.
- **KT 발송 판정 SQL 이 조용히 거짓이었다**: 시험 DB 가 숫자를 실수로 묶어 `'u' || 5.0 || '-%'` 가 됐다. `CAST(… AS INTEGER)` 로 고정. 그리고 발송 성공 때 연결 키를 KT 주문번호로 덮어쓰고 있어, 판정 SQL 만 고쳤다면 라이브에서도 조용히 거짓이었다. 측정기가 0 을 내면 측정기부터 의심.
- 어드민 조사 보고의 "`pending` 지급을 바로 `sent` 로 넘길 수 있다" · "viewer 가 환불할 수 있다" 는 **코드 읽기(E1)** 다. 시험으로 돌린 것은 "역할 admin 이 지급 승인에서 403" 하나뿐.

## 안 고친 것 (2026-11-25 오전 갱신 — 대표 *"그래서 찾은 에러들은?"* 뒤 2차 수리 반영)
**2차로 고친 것**(결재 기록 `docs/decisions/2026-11-25-payout-refund-ledger-fixes.md`): 받을 돈을 넘는 지급(일괄 승인·바로 송금 완료·이체 파일) · 조회 전용 어드민의 환불 실행 · 환불 원장 계정과 만료 환불 원장 줄 · 일부 사용 뒤 환불의 매장 몫 · 소개비 확정 시각 비교 · 어드민 수익 추정 요율.

**재확인해서 목록에서 내린 것**
- ~~`StoreBankPage` "매주 목요일" 문구가 틀렸다~~ → 목요일은 대표가 정한 규칙이다(`partners-facts.ts` `storePayoutDay`). 문구는 맞다. 남는 확인거리는 목요일 장치(`auto-settlement`, 라이브 `restaurant_settlements` 0행)와 월요일 09:45 장치(`payouts-generate`, 보류 14일) 중 어느 쪽이 실제로 돈을 내보내는가(미실행).
- ~~숙박 주문이 사장님 "오늘 매출" 에 안 잡힌다~~ → 코드를 다시 읽으니 오늘 매출 집계 둘(`seller-management.routes.ts` · `seller-operators.routes.ts`)은 `orders.seller_id` 기준이고 숙박 주문도 그 칸을 채운다. 처음 보고의 근거(시험 기록)가 남아 있지 않다 — **시험으로 다시 재지는 않았다(E1)**. 주문 목록처럼 `order_items` 로 묶는 화면에는 숙박 주문이 안 보일 수 있다(숙소는 전용 예약 목록이 있다).
- 역할이 'admin' 인 계정이 지급 승인에서 403 → 의도된 설계다(지급은 finance + 최고 관리자). 고칠 것 없음.

**아직 안 고친 것 (급한 순)**
1. `/api/admin/*` 밖에서 어드민 토큰을 받는 **다른 쓰기 경로**는 역할을 안 본다(이번에 닫은 것은 분쟁·반품뿐). 지금 제한 역할 계정이 0개라 노출은 없다. 제한 역할 계정을 만들기 전에 전수로 닫을 것 — 목록은 `grep -rln "type === 'admin'\|requireAdmin()" src/worker/routes src/features --include=*.ts | grep -v admin` (약 60파일, 대부분 읽기).
2. 지급 완료된 소개비는 환불돼도 회수되지 않는다(코드 읽기 단계). 다만 `payout_requires_voucher_use=true` 라 소개비는 **사용된** 이용권만 확정되고, 사용된 이용권의 환불 길은 어드민 분쟁 승인뿐이라 지금은 일어나기 어렵다.
3. 지급 대상이 계좌 없는 매장에도 만들어진다(승인·송금 단계에서 막힌다. 시험으로 확인).
4. 인플루언서 수익 화면이 둘이고(`/creator` 는 어필리에이트만), 지급 때 원장 줄이 없다 · 숙박 소개 링크는 유저 번호만 받는다(코드 읽기 단계).
5. 유저 화면: 딜 안내 문구가 꺼진 프로그램(친구 초대)을 가리킨다 · 프로모 코드 입력 화면이 없다 · 리뷰 등급 조건 상품은 못 살 수 있다 · 리뷰 보상이 장부에 `charge` 로 적힌다(전부 코드 읽기 단계).
6. 사장님 화면: 광고 과금이 안 된다 · 옛 정산 화면(`settlements`)이 빈 표를 읽는다(코드 읽기 단계).
7. 셀러 가이드 `security-pin` 섹션이 수동 편집 표시라 "첫 PIN" 문구가 안 실렸다.
