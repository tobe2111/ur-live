## 이번에 틀렸던 판단
- **숙박 만료를 "자동 환불" 로 고쳤다가 대표가 바로잡았다**: *"숙소는 시간 지나면 자동환불이 아니라 사용 완료로 환불이 안되는건데"*. 코드가 환불을 시도하다 실패하고 있었기에 "환불이 의도" 라고 읽었다. 의도한 규칙은 코드가 아니라 대표의 말에서 확인할 것.
- **KT 발송 판정 SQL 이 조용히 거짓이었다**: 시험 DB 가 숫자를 실수로 묶어 `'u' || 5.0 || '-%'` 가 됐다. `CAST(… AS INTEGER)` 로 고정. 그리고 발송 성공 때 연결 키를 KT 주문번호로 덮어쓰고 있어, 판정 SQL 만 고쳤다면 라이브에서도 조용히 거짓이었다. 측정기가 0 을 내면 측정기부터 의심.
- 어드민 조사 보고의 "`pending` 지급을 바로 `sent` 로 넘길 수 있다" · "viewer 가 환불할 수 있다" 는 **코드 읽기(E1)** 다. 시험으로 돌린 것은 "역할 admin 이 지급 승인에서 403" 하나뿐.
