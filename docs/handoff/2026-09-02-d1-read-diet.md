## 1. 계량기 (이 세션 · PR 별도)

- `src/worker/utils/d1-read-meter.ts` — D1 래퍼. `all/run/batch` 의 `meta.rows_read` 합산, `first/raw/exec` 는
  `qu`(unmetered) 로 횟수만. **`first()` 를 `all()` 로 바꿔 세지 않는다**(무제한 SELECT + first 가 37만 행을 실어 와
  워커를 죽일 수 있다).
- `d1-read-meter-als.ts` — cron 워커 작업별 귀속(AsyncLocalStorage). `scheduled.ts` 의 `safeCron` 이 계량기 안에서
  작업을 돌리고 `recordCronBeat(…, meter)` 로 하트비트에 `rr/rw/q/qu` 를 싣는다. 어드민 `/cron-heartbeats` 응답에
  `rows_read/rows_written/queries/unmetered`.
- 🩸 **`node:async_hooks` 를 정적으로 import 했더니 ur-wholesale Pages 프리뷰 빌드가 죽었다**(Pages 배포 단계 번들러는 프로젝트에
  `nodejs_compat` 이 없으면 `node:` 정적 import 를 못 푼다 — 워커 번들에 `node:` import 가 이 파일이 처음이었다). 런타임 문자열
  `import(spec)` 로 바꾸고 없으면 계량을 끈다(기능 불변). `esbuild.worker.config.js` 는 main 에서도 top-level await 로 이미 안 도는 스테일 파일.
- ⚠️ 이미 있던 도구: `d1-profiler.ts`(2026-07-22, `D1_PROFILE_ENABLED='true'` 로 Pages 요청경로 SQL 패턴별 집계,
  isolate 메모리·미저장, 어드민 `GET /api/admin/d1-profile`). **요청 경로는 이걸 켜서 재면 된다**(대표가 env 설정).
  계량기는 cron/레인 **작업별·영구 기록**이라 상보적이다.
