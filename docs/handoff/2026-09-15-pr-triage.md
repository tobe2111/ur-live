## 2. 이번에 배운 것 (다음 세션이 같은 오판을 하지 않게)

### 🔴 `dirty` 는 빨간불이 아니라 **부재**다
`mergeable_state: dirty` 면 GitHub 가 `refs/pull/N/merge` 를 못 만들고, 그래서
**`pull_request` 워크플로가 아예 안 돈다.** PR 화면에는 실패가 아니라 *아무것도* 안 뜬다 —
훑어보면 "체크가 없네" 정도로 보이고 통과처럼 읽힌다. 이 레포가 반복해 당한 **조용한 부재**의
또 다른 얼굴이다. ⇒ **오래 열린 PR 은 `mergeable_state` 부터 본다.**

### 🩸 범위 기반 가드는 **커밋한 뒤에** 다시 돌려야 한다
`check-file-size` 는 `origin/main..HEAD` 범위로 본다. 커밋 전에 pre-push 게이트를 돌리면
그 가드는 **"대상 없음(skip)"** 으로 조용히 통과한다. 실제로 커밋 전 95개 초록 → 커밋 후
`worker/index.ts 2642 > 2638` 빨간불이 났다. 게이트를 돌렸다고 다 검사된 게 아니다.

### 🩸 #1123 의 IDOR 가드가 **주석 덕에** 통과하고 있었다
`mall-operator-console.test.ts` 가 따옴표/백틱 **짝짓기**로 SQL 문장을 잘라냈다. 한국어 주석의
아포스트로피와 `${sets.join(', ')}` 의 작은따옴표가 짝을 어긋내 **엉뚱한 구간 4개**를 잡았고
(실제 SQL 은 1개만 포착), 그중 하나가 주석 `// 🔴 mall_id 를 WHERE 에 함께` 를 품고 있어서
`UPDATE mall_notices … WHERE id = ?` 로 **mall_id 를 빼도 초록불**이었다.
⇒ 교훈 둘: **(a)** 소스를 문자열로 읽는 검사는 반드시 `readCode`(SSOT `stripComments`)를 쓴다.
**(b)** 따옴표 짝짓기로 문장을 자르지 말고 **키워드 앵커 + 유계 창**으로 잰다.

### 🩸 "주입으로 빨강 확인 완료"가 **손으로만** 돌아 있었다
#1123 본문은 주입 4건을 확인했다고 적었지만 매니페스트에 등록하지 않았다. 손으로 하면
