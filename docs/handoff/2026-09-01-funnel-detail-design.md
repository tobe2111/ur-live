# 구매 흐름(상세·장바구니·결제) 디자인 정리 · 가드 두 개 확장 (2026-09-01)

대표 *"결제 페이지도 다 했어? 유어딜의 세부페이지들 말이야"* → *"이모지 말고도 전체 페이지 디자인들 말이야"*

## 🔴 먼저 — 내가 과하게 말했다

앞서 *"서비스 전체에 아이콘 자리 이모지가 0"* 이라고 보고했다. **틀렸다.**
그건 `check-design-slop` 이 **세는 좁은 범위**에서 0이라는 뜻이었고, 실제로는 소비자·셀러 표면에
이모지가 **475건**, 구매 흐름에만 **45건** 남아 있었다. 대표가 물어서 알았다.

가드가 못 본 이유:

```
예전 UI_SLOT = icon:/emoji: 필드 · label: · <h1~6|button> 끝 텍스트
실제 코드    = <span className="text-2xl">📱</span>     ← <span> 텍스트
              📦 합배송                                   ← 평범한 JSX 텍스트
              charge: '💳', donate: '🛒'                  ← 필드명이 icon 이 아닌 값 맵
```

⇒ 넷을 다 보도록 넓혔다. **emoji 래칫이 0 → 533 으로 뛴 것은 코드가 나빠진 게 아니라 자(尺)가
넓어진 것**이다. baseline `_comment` 에 그렇게 적어 뒀다 — 다음 세션이 "0 → 533 대참사" 로 읽지 않도록.

기존 가드 둘은 **파일 이름을 박아 둔 계약 테스트**라 셋째를 못 봤고, 셋째는 인라인 스타일이라
className 을 보는 검사로는 **애초에 못 잡는다.** ⇒ `check-discount-not-on-photo` 로 규칙을
**파일 무관·표기 무관**으로 옮겼다. 세 구현 각각에 배지를 되살려 전부 빨간불 확인.

## 무엇을 고쳤나

**상세 페이지(렌더해서 눈으로 찾음)**
- `OtherDealsRow` 할인율을 사진 밖 가격 줄로
- 신뢰 스트립 아이콘이 **셋 다 같은 `ShieldCheck`** 였다 → 결제=방패 / 판매자=인증 / 환불=되돌림.
  같은 그림을 세 번 쓰면 아이콘의 정보량이 0이고, 3열 균등 + 동일 글리프는 "찍어낸" 인상을 만든다.

**구매 흐름 이모지 45곳 → lucide** (상세 4종 · 장바구니 · 결제 · 결제완료 · 딜내역)
- `MyDealHistoryPage` 는 바로 위 `FILTER_OPTIONS` 가 **이미 같은 종류를 lucide 로** 갖고 있었는데
  목록 행만 이모지 맵을 따로 썼다 — 한 화면에서 두 가지 그림 언어를 쓰던 셈이다.

**결제 완료(`PaymentSuccessPage`)는 Toss V2 감사-잠금이라 대표에게 물어 "허가 — 시각만 변경" 을
받고 진행.** confirm/금액검증(`serverTotal`)/`TossPaymentObject` 표시(receipt.url·cashReceipt·
easyPay·approvedAt)/pendingBookings/셀러 넛지 **전부 byte-불변** — 바뀐 것은 글리프 6개뿐.

## 남은 것 (정직하게)

- **이모지 533건이 앱 전체에 남아 있다.** 구매 흐름은 0이지만 나머지는 아니다. 래칫이라 더 늘지는
  않는다. 다음에 정리한다면 `InfluencerDashboardPage`(14) · `CuratorEarningsPage`(13) ·
  `BlogCover`(12) 순으로 크다.
- `/checkout` 실화면은 **못 봤다** — 하네스에 장바구니 시드가 없어 빈 상태만 렌더된다.
  결제 화면 자체의 레이아웃 판단은 시드를 만든 뒤에 해야 한다.
- 면제로 남긴 6건은 토스트 본문·카카오 공유문·**문자열 파싱**(`/^(📅|❗|✅)/` 로 매장 안내문의
  이모지 줄을 감지)이다. 파싱은 지우면 기능이 깨진다.
