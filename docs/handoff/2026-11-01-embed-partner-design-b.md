## 이번에 한 것 — 제휴 위젯을 시안 A → B 로
대표 *"제휴사 입점 관련한 위젯은 디자인을 되게 고급지고 세련되게 할 필요가 있었어"* → 3안 제시 → **B 확정**.

- `renderPartner` 마크업 + `.pt*` CSS 신설(옛 `.tk*` 제거). 머리띠에 `urdeal.` 과 제휴사 이름을 **가는 선 하나로 나란히**.
- **비교 블록(col old/new) 마크업은 A 와 byte-동일**이다 — 칸을 가르는 건 박스가 아니라 CSS `border-left` 하나.
  (그래서 기존 가드 `:150` 정규식이 그대로 산다. 마크업을 바꿨으면 그 가드를 건드려야 했다.)
- `EMBED_HEIGHT.partner` **400 → 360**. 실측: 카드 340 + 바깥 여백 20 = 360.
  400 일 때 아래가 **60~94px 비어** 있었고 그 허전함이 투박함의 큰 몫이었다.
- 토큰 `--pbg`(제휴 위젯 바깥 바탕) · `--lift` · `--glow` 신설.

### 🔴 --bg 는 일부러 안 건드렸다
라이트 `--bg` 와 `--card` 가 **둘 다 흰색**이라 카드가 떠 보이지 않는 게 결함의 하나였다. 그런데 `--bg` 를
회색으로 바꾸면 **strip·single 위젯 다섯이 남의 흰 사이트에서 회색 사각형**이 된다(제휴 화면만 보면 멀쩡하다).
⇒ 제휴 전용 `--pbg` 로 분리. 가드 ④가 이 방향을 양방향으로 고정한다.

## 이번에 틀렸던 판단
- **`toContain('--bg:#FFFFFF')` 로 "안 바뀌었다"를 단언했는데 헛돌았다.** 주입이 뒤에 `--bg:#F8F7FC` 를
  **덧붙이자** 통과했다 — CSS 는 나중 선언이 이기는데 옛 문자열은 그대로 남는다. ⇒ 토큰 줄을 **파싱해서**
  `--bg:` 선언이 **정확히 하나**이고 그 값이 무엇인지 본다.
- 처음에 `origin/main` 이 낡은 상태에서 `merge-base` 를 돌려 **"임베드 코드가 main 에 없다"** 고 읽었다.
  `git fetch` 후 보니 전부 머지돼 있었다. **fetch 없이 main 과 비교하지 말 것.**
- `/api/curator/:handle` 응답을 `data` 래퍼로 파싱해 "핀 0개" 로 읽었다. 실제로는 **최상위에 `pins`** 가 있고 1개다.
- fullPage 스크린샷이 **뷰포트 밖 cross-origin iframe 을 안 그린다.** 지역 위젯이 빈 칸으로 찍혀 결함으로
  오진할 뻔했다 — 스크롤 후 뷰포트 캡처로 재니 멀쩡했다.

# 2차 (같은 날) — 에이전시 위젯 + "홈페이지에 넣기"

대표 *"에이전시와 제휴사 입점 부분이 가장 중요"* → 제휴 B안 머지 뒤 *"모두 이상적으로"*.

## 에이전시 위젯 (`/embed/agency/:id`)
종전엔 유어샵·매장·지역과 **똑같은 `renderStrip`** 이었고 제목만 달랐다. 더 나쁜 것은 `전체 보기` 가
**유어딜 홈**으로 갔다는 점이다 — 에이전시가 자기 사이트에 건 위젯이 손님을 우리 쪽으로 보내고 있었다
(에이전시 공개 페이지가 **없어서** 갈 곳이 없었다).

- `StripInput` 에 선택 옵션 `brand`(머리띠에 나란히 설 회사 이름) · `meta`(운영 매장 N곳) 신설,
  `moreHref` 를 선택으로. **안 넘기면 머리띠 마크업이 종전과 byte-동일**이다(나머지 셋 무접촉 — 가드 ②).
- 머리띠가 제휴 위젯(시안 B)과 **같은 언어**가 됐다: `urdeal. │ 한빛 마케팅 … 운영 매장 8곳` + 아래 구분선(`.hd.co`).
- `전체 보기` 제거. **링크는 도착지가 있을 때만 건다.**
- ⚠️ **0 곳이면 지표를 안 그린다** — 신뢰를 주려고 넣은 자리에 0 이 서면 없느니만 못하다(새 에이전시에서 바로 난다).

## "홈페이지에 넣기" (`src/shared/embed-code-link.ts`)
🔑 **에이전시 번호는 로그인 응답(`AgencyInfo.id`)이 이미 주고 있었다** — 화면에 안 썼을 뿐이다.
⇒ 번호를 *보여주는* 대신 **몰라도 되게** 했다: 버튼이 키를 싣고 `/embed?type=&key=` 로 간다.

- **에이전시 콘솔**(`AgencyStoresPanel`) — 영입 링크 카드 아래 버튼. 번호를 모르면(프로필 부재) **안 그린다**.
- **유어샵 관리**(`UShopManagePage`) — '내 유어샵' 판에 줄 하나(`openEmbedCode('ushop', curator.handle)`).
- ⚠️ 위젯 종류를 버튼 둘로 나누지 않았다 — 운영 매장 ↔ 제휴사 입점은 **같은 번호**를 쓰고
  `/embed` 화면이 이미 6종 드롭다운을 갖고 있다. 나누면 같은 말을 두 번 하는 입구가 된다.
- 🔴 `/embed` 는 **워커가 그리는 화면**이라 SPA 이동으로 열면 안 된다(`window.open`). 가드가 고정.

## 🔴 마이 '내 가게' 는 일부러 뺐다
판매 판은 **줄 다섯이 상한**(2026-09-30 대표 확정 ⑥ — *"바로가기가 아홉이면 바로가기가 아니다"*)이고
이미 다섯이다. 그리고 위젯 코드는 **한 번 받아 붙이면 끝**이라 그 판의 기준(*하루에 몇 번 여는가*)에 안 맞는다.
`전체 도구` 시트는 **셀러 라우트 표를 그대로 렌더**하는 구조라 `/embed`(워커 화면)가 거기 들어가지 않는다.

## 이번에 틀렸던 판단
- **가드가 `renderStrip` 만 호출해서 헛돌았다.** 호출부(라우트)가 `moreHref` 를 되살려도 렌더 결과만 보는
  단언은 통과한다 — 주입이 잡았다. ⇒ 에이전시 핸들러 **소스**도 함께 본다.
- 주입 앵커를 `user.name` 으로 적었는데 실제 소스는 `name` 이었다(지역변수로 한 번 거친다). 러너가 "낡은 지도" 로 잡았다.
- `--only "a\|b"` 는 **안 먹는다** — 부분일치라 각각 따로 불러야 한다.
