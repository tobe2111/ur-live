# 2026-08-27 — 모바일 지역 선택 패널이 화면 밖으로 나가던 것

대표 폰 스크린샷 신고: *"폰으로 보니까 이렇게 화면에서 나가고 있어"* — 지역 선택 패널이 오른쪽으로
삐져나가고, 페이지 전체가 가로로 밀려 `urdeal.` 로고가 왼쪽으로 잘려 있었다.

## 원인 — 패널이 **버튼**에 붙어 있었다

`PcHomeLocationBar` 의 패널이 `absolute left-0 … w-[520px] max-w-[90vw]`.
`left-0` 은 **버튼의 왼쪽 가장자리** 기준인데, 모바일 헤더에서 그 버튼은 오른쪽에 있다.
그래서 패널이 화면 오른쪽 밖으로 뻗어 **문서 자체를 화면보다 넓게** 만들었다.

라이브 실측 (수리 전):

| 화면 | 패널 x | **문서 폭** |
|---|---|---|
| 360px | 96 → 420 | 360 → **420** (+60) |
| 390px | 126 → 477 | 390 → **477** (+87) |
| 430px | 166 → 553 | 430 → **553** (+123) |

## 🔑 가장 중요한 것 — `max-w-[90vw]` 가 왜 안 통했나

패널에는 이미 `max-w-[90vw]` 가 붙어 있었다. **그런데 안 막혔다.**

> **문서가 넓어지면 `vw` 도 같이 커진다.** 그래서 90vw 는 자기 자신을 못 잡는다.

측정에서도 이게 함정으로 나타난다 — 수리 전 스크립트가 *"화면밖 0px"* 을 찍었다.
패널은 실제로 **잘리지 않았고**, 대신 **페이지가 커졌다**. 패널만 보면 멀쩡해 보인다.
⇒ 이 클래스를 잴 때는 패널 좌표가 아니라 **`document.documentElement.scrollWidth` 증가**를 봐야 한다.

## 수리

좁은 화면(<640px)에서는 버튼 좌표계를 벗어나 **뷰포트에 고정**한다.

- `fixed left-2 right-2` — 좌우 모두 뷰포트에 묶여 구조적으로 못 넘친다
- `top` 은 여는 순간 트리거의 `getBoundingClientRect().bottom` 을 재서 정한다
  (`fixed` 라 `top-[calc(100%+8px)]` 이 의미를 잃는다). resize 때만 다시 잰다.
- `max-h-[calc(100dvh-160px)]` — 세로로도 안 넘치게(작은 기기·가로모드에서 아래 지역을 못 고르던 문제)
- **640px 이상은 종전 그대로** (`absolute left-0 w-[520px]`) — PC 회귀 0

브라우저 실측 (수리 후): 360/390/430/360x640 전부 `fixed`, x[8..vw-8], **문서 증가 0**, 화면밖 0.
1440 은 `absolute` x[32..552], 문서 증가 0 — PC 불변 확인.

## 같은 클래스를 찾아봤고 — **다른 곳엔 없었다**

`absolute` + 고정 폭 드롭다운 7곳을 훑고 브라우저로 실측:

| 후보 | 판정 |
|---|---|
| `NotificationDropdown` (`right-0 w-[360px]`) | ✅ 안전 — `DesktopTopNav` 안이고 그건 `lg:` 미만 숨김 |
| `AccountMenu` (`right-0 w-[300px]`) | ✅ 같음 |
| `StayDateGuestPicker` ×2 | ✅ 이미 올바른 패턴(`left-0 right-0` + `lg:` 오버라이드) |
| `RestaurantMapPage` 시트 | ✅ 같음 |
| `IntroducePage` 장식 원 | ✅ 의도적 |

⚠️ 실측 중 `l:-112` 인 요소가 나와 잠깐 버그로 의심했는데, **장식용 그라데이션 원**이었다
(`-top-28 -left-28`, `pointer-events-none` 레이어 안). 일부러 화면 밖에 걸쳐 둔 것이다.
좌표만 보고 판정하면 이런 걸 "고친다" — 클래스명과 용도를 함께 볼 것.
