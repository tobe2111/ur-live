# 2026-08-05 — 공정위 가맹 레인이 **이름 하나로 22회를 버렸다**

## 1. 무엇이 있었나

```
ads_franchise_stats: total_runs 22 · total_saved 0
error: HTTP 400 · NO_OPENAPI_SERVICE_ERROR (2026-07-29부터 8회 연속 실패)
```

승인·활용기간(2026-07-27~2028-07-27)·키 **전부 정상**인데 0건이었다. 원인은 **오퍼레이션 이름 하나**:

```
우리 코드   getBrandList      ← 틀림
실제 이름   getBrandinfo      ← 대표가 준 포털 Swagger 화면(API 목록 + getBrandinfo_response)
```

🩸 **왜 오래 안 잡혔나**: 소스 주석이 *"✅ 실 엔드포인트(웹 확인 2026-07-23)"* 라고 **단언**하고 있었다.
그런데 이 환경은 `apis.data.go.kr` 이 프록시 차단이라 **개발 중에 찔러볼 수가 없다** — 확인했다는
문장만 남고 검증은 비어 있었다. **문서가 증거를 대신한 자리다.**

## 2. 수리 — 이름을 고치는 데서 그치지 않았다

Swagger 글자가 작아 대소문자를 100% 단정하기 어렵다. 추측을 코드에 굳히는 대신 **한 번의 실측으로
스스로 정하게** 했다:

- 기본값 `getBrandinfo`
- 첫 페이지가 `NO_OPENAPI_SERVICE_ERROR` 면 후보(`getBrandInfo` → `getBrandList`)를 순회
- 맞는 이름을 `platform_settings.ads_franchise_op` 에 **기억** → 다음 회차부터 재시도 0
- 우선순위: env override > 학습값 > 기본

⚠️ **주소 부재(code 12)일 때만** 후보를 돌린다. 키·트래픽·파라미터 오류에 돌리면 같은 실패를 3배로
반복해 예산만 태운다. 그리고 후보 호출도 예산을 쓴다(`budget.left <= 0` 이면 중단).

## 3. 같은 문자열이 **한 벌 더** 있었다 — 기존 가드가 잡았다

`ads-public-data-probe.test.ts` 가 빨간불을 냈다: 진단 프로브가 `getBrandList` 를 그대로 박아 두고
있었다. 그대로 뒀으면 **레인은 고쳐졌는데 프로브는 옛 주소를 찔러** 다음 세션이 또 오진했을 것이다
(2026-08-02 에 실제로 그 사고가 있었고, 그래서 그 시험이 생겼다).
⇒ 프로브가 **레인 상수를 import** 하게 바꿨다. 문자열을 두 벌 두면 반드시 갈라진다.

## 5. 나라장터 계약 레인은 **잘 돌고 있다**(대표 화면으로 교차확인)

대표가 준 포털 화면의 `조달청_나라장터 공공데이터개방표준서비스` 상세기능이 우리 코드와 정확히 일치한다:
```
End Point  https://apis.data.go.kr/1230000/ao/PubDataOpnStdService
상세기능 3  /getDataSetOpnStdCntrctInfo   계약정보    ← 우리가 쓰는 것
```
실적: `scanned 800 → matched 4 → saved 4` · 누적 10건 · **이메일 5건(50%)** · 전화 10건(100%).
수율 50% 는 우리 소스 중 최고다(통신판매 13.9% · webkr 15%). 다만 상권 키워드 필터가 좁아
800건 중 4건만 통과한다 — **필터를 넓히면 이메일이 훨씬 빨리 쌓인다**(미결정).

## 6. 🆕 아직 안 쓰는 소스를 하나 찾았다 — `조달청_나라장터 사용자정보 서비스`

대표 화면 2번째. **이메일 크롤 재료(홈페이지주소)를 직접 주는 소스**다:

```
End Point  https://apis.data.go.kr/1230000/ao/UsrInfoService02
  3  /getPrcrmntCorpBasicInfo02   조달업체 기본정보
     → 사업자등록번호 · 업체명 · 법인등록번호 · 주소 · 상세주소 · **전화번호** · **팩스번호**
       · **홈페이지주소** · 대표자명 · 업체업무구분 · 본사구분명 …
```

왜 값진가: 지금 B2B 이메일이 없는 행 162,456건 중 **크롤할 홈페이지가 있는 건 2,163건(1.3%)** 뿐이다.
이메일의 병목은 속도가 아니라 **재료 부족**인데, 이 소스는 그 재료를 직접 준다.

⚠️ 이 서비스의 다른 오퍼레이션(`getPrcrmntCorpBasicInfo`, 02 없음)이 **2026-08-04 에 code 12 로 죽어
있었다** — 그래서 계약 레인으로 옮겼던 것이다. 이번 화면의 `02` 접미 버전은 **후임일 가능성**이 있다.
⇒ 새 레인을 만들기 전에 **프로브로 먼저 찔러 확인**할 것(`/api/ads/probe?path=...`, 라이브에서만 동작).
