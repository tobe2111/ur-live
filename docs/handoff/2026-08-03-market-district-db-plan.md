# 상인회·상권 DB — 네 소스는 성격이 다르다 (2026-08-03 대표 지시)

> 대표: *"상인회·상권 DB — 나라가 이미 다 만들어놨습니다. 조인만 하면 됩니다."*
> 맞다. 다만 **네 개 중 하나만 '리드'이고 셋은 '신호'** 다. 이 구분을 놓치면 연락처 없는 명단을 쌓게 된다.

## 이 DB 의 성공 기준을 다시 적어 둔다

유어애즈의 지표는 총 인원이 아니라 **"제안 보낼 수 있는 리드 수"** 다(CLAUDE.md). 상권 축도 같다 —
**전화나 이메일이 붙지 않으면 0건과 같다.**

| 소스 | 형태 | 연락처 | 이 DB 에서의 역할 |
|---|---|---|---|
| **전국전통시장표준데이터** | 오픈API | **전화·홈페이지 有** | 🎯 유일하게 바로 제안 가능한 **리드** |
| 소상공인 상가(상권)정보 | 오픈API | 점포 단위 | 시장 안 점포 수·업종 구성(규모 신호) |
| 지자체 고시·공고 | HTML 크롤 | 없음 | **자격 신호** — 골목형상점가 지정 여부 |
| 보조금 공시 / 나라장터 낙찰 | 공시·API | 없음 | 예산 규모 + **경쟁사** |

⇒ **조인의 중심축은 전통시장 표준데이터**다. 나머지 셋은 그 위에 딱지를 붙이는 용도이고,
딱지가 붙은 곳이 우선순위 1번이 된다("지금 예산이 있는 상인회").

## 오늘 실측으로 확정된 것

### ✅ 소상공인 상가정보 — **우리 키가 이미 열려 있다**(대표 신청 불필요)

```
apis.data.go.kr/B553077/api/open/sdsc2/storeZoneInRadius
→ HTTP 200 · {"resultCode":"11","resultMsg":"NO_MANDATORY_REQUEST_PARAMETERS_ERROR"}
```

이 응답이 **좋은 소식**인 이유: *"필수 파라미터가 없다"* 이지 *"권한이 없다"* 가 아니다.
미신청이면 오늘 대조군으로 확인한 대로 **code 30**(403)이 온다. ⇒ 파라미터만 채우면 바로 쓴다.
필수 파라미터는 반경 조회 기준 `radius`·`cx`·`cy`(좌표) — 시장 좌표를 중심으로 돌리면 된다.

⚠️ `storeListInDong` 은 같은 프로브에서 **응답 없음(타임아웃)** 이었다. 죽었다고 단정하지 말 것 —
파라미터 부재로 게이트웨이가 늦게 끊었을 수 있다. 판정은 파라미터를 갖춰 다시 찔러서 한다.

### ⏳ 전통시장 표준데이터 — **호스트가 다르다**

```
api.data.go.kr/openapi/tn_pubr_public_trdit_mrkt_api      ← 's' 없다
apis.data.go.kr/…                                          ← 우리 레인 대부분
```

`apis.` 는 기관별 서비스, `api.` 는 **표준데이터**(`/openapi/tn_pubr_public_*`)를 서빙하는 **별개 호스트**다.
프로브 허용 목록에 없어서 찌를 수 없었다 → 이번 커밋에서 `api.data.go.kr` 추가(경로만 받는 계약은 불변,
`.go.kr` 경계 시험 신설).

**다음 세션의 첫 액션** — 배포 후 이 한 방으로 대표 신청 필요 여부가 갈린다:

```
POST /api/admin/partner-pool/probe-public-data
     ?target=license&path=openapi/tn_pubr_public_trdit_mrkt_api&host=api.data.go.kr&rows=3&page=1
```

| 결과 | 뜻 | 조치 |
|---|---|---|
| **200 + 행** | 키가 이미 열려 있다 | 바로 수집 레인 배선 |
| **code 30**(403) | 활용신청 안 됨 | **대표께 요청** — 데이터셋 15012894 활용신청 |
| **code 12**(400) | 주소가 안 맞는다 | 오퍼레이션명 재확인(오늘 인허가와 같은 클래스) |

⚠️ **code 12 를 보고 "폐기"라고 단정하지 말 것.** 오늘 그 오판을 실제로 했고, 원인은 경로 한 칸이었다.

📌 트래픽 한도: 표준데이터는 **개발계정 월 1,000요청**. 전통시장은 전국 ~1,400개소라
`numOfRows` 를 크게 잡으면 **전량이 몇 요청**이다 — 한도는 병목이 아니다. 다만 매시간 도는 레인으로
만들면 금방 소진되니 **일 1회**로 충분하다(정적에 가까운 원부다).

## 설계 메모 — 어디에 저장하나

**새 테이블을 만들지 말 것을 먼저 검토했다.** 상인회/시장은 `store_prospects`(매장 후보)와 성격이 다르다 —
점포가 아니라 **조직**이고, 우리가 제안할 상대가 "시장 상인회"다. 그런데 파트너 풀(`ad_company_leads`)은
이미 *조직* 단위이고 `category`/`tier`/`region`/`phone`/`email`/`website` 를 갖고 있다.
⇒ **`ad_company_leads` 에 `category='상인회'` 로 넣는 것이 자연스럽다**(새 테이블 0, 기존 내보내기·필터·
중복제거·연락처 보강 레인을 그대로 물려받는다).

고시·보조금·낙찰은 **딱지**라 별도 컬럼이 아니라 `memo`/`subcategory` 또는 사이드테이블이 맞다.
⚠️ `ad_company_leads` 컬럼 추가는 신중히 — 이 레포는 `products`/`sellers` 에서 D1 100컬럼 한도를 이미
겪었다(CLAUDE.md). 상권 축 메타가 늘어날 것 같으면 처음부터 K-V 사이드테이블로 간다.

## 아직 안 한 것 (다음 세션)

1. 전통시장 프로브 판정 → 수집 레인(`collect-market`) 배선
2. 소상공인 상가정보 파라미터 확정 후 **시장 좌표 기준 반경 조회** → 점포 수/업종 구성
3. 지자체 고시 크롤 — **가장 나중**이다. 연락처가 없어 단독으로는 리드가 안 되고,
   구청마다 게시판 구조가 달라 비용이 크다. 1·2 로 리드가 쌓인 뒤 딱지로 붙이는 게 순서다.

## 프로브 1차 실행 결과 (배포 직후) — **엔드포인트는 살아 있다**

```
GET api.data.go.kr/openapi/tn_pubr_public_trdit_mrkt_api?pageNo=1&numOfRows=3&…
→ 401 · {"errMsg":"SERVICE_KEY_IS_NULL","returnAuthMsg":"서비스 접근거부","returnReasonCode":"20"}
```

⚠️ **이건 "권한 없음"이 아니다.** 요청 URL 을 보면 `serviceKey` 파라미터가 **아예 없다** —
프로브가 키를 안 실어 보냈다. 즉 상대가 우리를 거절한 게 아니라 **우리가 신분증을 안 냈다.**

📌 그래도 하나는 확정됐다: **주소는 존재한다.** 없는 주소면 인증까지 못 가고 `code 12` 가 왔을 것이다.

### 원인 — 판정이 *호스트 하나*로 하드코딩돼 있었다

```ts
const needsKey = !candidate || candidate.host === 'apis.data.go.kr'   // ← 단일 비교
```

이 조건은 원래 `www.localdata.go.kr`(**자체 키 체계 `authKey`**)에 우리 `serviceKey` 를 흘리지 않으려고
쓴 것이다. 취지는 옳다. 그런데 같은 포털이 표준데이터를 **`api.data.go.kr`('s' 없음)** 로 서빙하면서,
**같은 발급처·같은 키인데 조건에서 빠졌다.**

⇒ 기준을 *호스트 하나*에서 **키가 유효한 발급처 집합**(`PORTAL_KEY_HOSTS`)으로 바꿨다.
`PROBE_ALLOWED_HOSTS`(찌를 수 있다)와 **일부러 분리**한다 — 허용과 인증은 다른 질문이다.

> 🔑 교훈이 오늘만 두 번째다. 인허가는 *"경로 한 칸"*, 이번엔 *"호스트 한 글자"* 였다.
> 둘 다 **집합이어야 할 것을 단일 값으로 하드코딩**해서 생겼다. 새 호스트/경로를 넣을 때는
> **"이 값이 하나뿐이라고 가정한 자리가 또 있나"** 를 같이 찾아야 한다.

## 활용신청 반영됨 — 그리고 **게이트웨이 성격이 달랐다** (2026-08-03 저녁)

대표가 전국전통시장표준데이터(15012894) 활용신청 → 재프로브:

```
code 30 (등록되지 않은 서비스키)
  → 200 · {"resultCode":"10","resultMsg":"INVALID_REQUEST_PARAMETER_ERROR (pageIndex)"}
```

**인증 통과.** 우리가 이미 갖고 있던 키가 그대로 통한다 — 대표가 키를 따로 줄 필요는 없었다
(공공데이터포털은 계정당 인증키 하나이고 데이터셋별로 *권한만* 붙는다).

### 🪤 그런데 프로브의 전제가 여기선 틀렸다

프로브는 후보를 찌를 때 **두 페이징 이름을 다 실어** 보낸다. 근거는 *"모르는 쪽은 조용히 무시된다"* 였고
기관별 서비스(`apis.data.go.kr`)에선 사실이다. 그런데 **표준데이터는 거부한다.**

⇒ 인증·주소가 다 맞은 요청을 **우리 편의 문법이 죽이고 있었다.** 진단 도구가 스스로 만든 실패다.

**수리**: `ProbeParamSet`(`both`|`std`|`legacy`) — 호스트로 기본을 정하되 **명시 옵션이 이긴다**.
`std` = `pageNo`/`numOfRows`/`type` 최소셋. 어드민 프록시에 `params` 쿼리 배선.

> 🔑 **오늘 같은 클래스가 세 번째다.** ① 경로 한 칸(`/info`) ② 호스트 한 글자(`api.` vs `apis.`)
> ③ 파라미터 문법. 전부 **"이 값/규칙은 하나뿐"** 이라는 가정에서 나왔다.
> 새 소스를 붙일 때는 *경로·호스트·파라미터·필드명* 넷을 **각각 실측**해야 한다 — 하나가 맞았다고
> 나머지가 따라오지 않는다.

### 전통시장 API 실제 규약 (실측 확정분)

```
https://api.data.go.kr/openapi/tn_pubr_public_trdit_mrkt_api
  ?serviceKey=…&pageNo=1&numOfRows=…&type=json
```
`pageIndex`/`pageSize`/`resultType`/`_type` **금지**(거부당한다).

### 다음 세션의 첫 액션

배포 후:
```
POST /api/admin/partner-pool/probe-public-data
     ?target=license&path=openapi/tn_pubr_public_trdit_mrkt_api&host=api.data.go.kr&rows=3&page=1
```
- **200 + `body.items` 에 행** → 필드명을 읽어 매핑 확정 → 수집 레인(`ad_company_leads`, `category='상인회'`)
- 또 `resultCode:10` 이면 **어느 파라미터인지 메시지가 이름을 말해 준다** — 그걸 빼면 된다.
