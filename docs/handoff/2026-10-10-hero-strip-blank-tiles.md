## 1. 무엇이 보였나 — 그리고 그게 무엇이었는지 **먼저 특정**했다

스크린샷은 가로로 흐르는 띠에 카드 4장(**마망갸또 롯데 본점 · 오늘은꽃단장 · 장군보쌈족발 · 연정풀빌라**),
글자·가격·할인율은 멀쩡한데 **사진 자리가 단색 사각형**이었다.

라이브 D1 로 대조하니 그 단색이 정확히 `products.dominant_color` 였다:

| 상품 | id | dominant_color |
|---|---|---|
| 마망갸또 롯데 본점 | 2521 | `#2d2820` |
| 오늘은꽃단장 | 2491 | `#6c6b68` |
| 장군보쌈족발 | 2515 | `#ae8c74` |
| 연정풀빌라 | 2764 | `#7c948c` |

⇒ **`<img>` 는 그 자리에 있는데 그려진 픽셀이 없다**(부모 배경색이 그대로 보인다).
그리고 넷은 인기순 **4~7위** — `HeroDealStrip`(PC 히어로 우측 이용권 띠)이 태우는 바로 그 구간이다.

## 2. 서버·CDN 은 멀쩡했다 (여기서 멈추지 말 것 — 같은 길을 또 파지 않게)

전부 실측으로 **배제**한 것들:

- `/api/sections`·피드의 `image_url` 정상, 활성 50건 중 48건이 `/api/media/uploads/...`
- `media.ur-team.com` 원본 **200**, `/api/media/...` 워커 서빙 **200**
- `/cdn-cgi/image/...` **200 · `cf-resized: internal=ok`** — 폭별로 실제 크기도 맞다(ispe 파싱: 400×266 / 600×399 / 1200×799)
- Safari 류 `Accept`(AVIF 없음)로도 webp 정상, 6~72KB
- 헤드리스 크로미움으로 모바일 홈 **105개 매대 중 사진 없는 칸 1개**(그나마 lazy 미진입)
- 히어로 띠 콜드 로드: 띠가 마운트되는 순간 보이는 타일 사진은 **이미 다 와 있다**

🩸 **`naturalWidth` 로 오판할 뻔했다**: DSR3 에서 `srcset` 의 `3x` 를 고르면 `naturalWidth` 는
**밀도로 나눈 값**(600/3=200)이 나온다. "모든 사진이 200px 로 깎여 온다"로 읽힐 수 있다 — 아니다.

## 3. 진짜 원인 — 마퀴에 `loading="lazy"`

`HeroDealStrip` 은 **스스로 흐르는 띠**다. 사용자가 스크롤하지 않아도 **한 바퀴(≈34초) 안에 모든 타일이
화면에 온다.** 그런데 앞 `HERO_STRIP_EAGER`(5)장 뒤는 `loading="lazy"` 였다 —
`lazy` 는 **화면에 들어온 *뒤에야*** 받기 시작한다.

⇒ 그 타일은 받는 동안 **반드시 대표색 사각형으로 먼저 보인다.** 에러가 없고, 빠른 회선에서는
0.2~0.4초라 아무도 신고하지 않는다. 느린 회선에서는 그게 **몇 초**가 되고 띠에 4.5장이 보이므로
**동시에 전부 빈 칸**이 된다.

**브라우저 실측**(1440×900 · 캐시 끔 · 35초 = 250ms × 140프레임):

| 회선 | 빈 타일이 보이는 프레임 | 동시 최대 |
|---|---|---|
| 빠른 회선 | 9/140 (6%) | 1장 |
| 2 Mbps / 120ms | 9/140 (6%) | 1장 |
| **800 kbps / 500ms** | **118/140 (84%)** | **4장** ← 대표 화면 그대로 |

SSOT 머리말은 *"마퀴는 한 바퀴 안에 모든 타일이 화면에 온다"* 까지 **옳게 적어 놓고**,
`lazy` 가 *들어온 뒤에* 받는다는 것을 안 셌다. 문서가 틀린 게 아니라 **반쪽이었다.**

## 4. 처방 — markup 은 그대로, **받는 시점만** 옮겼다

첫 페인트 뒤 한가할 때(`requestIdleCallback`, timeout `HERO_STRIP_WARM_TIMEOUT_MS = 1500`)
미룬 타일 URL 을 `new Image()` 로 **캐시에 미리 넣는다**. 타일이 화면에 들어올 때는 캐시 적중이다.

- **첫 페인트 바이트 불변** — markup 은 한 글자도 안 바뀌었다(앞 5장 eager · 나머지 lazy 그대로).
- **총 바이트 불변** — 어차피 34초 안에 받는 3장(≈40KB)을 *언제* 받느냐만 바뀐다. 요청 수도 8회 그대로.
- **데이터 절약 모드면 안 한다**(`navigator.connection.saveData`) — `cf-image` 가 이미 존중하는 신호.

### 🩸 첫 처방은 실측에서 **뒤집혔다** — 이게 이 작업에서 제일 값진 부분이다

처음엔 `loading` 을 **lazy → eager 로 접으려** 했다(명세의 "lazy load resumption"). 재 보니
크로미움은 **보류된 lazy 로드를 다시 시작하지 않는다**:

```
화면 밖 lazy 상태에서 요청:            0
loading 프로퍼티 = 'eager'   뒤 요청:  0
setAttribute('loading','eager') 뒤:   0
removeAttribute('loading')      뒤:   0
eager + 같은 값 src 재대입      뒤:   0
```

그대로 갔으면 **markup 만 바뀌고 증상은 그대로**였을 것이다(테스트도 초록이었을 것이다 —
속성을 보는 시험이었으니까). 그래서 시험도 *속성*이 아니라 **"바이트를 미리 받았는가"** 를 본다.

`new Image()` 방식은 실측으로 확인했다(실제 `urdeal.kr` + 실제 cdn-cgi URL, 800kbps/500ms):

```
워밍 안 함 | 요청 1 | 화면 진입 → 그려지기까지  980 ms
워밍 함   | 요청 1 | 화면 진입 → 그려지기까지   59 ms
```

### 전후 (라이브 페이지에 같은 동작을 주입해 측정, 800 kbps / 500 ms)

```
현행    빈 타일 프레임 117/140 (84%)   0-5s:18  5-10s:20  10-15s:20  15-20s:20  20-25s:20  25-30s:19  30-35s:0
워밍    빈 타일 프레임  63/140 (45%)   0-5s:20  5-10s:20  10-15s:20  15-20s: 3  20-25s: 0  25-30s: 0  30-35s:0
```

⇒ **빈 칸이 보이는 구간이 30초(=한 바퀴 내내) → 17초**로 줄고, 그 뒤로는 **0**이다.
남은 앞 구간은 스케줄이 아니라 **대역폭**이다(800kbps 에서 페이지 전체가 내려오는 시간).

### ❌ 같이 재 봤지만 **안 넣은 것** — 타일이 준비될 때까지 띠를 멈추기

`animation-play-state: paused` 로 첫 5장이 그려질 때까지 띠를 세워 보았다:
`45% → 41%`, 동시 최대 `5 → 3`. **델타가 작고** 새 실패 모드(사진이 영영 안 오면 띠가 안 움직인다 —
타임아웃이 또 필요하다)가 생긴다. 값에 비해 비싸서 뺐다. 다시 하려면 이 숫자부터 보라.

## 5. 가드

`src/tests/unit/hero-deal-strip-2026-09-28.test.tsx` — ③ 블록을 **지우지 않고 재조준**했다.
종전 단언(*"나머지는 영원히 lazy"*)이 지키려던 것은 **첫 페인트 바이트**였고 그건 그대로다.
그래서 불변식을 둘로 나눴다:

1. 첫 페인트에는 앞 N장만 eager(임계 경로 byte-동일)
2. 한가해지면 **미룬 타일 URL 이 하나도 빠짐없이** 미리 받아져 있다(앞 N장이 이미 받은 것 + 워밍분)
3. 먼저 받은 앞 N장은 **다시 안 받는다** · 워밍 목록에 중복 없음
4. 데이터 절약 모드면 **안 받는다**
5. 유휴 예약은 0ms 가 아니다(상수를 베끼지 않고 소스가 그 상수를 쓰는지 본다)
6. **속성 뒤집기로 하지 않는다** — 위 크로미움 실측을 코드로 고정

주입 `scripts/mutations/hero-strip-warm.mjs` **6건, 전부 빨간불 확인**.

🩸 **시험 하네스가 두 번 헛돌았다**(둘 다 "0건인데 초록" 계열이라 적어 둔다):
- `HTMLImageElement.prototype.src` 만 감시했더니 **markup 의 `<img src>` 까지 섞였다**(React 가
  프로퍼티로 쓴다) — 워밍을 통째로 지워도 통과했다.
- 그래서 `Image` 를 **subclass** 로 바꿨더니 이번엔 **0건**. jsdom 의 `Image` 는 생성자가
  `document.createElement('img')` 를 **반환**해서 서브클래스 프로토타입이 안 붙는다.
  그리고 vitest-jsdom 은 전역을 **복사**하므로 `window.Image` 만 바꾸면 컴포넌트가 못 본다.
  ⇒ 생성자가 만든 것에 **표식**을 달고 프로토타입 setter 가 그 표식만 센다.

## 6. 안 건드린 것 (의도)

- **잠금표 파일 0건** — `cf-image.ts`·`GroupBuyFeedCard.tsx`·`worker/index.ts` 전부 무접촉.
- **매대 카드(`DealCardMedia`)의 lazy 는 그대로** — 거긴 사용자가 스크롤로 움직이는 격자라
  `lazy` 가 **맞다**. 이 처방은 "스스로 모든 것을 보여 주는 띠" 에만 해당한다.
- 모바일은 띠가 `hidden md:block` 이라 애초에 안 그린다(대표 화면은 PC).
