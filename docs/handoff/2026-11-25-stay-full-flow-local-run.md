## 돌린 흐름 (전부 통과)
- 사장님: 숙박 등록(먼저 판매 · 날짜 지정) → 예약 목록 → 사용 처리 · QR 스캔 · [체크인] → 정산 화면.
- 유저: 예약 · 결제 확정(금액 변조 거절 · 두 번 확정해도 이용권 1장) → 내 숙소 예약 · 지갑 → 취소(전액 · 50% · 사용 뒤 거절) → 만료 환불 · 노쇼 마감.
- 에이전시: 수수료 저장 → 영입 링크 → 사장님 수락(남의 매장은 거절) → 대행 좌석 → 숙박 등록 → 매출 화면(몫 5% 표시).
- 정산: 사용 4건 320,000원 = 사장님 304,000 + 유어딜 16,000(5%). 보류 14일 뒤 주간 지급 대상 1건 304,000원. 옛 정산 레일은 같은 매출을 다시 안 잡는다.

## 찾아서 고친 것 (이 PR)
결재 기록의 표 1~5. 되돌려-검증 7건 전부 빨간불 확인(날짜 칸 NULL · 결제 수단 · 일반 환불 차단 · 장부 기록 · 만료 취소 차단 · 에이전시 숙박 · 예약 표 맞추기).

## 찾았지만 안 고친 것
- **숙소 매출이 '오늘 매출' 에 안 잡힌다.** 숙소 주문은 `order_items` 행을 만들지 않는데 사장님 대시보드·에이전시 매장 목록의 오늘 숫자는 `orders JOIN order_items` 로 센다
  (`agency-store-today.ts`). 에이전시 상세 매출 화면은 이용권 기준이라 맞게 나온다. 돈은 안 틀린다 — 표시만. `order_items` 를 넣으면 재고·환불·배송 판정이 따라 움직여 따로 본다.
- **에이전시 몫은 표시만이다.** `agency_share_payout_enabled` 가 꺼져 있고(설계: 매장이 에이전시에 직접 지급), 켜더라도 숙소 결제 확정 경로는 `creditAgencyShare` 를 부르지 않는다
  (이용권 결제 두 경로에만 있다). 그 스위치를 켜기 전에 숙소 경로를 이어야 한다.
- 계좌를 안 넣은 사장님도 주간 지급 대상이 만들어진다(계좌 칸 빈 값 · 어드민 승인 때 보인다).
- 숙박권 예약 만들기가 실패했던 동안 PENDING 주문 행만 남는 문제는 그대로다(결제 없음 — 청소 cron 대상).

## 대표 정정 — 숙소는 기간이 지나면 환불이 아니라 이용 처리 (같은 날 후속 PR)
수리 보고("기한 지난 숙박권이 환불되지 않아 자동 환불로 고쳤다")를 받고 대표: *"숙소는 시간 지나면 자동환불이 아니라 사용 완료로 환불이 안되는건데"*.
- 만료 환불 조회·선점에서 **숙소 이용권 전부** 제외(`notStaySql` = `stay_booking_id IS NULL`). 예약 표 맞추기 SQL 은 도달할 수 없어 제거.
- `cron/stay-no-show.ts` 가 날짜 예약 · 먼저 산 숙박권 둘 다 닫는다(`used` · 예약 `no_show` · 정산 원장 · 앱 안 알림).
- 기한 지난 숙박권의 손님 취소는 계속 거절(문구만 "환불 없이 이용 처리").
- 손님 문구: 숙소 상세의 먼저 판매 상자·취소 정책 아래 · 지갑 주의사항(6개 언어) · 셀러 가이드(`GUIDE_SEED_VERSION` 74).
- 시험: 흐름 시험에서 숙박권 A3 가 환불이 아니라 이용 처리로 닫히고 정산에 들어가는 것을 본다(사용 3 + 기간 경과 2 = 480,000원 → 사장님 456,000 · 유어딜 24,000).
- ⚠️ 대표에게 한 번 알린 것: 날짜 없이 파는 숙박권은 '상품권' 으로 볼 여지가 있고, 그 경우 유효기간 뒤에도 일정 비율 환불을 요청할 수 있다는 표준약관이 있다 — 법률 확인이 필요한 영역이다(세션은 판단하지 않았다).

## 틀렸던 판단
- **"만료된 숙박권은 이미 자동 환불된다" 고 새벽에 대표에게 정정 보고했다 — 그것도 틀렸다.** 조회 SQL 이 그 행을 잡는 것까지만 읽고, 환불 분기가
  결제 수단을 본다는 것을 안 봤다. 코드를 읽어 내린 결론은 E1 이다. 돌려 보니 3분 만에 드러났다.
- 2026-11-24 에 먼저 판매를 기본으로 바꾸면서 "서버·손님 화면은 2026-05 부터 세 방식을 다 처리한다" 고 적었다 — 처리하는 코드가 있었을 뿐 라이브 표에서는 한 번도 들어간 적이 없었다.
- 시험 스크립트 쪽 실수: 손님 알림 표를 `notifications` 로 봤다(실제는 `user_notifications`) · 응답 모양을 `data.url` 로 짐작했다(`invite.url`). 0 이 나오면 측정기부터 의심.
