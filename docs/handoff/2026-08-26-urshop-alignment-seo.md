## 다음 세션의 첫 액션

배포 후 **라이브 curl 로만 판정되는 것**이 셋 있다(HTMLRewriter·시드는 단위테스트 밖):

```bash
# ① 새로 사이트맵에 넣은 8개 표면이 실제로 200 인가
for p in /stays /experience /new-openings /business /influencer /introduce /faq /area-report; do
  printf "%-16s %s\n" "$p" "$(curl -s -o /dev/null -w '%{http_code}' "https://urdeal.kr$p")"
done
# 전부 200 이어야 한다. 3xx/404 가 하나라도 있으면 그 줄을 sitemap 에서 빼라 —
# 죽은 URL 제출은 색인 신뢰도를 깎고, 그 손해는 되돌아오지 않는다.

# ② 블로그 시드 v12 가 라이브에 반영됐나 ('쇼핑몰' 이 사라졌는지)
curl -s "https://urdeal.kr/api/blog/public/urshop-my-own-shop" | grep -c 쇼핑몰   # 0 이어야 함
# 슬러그가 바뀌었으면: curl -s https://urdeal.kr/api/blog/public | head

# ③ 가이드 시드 v18 — 셀러 가이드에서 폐기 기능 안내가 사라졌나
#    /seller/guide 에 로그인해서 "지금의 유어딜 — 무엇이 살아 있고 무엇이 끝났나" 섹션이 보이면 OK
```

⚠️ 시드는 **버전이 올라야만** 반영된다(`BLOG_SEED_VERSION` 11→12, `GUIDE_SEED_VERSION` 17→18).
배포했는데 안 바뀌었으면 다른 브랜치가 같은 번호를 선점했는지 확인할 것(`check-seed-version-monotonic`).

## 이번에 고친 것

### A. 진입점이 말과 다른 곳으로 보내고 있었다 (실제 동작 결함)

**"내 가게 등록"이라 적힌 버튼 14곳이 사업자 가입 폼(`/seller/register/supplier`)으로 보내고 있었다.**
대표 확정 순서는 **매장 등록이 선행**이고(`StoreClaimPage` 헤더), 사업자 인증은 그 다음에 대시보드가 안내한다.
말과 목적지가 갈리면 사장님은 사업자등록번호 입력 화면에서 멈춘다 — 등록하러 왔는데 가입 심사를 만난다.

전부 `/store/new` 로 통일: 하단 네비(비로그인 포함) · 유어샵 온보딩 모달 · 빈 유어샵 CTA ·
결제완료 넛지 · 유어샵 판매 CTA · `/join` · `/partners` · `/business`(4곳) · `/my-store` ·
블로그 헤더 2곳 · `/introduce` · 큐레이터 수익 · 공구 등록 권한 안내.
방문자 레일은 `/host/new`(HOSTING_HIDDEN 으로 숨긴 카탈로그)로 가고 있어 함께 교정했다.

### B. 유어샵을 "새로 여는 것"처럼 말하고 있었다

유어샵은 **가입 시점에 자동 생성**된다(`KakaoAuthService.upsertUser`). 그런데 15곳이
"내 쇼핑몰 열기 / 5분이면 오픈 / 사업자 등록만 하면 내 유어샵이 열립니다"라고 말하고 있었다.
특히 결제완료 넛지는 **바로 윗줄에서 "이미 준비돼 있어요"라 해 놓고** 아랫줄에서 "열립니다"였다.

### C. 사람을 신분으로 부르던 문구 (대표 확정 모델과 정면 충돌)

대표: *"사람을 인플루언서/대행사로 나누지 않는다. 행위 2개(담기·운영)로 말한다."*
`seller-roles.ts` 라벨(셀러 사이드바에 실제로 렌더된다)부터 SEO 표·랜딩 4종·셀러 협업 화면·
라이브 가이드까지 행위 기준으로 교체. **키(`seller_type='influencer'`)와 라우트는 불변** —
바꾼 건 화면에 뜨는 말뿐이다.

### D. 라이브 문서가 사실과 달랐다 (명칭이 아니라 **사실** 문제)

셀러 가이드 두 섹션이 **폐기된 기능 3종을 현행처럼** 안내하고 있었다:
- 어필리에이트 1% (2026-08-22 대표 결정으로 **종료**)
- 라이브 송출 (**영구 중단**)
- 공구 호스팅 (**진입 숨김**)
- "큐레이터 → 셀러 승급" (신분 계층 모델 — 확정 모델과 충돌)

`hosting-and-upgrade` 섹션을 **"무엇이 살아 있고 무엇이 끝났나"** 표로 전면 재작성했다.
사장님이 문서를 믿고 없는 기능을 찾는 것이 이 클래스의 실제 피해다.

### E. `/influencer` 랜딩 — 없는 것을 셋이나 광고하고 있었다

① "친구 추천 양쪽 0.5% 보너스 딜" — `invite_reward_enabled` 기본 OFF(행 부재 = 꺼짐)
② "누구나 share 하면 커미션" — 어필리에이트 종료
③ **"실제 인플루언서 수익 사례 — 월 1,500만원+ / 베타 참여 평균"** — 출처가 코드 어디에도 없는
   하드코딩 숫자였다. 공개 페이지에서 수익을 숫자로 약속하는 것은 표시광고 문제가 되고,
   사실이 아니면 처음 온 사람과의 관계가 거기서 끝난다.

⇒ **지금 실제로 도는 것 하나만** 말하도록 전면 재작성: 매장과 맺은 딜이 있어야 커미션이 붙고
비율은 매장이 정한다. 그 문장은 `ShareRewardBanner` ↔ 결제 적립이 쓰는 `findActiveDealPct` 와
같은 사실이라 화면과 정산이 갈릴 수 없다. 덤으로 `min-h-screen`(모바일 하단 잘림) →
`100dvh`, `bg-pink-500` → `bg-brand` 로 룰 정합.

## SEO — "우리 서비스에 맞게"

### 가장 큰 구멍: **메타는 있는데 사이트맵에 없던 표면 8개**

`/stays` `/experience` `/new-openings` `/business` `/influencer` `/introduce` `/faq` `/area-report`.
전부 라우트가 있고, 인증 게이트가 없고, robots 도 안 막고, `CONSUMER_SURFACE_SEO` 에 문구까지
갖췄는데 **사이트맵이 제출하지 않아 검색엔진이 존재를 몰랐다**. 내부 링크(푸터/네비)만으로는
네이버 Yeti 가 사실상 도달하지 못한다. 약관 3종도 넣었다 — 유입은 적지만 신뢰 신호다.

추가 전 확인한 3가지(다음에 늘릴 때도 이것부터): ① App.tsx 에 라우트 실재 ② ProtectedRoute 아님
③ robots prefix 에 안 걸림(`/influencer` 는 `/influencer/` 만 차단이라 통과).

### 문구를 검색 의도에 맞게 다시 씀

- 홈 `돈버는 쇼핑` → `우리 동네 맛집·카페·뷰티 이용권 할인` — "돈버는 쇼핑"은 우리만 아는 말이라 검색이 안 된다
- `교환권` → `기프티콘 교환권 - 카페·편의점·치킨 할인` — 실제로 검색되는 단어는 "기프티콘"이다
- `내 주변 동네딜 지도` → `+ 걸어갈 수 있는 할인`, `숙소` → `+ 펜션·호텔·풀빌라`
- `restaurantMap.seoDesc` 와 `mainHome.seoDesc` 가 **영구중단된 라이브 방송을 아직 광고**하고 있었다 → 교체
- 신분어(인플루언서/크리에이터) 제거 — 검색결과에 그대로 노출되는 자리다
- `/store/new` robots 차단 추가(ProtectedRoute 인데 열려 있었다)

⚠️ **약관 정본 제목은 안 바꿨다.** `/terms/seller` 의 "판매자 이용약관"은 명칭 SSOT 금지어지만
시행 중인 계약 문서 제목(`terms/seller-terms-content.ts` v1.0, 대표 확정)이라, SEO 편의로 바꾸면
정본과 검색결과가 갈린다. 그 이유를 코드 주석에 남겼다 — 정본을 개정할 때 함께 바꿀 것.
