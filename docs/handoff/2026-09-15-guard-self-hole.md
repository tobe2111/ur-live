# 🚨 검사기 자신이 "실패할 수 없는" 구멍을 갖고 있었다 (2026-09-15, 4차)

## 다음 세션의 첫 액션

```bash
# 이 구멍이 다시 생기지 않았는지 — 러너를 실제로 돌려 종료 코드를 본다
node scripts/check-guard-mutations.mjs --map-only --only "존재하지않는이름zzz" >/dev/null 2>&1; echo $?
```
**판정**: `1` 이면 통과. `0` 이면 구멍이 돌아온 것이다.

## 무엇이 잘못이었나

`check-guard-mutations.mjs` 는 **"가드가 실제로 실패할 수 있는가"** 를 확인하려고 있는 도구다.
그런데 `--only` 가 아무것도 못 고르면 실패라는 그 판정이 **`--map-only` 조기 종료 뒤에** 있었다.

```
if (MAP_ONLY) { …"✅ 주입 지도 0건 성함"… ; process.exit(0) }   ← 여기서 끝나고
if (ONLY && onlyMatched === 0) { … exit(1) }                     ← 여기까진 안 온다
```

⇒ `--map-only --only <오타>` 가 **초록불 + exit 0**. 하필 `--map-only` 가 **커밋 전에 돌리는
모드**라, 가짜 초록불이 가장 필요한 순간에 떴다.

**이 세션에서 실제로 당했다**: 새 매니페스트를 확인하려고 `--only "cache-error-rethrow"`
(파일명)로 불렀는데, 필터는 **주입 이름** 부분일치라 0건이었다. 그런데 `✅ 주입 지도 0건 성함`
이 떠서, 그대로 "확인됐다" 고 넘어갈 수 있었다.

## 고친 것

0건 판정을 `MAP_ONLY` **위로** 옮겼다. 조건에 `mapOk === 0` 를 함께 넣어 정상 사용은 안 막는다.

실측한 종료 코드 네 가지:

| 호출 | 기대 | 결과 |
|---|---|---|
| `--map-only --only <안 걸림>` | 1 | ✅ (예전엔 **0**) |
| `--map-only --only <걸림>` | 0 | ✅ |
| `--map-only` (필터 없음) | 0 | ✅ ← 여기서 막으면 pre-commit 이 통째로 멎는다 |
| `--only <안 걸림>` (되돌려-검증 모드) | 1 | ✅ (원래 방어, 안 깨짐) |

가드 `guard-mutations-zero-match-2026-09-15.test.ts` 는 러너를 **`spawnSync` 로 실제 실행**해
종료 코드를 잰다(소스 문자열이 아니다 — 그랬으면 이 시험도 같은 병에 걸린다).
주입 2건은 **러너 자신을 대상으로** 한다. 동작한다 — 시험이 러너를 새 프로세스로 부르므로
그때 디스크의 주입본을 읽는다.

## 이번에 틀렸던 판단

1. 🩸 **내 검증 자체가 틀린 것을 재고 있었다.** 종료 코드를 `node … | tail -4; echo $?` 로 봤는데
   그건 **`tail` 의 종료 코드**라 늘 0 이었다. 파이프를 빼고 다시 재서야 1/0 이 보였다.
   ⇒ **종료 코드를 잴 때 파이프를 물리지 말 것**(또는 `${PIPESTATUS[0]}`).
