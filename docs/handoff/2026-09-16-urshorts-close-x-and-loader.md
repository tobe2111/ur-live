## 3. 로딩 — 라이트 테마 색 점프 (실측)

`/videos` 는 **도착 화면이 다크 고정**(`bg-[#0A0C12]`)인데 거기로 가는 로더 둘의 색이 갈려 있었다:
청크 로더(`BootFirstScreenLoader`)는 **테마 추종**, VideosPage 자체 로더는 `forceDark`.

브라우저 실측(로컬, 라이트 테마, 홈 → 전체보기 SPA 이동):

```
수정 전   18ms 흰색 → 80ms 검정 → 472ms 본문     ← 흰 깜빡임 62ms
수정 후   20ms 검정 →            476ms 본문     ← 깜빡임 0
```

처방은 새로 만든 게 아니라 **이미 있는 규칙의 반대 방향**이다 — 대시보드는 도착이 라이트 고정이라
`DashboardLoader` 가 `forceLight` 를 쓴다. 즉 **"로더는 도착 화면의 색을 미리 입는다."**

`App.tsx` 는 1112줄 동결이라 **줄 수 불변**으로 넣었다(술어 2줄→1줄·`DashboardLoader` 5줄→3줄로 상쇄).

### ⚠️ 남은 것 — 하드로드는 여전히 튄다

주소창에 `/videos` 를 직접 치거나 새로고침하면 **워커 정적 로더**(`urdealLoaderHtml`)가 먼저 뜨는데
그것도 테마 추종이라 라이트에서 흰색이다(실측: 139ms 흰색 → 919ms 검정).
그 파일(`worker/index.ts` `#root` 로더)은 **잠금표 대상**이라 대표 승인이 필요하다.
홈 레일 「전체 보기」로 들어오는 경로엔 그 로더가 **없어서** 이번 수정만으로 끊김이 사라진다.

### 오진했다가 뒤집은 것 🩸

처음에 `/api/urshorts` 응답이 1.0~1.5s 라 "API 가 느리다" 로 갈 뻔했다. 5회 표본을 내니 **중앙값 0.41s**
(같은 순간 `/api/group-buy/products` 는 0.76s) — **단발 측정이 이 컨테이너 프록시 잡음**이었다.
⇒ 이 환경에서 절대 ms 로 단정하지 말 것. 같은 창에서 기준선과 비교하거나 표본을 늘려야 한다.
