## 한 것
1. **index.css 죽은 클래스 36종·keyframes 8개 제거** (라이브커머스·도매·옛 카드 잔재). CSS 28.77 → 27.76KB br.
   가드 `css-dead-classes-2026-10-14.test.ts` — index.css 가 정의한 클래스는 소스 어딘가에 실재해야 한다.
2. **Tailwind content 에서 `src/tests/**` 제외** — 시험 픽스처의 클래스 문자열로 유틸을 만들고 있었다(−3.4KB raw · −0.36KB br).
   워커(`src/worker`)는 **빼지 않는다**(서버 첫 화면 HTML 이 클래스를 쓴다) — 가드가 양방향.
   ⇒ 1+2 합쳐 전 화면 첫 화면 −0.7~1.7KB br (surface-budgets 잠금).
3. **유어쇼츠 레일 — 부팅 중 강제 동기 레이아웃 제거**: 화살표 측정(`scrollWidth`)을 마운트 effect → `onPointerEnter`.
   CPU×4 홈 프로파일에서 앱 함수 1위(76ms)였다. 폰은 한 번도 안 잰다.
4. **유어쇼츠 레일 — 목록 도착 전 자리 예약** (라이브 vitals: 홈 CLS p75 0.199). 목록이 오면 ~296px 레일이 인기 이용권
   아래 끼어들어 피드를 밀었다. 같은 패널 + 카드 크기 자리표시자 4장을 먼저 세운다. 영상 0 이었던 기억(localStorage
   `ur_urshorts_n`)이 있으면 예약 안 함(대표 확정 "없으면 섹션 자체 안 보임"), 요청 실패 시 예약 거둠.
   하네스 `--cls` 홈: 모바일 0.576 → 0.103 · PC 0.518 → 0.034 (남은 0.103 은 하네스에 `/api/sections` 스텁이 없어
   섹션 스켈레톤이 접히는 것 — 라이브는 시드가 있다). 부수 수리: 종전엔 빈 div→section 으로 노드가 바뀌어
   썸네일 관측(300px IO)이 떨어져 나간 div 를 보고 있었다(같은 노드라 이제 안 끊긴다).
5. 하네스 `--cpu-profile=path` — CDP 프로파일 저장(원인 찾기용).

- **원인(하네스 `--cls --slow=1500` + 섹션 스텁 실측)**: 섹션 응답 전 자리가 [제목 + 사진 + 13px 막대 둘]이고
  **유어쇼츠 레일을 빠뜨렸다**. 응답 순간 레일(~240px) + 카드당 ~90px(두 줄) = 피드 **415px 밀림, CLS 0.16**.

  (진짜 카드와 같은 줄 구조·클래스, 글자 투명)로. 결과 모바일 **0.16 → 0.008**, PC 0.005.
