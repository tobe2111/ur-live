# 2026-11-24 토스 API 키 접근 정책(IP·국가 제한) 대응

서비스: **유어딜(소비자 결제)** · 머니 경로 접촉: 승인·취소 로직 없음(에러 안내 1건 추가 + 진단 알림)

## 배경
토스 공지 — 2026-11-09 부터 시크릿 키 호출은 등록된 IP·국가에서만. 밖이면 403 `API_KEY_ACCESS_DENIED`.
대표가 토스 화면 확인: 우리 키 4개(MID `cp_urteamw10d`·`urlivepn92`·`urteamgoh1`·`urteamizy1`) 전부
**"국내(대한민국) IP 주소 전체 허용"**. 테스트 환경 정책도 국가=대한민국.

## 완료분
- 자가진단 프로브가 `API_KEY_ACCESS_DENIED` 를 `blocked` 로 판정 → 디스코드 🔴 (요청 IP 포함)
- 에러 안내표에 코드 추가(`[UNLOCK]` 기록 `docs/locks/toss/2026-11-24-api-key-access-denied.md`)
- 시험 11건 · 주입 2건 빨간불 확인

## 이어받는 세션의 첫 액션 (대표가 이 작업을 이어서 하라고 했을 때만)
D1 메인에서 `SELECT value FROM platform_settings WHERE key='cron_hb:daily-self-diagnostic'` →
`r` 의 `toss=valid` 면 그 회차 통과, `toss=blocked` 면 토스 개발자센터에서 허용 범위를 넓혀야 한다.

## 이번에 틀렸던 판단
- 처음엔 *"토스가 최근 쓴 IP 몇 개만 등록했을 것"* 이라 가정하고 "국가로 바꾸라" 고 권했다. 대표가 화면을 보여주니
  **이미 국가(대한민국) 단위**였다. 공지 문구만으로 등록 형태를 추정하지 말 것.

## 남은 결정/대기
- **Cloudflare 출구 IP 가 항상 한국으로 분류되는가는 미확인.** 새벽 프로브 1회 통과가 유일한 증거다.
  확정하려면 실결제 1건 + 취소 1건(대표). 막히면 디스코드 알림에 찍힌 IP 로 원인을 본다.

## 2차 — 외국인 손님(해외에서 미리 구매) 경로 실측 도구 (같은 날)
대표: *"외국인 대상으로 할 때 저 토스 IP 문제는 없는거야? … 해외에서 우리 서비스를 미리 사용하는데에 문제도 없어야 해. 결제같은 부분들"*

- 위험: 워커는 **손님과 가까운 Cloudflare 거점**에서 돌고 토스 호출도 거기서 나간다. 토스 정책은 "대한민국만".
  해외 손님의 결제 승인이 해외 거점 출구 IP 로 나가면 `API_KEY_ACCESS_DENIED` 가 될 수 있다. 새벽 cron 프로브는 이 경로를 못 본다.
- 도구: `GET /api/admin/toss-access-probe` — 호출자가 닿은 거점에서 없는 결제키 조회 1회 → `{verdict, toss_code, colo, caller_country}`.
  `getTossPayment`(SSOT) 호출만 한다. 부수효과 0.
- 판정법: 이 세션 컨테이너는 미국 거점(`colo=IAD`)에 닿는다 → 배포 뒤 세션이 부르면 **해외 경로** 실측, 대표가 한국에서 부르면 국내 경로.
- `blocked` 가 나오면 처방 후보(대표 결정): 토스 정책의 허용 국가를 넓히거나(최대 50개국), 승인 호출만 한국 거점에서 나가게 하는 구조 변경.
