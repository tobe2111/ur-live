# 다크 대비 가드 범위 확장 — 가입 폼이 안 읽히고 있었다 (2026-09-07)

`/store/new` 흰 글자 수리(#1344) 뒤 남겨 둔 사각지대를 닫다가 **실사고를 하나 잡았다.**

## 먼저, 그날 내가 적은 것이 틀렸다

#1344 인계에 *"로그인 필요 페이지는 `check-dark-contrast` 목록에 넣어도 리다이렉트된다"* 고 썼다.
**틀렸다** — `auth: 'user'` 가 localStorage 를 시드해 그리고, 이미 8개 경로가 그렇게 돌고 있었다.
`/store/new` 가 빠진 것은 **못 넣어서가 아니라 안 넣어서**다. 구조적 한계로 오해하면 다음 세션도
같은 자리를 비워 둔다.

## 커버 실측 — 소비자 정적 라우트 95개 중 20개

전부 넣으면 느려지고 흔들린다(그러면 결국 가드를 꺼 버린다). 두 부류만 골라 **11개 추가**:
- **입력 화면** — 이 클래스의 진앙. 전역 `.dark input`(특이도 0,5,1)이 요소의 `text-gray-900`(0,1,0)을
  **언제나** 이기므로, 늘 흰 표면 위 입력은 클래스 유틸로 못 이긴다.
  `/store/new`(모바일·PC) · `/account/settings` · `/mypage/addresses` · `/community-group-buy/new` ·
  `/register` · `/u/me/add` · `/join`
- **머니 화면** — 글자가 안 보이면 사람이 돈을 잘못 낸다: `/checkout` · `/points/charge` ·
  `/payment/success` · `/my-coupons`

## 잡힌 것 ① 가입 폼이 다크에서 통째로 안 읽혔다 (실사고)

`RegisterPage` 는 **다크 이행이 반만** 돼 있었다. 바깥 배경만 `dark:bg-[#11141C]` 로 뒤집히고
안쪽 폼은 라이트 전용으로 남아 있었다.

| | 실측 |
|---|---|
| 약관 링크 "서비스 이용약관" | `#111` on `#11141C` → **1.03:1** |
| 입력 상자 | 흰 글자 / 흰 배경 → **1.00:1** |
| 라벨 "이메일" "비밀번호" | **2.47:1** |
| 워드마크 (`forceLight`) | **1.04:1** |

원인은 **원시 hex**(`text-[#555]` 15곳 · `text-[#111]` 7곳 등)다. 원시 hex 는 `dark:` 짝을 가질 수
없고, `check-theme-consistency` 는 **이름 있는 토큰만** 보므로 통째로 새어 나간다. 형제인
`LoginPage` 는 이미 제대로 이행돼 있어 0건이었다 — 그래서 둘을 나란히 놓으면 원인이 바로 보였다.

**진입로가 실재한다**: 로그인 화면 하단 "회원가입" 링크 + 계정 메뉴.

수정: 로그인 화면의 매핑을 그대로 따라 토큰 이행 + 입력 상자에 `bg-white dark:bg-[#1D1F29]`
(배경이 없으면 브라우저 기본 흰색이라 `dark:text-white` 가 흰 위 흰이 된다) + 로고 `forceLight` 제거.

## 잡힌 것 ② 그 결함을 **가드가 명시적으로 숨기고 있었다**

`check-light-input-guard.mjs` 의 `CONSUMER_EXCLUDE` 에 `RegisterPage.tsx` 가 있었다 —
*"소비자(다크 토글) 진입 페이지 — 라이트 고정 아님(의도적 다크), scope 밖."*

**그 다크 대응이 실제로는 안 돼 있었다.** 목록이 가정을 사실로 굳혀 놓은 자리다.

⇒ 면제는 면제가 아니라 **약속**으로 규정하고, 그 약속을 테스트로 묶었다:
`theme-guard-pairing-2026-09-07.test.ts` — **면제한 페이지는 반드시 `check-dark-contrast` 의
경로 목록에 있어야 한다**(그래야 브라우저가 실제로 확인한다). 주입 3종 되돌려-검증 빨간불.

## 잡힌 것 ③ 가드 자신의 오탐 2종

`/store/new` 에서 나온 4건은 진짜가 아니었다.
- **포커스 경로에만 텍스트 검사가 없었다** — 호버 경로(419행)는 직접 텍스트 노드를 요구하는데
  포커스 경로(432행)만 빠져서, 글자가 자식에 있는 `<button>`(자기 텍스트 0)까지 쟀다.
- **체크박스의 `value === 'on'`** 을 읽는 글자로 셌다. 그 'on' 은 화면에 안 그려진다.

읽을 것이 없는 요소를 신고하면 진짜 결함이 소음에 묻히고, 그러면 결국 가드를 꺼 버린다. 둘 다 수정.

## 이번에 내가 밟은 것 (다음 세션이 안 밟게)

1. **일괄치환이 variant 접두사를 먹었다.** `text-[#555]` 치환이 `hover:text-[#555]` 도 먹어
   다크 짝이 `hover:` 를 잃었다(`hover:text-gray-600 dark:text-gray-400` — 다크에서 **평소 색**이 바뀐다).
   `placeholder:` 도 같은 방식으로 깨졌다. CLAUDE.md 가 경고한 그 함정이다.
   ⇒ 되돌리고 **접두사를 캡처해 양쪽에 붙이는** 방식으로 재작업, 유실 0 을 정규식으로 확인.
2. **되돌려-검증 주입이 헛돌았다.** `/store/new` 를 목록에서 뺐다고 생각했는데 **모바일·PC 두 줄 중
   한 줄만** 지워서 여전히 목록에 있었다 → 가짜 통과. **주입이 실제로 적용됐는지 먼저 확인할 것.**
3. **체크박스의 `text-[#111]` 은 건드리지 않았다** — 그건 체크 색(장식)이지 읽는 글자가 아니다.
   치환에서 `accent-[#111]` 이 있는 줄을 건너뛰어 구분했다.
