# 2026-09-16 — 다크 대비 가드가 **죽은 화면을 재고 살아 있는 결제 화면을 안 보고 있었다**

대표 지시: *"알아서 최대한 잘 해줘. 가장 이상적으로"* 의 연장.

## 한 줄

`scripts/check-dark-contrast.mjs` 는 몇 달간 **0건**을 보고해 왔는데, 그 0건은 "안 보이는 글자가
없다"가 아니라 **"머니 화면을 안 봤다"** 였다. 실측으로 결함 2종을 찾아 고쳤다.

## 무엇이 잘못돼 있었나 (전부 실측)

| # | 무엇 | 증거 |
|---|---|---|
| ① | 목록이 **꺼진 화면**을 잰다 | `/points/charge` = `TOPUP_DISABLED`(2026-07-18 종료) · `/community-group-buy/new` = `COMMUNITY_PROPOSAL_HIDDEN` |
| ② | **살아 있는 카드결제 화면이 목록에 없다** | 파일 전체에서 `pay/widget` 매치 **0건**. 이용권을 카드로 사는 유일한 화면이고, 하필 `light-island`(가드가 가장 조심하라고 적은 구조)를 갖고 있다 |
| ③ | 머니 화면들이 **자기 빈 상태만** 재고 있었다 | `/cart` 4개 · `/checkout` 3개 · `/payment/success` 4개. 그려지던 것은 *"장바구니가 비어있습니다"* · *"결제 승인 실패"* |
| ④ | 합계 하한(200)은 **한 경로가 통째로 안 그려져도** 못 잡는다 | 다른 41개가 합계를 채운다 |
| ⑤ | 워크플로 `paths:` 에 **머니 화면이 없다** | `CheckoutPage` 를 고치는 PR 은 이 검사를 안 돌린다 |

③이 제일 아프다 — 가드 자신의 주석이 그 화면들 위에 **"여기서 글자가 안 보이면 사람이 돈을
잘못 낸다"** 고 적어 두고 있었다.

## 그래서 실제로 무엇을 찾았나

경로별 검사(④ 수리)를 넣자마자 ③이 드러났고, ③을 고치자 **실제 결함**이 나왔다:

```
결제 (/checkout)
  <input> "쿠폰 코드 입력"      대비 1:1  글자 rgb(255,255,255) / 배경 rgb(255,255,255)
  <input> "사용할 딜 포인트 입력"  대비 1:1  (같음)
```

원인은 오타가 아니라 **반쪽짜리 전역 규칙**이다. `src/index.css` 의 `.dark input` 은
**글자색만** gray-100 으로 바꾸고 **배경은 안 건드린다.** 이 앱은 `color-scheme: dark` 를
어디에도 선언하지 않으므로, 배경 클래스가 없는 입력은 브라우저 기본값 **흰색**이다
⇒ 흰 배경 위 흰 글자.

**한 곳이 아니다.** 정적 스캔으로 소비자 화면 **20곳**이 같은 모양이고, 그중
`/mypage/addresses` 를 열어 재 보니 **이름·연락처·상세주소·요청사항 5개**가 실제로 1:1 이었다
(가드가 못 본 이유: 그 폼은 버튼을 눌러야 열린다).

## 고친 것

1. **전역 기본값** (`src/index.css`) — `.dark input/textarea/select` 에
   `background-color: transparent`(늘 밝은 표면 `light-island`·`*-light-theme` **안쪽은 제외**).
   배경을 **명시한** 입력(`bg-gray-50 dark:bg-[#1D1F29]` 등)은 한 픽셀도 안 바뀐다.

   ⚠️ **여기서 두 번 고쳤다.**
   ① 처음엔 "`@layer base` 라서 utilities 레이어가 이긴다"고 적었는데 **틀렸다** —
      Tailwind v3 는 `@layer` 를 빌드에서 걷어낸다(산출 CSS 에 `@layer` **0개**, 실측).
      승자를 정하는 건 특이도다.
   ② 그래서 평범하게 쓴 `.dark input:not(…)` 은 **(0,6,1)** 이었고, 그건 `bg-surface`(0,1,0)
      **같은 디자인 토큰까지 이겨 버린다** — 토큰을 써도 조용히 무시되는 함정이다.
      실제로 pre-push 게이트가 내 `dark:bg-[#1D1F29]` 를 "손으로 박은 색"으로 잡아 주지 않았다면
      그대로 갔다. ⇒ 규칙 전체를 `:where()` 로 감싸 **(0,0,0)** 으로 만들었다. 이제
      배경을 어떤 형태로든 선언한 입력이 **언제나** 이긴다.
      뒤쪽 제외 구문까지 감싼 것도 일부러다(안 감싸면 (0,1,0) 동점 → 승자가 소스 순서에 달린다).
   ⇒ 대신 `bg-white` 만 있고 `dark:` 변형이 없는 입력은 이 기본값이 **못 고친다.**
      그건 `check-theme-consistency` 가 잡는 별개 결함이다(현재 GREEN).
2. **호출부 2곳**(`checkout/CouponSection` · `checkout/DealPointsSection`) — 배경 명시 +
   `dark:text-gray-500` → `dark:placeholder:text-gray-500` 오타(placeholder 규칙이 아니라
   **글자색 규칙**이 되어 `dark:text-white` 와 다투고 있었다).
3. **가드**: `/pay/widget`·`/payment/fail`·`/group-buy/confirm-payment` 추가 ·
   경로별 "안 그려짐 = 실패" · `/api/cart`·`/api/payments/confirm` 표시용 스텁 ·
   비활성 컨트롤 면제(WCAG 1.4.3).
4. **워크플로 `paths:`** 에 머니 화면 6종 추가.
5. **가드의 가드**: `src/tests/unit/dark-contrast-coverage-2026-09-16.test.ts` (7건) —
   브라우저 가드는 주기 실행이라 목록이 낡아도 아무도 모른다. `light-island` 사용처가
   전부 목록에 있는지, 스텁이 **선언만 있고 배선이 없지는** 않은지 PR 에서 본다.
   주입 7건 등록(`scripts/mutations/dark-contrast-coverage.mjs`) — 전부 빨간불 확인.

## 이번에 내가 틀린 것

- **전역 수리 첫 판이 `/map` 을 깨뜨렸다.** `light-island` 안쪽까지 배경을 투명하게 만들어,
  잉크색으로 강제된 글자가 **어두운 페이지 배경 위**에 놓였다(`rgb(22,24,28)` / `rgb(29,31,41)`).
  2026-09-03 대표 신고와 **정반대 방향의 같은 사고**다. 렌더로 재 보고서야 알았다 —
  ⇒ 전역 CSS 는 반드시 **양쪽 방향**(고쳐졌나 / 멀쩡하던 게 깨졌나)을 재고 나서 커밋할 것.
- **`@layer` 로 이긴다고 적었는데 틀렸다**(위 참조). 산출 CSS 를 열어 보고서야 알았다.
- **`pkill -f probe-tmp` 로 내가 방금 띄운 프로세스를 죽였다**(자기 패턴 매칭). PID 로 죽일 것.
- **디자인 토큰이 있는데 hex 를 손으로 박았다.** `--surface` 가 정확히 `#FFFFFF`/`#1D1F29` 쌍인데
  `bg-white dark:bg-[#1D1F29]` 로 썼다. **pre-push 게이트가 18초 만에 잡았다** — 그게 없었으면
  CI 57분을 태웠을 것이고, 더 나쁘게는 위 ②(토큰이 무시되는 함정)를 영영 못 봤을 것이다.
- **`audit-gate` 타임아웃(143)이 자식 `check-guard-mutations -s` 를 안 죽였다** — CLAUDE.md 가
  경고한 그대로다. `git status` 에 남의 주입분(`company-subcat-yield.ts`)이 떠 있었고,
  그대로 `git add -A` 했으면 주입된 결함을 커밋할 뻔했다. **PID 로 죽이고 트리를 확인한 뒤** 커밋했다.

- **처음 넣은 테스트 ⑤가 헛돌았다.** `filter(` 존재만 봐서, 임계를 `r.n < 0` 으로 바꿔
  검사를 통째로 죽여도 초록이었다. 되돌려-검증이 잡았다 ⇒ **모양이 아니라 값**을 보도록 교체.
- **꺼진 두 화면을 지우려다 말았다.** 지우는 게 깔끔해 보이지만, 종료가 뒤집히면 커버리지가
  조용히 사라진다. 남겨 두고 주석으로 이유를 적었다.
- 처음엔 정적 스캔이 **76건**을 냈다. `bg-surface`·`bg-warm` 같은 **테마 토큰**을 "배경 없음"
  으로 오판한 것이다(그건 정상이다). 실제 결함은 20건.

## 이 수리가 못 하는 것

- **20곳 중 7곳만 렌더로 확인했다.** 나머지 13곳은 같은 모양이라 전역 기본값이 덮을 것으로
  보지만, 그 화면들이 가드 목록에 없어 **측정되지 않았다.**
- 비활성 컨트롤 면제는 *비활성처럼 보이지만 실제로는 활성*인 컨트롤(속성 없이 색만 회색)을
  여전히 잡는다. 반대로, 진짜 비활성이 읽히지 않는 것은 이제 안 잡는다(WCAG 면제).
- `TossPaymentWidget` 의 비활성 CTA(`bg-gray-300 text-white`, 1.5:1)는 **잠금 파일**이라
  건드리지 않았다. WCAG 1.4.3 면제 대상이기도 하다.
