# 2026-10-18 마이 점검 — 개인 캐시 주인 · 이용권 현황 높이 고정

대표 *"이젠 마이페이지 모두 가장 이상적이야??"* → 다섯 경우(구매자·사장님 × 폰·PC, 다크)로 그려서 재 봤다.

## 다음 세션의 첫 액션
1. PR 머지·배포 뒤: 같은 폰에서 계정 A 로그인 → 마이 → 로그아웃 → 계정 B 로그인 → 마이 첫 화면에 A 의 이용권·배송지가 **한 프레임도** 안 뜨는지(localStorage `urq:__owner` 가 B 의 id 인지).
2. 밀림 가드: `node scripts/check-layout-shift.mjs --only=마이` (빌드 후) — 셀러·구매자 둘 다 🟢.

## 고친 것
| 무엇 | 왜 |
|---|---|
| `localCache` 에 주인(`urq:__owner`) — 사람이 바뀌면 개인 항목을 읽기 전에 지움, 공개(`seller:`·`product:`·`gb:`)는 남김 | 캐시 키에 사람이 없고 `clearAllUserCache` 는 호출 0 이었다. 같은 폰에서 B 의 첫 화면이 A 의 배송지·이용권·잔액으로 먼저 그려졌고, 서버가 실패하면 `cacheOrRethrow` 가 그 값을 계속 돌려줬다 |
| 소비자 로그아웃(`clearAuthData('user')`)이 `clearAllUserCache()` 호출 — 모든 로그아웃 경로가 지난다 | 로그아웃한 폰에 개인 데이터를 남길 이유가 없다 |
| '이용권 현황' 이 세 상태(모름·0장·있음) 모두 같은 숫자 줄로 높이를 잡음, 0장이면 같은 자리에 "아직 산 이용권이 없어요 · 이용권 둘러보기" | 첫 방문에 바가 응답 뒤에 생겨 '내가 산 것' 이 100px 밀렸다(보이는 줄 13~28개) |
| 밀림 가드 마이 경로에 `--wallet --auth=user` + 마이(구매자) 경로 추가 | 시드가 없어 이 바가 아예 안 떠서 가드가 못 봤다 |

## 이번에 틀렸던 판단
- 처음엔 밀림을 "캐시가 있으면 재방문엔 없다" 로 가볍게 볼 뻔했다. 캐시를 추적하다가 그 캐시에 **주인이 없다**는 더 큰 결함이 나왔다 — 고친 뒤엔 계정을 바꿀 때마다 첫 방문이 되므로 밀림 수리가 더 중요해졌다.

## 남은 결정 (대표)
- 마이 폰 화면에서 이용권 장수가 **세 번** 나온다: 위 숫자 줄 `이용권 3` · `이용권 현황` · `내 이용권 3` 행. 쿠폰도 위 `쿠폰 0` 과 `쿠폰함 0` 두 번. 하나로 줄일지는 화면 구성 결정이라 올리지 않고 묻는다.
- PC 머리줄은 숫자 4칸(교환권 포함), 폰은 3칸 — 의도인지 확인 필요.
- 설정의 `현재 OS: 라이트` · 하단 `유어딜 v1.0.676 (…)` · `최신 버전인지 확인` 은 개발자용 표시로 보인다 — 손님 화면에 둘지.
