# 카드 사진 넘길 때 "이전 사진이 그대로" — 신호가 없던 것 (2026-09-06)

대표: *"메인페이지에서 이용권 이미지 넘길 때 로딩이 생길 때 문제인 것 같은데, 로딩이 걸린다면
이전 사진과 똑같이 나오는 것 같아."*

## 맞다. 그리고 그건 내가 09-02 에 넣은 처방의 절반이 빠진 상태였다

09-02 에 *"넘기면 회색 빈 칸"* 을 고치면서 **직전 사진을 그대로 두는** 방식으로 바꿨다. 방향은 맞다.
문제는 **"받는 중"이라는 신호가 없었다**는 것이다:

- 직전 사진을 `opacity: 0.65` 로 어둡게만 했다 → **밝은 사진에선 거의 안 보인다**
- 게다가 **도트는 이미 다음 칸으로 가 있다** → "점은 넘어갔는데 사진은 그대로" = *안 넘어갔다*로 읽힌다

### 📏 실측 (라이브 · 홈 다장 카드)
```
PC 빠른 회선   130ms → 128 → 126 → 132        (사람 눈에 안 띔)
모바일 4G      2,180ms → 383 → 126 → 106      ← 첫 넘김이 2초 넘게 걸린다
라이브 상태 샘플링   60프레임 중 59가 "어둡기만", 흐림 0, 그것도 opacity 0.917
```
2초 동안 "같은 사진"이 서 있었다. 대표 신고와 정확히 일치한다.

⚠️ **첫 넘김만 느린 이유**: idle 프리페치는 *다음 한 장*만 받는데, 모바일 4G 에선 그 프리페치 자체가
~2초 걸려 사용자의 첫 클릭을 못 따라간다. 두 번째부터는 `step` 이 next+after 를 미리 받아 빨라진다.

## 처방 — 블러-업 (새 자산·새 요청 0)
받는 중이면 직전 사진을 **흐리게**(`blur(10px)` + `scale(1.06)` + `opacity .8`) 남긴다.
흐려지는 순간(0ms) *"이건 아직 그 사진이 아니다"* 가 읽히고, 도착하면 선명해진다.
업계 표준 idiom 이고, 요청 수·트래픽은 **그대로**다(이 파일의 1원칙인 트래픽 보호 무접촉).

- `scale(1.06)` 이 필요한 이유: 블러만 걸면 가장자리에 투명 테두리가 생긴다.
- 도트는 그대로 `shown` 을 따른다 — 이제 흐림과 짝이 맞아 "다음 장 받는 중"으로 읽힌다.

### 실측 확인 (강제 대기 상태 고정 — 사진 요청을 8초 붙잡아 재현)
```
before(라이브)  [{o:1,    f:none}]        ← 선명한 채로 그대로
after (새 빌드)  [{o:0.8, f:blur(10px)}]  ← 흐림
```
스크린샷 한 장에 대비가 잡혔다: 왼쪽 카드(받는 중)는 흐리고 오른쪽(로드 완료)은 선명하다.

## 가드
`deal-card-swipe-continuity.test.ts` — 기존 3건 유지 + **블러 신호 2건 추가**(`waiting` 판정 존재,
`filter` 배선). 주입 매니페스트: **신규 1건**(블러 소실) + **낡은 지도 1건 재조준**
(`opacity: … 0.65` 문자열이 바뀌었다). 되돌려-검증 2/2 빨간불 확인.

⚠️ 또 같은 함정을 밟을 뻔했다 — 스타일 한 줄을 고쳤을 뿐인데 그 줄을 **문자열로 가리키던**
매니페스트 항목이 낡았다. 이 세션에서만 네 번째다. **코드를 고치면 그 줄을 가리키는 지도도 같이.**

## 못 한 것 / 남은 판단
**2초 자체는 안 줄였다.** 줄이려면 프리페치를 늘려야 하는데(예: 손이 닿은 카드의 사진을 전부),
그건 이 파일의 1원칙(**본 장면만 로드** — 카드 50개 × 갤러리 = 첫 화면 트래픽 몇 배)과 정면으로
부딪힌다. 대표 신고의 핵심은 *"안 넘어간 것처럼 보인다"* 는 **인지**였고 그건 블러로 해결된다.
속도 자체를 더 원하시면 **트래픽 비용과 맞바꾸는 별도 결정**이라 남겨 둔다.

## 후속 — "속도도 개선했으면. 부작용은?" (대표, 2026-09-06)

### 원인은 다운로드가 아니라 **시작 시점**이었다
```
커버 lazy 로드 → 커버 onLoad → 카드가 60% 보임 → 브라우저 idle(최대 2초) → 그제서야 요청
```
스크롤해서 만난 카드를 바로 넘기면 이 사슬을 정면으로 맞는다.

**실측(4G · 카드가 보인 뒤 다음 장 준비까지)**
```
종전   4,723ms · 458ms · >5,000ms · 1,044ms    중앙값 1,044 · 최악 5초 초과
지금   1,832ms ·  29ms ·    253ms ·    25ms    중앙값   253 · 최악 1.8초
```

### 💸 그런데 공짜가 아니었다 — 내가 두 번 틀렸다
처음 대표께 *"트래픽과 맞바꾸는 결정"* 이라 했다가, 측정 후 *"시점만 앞당기니 트래픽은 안 는다"* 로
바꿔 말했다. **둘 다 정확하지 않았다.** 같은 스크롤로 실측:
```
종전  60장 2,624KB   →   지금 71장 3,326KB   (+11장 · +702KB · +27%)
여백 0px 로 줄여도    68장 3,185KB (+21%)  ← "일찍"의 값이지 여백만의 값이 아니다
```
`threshold: 0.6` 이 **스치듯 지나간 카드를 놓치고 있었고**, 그게 절약처럼 보였을 뿐이다.

### 그래서 머문-시간 게이트를 넣었다
`rootMargin: 400px` 로 넓게 관측하되 **250ms 머물러야** 실제로 받는다(`DWELL_MS`).
빠르게 훑고 지나가는 카드는 타이머가 취소돼 한 장도 안 받는다.
⚠️ **다만 이 게이트의 절감은 실측으로 확인하지 못했다** — 하네스가 매 스크롤마다 1.1초씩 멈춰
모든 카드가 250ms 를 넘겼기 때문이다(멈추지 않는 연속 스크롤은 하네스 기준선이 갈려 비교 실패).
즉 **+27% 는 "천천히 훑는 사용자" 기준의 상한**이고, 빠른 스크롤에선 그보다 적을 것으로 **기대**하되
숫자로는 못 박지 않는다.

### 되돌리기
상수 셋만 원복하면 종전과 동일: `DWELL_MS`(250) · `rootMargin`('400px') · `threshold`(0 → 0.6) ·
`timeout`(800 → 2000).

## ✅ 배포 후 라이브 판정 (2026-09-07 15:5x KST · `ff0331dd1` · deploy run 4691)

번들에 상수가 실제로 실렸는지부터 확인했다 — `rootMargin:"400px"` · `threshold:0` · `timeout:800`
(잠긴 카드 뷰포트 prefetch `rootMargin:"100px"` 은 그대로 = 무접촉 확인).

### 카드 상태를 직접 재니 기대대로였다
`slide-state.mjs`(4G 에뮬 · iPhone 13 · 카드 7장):
```
들어올 때 이미 2장 확보  5/7      2장 준비 성공  7/7      중앙값 489ms
느린 2장(4,726 / 5,286ms) = 들어올 때 아직 1장뿐이던 카드 = 관측 범위 밖에 있던 맨 아래 카드
```
**7/7 이 끝내 준비됐다**는 것이 핵심이다. 종전엔 5초 안에 못 끝내는 카드가 남았다.

### 🩸 하네스 두 개가 연달아 나를 속였다 — 둘 다 *내가 만든* 함정
1. `ready-when.mjs` 는 "2장 **로드 완료**"를 재는데, 이 환경의 라이브 경로는
   [브라우저 → 로컬 노드 프록시 → 에이전트 HTTPS 프록시 → CF] 라 **이미지 다운로드 자체가 수 초**다.
   그래서 "요청이 일찍 나갔는가"(이 변경이 실제로 바꾼 것)와 "다운로드가 끝났는가"(네트워크 사정)가
   한 숫자에 섞여 `>5000` 두 개가 찍혔다 — 로컬 측정 253ms 와 어긋나 보였지만 **다른 것을 잰 것**이다.
2. 그래서 만든 `req-start.mjs` 는 더 나빴다: 진입 전 스냅샷에 없는 `<img>` 가 새로 생기는지를 봤는데,
   **prefetch 가 이미 끝난 카드는 새 `<img>` 가 안 생겨** 그걸 "발사 실패"로 셌다.
   `발사 2/6` 이라는 새빨간 오판이 나왔다 — **성공을 실패로 읽는 하네스**였다.

> 🧭 교훈: 측정 대상이 "우리가 통제하는 것"인지 먼저 정하라. 이 변경이 통제하는 것은 **요청 시점**이지
> **완료 시점**이 아니다. 그리고 "변화가 있었는가"로 성공을 판정하면 **이미 성공한 상태**를 못 읽는다.
> 상태를 직접 재는 것(`slide-state.mjs`)이 셋 중 유일하게 옳았다.
