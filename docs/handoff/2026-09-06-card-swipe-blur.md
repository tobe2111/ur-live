# 카드 사진 넘길 때 "이전 사진이 그대로" — 신호가 없던 것 (2026-09-06)

대표: *"메인페이지에서 이용권 이미지 넘길 때 로딩이 생길 때 문제인 것 같은데, 로딩이 걸린다면
이전 사진과 똑같이 나오는 것 같아."*

## 맞다. 그리고 그건 내가 09-02 에 넣은 처방의 절반이 빠진 상태였다

09-02 에 *"넘기면 회색 빈 칸"* 을 고치면서 **직전 사진을 그대로 두는** 방식으로 바꿨다. 방향은 맞다.
문제는 **"받는 중"이라는 신호가 없었다**는 것이다:

- 직전 사진을 `opacity: 0.65` 로 어둡게만 했다 → **밝은 사진에선 거의 안 보인다**
- 게다가 **도트는 이미 다음 칸으로 가 있다** → "점은 넘어갔는데 사진은 그대로" = *안 넘어갔다*로 읽힌다

### 📏 실측 (라이브 · 홈 다장 카드)
```
PC 빠른 회선   130ms → 128 → 126 → 132        (사람 눈에 안 띔)
모바일 4G      2,180ms → 383 → 126 → 106      ← 첫 넘김이 2초 넘게 걸린다
라이브 상태 샘플링   60프레임 중 59가 "어둡기만", 흐림 0, 그것도 opacity 0.917
```
2초 동안 "같은 사진"이 서 있었다. 대표 신고와 정확히 일치한다.

⚠️ **첫 넘김만 느린 이유**: idle 프리페치는 *다음 한 장*만 받는데, 모바일 4G 에선 그 프리페치 자체가
~2초 걸려 사용자의 첫 클릭을 못 따라간다. 두 번째부터는 `step` 이 next+after 를 미리 받아 빨라진다.

## 처방 — 블러-업 (새 자산·새 요청 0)
받는 중이면 직전 사진을 **흐리게**(`blur(10px)` + `scale(1.06)` + `opacity .8`) 남긴다.
흐려지는 순간(0ms) *"이건 아직 그 사진이 아니다"* 가 읽히고, 도착하면 선명해진다.
업계 표준 idiom 이고, 요청 수·트래픽은 **그대로**다(이 파일의 1원칙인 트래픽 보호 무접촉).

- `scale(1.06)` 이 필요한 이유: 블러만 걸면 가장자리에 투명 테두리가 생긴다.
- 도트는 그대로 `shown` 을 따른다 — 이제 흐림과 짝이 맞아 "다음 장 받는 중"으로 읽힌다.

### 실측 확인 (강제 대기 상태 고정 — 사진 요청을 8초 붙잡아 재현)
```
before(라이브)  [{o:1,    f:none}]        ← 선명한 채로 그대로
after (새 빌드)  [{o:0.8, f:blur(10px)}]  ← 흐림
```
스크린샷 한 장에 대비가 잡혔다: 왼쪽 카드(받는 중)는 흐리고 오른쪽(로드 완료)은 선명하다.

## 가드
`deal-card-swipe-continuity.test.ts` — 기존 3건 유지 + **블러 신호 2건 추가**(`waiting` 판정 존재,
`filter` 배선). 주입 매니페스트: **신규 1건**(블러 소실) + **낡은 지도 1건 재조준**
(`opacity: … 0.65` 문자열이 바뀌었다). 되돌려-검증 2/2 빨간불 확인.

⚠️ 또 같은 함정을 밟을 뻔했다 — 스타일 한 줄을 고쳤을 뿐인데 그 줄을 **문자열로 가리키던**
매니페스트 항목이 낡았다. 이 세션에서만 네 번째다. **코드를 고치면 그 줄을 가리키는 지도도 같이.**

## 못 한 것 / 남은 판단
**2초 자체는 안 줄였다.** 줄이려면 프리페치를 늘려야 하는데(예: 손이 닿은 카드의 사진을 전부),
그건 이 파일의 1원칙(**본 장면만 로드** — 카드 50개 × 갤러리 = 첫 화면 트래픽 몇 배)과 정면으로
부딪힌다. 대표 신고의 핵심은 *"안 넘어간 것처럼 보인다"* 는 **인지**였고 그건 블러로 해결된다.
속도 자체를 더 원하시면 **트래픽 비용과 맞바꾸는 별도 결정**이라 남겨 둔다.
