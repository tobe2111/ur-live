# 🛒🕐 장바구니 정보·자동분할 + 로딩이 "없어요"라고 거짓말하던 것 (2026-09-15, 2차)

대표: *"시안에서 보니까 조금 더 정보들이 들어갔으면 좋겠어 할인이라던지, 따로 골라서 결제할 필요도
또 없지 않나? … 각 페이지들마다 접속 시 로딩들이 좀 불만이야. … 계속 중간에 연관없는 페이지도
보이는 것 같고?"*

## 다음 세션의 첫 액션

```bash
# 배포 뒤 라이브에서 로딩 시퀀스를 다시 뜬다(절대 ms 가 아니라 **무엇이 먼저 보이는가**를 본다)
node scripts/probe-loading.mjs /my-vouchers /user/profile /my-orders
```
**판정**: 로더가 1회만 뜨고, 그 자리에 `받아둔 이용권이 없어요` / `0곳` / `0` 이 **먼저** 나오지 않으면 통과.

## 무엇을 고쳤나

### ① 로딩과 "없음"이 같은 말이었다 (대표가 말한 "연관없는 페이지")

`initialData: () => readCache(key, [])` — **캐시가 없어도 빈 배열을 "진짜 데이터"로** 넘긴다.
그러면 React Query 가 `isLoading: false` 로 보고하고, 화면은 로더 대신 결론을 그린다.

렌더 실측(로컬 빌드, 프레임 캡처):

| 경로 | 전 | 후 |
|---|---|---|
| `/my-vouchers` | 806ms **"받아둔 이용권이 없어요"** | 644ms **로더** |
| `/user/profile` | "내 이용권 **0** · 내 교환권 **0**" | 숫자 없이 스켈레톤 |
| `/map` | 696ms **"0곳"** → 957ms "336곳" | "…곳" → 336곳 |

훅 **20곳**이 같은 패턴이었다(주소·팔로잉·숙소·쿠폰·관심·주문·이용권·예약·알림·팔로우·디지털·
반품·위시리스트·잔액·장바구니수·상품·셀러·프로필…). 즉 **"내 것" 페이지 거의 전부.**

⚠️ **이 함정은 이미 절반만 발견돼 있었다.** 2026-07-02 에 *에러 폴백* 방향으로 `readCacheOrNull`
이 생겼고 주석까지 남아 있는데(*"readCache(key, []) 는 캐시 없음과 캐시된 빈 목록을 구분 못 해"*),
**로딩 방향엔 안 붙였다.** 나머지 반쪽이 `cachedInitialData` 다.

### ② 장바구니 — 정보를 더, 그리고 "따로 골라서"를 없앰

- **할인**: 서버 SELECT 에 `p.original_price`·`p.discount_rate` 추가(additive) → 카드 줄이
  `[25% 22,000원] / [16,500원]` 2줄. 홈 카드와 **같은 SSOT**(`shared/price-display.ts`).
  요약에 `할인 −27,500원`.
- **자동 분할**: 섞여 있으면 버튼을 잠그는 대신 **버튼이 한 덩어리를 골라 준다** —
  `이용권 3개 먼저 결제 · 74,500원`. 누르면 그 종류만 선택해 결제로 가고 나머지는 장바구니에 남는다.
  판정은 `pages/cart/cart-cta.ts` 순수 함수(실행해서 잰다).

  ⚠️ **한 번에 묶어서 결제하는 것과는 다르다.** 교환권은 딜에서 빠지고 이용권은 카드로 청구되며
  끝나는 방식도 다르다(문자 발송 ↔ 매장 QR). 한 주문으로 합치려면 두 발급 후처리를 한 결제에
  얹어야 하고 그건 머니 경로 대공사다 — 지금은 **노동만 없앴다**(위험 0). 통합은 대표 결정 사항.

## 이번에 틀렸던 판단 — 이게 제일 값지다

1. 🩸 **내가 만든 탐지기가 첫 판에 헛돌았다.** "남의 화면" 검사를 낱말 목록으로 짰는데, 세션을 안
   넣어서 보호 라우트가 **로그인 페이지**로 튕긴 것을 "랜딩 문구가 뜬다"로 오독할 뻔했다.
   ⇒ 보호 라우트를 잴 때는 **세션을 넣어라.** 그리고 목록 기반 탐지는 자기가 안 적은 것을 못 본다.
2. 🩸 **SQL 주석에 백틱을 썼다** — 그 블록이 템플릿 리터럴 안이라 문자열이 끊겨 `TS1005`.
   tsc 가 잡았지만, 같은 자리에 또 쓰지 말 것(주석으로 박아 뒀다).
3. 🩸 **기존 가드가 옛 동작을 지키고 있었다.** "섞이면 버튼을 잠근다"는 주입·테스트가 있었는데
   대표 지시로 그 동작이 폐기됐다. **지우지 않고 새 의도로 재조준**했다(페이지가 라벨을 다시 직접
   짓는 것을 막는 쪽으로). 가드를 지우면 그 자리가 다시 빈다.
4. 🩸 **테스트 픽스처를 `const mk = (...)` 로 짓지 말 것.** `check-branch-scope` 의 주입 시그니처
   목록에 정확히 그 이름이 있어서(`가짜 헬퍼(mk) 주입`) **pre-push 가 푸시를 막는다.**
   가드가 옳다 — 이름만 피하면 된다(여기선 `cartItem`). 그리고 그 탐지기는 **diff** 를 보므로
   작업트리만 고치면 안 되고 **커밋을 amend** 해야 한다.
5. ⚠️ **프록시를 거친 ms 는 믿지 말 것.** 첫 측정이 콘텐츠 6~8.6초로 나왔는데 그건 Node 중계가
   직렬로 받아서다. 보는 것은 **순서와 내용**이고, 절대 속도는 **배포 후 라이브**가 판정한다.
