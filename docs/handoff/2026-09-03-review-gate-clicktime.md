## 그래서 원인 대신 **버그 클래스**를 없앴다

이 레포에 같은 교훈이 이미 있다 — 2026-06-26 `TossPaymentWidget` 은 약관 동의를 React state 로
미러링해 결제 버튼 `disabled` 에 묶었다가 desync 로 **버튼이 잠기는 사고**를 냈고,
대표 지시("대형 서비스처럼")로 **클릭-시점 검증**으로 전환했다. 리뷰 버튼만 그 옛 패러다임에 남아 있었다.

- 버튼은 **제출 중에만** 잠긴다(길이 조건 제거)
- 길이는 **누를 때** 재고, 모자라면 **그 자리에** 남은 글자 수를 쓴다 + textarea 포커스
- 규칙(10자)은 그대로 — 바뀐 것은 *언제 재는가* 와 *어디에 말하는가*

## 서버 거절 사유를 인라인에도

토스트는 `fixed top-4`(화면 **맨 위**)인데 리뷰 폼은 페이지 **맨 아래**, 모바일은 키보드까지 올라와 있다.
토스트로만 알리면 사용자에겐 **"아무 일도 안 일어났다"** 로 보인다 — 대표가 "안 눌러진다" 고 읽은 것이
이것일 가능성도 있다. 403 사유를 `hint` 로 폼 안에도 남긴다.

## 자격은 쓰기 전에 (대표 지시)

신규 `GET /api/reviews/product/:productId/eligibility` — **POST 와 같은 판정 함수**
(`checkReviewEligibility`)를 그대로 노출한다(두 답이 갈릴 수 없다). 판정을 여기서 다시 쓰지 않는다.

요청 시점은 **"리뷰 작성하기" 를 누를 때**다(상세 페이지를 열 때가 아니라) — 모든 방문자에게
자격 조회를 한 번 더 물리지 않으려는 것. 자격이 없으면 **폼을 열지 않고** 사유를 그 자리에 쓴다.

⚠️ **조회가 실패하면 막지 않는다**(fail-open) — 여긴 안내용이고 최종 권위는 POST 다.
여기서 막으면 조회 한 번 삐끗에 정당한 사용자가 리뷰를 못 쓴다.
