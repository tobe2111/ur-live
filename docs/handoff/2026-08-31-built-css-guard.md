# 2026-08-31 — 빌드 산출 CSS 가드를 실제로 도는 자리로 옮김

## 대표 지시

`button-system.test.ts` 의 "빌드 산출 CSS 에 `.ur-btn-lg` 가 실려야 한다" 검사가 **CI 에서 실패할 수 없다**는
발견을 그대로 과제로 받았다. 제안 3안 중 **1번(빌드 뒤로 옮긴다)** 을 지시받은 대로 택했다.

## 무엇이 문제였나

```
verify.yml   step  5  Run unit tests     ← 판정이 여기 있었다
             step 96  Build client       ← dist/ 는 여기서 처음 생긴다
```

테스트 코드가 `if (!existsSync(dir)) return` 이라 **dist 가 없으면 조용히 통과**했다.
CI 에서는 dist 가 존재한 적이 없으므로 이 판정은 **한 번도 실행된 적이 없다.**

반대로 로컬에서는 낡은 `dist/` 를 읽어 **가짜 빨간불**을 냈다 — 2026-08-31 에 실제로 그랬다
(4일 전 산출물이라 실패 → 새로 빌드하니 통과). 판정이 언제나 틀린 검사였다.

레포가 반복해 당한 **"가드가 있는데 안 돎 / 실패할 수 없음"** 클래스다
(`check-bundle-size` 의 gzip 예산이 몇 달간 0 을 재며 통과만 하던 사고와 같은 모양).

## 무엇을 했나

- **신규 `scripts/check-built-css.mjs`** — `verify.yml` 의 `Build client` **뒤**(번들 가드들 옆)에서 돈다.
  - 산출물이 없으면 **exit 1**(예전의 조용한 통과를 뒤집었다).
  - 기대 목록을 **손으로 안 적는다**: `src/index.css` 가 정의한 `.ur-btn*` 중 **소스가 실제로 쓰는 것**만
    빌드 CSS 에 있어야 한다. 크기를 새로 만들거나 없애도 검사가 저절로 따라온다.
  - 파일명을 가정하지 않는다(`index-*.css` 고정 → `assets/*.css` 전부 합쳐 봄). 청크가 갈려도 안 깨진다.
  - 판정 대상이 0건이면 실패(측정 0 = 통과 아님).
- **`button-system.test.ts`** — 그 케이스 제거 + 헤더 주석에 경위 기록(왜 여기 없는지).
- **신규 `src/tests/unit/built-css-guard.test.ts`** — *가드의 가드*. 빌드 뒤에만 돌 수 있는 검사라
  유닛 단계에서는 CSS 를 못 보므로, 대신 **호출이 있는지 · 빌드 뒤인지 · 부재를 통과로 접지 않는지 ·
  유닛테스트로 되돌아가지 않았는지**를 본다. 이 가드의 전부가 순서이므로 순서를 고정한다.

## 되돌려-검증 (3건 전부 빨간불 확인 후 복원)

| 주입 | 무엇이 되돌아가나 |
|---|---|
| 워크플로에서 `run:` 제거 | 파일만 남고 안 돎 |
| 부재 시 `exit(0)` | 조용한 통과 |
| `button-system.test.ts` 가 다시 dist 참조 | 원래 사고 자리로 복귀 |

## 🩸 이번에 내가 만든 헛도는 가드 (다음 세션 교훈)

부재 분기 판정을 처음에 `/dist\/client\/assets 가 없다[\s\S]{0,400}process\.exit\(1\)/` 로 썼다.
그 400자 창 안에 **바로 다음 분기의 `process.exit(1)`** 이 들어와서, 그 분기를 `exit(0)` 으로 바꾸는
주입에도 **초록이 떴다.** 되돌려-검증이 아니었으면 못 잡았다.

⇒ 분기를 잘라서 보도록 고쳤다(`sliceBetween`). **넓게 훑는 정규식**은 이 레포가 반복해 당한 헛도는
가드의 전형적인 모양이다 — `toContain(이름)` 이 `이름_REMOVED` 를 통과시킨 것(같은 날 #1260)과 같은 병이다.
