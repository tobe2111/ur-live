## ① 로그아웃했는데 로그아웃 버튼이 뜬다 — 원인 둘, 둘 다 고쳐야 사라진다

### 재현 (브라우저 실측 — 추측 아님)

`localStorage` 에 **`admin_token` 하나만** 두고 홈을 열면 대표 스크린샷과 **정확히 같은 화면**이 나온다:

```
인사: 유어딜에 오신 걸 환영해요            ← 손님 인사(이름이 없다)
항목: 유마이 | 찜한 이용권 | 내 이용권 | 내 교환권 | 주문 내역 | 딜 내역 | 알림 | 설정 |
      고객센터 | 앱으로 보기 | 유어딜에서 판매하세요 | 로그아웃      ← 로그인 메뉴
```

손님 인사 + 로그인 메뉴가 한 화면에 있는 **모순된 상태**다. `seller_token` 만 둬도 같다.
프로브: `scratchpad/probe-logout.mjs`(세션 종료 시 사라짐 — 필요하면 아래 설명으로 재작성).

### 원인 A — 소비자 헤더가 *대시보드* 토큰을 로그인으로 셌다

`DesktopTopNav.tsx:38` 이 `isLoggedInSync()` 를 읽고 있었다. 그 함수는 **설계상**
`seller_token`·`admin_token`·`agency_token` 까지 로그인으로 센다(라우트 가드용으로는 그게 맞다).
그래서 소비자 로그아웃을 끝내도 대시보드 토큰이 하나라도 남으면 헤더가 계속 로그인 상태로 그려졌다.

**이미 올바른 함수가 있었다** — `hasConsumerSession()`. 그 주석이 경계까지 적어 뒀다:
> *"seller_token / admin_token 단독은 *소비자* 세션이 아니므로 포함하지 않는다."*

⇒ `const loggedIn = hasConsumerSession()`. 이 값이 가르는 셋(계정 메뉴·찜·알림)은 전부 소비자 기능이다.

### 원인 B — 계정 메뉴의 로그아웃이 반쪽이었다

**이 버그는 2026-07-07 에 이미 진단·수정됐다.** 그때 대표가 *"전부 로그아웃"* 으로 확정했고
`logoutAll()`(전 역할 종료)이 만들어져 **마이페이지**에 배선됐다. `UserProfilePage.tsx:126` 주석이
오늘 증상을 그대로 적고 있다 — *"대시보드 Bearer 토큰이 남아 isLoggedInSync()=true → 홈이 여전히
로그인됨으로 보임 → 대표 신고 '로그아웃이 안 됨'"*.

그런데 **PC 계정 메뉴는 그 확정 한 달 뒤(08-19)에 만들어졌고 옛 방식**(`clearAuthData('user')` =
소비자만 정리)을 썼다. 같은 버그가 **새 문으로** 다시 들어온 것이다.

⇒ `AccountMenu.signOut()` 도 `logoutAll()` 로. 두 입구가 다른 로그아웃을 하면 안 된다.

> 🔑 **둘 다 고쳐야 한다.** 신호(A)만 고치면 대시보드 토큰이 계속 남고,
> 동작(B)만 고치면 다른 탭에서 어드민으로 로그인하는 순간 또 틀어진다.

### 수정 후 실측 (다섯 상태 전수)

| localStorage | 수정 전 | 수정 후 |
|---|---|---|
| `admin_token` 만 | 🔴 로그인 메뉴 + 로그아웃 | ✅ 로그인·회원가입 |
| `seller_token` 만 | 🔴 로그인 메뉴 + 로그아웃 | ✅ 로그인·회원가입 |
| 비어 있음 | ✅ 로그인·회원가입 | ✅ 그대로 |
| 소비자 로그인 | ✅ | ✅ "안녕하세요, 정지원님!" + 전체 메뉴 |

**반대 방향도 확인했다** — 진짜 소비자 로그인이 깨지지 않았다.

## ② 이메일 가입·로그인

### 서버는 이미 멀쩡했다 (라이브 실측)

```
POST /api/auth/login    → 401 {"error":"이메일 또는 비밀번호가 올바르지 않습니다"}
POST /api/auth/register → 400 {"error":"비밀번호는 10자 이상이어야 합니다."}
```

둘 다 살아 있다. 2026-09-20 에 고친 `users.id` INTEGER PK 사고도 반영돼 있다.
**막고 있던 건 화면 쪽 세 가지**였다.

### 가-1. 폼과 서버의 비밀번호 규칙이 달랐다

| | 규칙 |
|---|---|
| 서버 `/api/auth/register` | **10자 이상** + 대문자·소문자·숫자·특수문자 **전부** |
| 가입 폼 `RegisterPage` | `password.length < 8` **하나** |

`password1`(9자) 같은 값이 **폼을 통과해 전송되고 서버가 처음 보는 규칙으로 400** 을 돌려줬다.
사용자에겐 *"폼은 괜찮다는데 가입이 안 되는"* 화면이다.

⇒ 정책을 **`src/shared/password-policy.ts` 한 곳**으로 뽑고 서버·폼이 같은 함수를 쓴다.
`src/lib/password.ts` 는 그걸 **재수출**하므로 서버 import 경로(12곳)는 한 줄도 안 바뀐다.
🪶 crypto 가 없는 순수 모듈이다 — 폼이 `lib/password`(PBKDF2)를 통째로 import 하면 쓰지도 않는
해시 코드가 브라우저 번들에 실린다.

### 가-2. 규칙을 어디에도 안 적어 놨다

`"8자 이상 입력해주세요"` placeholder 하나뿐이라, 거절당해도 **무엇을 고쳐야 할지 알 수 없었다.**
⇒ 비밀번호 칸 아래에 **실시간 체크리스트**(10자 이상 / 대문자 / 소문자 / 숫자 / 특수문자).
판정은 제출 검사와 **같은 모듈**에서 나온다 — 화면과 게이트가 갈리지 않는다.

⚠️ **placeholder 는 `defaultValue` 만 고치면 소용없다** — locale 값이 이긴다(CLAUDE.md 가 경고하는 함정).
`public/locales/{ko,en,ja,zh,es,fr}` 6개 전부 갱신했고, 거짓이 된 `errorPasswordLength`·
`errorWeakPassword`("8자") 키는 **참조 0 확인 후** 제거했다.

### 가-3. 서버가 알려준 실패 이유를 화면이 버렸다

- **가입**: Firebase 에러코드(`email-already-in-use`·`weak-password`)로 분기하고 있었다. Firebase 는
  2026-08-04 에 제거됐고(#804) 서버는 **한국어 문장**을 준다 → 어떤 가지도 매치되지 않아
  **항상** `"회원가입에 실패했습니다"` 만 떴다.
- **로그인**: 무슨 이유든 `"이메일 또는 비밀번호가 올바르지 않습니다"`. 서버는 **423 계정 잠금**을
  구분해 주는데 그걸 버렸다 — 잠긴 사람이 계속 시도해 **잠금이 더 길어진다.**

⇒ 둘 다 서버 문장을 그대로 보여 준다.
🔒 **계정 존재 여부는 안 샌다** — 서버가 미존재 계정과 비번 오류에 *같은 문장*을 주도록 이미
설계돼 있고(테스트가 그 동일성을 고정한다), 그래서 메시지를 그대로 노출해도 enumeration 이 안 된다.

## ✅ E4 라이브 판정 — 둘 다 통과 (2026-10-01, 머지 `5cf6a209e` 배포 후)

### ① 로그아웃 — **배포된 실제 바이트**로 다섯 상태 전수

| localStorage | 인사 | 메뉴 |
|---|---|---|
| `admin_token` 만 | 유어딜에 오신 걸 환영해요 | **로그인 · 회원가입**(로그아웃 없음) ✅ |
| `seller_token` 만 | 〃 | **로그인 · 회원가입** ✅ |
| 비어 있음 | 〃 | 로그인 · 회원가입 ✅ |
| 소비자 로그인 | 안녕하세요, {이름}님! | 전체 메뉴 + 로그아웃 ✅ |
| 소비자 + 어드민 | 안녕하세요, {이름}님! | **소비자 메뉴 유지**(듀얼 로그인 보존) ✅ |

🔒 **TLS 를 끄지 않고 라이브를 쟀다.** Node 가 검증된 TLS 로(`NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt`)
라이브 바이트를 받아 로컬 http 로 중계하고, 브라우저는 그걸 렌더한다 ⇒ **배포된 자산**을 보면서
브라우저는 평문만 쓴다. 프로브: `scratchpad/live-mirror-logout.mjs`(세션 종료 시 사라짐 — 이 설명으로 재작성 가능).

> 🩸 **먼저 시도한 두 길은 실패했다. 다음 세션이 같은 길을 또 파지 않도록 적는다:**
> ⓐ Chromium 직접 접속 → `ERR_CERT_AUTHORITY_INVALID`(에이전트 프록시가 MITM 한다)
> ⓑ `--ignore-certificate-errors-spki-list` 에 **체인 세 장의 SPKI 를 전부** 넣어도 그대로 실패했다
>   (이 Chromium 빌드에서 그 플래그가 안 먹는다). `ignoreHTTPSErrors: true` 로 통째로 끄는 길은
>   **쓰지 않았다** — 중계가 같은 판정을 주면서 TLS 는 살아 있다.
> 🕳️ 그리고 선택자도 한 번 틀렸다: 계정 트리거는 **글자가 없는 아이콘 버튼**이라
>   `innerText` 로 못 찾는다 → `button[aria-label="마이"]`(`DesktopTopNav:390`).
