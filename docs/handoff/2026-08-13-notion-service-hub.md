## 이번에 알게 된 것 (다음 세션이 반복하지 않게)

### 1. 유어애즈 수치는 문서가 낡아 있었다 — 라이브로 재면 4배였다

`CLAUDE.md` 의 유어애즈 절이 인용하는 값(2026-08-05 기준 발송 가능 5,801명 / 전체 54,033)을 그대로
옮겨 적을 뻔했다. **D1 직접 조회로 다시 재니 8일 만에 이렇게 바뀌어 있었다:**

| | 2026-08-05 (문서) | 2026-08-13 (실측) |
|---|---|---|
| 전체 | 54,033 | **97,698** |
| 이메일 보유 | 8,187 | **23,520** |
| 발송 가능(거부·브랜드·무카테고리 제외) | 5,801 | **22,670** |

⇒ **대표에게 수치를 보고할 때 문서를 인용하지 말 것.** 이 레포의 수치는 며칠이면 낡는다.
쿼리는 `CLAUDE.md` 「☁️ Cloudflare API 접근」 절차 그대로(D1 uuid `d9530ba6-…`, 테이블
`ad_influencer_leads`).

### 2. 유어애즈 통계는 어드민 API 로 다 안 나온다

- `/api/admin/partner-pool/stats` → **된다**(업체 풀 292,378 · 연락처 43,180 · 대행사 8,077).
- `/api/ads/influencer-pool/stats` → **Bearer 로 안 된다** (`로그인이 필요합니다`). `ur-ads` 는 별도 워커라
  인증이 다르다. Cookie/X-Admin-Token 변형도 전부 실패. ⇒ **인플루언서 풀은 D1 직접 조회가 유일한 경로.**

### 3. Notion MCP 에서 물린 것 두 가지

- **한 번에 보내는 페이로드가 크면 조용히 잘려 `InputValidationError`** 가 난다(4KB 언저리에서 재현).
  ⇒ 페이지는 1개씩, DB 행은 4개씩 나눠 보낼 것.
- **linked view 는 `data-source-url` 로 안 붙었다** (`collection://…` · `{{collection://…}}` 둘 다
  `Data source not found`). ⇒ `<mention-database url="…">` 로 대체했다. 인라인 뷰가 꼭 필요하면 UI 에서
  붙여야 한다.
- ⚠️ 사이드바 편집 시 `<page url=…>` 태그를 지우면 **그 하위 페이지가 삭제된다**(스펙 경고). 기존 태그를
  그대로 두고 `<mention-page>` 만 덧붙이는 방식으로 했다.

   유어딜이 됐다. **대표 확인 없이 이름·상태를 바꾸지 않았다.** 병합할지 과거 기록으로 남길지 판단 필요.
