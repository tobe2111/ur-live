## 3차 (같은 날) — 온보딩용으로 방향 전환

대표가 Notion 의 **용도를 새로 정의**했다: *"이 notion은 신입이 입사 시, 온보딩을 하는 용도야.
어떠한 기술로 구현이 되었다는 필요없고 어떤 서비스인지 각각 알려주는 형태로."*
그리고 *"원래 이 템플릿은 한 사업을 하는 업체를 위한거였으니까"* — **구조적 미스매치**를 직접 짚었다.

### 진단 (다음 세션이 같은 걸 다시 파지 않게)

1. **템플릿 전제가 안 맞는다** — Business OS 는 사업 1개 회사용이라 목표·프로젝트·캠페인·회의가 전부
   평면 DB 하나씩이다. 사업이 21개면 모든 DB 에 21개 사업 것이 섞인다.
2. **사업 페이지 대부분이 비어 있었다** — 21개 중 실제 설명이 있는 건 2개뿐이었고 나머지는 템플릿 기본
   상태(DB 5개만)였다. TOKPICKS 를 열어 확인.
3. **1·2차에서 내가 만든 것이 방향과 어긋났다** — 「서비스 개발 현황」·「개발 업데이트 로그」는 개발자용이다.
   온보딩 동선에서 빼서 「개발자 코너」 아래로 옮겼다.

### 한 것

- **「신입 온보딩」 페이지 신설**(`3bb0adee-652b-8118-9584-e848c6bb26aa`) — 3단계 코스 + 첫 주 체크리스트
- **「개발자 코너」 신설**(`3bb0adee-652b-8131-be86-f57f3e604155`) — 기술 문서를 여기로 이동
- **메인페이지 = 온보딩 입구**로 재구성: 온보딩 → 사업 → 일하는 법 → (구분선) → 운영 DB
- **사업 21개 전부에 표준 6항목** 삽입 — 한 줄 정의 / 누구의 어떤 문제 / 어떻게 돈을 버나 /
  지금 어디까지 / 이 사업에서 쓰는 말 / 담당·문의

### ⚠️ 한글 일부 음절이 전송 중 깨진다

`흩` `몫` `삽` 같은 **덜 흔한 음절이 다른 글자로 바뀌어 저장**됐다(`흩어져`→`흔어져`, `몫`→`몲`,
`삽니다`→`샿l니다`). 고치려고 같은 글자를 다시 보내면 **또 다른 글자로 깨져서** 매칭조차 안 된다.

⇒ **대응 두 가지**: ① 흔한 어휘로 우회한다(`몫`→`부담하는 금액`, `삽니다`→`결제합니다`)
② 이미 깨졌으면 부분 치환하지 말고 **`replace_content` 로 페이지를 통째로 다시 쓴다.**
⇒ **한국어를 길게 쓴 뒤에는 반드시 fetch 해서 눈으로 확인할 것.**

### 남은 것 (대표 확인/입력 필요)

1. **사업 15개의 6항목이 비어 있다** — 내가 모르는 사업이라 **지어내지 않고 빈칸으로 뒀다.**
   실제 내용을 아는 사람이 채워야 한다. 채워진 6개: 유어딜 · 공구 서비스 · 유어애즈 · 유통스타트 ·
   라이브 커머스 · 상인회 홈페이지.
2. **MVC 의 미션이 실제 사업과 어긋난다** — 미션은 *"고객사의 국내 유통과 해외 수출을 돕는다"* 인데
   실제로는 소비자 커머스·DB·상인회 홈페이지까지 넓다. 신입이 첫 페이지에서 읽는 문장이라 중요하다.
   **대표의 말이라 임의로 고치지 않았다.**
3. 운영 DB 3개 접기 · 갤러리 상태별 그룹은 여전히 **Notion UI 작업**(API 불가).

### 🚨 "성공 응답"을 믿지 말 것 — 같은 함정에 두 번 빠졌다

메인페이지 재구성을 적용하고 **성공 응답을 받았는데 실제로는 아무것도 안 바뀌어 있었다.**
원인은 `old_str` 안의 `<empty-block/>` 하나 — 문서에서는 이미 사라진 상태였는데 내 문자열엔 남아 있었다.
`update_content` 는 **매칭 실패를 에러로 알려주지 않고 조용히 넘어간다**(토글 이동 때와 같은 클래스).

⇒ **Notion 을 고친 뒤에는 반드시 `fetch` 로 눈으로 확인한다.** 대표가 *"이제 다 끝난거야?"* 라고 묻지
않았으면 안 고쳐진 채로 완료 보고를 할 뻔했다.
⇒ **`old_str` 은 짧게 잡는다.** 긴 블록을 통째로 매칭하면 공백 한 칸 때문에 실패한다. 헤딩 한 줄처럼
짧고 고유한 앵커가 안전하다.

### 페이지 이동은 `move-pages` 로 (본문 `<page url>` 말고)

`<page url="...">` 을 새 페이지 본문에 넣는 방식으로는 **이동이 일어나지 않았다.**
`mcp__Notion__notion-move-pages` 를 쓰면 한 번에 된다 — 「서비스 개발 현황」을 이 도구로 「개발자 코너」
아래로 옮겼다.

### 최종 확인된 메인페이지 구조 (fetch 로 검증)

`👋 처음 오셨나요` → `📣 공지` → `🏢 사업` → `📚 일하는 법·자료` → **구분선 + "여기서부터는 운영용"**
→ `🎯 목표` → `📋 프로젝트` → 캠페인 → 회의 → 팀/부서

### 4차 — 내가 만든 것 안의 모순 하나 (대표 *"더 할 건 없어?"* 로 발견)

「신입 온보딩」 2단계가 *"주력 3개를 읽으세요"* 하면서 **기술 페이지**(개발자 코너 아래로 옮긴 것)를
링크하고 있었다. 온보딩 동선에서 기술을 빼 놓고 온보딩 입구에서 다시 기술로 보내고 있었던 셈이다.
⇒ **제품 목록의 사업 카드**(`3bb0adee…81be` 유어딜 · `…819f` 공구 · `…8121` 유어애즈)로 교체.
같은 편집에서 제목 오타(`막힘 때는` → `막힐 때는`)도 수정. **fetch 로 둘 다 확인.**

> 🧭 **교훈**: 페이지를 옮기면 **그 페이지를 가리키던 링크가 조용히 틀린 곳을 가리키게 된다.**
> `move-pages` 로 옮긴 뒤에는 **그 페이지를 참조하던 곳을 되짚어야** 한다.

## 5차 — 템플릿 전 섹션 내용 채우기

대표 지시: *"유어팀 메인페이지의 노션을 가득 채웠으면 좋겠어. 우리끼리 일정도 조정해서 넣어보고
운영, 제품&서비스, 마케팅, 세일즈, 재무, 인사, 자료 및 매뉴얼, 데이터베이스 등 모두."*

### 원칙 — 무엇을 쓰고 무엇을 안 썼나

| 썼다 | 안 썼다 |
|---|---|
| **규칙·절차** (무엇을 어떻게 기록하나, 언제 결재를 올리나) | **기록성 데이터** — 매출 금액, 실고객 명단, 직원 정보 |
| **정책 초안** (주간/월간 일정, 결재 기준, 복지) — "초안"이라 명시 | 확정된 제도인 것처럼 단정하기 |
| **유어팀 고유 사실** (5% 수익, 사업 3개 지표, 마케팅 2축) | 모르는 사업의 사업 내용 |

⇒ **지어낸 사실 0.** 정책은 전부 "초안 — 안 맞으면 바꾸세요"로 표시했다.

### 채운 페이지 (17개, 전부 `insert_content` position:start — 기존 템플릿 내용 보존)

**운영 7** 루틴(주간·월간·분기 일정표) · OKR&KPI(목표 3개 제한, 총계 함정) · 프로젝트&태스크
(등록 기준, "진행 중 2주=멈춤") · 공지사항 · 회의 로그(회의 3종) · 팀/부서 · 결재 보고 센터(기준선 초안)
**마케팅 2** 판매 대시보드(보는 순서, 사용률 누수) · 전략&리소스(광고 안 사는 이유, 2축)
**세일즈 3** 잠재고객(유어애즈 연결, 무산 이유 기록) · 실고객(조용히 떠남) · 견적서
**재무 4** 월별 리포트(런웨이) · 매출(**거래액≠매출, 5%만**) · 지출(한번 vs 매달) · 계좌카드(보안 금지선)
**인사 2** 직원 관리(민감정보 금지) · 채용 관리
**자료 4** 표준 업무 매뉴얼(일하는 기본 4원칙) · 복지 문화 위키 · 공식 문서 보관함 · 내부 교육 자료
**기타 2** 데이터베이스 원본 목록(지우면 전부 사라진다 경고) · 제품&서비스

### 대표 확인이 필요한 초안

- **주간/월간 일정** — 월요일 시작회의 · 수요일 사업점검 · 금요일 마무리 · 매월 1~3일 재무정리
- **결재 기준** — 금액 기준선은 비워 뒀다(대표가 채울 자리)
- **복지·휴가** — 실제 제도와 다르면 고쳐야 한다

### 검증

`루틴` 페이지를 fetch 해 **한글 깨짐 0 · 기존 템플릿 블록 보존** 확인. 나머지는 동일 패턴(짧은 앵커 없이
start 삽입)이라 실패 위험이 낮다.
