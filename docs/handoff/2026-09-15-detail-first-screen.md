# 🖼️ 로더 대신 사진 — 서버가 이용권 상세 첫 화면을 그린다 (2026-09-15, 4차)

대표: *"꼭 로딩이 걸려야 해?"* → *"없어지는게 좋으면 없애도 돼. 그게 가장 이상적이야?"*

## 다음 세션의 첫 액션

```bash
# 배포 뒤. 마운트 전/후 히어로 박스가 **같은 자리**인지가 유일한 판정이다(ms 가 아니다).
node scripts/probe-loading.mjs /group-buy/2888
```
**판정**: 사진이 로더보다 **먼저** 뜨고, React 마운트 순간 **안 움직이면** 통과.
움직이면(튀면) `#root` 의 DETAIL 분기 1개를 지워 즉시 되돌린다.

## 답부터 — "없애는 게 이상적이냐"는 절반만 맞다

**"로더를 없앤다"가 목표면 아니고, "로더 자리에 진짜 첫 화면을 그린다"가 목표면 맞다.**
전자는 빈 화면이 되고, 후자는 로더가 *안 보이게* 된다(코드엔 남아 시드 없는 화면에서 계속 일한다).

실측이 그 이유다 — 하드로드 타임라인:
```
0.2초  HTML 도착 — __SSR_INITIAL_DETAIL__ 에 상품이 이미 들어 있다
0.5초  히어로 사진 도착 — 워커 preload 가 당겨 놨다
1.4초  React 마운트 — 그제서야 사진이 그려진다
```
그 1.2초의 대부분은 앱 코드가 아니라 **`(program) 967ms`(V8 파싱·컴파일)** 다. 코드로 줄일 수
있는 성질이 아니라, 번들을 줄이거나(−15% 추정) **기다리지 않고 그리거나** 둘뿐이다.

## 🔎 이 레포엔 React SSR 기계가 **이미 있었다**

`src/entry-server.tsx` + `scripts/prerender-main.mjs` 가 **매 빌드마다** 돌아
`dist/client/index.html` 에 `data-ssr="main"` 마크업을 굽는다. 그런데 워커가 2026-07-07 에
그걸 버리고 로더로 덮는다. **그 판단은 지금도 옳다** — prerender 는 `initialData = null` 이라
빌드 시점에 라이브 데이터가 없고, 데이터 없는 shell 은 [빈 shell → 로더 → 콘텐츠] 3단이 된다.

⇒ 남는 길은 **워커가 시드로 그리는 것**이고, 선례도 이미 있다(`/blog` 의 `blog-ssr-body.ts`,
그 주석이 이번 트레이드오프를 정확히 적어 뒀다: *"createRoot(비-hydrate)라 그대로 덮어쓴다"*).

## 이번에 틀렸던 판단 — 이게 제일 값지다

1. 🩸 **첫 타깃을 `/vouchers` 로 잡았다가 물렸다.** 카드 격자라 깨끗해 보였는데, 그 위 chrome
   (잔액 슬래브)이 **로그인 상태에 따라 250px ↔ 44px** 이고 서버 HTML 은 엣지 캐시라 per-user
   를 담을 수 없다 → 카드가 잘못된 Y 에 앉았다가 튄다. **상세가 오히려 안전한 표면**이다
   (히어로가 user-independent 하고 이미 preload 돼 있다).
2. 🩸 **로컬 하네스를 두 번 잘못 짰다.** ① `/before.html` 로 열어서 React Router 가 NotFound 를
   그렸고(경로가 `/group-buy/2888` 이어야 한다) ② 프록시 환경이라 chromium 직결이 `ERR_CERT` /
   `ERR_TOO_MANY_RETRIES` 로 죽었다(`PROXY_RELAY` 방식 + `urdeal.kr` 로 해결 — `live.ur-team.com`
   은 301 이라 릴레이에서 루프가 난다). **하네스가 0 을 뱉으면 결론이 아니라 하네스를 의심할 것.**
3. ⚠️ **파일크기 래칫을 +7 리베이스라인했다.** 본체 123줄은 새 모듈로 뺐지만, 남은 7줄은
   `check-loader-continuity` 불변식 ②가 **worker/index.ts 안에 있으라고 요구**하는 배선이라
   더 못 뺀다. 로더 const 를 옮기면 그 가드가 빨간불이 된다 — 가드가 옳다.

## 남은 것 (순서대로)

1. **판정 후** 제목·가격까지 확장 — 그러려면 `ShareRewardBanner` 를 제목 **아래**로 내려야 한다
   (UX 변경이라 별건). 그러면 첫 화면이 사실상 완성된다.
2. **PC(lg+) 히어로** — 별도 레이아웃이라 복제 면적이 크다. 상세 PC 트래픽을 먼저 재고 판단.
3. **JS 다이어트** — lucide 20KB → i18n 20.5KB → axios 17.7KB, 232KB→174KB 추정(로더 2.7s→2.3s).
   **−15% 라 그것만으론 답이 아니지만**, "보이는데 아직 안 눌리는 창"을 같이 줄인다.
4. `/vouchers`·홈은 위 ①의 per-user chrome 문제를 먼저 풀어야 한다.
