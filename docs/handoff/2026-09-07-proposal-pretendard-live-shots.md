## 이번에 틀렸던 판단

- **브랜치의 덱이 최신인 줄 알았다.** 실제로는 main 이 더 새것이었다(블루 이행).
  브랜치 셋의 blob 해시를 비교해 보고서야 알았다. 덱처럼 여러 세션이 만지는 파일은
  **작업 전에 main 과 대조**할 것.
- **`/map` 캡처를 5.5초에 찍어 타일이 흰 사각형으로 남았다.** 카카오 지도 타일은 늦게 온다.
  `settle: 18000` 으로 올려야 깨끗하다. 위치 권한(`geolocation`)도 없으면 전국 축척이라
  핀이 안 보인다 — 둘 다 `scripts/capture-proposal-shots.mjs` 에 반영했다.
- **격자에서 `margin-top:auto` 가 안 먹었다.** 05번 어두운 패널을 바닥에 붙이려고
  격자 항목에 `margin-top:auto` 를 줬는데 아무 일도 안 일어났다(격자 항목은 그 축으로
  자유공간을 안 받는다). 격자 **밖으로 빼서** 슬라이드의 flex 흐름에 놓아야 붙는다.
- **`grid-row` 만 주고 `grid-column` 을 빼먹어** 02번 화면이 1열로 튀었다.
  자동 배치는 빈자리를 먼저 채운다.

## 곁가지 발견 — Chromium TLS

이 원격 환경에서 Chromium 이 TLS 터널을 못 여는 원인은 **TLS 1.3** 이었다.
`--proxy-server` 에 `--ssl-version-max=tls1.2` 를 더하면 브라우저가 직접 붙는다
(`https://urdeal.kr/api/version` → 200 실측). `capture-proposal-shots.mjs` 헤더 주석에
남겼다. 기존의 "모든 요청을 Node fetch 로 대신 받는" 우회는 그대로 두었다 — 이미
검증돼 있고 바꿀 이유가 없다.

## 후속 (같은 세션, 커밋 f07a70e09)

**07번 화면 잘림이 CSS 가 아니라 우연이었다.** `.phone.crop` 으로 268px 만 보이게 해 뒀는데
실제로 자르던 건 부모의 `overflow:hidden` 이었다. img 인라인 `height:auto` 가
`.phone.crop img{height:100%}` 를 이겨, 이미지 레이아웃 상자는 424px 로 남아 슬라이드 밖으로
28px 넘쳐 있었다. `object-fit:cover` 도 height 가 auto 라 죽은 코드였다. 인라인에서 height 를
빼서 CSS 가 정하게 고쳤다. **렌더 결과는 byte-불변.**

> 교훈: 화면이 맞게 보인다고 규칙이 적용된 게 아니다. **인라인 스타일은 클래스 규칙을 이긴다.**
> 생성 스크립트가 인라인을 박으면 스타일시트의 의도가 조용히 죽는다.

실측으로 확인한 것(전부 이 세션에서 직접 잼):

| 항목 | 값 |
|---|---|
| 슬라이드 밖 넘침 (프리텐다드) | 07번 +28px → **0** |
| 슬라이드 밖 넘침 (CDN 차단, 폴백 글꼴) | 08번 +14px → **0** |
| PDF | 9장 · 960x540pt (정확히 16:9) |
| 인쇄 미디어 폰트 | Pretendard 유지 |
| `tsc --noEmit` | 0 |
| `admin-proposals-asset.test.ts` | 5 pass |
| robots.txt (레포·라이브 양쪽) | `Disallow: /static/proposals/` 확인 |

⚠️ 표지의 +180px 은 배경 광원 그라디언트의 **의도된 번짐**이다(`overflow:hidden` 이 자른다).
넘침 검사를 다시 돌리는 세션은 이걸 결함으로 오해하지 말 것.

⚠️ **`*.pages.dev` 는 이 환경 프록시가 정책으로 막는다**(`connect_rejected ... 403 to CONNECT`).
