# 업체 정보 — 세 곳에 흩어진 것을 한 페이지로 (2026-09-16)

## 대표 지시 (그대로)

> *"셀러대시보드에서 업체 정보 입력하는 페이지는 하나로 통일하고 보내준 당근 이미지처럼
> 구성해줄래? 굳이 분산할 필요없는 것들은 한 페이지로 모아주면 좋을 것 같아"*

당근비즈니스 '업체 정보' 화면(좌 편집 / 우 미리보기 / 하단 저장) 캡처를 함께 받았다.

## 실측 — 종전에 어디에 흩어져 있었나

| 화면 | 담고 있던 것 |
|---|---|
| `/seller/stores` → [정보] **모달** | 이름·주소·전화·좌표·확인 PIN·담당자 전화 |
| `/seller/mini-shop` (유어샵 설정) | 배너 이미지·브랜드 컬러 + **죽은 라이브 URL 3개** |
| `/seller/profile` (셀러 프로필) | 대표 이미지·소개글·SNS 4종·홈페이지·카톡 채널 |

그리고 같은 모달이 **두 화면**에서 열리고 있었다(`/seller/stores` + 셀러 홈 `MyStoresPanel`).
`external_live_*` 세 칸은 **저장되고 API 로 내려가는데 렌더하는 곳이 0** 이었다(라이브커머스 영구
중단 이후 죽은 칸) — UI 에서만 걷어냈고 컬럼·`repair-schema` 는 그대로 뒀다.

## 지금 — `/seller/store` 한 장

- **왼쪽** 기본 정보 / 소개 / 홈페이지·SNS / 운영 정보(비공개)
- **오른쪽** 손님에게 보이는 모습 미리보기 — **타이핑을 따라온다**(서버를 다시 안 부른다)
- **하단** 저장(PC 는 우측 열 sticky, 폰은 `SellerBottomBar`) — 바뀐 게 있을 때만 활성

저장은 **두 저장소로 나간다**(매장 PATCH + 유어샵 PUT). 한쪽만 실패하면 그쪽만 말하고 그쪽
값만 '안 저장됨' 으로 남긴다 — 뭉치면 이미 저장된 절반까지 다시 입력하게 된다.

## 다음 세션의 첫 액션

```bash
# 배포 후 — 옛 주소가 새 페이지로 가는지 (북마크·가이드에 퍼져 있다)
curl -s -o /dev/null -w '%{http_code}\n' https://urdeal.kr/seller/mini-shop   # SPA 라 200, 화면에서 /seller/store 로 이동
```
화면 판정: `/seller/store` 에서 매장 이름을 고치면 **오른쪽 카드가 즉시 바뀌고**, 저장 버튼이
`저장 (이용권 N개 반영)` 으로 바뀌는지. 소개글만 고치면 그 문구가 **안 떠야** 한다.

## 이번에 틀렸던 판단

1. `storeFieldsDirty()` 를 **항상 `true` 를 돌려주는 자리표시자**로 넣고 넘어갈 뻔했다. 그러면
   소개글만 고쳐도 "이용권 N개 반영" 이라고 거짓말한다 — 훅에서 `STORE_KEYS` 로 실제 계산하게 고쳤다.
2. `/seller/profile` 에서 업체 칸을 들어내고 나니 **하단 [저장] 이 화면에 없는 폼을 저장**하고 있었다
   (기본 탭이 `'business'`). 그 버튼과 죽은 핸들러 둘을 제거. ⚠️ `handleSaveBusiness`/`Personal`/
   `ChangePassword` 는 **입력칸이 없는 채로 예전부터 남아 있던** 죽은 핸들러다 — 이번 범위 밖이라 남겼다.
3. 주입이 내 시험 둘을 헛돈다고 잡았다: `failed.store` 를 파일 전체에서 찾아 타입 선언 때문에 늘
   통과했고, 미리보기의 `api.` 검사는 **import 줄**(`from '@/lib/api'`)을 못 봤다.
4. 스크린샷 하네스는 포기했다 — 정적 서버 위에서 **기존 페이지도 똑같이** ErrorBoundary 로 떨어진다
   (환경 문제). 대신 jsdom 렌더 시험 6건으로 바꿨는데 그게 더 값지다(영구 가드가 된다).

## 함께 갚은 부채 — `seller-registration.routes.ts` 764 → 534 + 261

CLAUDE.md 의 god 파일 룰(600줄)을 이 세션이 두 번 넘겼다(앞문 등록증으로 758→764).
**가입**(`/register`, `/register-from-user`)과 **세션 전환**(`/my-seller-status`,
`/switch-to-seller`, `/switch-to-user`)은 같은 파일에 있을 이유가 없다 — 앞은 행을 만들고
뒤는 이미 있는 행으로 *누구로서 들어갈지* 를 정한다. 뒤 셋을
`seller-registration/session-routes.ts` 로 옮겼다(**이동만** — 경로·본문·순서 불변).

⚠️ `ensureSellerColumns` 는 **주입**한다. 옮긴 파일이 자기 메모를 새로 만들면 그 보장이
두 벌이 되어 요청마다 `ALTER TABLE` 이 도는 날이 온다(머니 룰의 per-request DDL).
⚠️ 동적 import 의 상대 깊이가 한 단 깊어졌다(`../../../../worker/utils/session`).
   **alias 로 바꾸면 안 된다** — 워커에서 `await import('@/…')` 는 런타임 크래시다.

### 🩸 이 분해가 드러낸 것 — `not.toContain` 은 코드가 옮겨가면 **조용히 항상 통과**한다

가드 둘이 옛 파일을 가리켜 빨간불이 났는데, **셋째 하나는 초록이었다**:
`switch-to-seller` 본문 슬라이스가 `''` 가 되자 `not.toContain("'PENDING'")` 이 무조건 통과했다.
⇒ 슬라이스 길이를 먼저 단언하는 `switchToSellerBody()` 로 바꿨다.
**부정 판정(`not.*`)을 쓰는 시험은 "무엇을 봤는지" 를 먼저 증명해야 한다.**
