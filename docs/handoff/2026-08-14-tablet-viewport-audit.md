# 태블릿 이중 헤더 · 화면 비율 전수조사 (2026-08-14)

대표가 태블릿 가로 스크린샷을 보냈다 — **`urdeal.` 로고가 두 개**, 지도 버튼과 상단바 버튼이 겹침.
*"지금 이 화면 비율이나 고정되는데에 문제가 있어 전수조사 해줘."*

로컬 dev 서버(vite)를 띄우고 **Playwright 로 실제 픽셀을 재서** 판정했다. 추측 없음.

## 결함 2건 — 둘 다 같은 원인, 다른 증상

원인 한 줄: **홈은 `lg`(1024) 미만에서 `RestaurantMapPage` 를 렌더한다**(`HomeRoute`).
즉 `/` 와 `/map` 은 태블릿·모바일에서 **같은 화면**이다. 그런데 그 사실이 **두 곳에 손으로** 적혀
있었고, **둘 다 `/map` 만 넣고 `/` 를 빠뜨렸다.**

| # | 빠진 곳 | 실측 증상 | 누가 봤나 |
|---|---|---|---|
| ① | `DesktopTopNav.LEGACY_OWN_HEADER` | 768~1023 에서 상단바 2개 | 대표 스크린샷 |
| ② | `App.tsx mapFullScreen` | **390 포함 전 폭**에서 문서가 뷰포트보다 56px 큼 | 아무도 — 조용했다 |

### ① 이중 헤더 (768~1023)

`DesktopTopNav` 는 **`md`(768)** 부터 뜨는데 홈은 **`lg`(1024)** 에서만 `PcHomePage` 로 바뀐다.
그 사이 256px 구간에서 [전역 네비(로고+탭)] + [지도 페이지 자체 헤더(로고)] 가 둘 다 렌더된다.
되돌려-검증(고친 줄만 되돌리고 재측정):

```
고침 O   768~1023   bars=0            logos=3(한 헤더의 중첩 매치)
고침 X   768~1023   bars=1 top=0 h=102 desktop-topnav …   logos=4 @18,114,124,126
                    ↑ 전역 네비          ↑ 지도 헤더 로고가 114px 아래에 또
```

버튼 좌표로도 같은 이야기가 나온다(900px, 고침 전): 네비 탭 `홈/교환권/동네딜/링크샵/블로그` 가 y=63,
지도 헤더 버튼이 y=114. 네비가 102px 를 차지하는데 지도 루트는 `h-[100dvh]` 라 문서가 102px 넘치고,
**그 102px 를 스크롤하면 sticky 네비가 지도 상단을 덮는다** — 대표가 본 겹침이 이것이다.

`lg+` 는 이미 `lg:h-[calc(100dvh-102px)]` 로 네비 높이를 빼고 있었다. **`lg+` 만 고려한 흔적**이고,
`/map` 은 목록에 있어 보호됐고 홈만 새어 나갔다.

### ② 홈만 56px 넘침 (모든 폭)

`App.tsx` 의 `mapFullScreen` 은 `<main>` 의 하단 네비 여백(`pb-3.5rem` = 56px)을 뺄지 정하는데,
`/map` · `/restaurant-map` 만 있고 `/` 가 없었다. 지도 루트는 이미 자기 `pb-16` 을 갖고 있어 **이중 계상**:

```
고침 X   / @390·768·900·1023   문서 756 / 뷰포트 700  넘침=56px
         /map @390·900         문서 700 / 뷰포트 700  넘침=0      ← 같은 컴포넌트인데 다르다
고침 O   / 전부                문서 700 / 뷰포트 700  넘침=0
```

**모바일 홈이 전부 해당된다** — 바텀시트가 56px 밀리고 그만큼 화면이 흔들린다. 에러가 없어서
아무도 신고하지 않았고, 대표 스크린샷이 없었으면 계속 조용했을 것이다.

🧭 그 줄의 주석이 **`홈(/)=리스트는 일반 페이지(여백 필요)`** 였다. 2026-06-20 에는 참이었고
그 뒤 홈이 지도로 바뀌었다. **낡은 주석이 다음 사람을 반대로 이끈 전형** — 이 레포가 반복해 만나는 형태다.

### ③ `/search` — 페이지 검색바가 전역 네비를 **덮음** (md+, 스크롤 후)

전수조사에서 추가로 나왔다(대표가 본 화면과는 다른 페이지). `SearchHeader` 가 `sticky top-0 z-50` 인데
전역 네비는 `sticky top-0 z-40` → **158px 만 스크롤해도** 검색바가 네비 위에 올라앉고 네비 아래
**37px 짜리 반쪽 바**만 남는다. 3회 재현:

```
고침 X   scrollY=158   [네비] 0~102 z=40   [페이지] 0~65 z=50   ← 겹침
고침 O   scrollY=158   [네비] 0~102 z=40   [페이지] 102~167     ← 아래에 쌓임
모바일   @390          네비 없음            [페이지] top=0       ← 불변
```

**수리**: `md:top-[102px]`. 형제 22곳이 `md:top-14`(=56, 네비 57px 경로)로 쓰는 **기존 규약**인데
`/search` 는 풀너비 경로라 네비가 [로고행+카테고리행]=102px 라 값만 다르다.
⚠️ **남은 빚**: 이 `102` 가 이제 두 곳에 손으로 있다(`RestaurantMapPage` 의 `lg:h-[calc(100dvh-102px)]`).
네비가 자기 높이를 CSS 변수로 발행하고 페이지가 그걸 읽는 게 옳다 — 지금 고칠 범위는 아니라 남긴다.

## 수리 — 목록을 하나로 합쳤다

`src/shared/map-surface.ts`(신규) 의 `MAP_SCREEN_PATHS` 하나를 두 소비자가 함께 쓴다.
결함의 형태가 *"같은 질문에 답하는 손글씨 목록이 두 벌"* 이므로, 한 벌로 만들지 않으면 또 갈라진다.

- `DesktopTopNav`: `LEGACY_OWN_HEADER = [...MAP_SCREEN_PATHS, '/vouchers', '/stays', '/group-buy']`
- `App.tsx`: `mapFullScreen = isMapScreenPath(pathname)`
- `pc-fullbleed.ts` 의 *"홈은 자체 헤더 없음"* 주석에 **"`lg+` 에서만 참"** 을 명시(같은 오독 재발 차단)

⚠️ `lg+` 회귀 없음 실측: `/` @1024·1280 → `PcHomePage` 정상 스크롤(문서 2040), 네비 102, 하단바 숨김.

## 이번에 틀렸던 판단 (반복 방지 — 셋 다 "측정을 잘못 읽음")

1. **grep 개수를 증상으로 착각할 뻔했다.** `sticky top-0` 을 가진 페이지가 70곳이라 *"70곳이 같은 병"*
   으로 적을 뻔했다. 실제로 재 보니 대부분 안 겹친다(자기 헤더뿐이거나 `md:top-14` 로 이미 쌓임).
   확정 결함은 **3건**이다. 이 레포의 반복 교훈("집계만 보고 기전을 추측하면 틀린다")과 같은 함정.
2. **"겹침 없음"이 사실은 "아무것도 못 찾음"이었다.** 첫 스윕이 `/wishlist`·`/my-vouchers` 등에
   ✅ 를 줬는데, 바(bar)를 **하나도** 못 찾은 채 준 초록이었다 — 이 레포가 경고하는 *헛도는 검사* 그 자체다.
   판정에 **"전역 네비가 실제로 있을 것"** 을 전제로 넣고 나서야 그 행들이 `⬜ 판정 불가`로 바뀌었다.
3. **그 `⬜` 를 "로그인 리다이렉트"로 오진했다.** 진짜 원인은 **dev 서버 청크 오류 자가복구**였다
   (URL 에 `__cb=` 가 붙어 있었는데 처음엔 안 봤다). vite 를 `--force` 로 재시작하니 정상 측정됐다.
   ⇒ **측정 환경이 고장 났을 가능성을 먼저 배제할 것.** 안 그러면 도구의 병을 코드의 병으로 적게 된다.

⚠️ 그래서 **로그인이 필요한 소비자 페이지(`/wishlist`·`/my-vouchers`·`/user/profile`·`/my-orders`)는
이 세션에서 결국 측정하지 못했다.** "문제 없음"이 아니라 **미측정**이다 — 다음 세션이 로그인 세션을
붙여 같은 프로브를 돌리면 된다.
