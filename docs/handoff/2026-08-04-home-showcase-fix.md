# 인계 — 홈 쇼케이스 라이브 수리 (2026-08-04)

대표가 라이브 홈 스크린샷과 함께 **"이렇게 뜨는게 정상이야?"** → **"너가 줬던 시안이랑 완전 다르잖아"**.
둘 다 맞는 지적이었고 **내 설계 실수 두 개**다.

## 무엇이 잘못됐나

### ① 옛 배너가 저절로 홈에 나타났다 (대표 확정 규칙 위반)
`banner_type` 을 **`DEFAULT 'inline'`** 로 ALTER 했는데, **SQLite 는 ADD COLUMN 의 기본값을
기존 행에도 적용**한다. 그래서 예전에 다른 용도로 올려둔 배너(id 1 "UR-Live 메인 배너")가
**중간 배너 자리에 저절로 떴다.** 대표가 못박은 *"안 올리면 아예 안 보이게"* 를 정확히 어긴 것.
게다가 가로로 긴 홍보 이미지가 **3열 그리드의 1/3 폭**에 홀로 들어가 잘렸다.

**수리**: `banner_slot` 새 컬럼(**DEFAULT 없음** → 기존 행 전부 NULL) + 조회는 **엄격 일치**
(`AND banner_slot = ?`, COALESCE 금지). 어드민에 **'홈에 노출 안 함'** 칩 추가(첫 번째 = 정상 상태).
⇒ **데이터 수정이 필요 없다** — 기존 배너는 NULL 이라 자동으로 안 뜬다.
⚠️ 옛 `banner_type` 컬럼은 프로덕션에 남아 있지만 **아무도 읽지 않는다**(무해).

### ② 시안과 다른 진짜 이유: 섹션이 하나도 없었다
#1046 은 섹션 **기능**만 넣고 섹션을 만들지 않았다. 어드민이 손으로 만들어야만 보이니
라이브 홈은 *"틀만 있고 안이 빈"* 화면이었다. 내가 대표에게 **"홈이 지금과 똑같아야 정상"**
이라고 말한 것 자체가 틀린 안내였다(시안은 내용이 채워진 그림이다).

**수리**: `section-seed.ts` — 승인 시안의 세 줄(지금 인기 이용권 / 오늘 마감 임박 /
주말에 떠나는 숙소)을 **규칙 섹션으로 시드**. 상품이 저절로 채워져 손볼 필요가 없다.
블로그·가이드 시드와 같은 철학: **제목이 같으면 건너뛰고, 지운 것은 되살리지 않는다.**

## 다음 세션의 첫 액션

배포 후 라이브 실측(명령 그대로):
```
curl -sS -A "Mozilla/5.0" "https://urdeal.kr/api/banners?type=inline"   # → data: []  (옛 배너 사라져야 정상)
curl -sS -A "Mozilla/5.0" "https://urdeal.kr/api/sections" | head -c 300  # → 세 줄 시드가 상품과 함께
```
그리고 PC 홈을 눈으로: **섹션 3줄 + 더보기**가 뜨고, 중간 배너 자리는 **비어 있어야** 한다.

## ⚠️ 이번에 배운 것 (다음 세션이 같은 함정에 안 빠지게)

1. **SQLite `ALTER TABLE ADD COLUMN ... DEFAULT x` 는 기존 행에도 x 를 채운다.**
   "새 컬럼이니까 기존 행은 NULL" 이 아니다. 기본값을 주는 순간 **과거 데이터가 새 기능에
   자동 편입**된다. 자리·노출·활성 같은 **의미 있는 상태**에는 DEFAULT 를 주지 말 것.
2. **"기능을 넣었다"와 "화면이 시안대로 보인다"는 다른 일이다.** 컨테이너만 만들고 콘텐츠를
   안 넣으면 대표 눈에는 아무것도 안 한 것과 같다. 시드가 필요한지 항상 같이 판단할 것.
3. **가드가 또 헛돌았다** — "시드가 홈 조회에서 실행된다" 테스트가 **어드민 목록의 같은 호출**에
   매칭돼, 홈 경로에서 빼도 초록이었다. 공개 GET 블록 **범위를 잘라서** 확인하도록 고쳤다.
   (직전 세션의 "플래그가 파일 어딘가에 있다" 와 **완전히 같은 클래스**다 — 세 번째다.)
