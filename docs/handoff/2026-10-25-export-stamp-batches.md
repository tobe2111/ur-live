# 📥 내보낸 리드에 도장 — "받은 건 다시 안 준다" (2026-10-25)

> 대표: *"인플루언서 DB 페이지나, 업체 DB 페이지나, 엑셀파일로 다운로드 받으면 받았다고 필터링이
> 될 수 있나? 이후에 수집한 DB인지 구별이 안가잖아."*
> 확정: **500행씩 · 기본 제외(안 받은 것만)** — `AskUserQuestion` 두 문항.

## 1. 답: 지금은 안 됐다. 그리고 문제가 셋이었다 (라이브 실측)

```
               전체      연락 가능          한 파일      받을 방법이 없던 분량
 인플루언서  445,026   이메일 83,677       60,000      23,677 (28%)
 업체        491,162   이메일 63,504        2,000      61,504 (97%)
 매장후보    360,999   전화  256,997        2,000     254,997 (99%)
```

1. **다운로드가 아무 표시를 안 남긴다.** 표시할 자리(`contacted_at`)는 이미 있었지만 **손으로**
   눌러야 했고 — 130만 행 중 **5번** 눌렸다(인플 3 · 업체 2 · 매장 0). 사실상 안 쓰이는 기능.
2. 정렬이 점수순 고정이라 **다시 받으면 같은 상위 N행**. 아래쪽은 구조적으로 도달 불가.
3. **잘렸다고 말하지 않았다** — 인플루언서는 고지 코드가 **아예 없고**, 업체는 고지 조건이
   `rows.length >= 5000` 인데 `listCompanyLeads` 가 **2,000** 으로 클램프해 **한 번도 안 떴다**(무음 캡).

## 2. 🩸 "지난 다운로드 이후 수집분만" 으로는 못 푼다 — 설계를 가른 측정

이메일 보유 인플루언서 85,214명의 **수집 ↔ 측정** 간격:

```
same_day 45,263 (53%)   d1_7 871   **d7_plus 38,897 (46%)**   unmeasured 191
```

**46%가 수집 7일 이상 뒤에** 측정돼 그때 이메일이 나왔다(CLAUDE.md: *"측정이 이메일을 만든다(17배)"*).
몇 달 전 수집된 행이 오늘 연락 가능해지는 구조라, `collected_at > 지난 다운로드` 로 거르면
**새로 쓸 수 있게 된 리드의 절반을 영영 못 본다.** ⇒ 기준은 수집 시점이 아니라
**행마다 "내가 받았는가"**(`exported_at`) 여야 한다.

## 3. 무엇을 만들었나

SSOT: **`src/features/marketing/api/pool-export-batch.ts`**(머리말에 설계 근거 전부).

- `exported_at` 컬럼 + 인덱스를 세 표에 보강(`runDdlOnce`, isolate 당 풀마다 1회 메모)
- **도장 시각 그 자체가 배치 id** — 별도 표를 만들지 않았다. `adsLeadsDb` 는 **SQL 텍스트로 DB를
  고르는 라우터**라(인플·매장 → leads DB, 업체 → company DB) 새 표는 **main 으로 간다**.
  `GROUP BY exported_at` 이 이력이고 취소는 `SET exported_at = NULL WHERE exported_at = ?` **한 줄**.
- `runBatchExport` — 업체·매장 CSV 공용(목록 → 도장 → **도장 뒤에** 남은 건수 → 안내)
- 되돌리기: `GET/POST /api/admin/pool-export-batches` + 화면 `PoolExportBatches.tsx`
- 버튼: `[다음 500건] [전부 다시] [내보낸 묶음]` — 업체·매장은 공용 `PoolExportButtons.tsx`

**기본값**: 작업 목록(인플루언서 `contactable` · 업체·매장 CSV)은 **묶음 + 도장**.
**풀 사본**(인플루언서 "엑셀 다운로드 (전체)"·매체별, `newOnly=0`)은 **종전 동작 · 도장 0** —
사본 한 번이 전 리드를 소진시키면 안 된다(주입이 양방향 고정).

## 6. ⚠️ 못 하는 것 / 설계상 대가

- **도장은 행을 모은 직후 찍힌다** — 전송이 끊기면 "찍혔는데 파일은 없는" 상태가 된다.
  서버가 전송 완료를 알 방법이 없다(브라우저가 받는다) ⇒ **배치 취소가 그 복구 경로**다.
- **어떤 필터로 받았는지는 기록되지 않는다**(행수와 시각만). 필요해지면 표를 만들고 라우터에 등록할 것.
- 같은 초에 두 번 받으면 **한 배치로 합쳐진다**(취소도 함께).
- 쓰기 비용: 묶음 500 = 500 rows_written(무시 가능). **전체 덤프는 도장 0.**

curl -sS "https://live.ur-team.com/api/admin/partner-pool/export?format=csv&hasEmail=1" -H "Authorization: Bearer $TOK" -H "User-Agent: $UA" > /tmp/b.csv
# 기대: 각 ≤501행 + 마지막 줄에 '내보냄 표시 · 남은 N건', 두 파일의 상호 교집합 **0**
# ② 반대 방향 — 전체 덤프는 도장을 안 찍는다
curl -sS ".../partner-pool/export?format=csv&newOnly=0&hasEmail=1" ... | wc -l   # 기대 2,000 대 + 절단 고지
curl -sS ".../pool-export-batches?pool=company" ...                              # 기대: 배치가 ①의 2건만
# ③ 되돌리기 — 배치 하나 취소 후 ①을 다시 받으면 그 행들이 **돌아온다**
