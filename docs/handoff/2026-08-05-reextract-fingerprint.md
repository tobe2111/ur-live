# 2026-08-05 — 유튜브 발굴 계측 영구화 + 그걸 막던 가드를 **더 좁은 가드로 교체**

대표: *"유튭 발굴 계측도 영구적으로 하면 안돼?"*

## 1. 무엇이 막고 있었나 — 가드가 "파일이 바뀌었나"만 봤다

유튜브 발굴 계측(`DiscoverCalls.videos_email/contact/cat/empty`)은 `influencer-discovery.ts` 의
발굴 루프에 들어간다. 그런데 그 파일은 `check-rules-version-bump` 의 감시 대상이고, 그 가드는
**주석 뺀 파일 전체**를 비교한다 — 즉 **계측 카운터 한 줄에도 bump 를 요구**한다.

그리고 bump 는 공짜가 아니다:
```
올리면   → 36,880행 재추출이 처음부터 다시 돈다(진행 중이던 패스는 버려진다). CPU 가 지금 가장 희소하다.
안 올리면 → 개선된 추출기가 기존 행에 영원히 안 닿는다(이 상수엔 시간 폴백이 없다).
```
그래서 선택지가 **둘 다 나빴다**: 헛도는 재추출로 CPU 를 태우거나, `rules-version-ok` 로 고위험 가드를
**영구히** 침묵시키거나. 어제는 그래서 계측을 stash 로 빼 두고 판단을 미뤘다.

## 2. 셋째 길 — 판정을 좁힌다 (면제가 아니라 **교체**)

`src/tests/unit/reextract-rules-fingerprint.test.ts` 신설. **추출 결과를 실제로 바꾸는 것만** 해싱한다:

| 대상 | 방식 | 왜 |
|---|---|---|
| `influencer-email-rules.ts` · `contact-deobfuscate.ts` | **파일 통째로** | 규칙 전용 모듈 — 골라 담으면 빠뜨린다 |
| `influencer-discovery.ts` · `-parse.ts` | 정규식 상수 + 추출 함수 본문 + 호출 헬퍼 | 계측·로깅과 규칙이 한 파일에 섞여 있다 |

결과: **계측은 안 걸리고, 정규식 한 글자만 바뀌어도 걸린다.** 실패 메시지가 새 지문을 찍어 주고
"버전 +1 과 지문 교체를 **함께** 하라"고 지시한다.

## 3. 🩸 이 지문은 **두 번 헛돌았다** — 되돌려-검증이 잡았다

문서에 적을 가치가 있는 건 이쪽이다. 두 번 다 "만들었으니 됐다"로 끝냈으면 **가드가 있는데 아무것도
안 지키는** 상태로 배포됐을 것이다.

1. **이름으로 골랐다.** 처음엔 `_RE`/`_REGEX` 로 끝나는 상수만 지문에 넣었다. `NOT_EMAIL_SUFFIX` 는
   그 규칙에서 빠져 있었고, **그 정규식을 바꿔도 초록**이었다.
   ⇒ 이름은 사람이 짓는 것이라 규칙이 될 수 없다. **값의 모양**(`= /` 로 시작)으로 고르게 바꿨다.
2. **선언 형태를 가정했다.** `stripVideoTitles` 는 `function` 이 아니라 **여러 줄 화살표 상수**이고
   정규식이 **둘째 줄**에 있다. `fnBody` 는 못 찾았고 한 줄 캡처는 규칙을 놓쳤다.
   ⇒ **블록**으로 집게 바꿨다.

되돌려-검증 3종(전부 확인):
```
① NOT_EMAIL_SUFFIX 정규식 변경        → 빨강 ✅
② stripVideoTitles 정규식 변경(둘째 줄) → 빨강 ✅
③ 발굴 루프 계측 한 줄 추가             → 초록 ✅ (이게 이 교체의 목적이다)
```
`check-guard-mutations` 에 ①을 등록(217번째) — CI 가 앞으로 대신 깨뜨린다.

## 4. ⚠️ 이 지문이 **못** 보는 것

- **목록 밖 헬퍼.** 추출 경로에 새 헬퍼를 끼우고 지문 목록에 안 넣으면 아무도 안 잡는다.
  → 지문 파일의 `fingerprint()` 목록에 추가할 것. (이 한계는 그 파일 헤더에도 적혀 있다.)
- **지문만 갱신하고 버전을 안 올리는 것** — 이 시험을 무의미하게 만드는 유일한 방법이다.
  기계로는 못 막는다(둘 다 사람이 고치는 값이다). 실패 메시지가 둘을 함께 하라고 말하는 게 전부다.

## 5. 계측 자체 — 무엇을 재는가

```
yt_calls { search 3 · channels 3 · videos 24 }   ← 유튜브 30개 중 80%가 채널별 영상 스니펫
picks    planned 16 → processed 6                ← 예산 51/56 소진으로 10개 키워드 미처리
```
유튜브 쿼터는 **90 중 24**만 쓴다 — 병목은 구글이 아니라 서브리퀘스트다. 그 24개를 줄이면
키워드 처리량이 바로 오르는데, **그 24개가 뭘 벌어오는지는 아무도 안 셌다.** 찍어서 줄이면 수율이
같이 떨어지므로(그 파일 주석이 경고하는 그대로) 먼저 센다:
`videos_email`(없던 이메일) · `videos_contact`(인스타/틱톡/링크) · `videos_cat`(분류 신호) ·
**`videos_empty`(아무것도 못 벌어옴 — 이 비율이 곧 잘라도 되는 몫)**.

## 6. 다음 세션 첫 액션

   ```sql
   SELECT json_extract(value,'$.yt_calls') FROM platform_settings WHERE key='ads_autocollect_stats';
   ```

   - **낮으면** 이 24개는 값을 하고 있다 — 건드리지 말고 다른 레버를 찾는다.
2. 판단 전에 **한 회차만 보고 정하지 말 것.** 오늘 스냅샷 하나로 세 번 틀렸다.
