## 이번에 틀렸던 판단 (제일 값진 부분)

### ① 시안의 "리뷰 0건이면 섹션을 안 그림" 을 그대로 했으면 사고였다

`ProductReviews` 는 0건일 때도 **작성 진입**을 그리고, 대안 경로(주문 상세)는 **배송완료 조건**이라
배송이 없는 이용권·숙소엔 열리지 않는다. 숨겼으면 리뷰가 영원히 0 이 됐을 것이다.
⇒ 탭에서만 빼고 섹션은 남겼다. 만실도 같은 이유로 목록을 대체하지 않고 카드를 위에 얹었다.

**교훈: 시안이 "숨기자" 고 말할 때 그 안에 무엇이 함께 사라지는지 먼저 재라.**

### ② 내가 쓴 가드 4개가 헛돌았다

주입이 잡았다. 원인이 각각 달랐다:

| 헛돈 이유 |
|---|
| 조건부로 감싸도 `<ProductReviews` **문자열은 남는다** |
| 호출을 지워도 **import 줄에 이름이 남아** 카운트가 유지된다 (`checkPerPersonLimit`) |
| 같은 이유 — `resolveQtyCap` 도 import 줄에 있다 |
| 재수출 상수는 **구조적으로 갈릴 수 없어** "같은 수인가" 검사가 항상 참이다 |

넷 다 **모양이 아니라 동작**(실제 호출·실제 대입·재수출 여부)을 앵커로 바꿔 빨간불 확인.

### ③ pre-push 게이트는 **유닛 테스트를 안 돈다** (오늘 그 사각지대에 빠졌다)

오늘 main 에 들어온 pre-push 게이트가 가드 94개를 13.8초에 통과시켰는데 **CI 는 빨간불**이었다 —
게이트는 `verify.yml` 의 **strict 가드**만 돌고 `npx vitest run`(8,487건 · 348초)은 안 돈다.
실패 3건은 전부 **내가 코드를 옮겨 기존 가드가 옛 자리를 가리키게 된 것**이었다:

| 가드 | 옛 자리 | 새 자리 |
|---|---|---|
| `voucher-howto-2026-09-04` | 상세에 `<RedeemHowTo />` | 상세 → `UsageGuide` → `RedeemHowTo` **두 단계 사슬** |
| `seller-voucher-limit` | `/join` 에 보유분 쿼리 2벌 | 헬퍼에 1벌 + **호출 2곳** |
| `stay-detail-pc-booking-panel` | `<div className="mb-5 lg:hidden">` | `id="stay-sec-rooms"` 가 앞에 붙음 |

셋 다 **지우지 않고 재조준**했고(성질은 그대로 유효하다), 손으로 깨뜨려 빨간불을 확인했다.

⇒ **다음 세션 교훈: 파일을 옮기거나 추출했으면 push 전에 `npx vitest run` 을 한 번 돌려라.**
게이트 초록은 "가드가 통과했다" 이지 "테스트가 통과했다" 가 아니다.

### ④ `--only` 는 파일명이 아니라 **주입 이름** 부분일치다

처음에 `--only "2026-09-14"`(파일명)로 불러 0건이 걸렸다. 러너가 "0건이면 실패" 를 선언해 둬서
잡혔다 — 안 그랬으면 0건을 돌고 "전부 확인" 을 찍을 뻔했다. 이름에 `[상세0914]` 태그를 넣었다.

### ⑤ 파일크기 래칫에 "딱 맞추기" 를 또 할 뻔했다

`group-buy-public.routes.ts` 가 baseline 에 붙어 있어 주석을 깎아 1~3줄을 맞추려 했다. 그러지 말고
**분리**했다(규칙이 말하는 처방). 결과가 더 낫다 — meta 파생 8종이 `detail-meta-enrich.ts` 로 모였고
1157 → **1135**(19줄 여유). `/join` 도 중복 블록을 헬퍼로 합쳐 1444 → **1427**.
