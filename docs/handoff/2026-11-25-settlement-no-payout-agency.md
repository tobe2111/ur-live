# 2026-11-25 정산 재구성 — 지급대행 없이 최대 자동화

대표: *"알고보니 지급대행 필수가 아니었어. 다른 세션에서 확인했고, 이거에 맞게 다시 구성해줘. 최대한 자동화하자 지급대행 안쓰는 선에서. 이후에 도입을 하더라도"*
결재: `docs/decisions/2026-11-03-settlement-structure.md` (11-25 갱신 절)

## 1. 이 작업을 이어서 하라고 했을 때의 첫 액션
- 대표가 자동 승인 상한을 정하면: 어드민 `/admin/platform-settings` 머니 스위치 `payout_auto_approve_max_krw` 에 그 값(대표가 직접 — 게이트 ON 은 결재 C).
  판정: 다음 월요일 09:45 KST `payouts-generate` 하트비트/알림에 `자동 승인 N건(…원 이하)` 이 찍히는지.
- 첫 월 마감 요약: **2026-12-01 04:00 KST**. 판정 `SELECT month FROM monthly_close_reports` 에 `2026-11` 1행 + 어드민 알림 `monthly_close_report` 1건.

## 2. 완료분
- `worker/utils/payout-approve.ts` — 단건 승인 가드 SSOT(`approvePayoutGuarded`) + 소액 자동 승인(`autoApproveSmallPayouts`, 기본 0 = 꺼짐). 단건 승인 라우트가 이 함수를 부른다.
- `payouts-generate` 생성 직후 자동 승인 + 알림에 "승인 대기 N건 · 이체할 건 M건(합계)".
- `worker/utils/monthly-accounting.ts` — 세무사용 월 회계 집계를 라우트에서 꺼냄(식 불변) + 매월 1일 마감 요약(원천세 기한·안 보낸 정산 경고, UNIQUE(month)).
- 어드민 `/admin/payouts` 연말 리포트 탭에 **월 회계 마감 CSV** 카드(`?tab=annual` 로 바로 열림).
- 문구: 셀러 가이드의 "12월부터 지급대행 송금" 예고 삭제, 어드민 가이드에 자동 승인·월 마감 추가(GUIDE_SEED_VERSION 79), 사업계획서·플랫폼 모델·STAGING·OPS_GATES·머니 스위치 힌트 = "지급대행은 선택".
- 토스 지급대행 코드(`toss-payouts.ts`)는 그대로 꺼진 채 둔다 — 나중 도입용.
- 가드 `settlement-automation-2026-11-25.test.ts`(13건) + 주입 3건 빨간불 확인. 옛 가드 3개는 로직이 옮겨진 자리로 재조준(완화 아님).

## 3. 이번에 틀렸던 판단
- 11-03 에 "12월 17일 전에 지급대행 필수" 로 결론냈다 → 대표가 다른 세션에서 의무 아님을 확인. 그 근거 문서는 이 레포에 없다(대표 확인 문장만 기록).
- 매장 정산 달력은 문구상 "매주 목요일" 이지만 실제 지급 대상 생성은 **월요일 09:45 + 사용 후 14일 보류**다(다른 세션 11-25 실측, 결재 `2026-11-25-store-payout-thursday-vs-hold.md`). 자동 승인은 그 월요일 생성에 붙였다.

## 4. 남은 결정/대기
- 자동 승인 상한 금액(대표)
- 소개비·중개사 몫을 유어딜이 대신 보내는 흐름의 법적 정리(지급대행이 의무가 아니면 우선순위 낮음 — 대표 판단)
- 수수료 세금계산서 방향(유어딜 → 매장) — 세무사 확인 후
- 인플루언서 현금 지급은 아직 사람이 이체(`/admin/influencer-payouts`) — 다음 자동화 후보: 같은 이체 파일로 묶기
