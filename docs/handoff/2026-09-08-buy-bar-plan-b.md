# 유어쇼츠 구매 바 — 대표 확정 "안 B + 기존 가격정보" (2026-09-08)

대표: *"구매바는 안 b 로 하지만 기존 가격정보도 넣으면 되잖아. 전체 보기 화면은 그대로 해줘."*

## 🩸 내가 틀렸고 대표가 맞았다 — 이 세션에서 제일 값진 것

시안을 내면서 **"안 B 에는 정가가 안 들어간다 — 글자 자리 220px 에 가격 줄이 228px 필요"** 라고
보고했고, 그래서 안 C(버튼을 아래로)를 추천했다. **머리로 계산했고 틀렸다.**
대표가 *"넣으면 되잖아"* 라고 해서 **브라우저로 실제로 재 보니**:

| 뷰포트 | 글자 자리 | 보통 | 숙소 6자리 | 최악(7자리·2자리%) |
|---|---|---|---|---|
| 430px | 267px | 139px | 162px | 175px |
| 390px | 227px | 139px | 162px | 175px |
| 360px | **197px** | 139px | 162px | **175px** |

가장 좁은 360px 에서도 **22px 남는다**(최악값 = `9,900,000원 99% 9,900,000원`).
내가 말한 220px 이라는 자리 폭 자체가 틀린 숫자였다.

⇒ **교훈: 폭이 문제라고 말하기 전에 재라.** 이 레포가 6자리 가격에서 이미 깨진 적이
있어서(2026-08-31 홈 카드) 경계한 것 자체는 맞았지만, **경계와 측정은 다른 일이다.**
추측으로 대표의 선택지를 하나 지울 뻔했다.

## 무엇이 바뀌었나

구매 바가 세 줄이 됐다 — **매장 / 상품명 / [정가 취소선 · 할인율 · 판매가]**.
상품명 줄의 존재 이유는 하나다: **무엇을 사는지 모른 채 누르게 하지 않는다.**

- 가격 줄은 `whitespace-nowrap` — 6~7자리에서도 줄이 안 깨진다(홈 카드가 2줄로 나눈 것과
  다른 선택이다. 여기는 **영상을 덜 가리는 게 우선**).
- 크기 위계: 판매가 15px 굵게 > 할인율 12.5px > 정가 11px 회색 취소선.
- 흰 바 위라 할인색은 **라이트 값 `text-sale`**. 레일 카드가 쓰는 다크 값(`#FF5C69`)을
  그대로 가져오면 흰 배경에서 옅어진다(가드가 이걸 고정한다).
- 버튼은 **오른쪽 그대로** — 안 C 로 바뀌지 않았다(안 C 는 영상을 20% 가린다).
- 할인이 없는 상품은 할인 줄 자체가 안 뜬다(실제 렌더로 확인).

## 🔑 정의를 두 벌로 만들지 않았다

구매 바가 할인율을 **따로 계산하면** 같은 상품이 홈 카드에서 30%, 구매 바에서 0% 로 보이는
날이 온다 — 에러가 안 나서 아무도 모른다. 이 레포는 정의가 갈려서 이미 당했다
(2026-09-03: 서버 정렬 정의 ≠ 클라 `discountOf` → "인기순"이 인기순이 아니었다).

⇒ 신규 SSOT **`src/shared/price-display.ts`**. 홈 딜 카드가 갖고 있던
`Math.max(선언값, 계산값)` 규칙을 **행동 그대로** 옮겼고(그 규칙이 생긴 이유는 2026-08-19
실사고 — 서버가 `discount_rate` 기본값 0 을 내려주면 `??` 가 그 0 을 채택해 계산식에 못 갔다),
**카드와 구매 바가 같은 함수를 쓴다.** 카드의 잠긴 계약(memo·prefetch·aboveFold·fade-in)은
전부 byte-불변 — 렌더 JSX 는 한 글자도 안 바뀌었다.

## 🕳️ 가드가 두 번 잡았다

1. **홈 청크 오염** — 새 import 가 `manualChunks` catch-all 로 떨어져 홈 폐쇄가 청크를 하나 더
   끌고 왔다. `home-chunk-diet` 가 즉시 빨간불. 형제 `deal-card-grid` 와 같은 자리에
   `app-shared` 규칙 추가로 해소(그 가드의 `OK_PARTS` 미러도 갱신했고, **미러 자기검증이 진짜
   발화하는지** vite 규칙을 잠깐 빼서 확인했다).
2. **내 가드 하나가 헛돌았다** — "상품명 줄이 있다"를 `/cur\.product_name/` 로 썼더니
   렌더를 `{false && cur.product_name && (` 로 꺼도 그 이름이 줄에 남아 **통과**했다.
   렌더 조건(`{cur.product_name && (`)을 앵커로 교체. **이 기능에서만 같은 함정을 두 번 밟았다**
   (앞서 `key={cur.video_id}` ↔ `data-key=`).

# 어드민 사용성 2건 — 대표가 실제로 넣어 보고 신고 (2026-09-08)

대표가 어드민에서 쇼츠를 **직접 한 편 넣어 보고** 두 가지를 물었다. 둘 다 맞는 지적이고,
둘 다 **에러가 안 나는 종류의 결함**이라 안 고치면 계속 불편하기만 하다.

## ① *"이용권 ID 입력 말고 다른 방법 없을까? ID 하나하나 다 모르는데."*

내 설계 실수였다. `<input type="number" placeholder="상품 ID">` 였는데 —
번호를 아는 사람은 아무도 없고, 더 나쁜 건 **틀린 번호를 넣어도 아무 에러가 안 난다**는 것이다
(존재하는 다른 상품이면 엉뚱한 이용권에 영상이 조용히 붙어 그대로 홈에 나간다).

⇒ `admin-urshorts/ProductPicker.tsx` — 이름·매장명으로 찾아 누른다.
**새 API 는 안 만들었다.** `GET /api/admin/products?q=` 가 이미 있고, 그 쿼리는 이름·설명뿐
아니라 **매장명(`restaurant_name`)까지 훑는다** — 2026-08-01 에 남긴 그 주석이 정확히 이 경우를
말한다(*"이용권은 상품명이 서로 비슷해서 매장명이 사실상 식별자다"*).

- 후보에 **사진·매장명·상품명·가격**을 함께 보여 준다(이름만으로는 "버섯 샤브 2인" 셋 중에 못 고른다).
- `status=active` 로만 찾는다 — 꺼진 상품에 붙이면 공개 쿼리(`p.is_active = 1`)가 걸러 **홈에 영영 안 나오는데** 화면은 "연결됨"으로 보인다.
- 타이핑마다 안 부른다(280ms). 어드민이라 트래픽은 작지만 **D1 읽기는 계정 단위 한도**다(2026-09-01 에 그 한도를 넘겨 소비자 API 가 통째로 멈춘 적이 있다).
- 숫자 입력 + 상태 pill **두 칸이 한 칸으로** 합쳐졌다. 안 고른 것이 빨갛게 남는 성질은 그대로.

## ② *"그리고 채널 정보, 영상 제목 이런거 자동으로 못가져오나?"*

**된다. 그리고 공짜다.** `videos.list` 는 **파트를 몇 개 붙이든 1 unit** 이라
`part=contentDetails` → `part=contentDetails,snippet` 으로 바꾸면 제목·채널이 그냥 따라온다
(`search` 는 100 unit 이고 그 쿼터는 유어애즈가 이미 다 쓴다 — 여기서 쓰면 안 된다).

원인은 따로 있었다: **`/shorts/` 주소는 유튜브 조회를 아예 건너뛰고 있었다.**
주소 자체가 쇼츠임을 증명하니 길이를 잴 필요가 없어서인데, 그 바람에 제목·채널도 안 받아
화면이 "채널 미상"이 됐다. 이제 쇼츠 형태도 메타를 받되 **fail-soft** 다 —
키가 없거나 조회가 실패해도 **저장은 그대로 된다**(오늘의 동작이 안 깨진다).
`watch?v=` 는 여전히 길이를 못 재면 **통과시키지 않는다**(쇼츠 판정은 불변).

- 사람이 적어 넣은 값이 **유튜브 값을 이긴다** — 다듬어 놓은 제목을 원제로 덮지 않는다.
- 이 기능 **이전에 넣은 영상**을 위해 `POST /api/admin/urshorts/:id/refresh-meta` + 행에
  "가져오기" 버튼(비어 있을 때만 보이고, 채워지면 사라진다).

🔑 **확인하고 지었다**: `YOUTUBE_API_KEY` 가 **이 워커(ur-live Pages)에 실제로 바인딩돼 있다**
(production env 67개 중 존재). `/api/version` 은 그 키를 검사 목록에 안 넣어서 `None` 으로
보이는데 **그건 "없다"가 아니다** — 그 응답만 보고 판단했으면 헛다리를 짚었을 것이다.
