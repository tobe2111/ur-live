# 2026-09-14 — 유어쇼츠: 위로 되돌아가는 스와이프 + 닫기 버튼 겹침

> 앞: `2026-09-13-comment-stripper-blind-spot.md` (PR #1421 머지 완료).
> 대표 신고(라이브 스크린샷 첨부): *"유어쇼츠 아래로는 넘겨지는데 위로는 다시 안됨. 추가로
> 좌측 위 x표시가 겹침."*

## ① 한 방향만 죽어 있었다 — 원인은 우리 계산이 아니었다

`go(d)` 는 `Math.min(len-1, Math.max(0, i + d))` 로 **완전히 대칭**이다. 그런데 한쪽만 안 됐다.

원인은 **브라우저가 그 손짓을 먼저 가져간 것**이다. 이 화면은 스크롤이 없으므로
(`overflow-hidden`) 화면 맨 위에서의 **아래로 끄는 손짓**이 인앱 브라우저의 당겨서-새로고침으로
잡힌다. 그 순간 브라우저는 `touchcancel` 을 쏘고 **`touchend` 는 오지 않는다** →
이전 영상으로 가는 `go(-1)` 이 영영 안 불린다. 위로 끄는 손짓엔 그런 네이티브 제스처가 없다.

🔑 **"코드가 대칭인데 동작이 비대칭"이면 코드 밖을 보라.** 여기선 브라우저의 기본 제스처였다.

**방어 셋** — 하나만으로는 기기·브라우저마다 샌다:
1. 제스처 층에 `touch-none` — 세로 팬을 브라우저가 안 가져간다(근본).
2. 루트에 `overscroll-none` — 그래도 새는 당겨서-새로고침을 막는다.
3. **판정을 `touchend` 가 아니라 `touchmove` 임계(60px)에서** — 뗄 때를 안 기다리므로,
   취소가 나도 이미 넘어가 있다. 1·2가 실패해도 동작이 남는다.
   (+ `swiped` ref 로 이동 판정과 뗄 때 판정이 겹쳐 **두 칸** 가는 것을 막고,
   `onTouchCancel` 에서 시작점을 지운다 — 안 지우면 다음 탭이 거대한 dy 로 읽힌다.)

## ② 닫기 X 가 유튜브 Shorts 로고와 **같은 자리**였다

스크린샷에서 로고의 'S' 가 우리 원에 가려 `horts` 로 보인다.
실측(980px 이미지 ÷ 2.5 = CSS): 로고 줄 y≈18~42 · x≈22~90, 우리 X 는 y 12~48 → 정면 충돌.

🔴 **덮어서 해결하면 안 된다.** `shared/urshorts.ts` 가 이미 적어 뒀다 —
*"남는 것(제목 띠·🔗·Shorts 로고)은 유튜브가 정하고, 덮는 것은 embed 약관 위반이다."*
상단 가로 띠는 통째로 유튜브 것이라(왼쪽 로고 · 오른쪽 음량/⋮) 좌우로 피할 자리가 없다
⇒ 우리 X 를 **아래로** 내린다: `top-3` → `top-14`(56px).

## 대표 질문 — "해당 이미지에 이용권 카드가 어떻게 보이는지"

**그 화면엔 이용권 카드가 없다.** 아래쪽 검은 띠는 **유튜브 것**이다
(`1분 @1분썰맛집` · 제목 · `공유` · 좋아요 1.6만). 우리 구매 바가 아니다.

의도한 동작이다 — 그 영상엔 이용권이 안 붙어 있고(`product_id` 없음), 코드가
`{cur && cur.product_id ? (...) : null}` 로 **바 전체를 안 그린다**(안 그러면 `/group-buy/null`
로 가는 버튼이 된다). 가드도 있다: `🎬 살 게 없는 영상에 구매 버튼이 뜬다`.

붙어 있었다면 이렇게 보인다 — 화면 아래 `inset-x-2.5 bottom-2.5` 에 **흰 라운드 카드**,
왼쪽 46px 썸네일, 가운데 세 줄(매장명 10.5px 회색 / 상품명 12.5px 세미볼드 /
정가 취소선 + 할인% + 판매가 15px 볼드), 오른쪽 파란 `구매` 버튼.

## 🔭 곁가지 — 라이브 화면을 찍는 도구 (`scripts/live-shot.mjs` + dispatch 워크플로)

어제 기록한 대로 **세션 컨테이너에서 브라우저가 막혀**(curl 200 ↔ Chromium 전 호스트 끊김)
지도 눈 검증을 통째로 대표께 넘겼다. CI 러너는 네트워크가 열려 있으므로 거기서 찍어
아티팩트로 받는다. `workflow_dispatch` 전용 · 공개 페이지 GET 만 · 항상 exit 0(판정기가 아니다).

⚠️ **아직 한 번도 안 돌려 봤다.** `workflow_dispatch` 는 워크플로가 **main 에 있어야** 띄울 수
있어서, 머지 전에는 시험할 방법이 없다. 머지 후 첫 dispatch 로 검증할 것:
`paths=/videos,/map · device=phone` → 아티팩트 `live-shot` 다운로드.

### 🩸 이번에도 낡은 지도가 하나 나왔다 (파일 스윕이 잡았다)
`🎬 스와이프가 다시 iframe 에 먹힌다` 의 `find` 가 `className="absolute inset-0 z-10"` 인데
내가 `touch-none` 을 붙여 앵커가 사라졌다. **이름(`--only`)이 아니라 파일로 쓸어서** 푸시 전에
잡혔다 — 어제는 같은 클래스를 CI 에서 맞았다.

### 🩸 그리고 기존 가드 3개를 재조준했다 (지우지 않았다)
`urshorts-viewer-chrome.test.ts` 가 클래스 문자열을 **통째로** 박아 둬서
(`"absolute inset-0 z-10"` · `absolute left-3 top-3 z-20`), 같은 층에 유틸을 **더하기만** 해도
빨간불이 났다. 지키려던 성질(층 존재·z 순서)은 그대로이므로 열린 집합으로 고쳤고,
버튼의 **세로 자리**는 새 describe 가 따로 지킨다.
