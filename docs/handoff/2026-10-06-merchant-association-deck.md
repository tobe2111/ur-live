# 상인회 서비스 소개서(입점 요청 포함) 신설 + 네 덱 실측 갱신 (2026-10-06)

> 대표: *"매장을 운영하는 상인회원들을 대상으로도 우리 서비스를 소개해야해. 소개서 만들어줘.
> 서비스 소개서야. **입점도 요청하면서**."*

**레일 선언**: 🎟️ **유어딜 소비자 이용권**(직접 입점 10% / 중개 5%). 도매몰·공구 서비스(운영자 몰)·유어애즈 아님.
**머니 경로 접촉 없음**(문서 생성기와 산출물만). **롤백**: 새 파일 삭제 + `deck-common.mjs` FACTS 를 되돌리고 재빌드.

## 1. 만든 것

`docs/business/proposals/urdeal-merchant-association-deck.{build.mjs,pptx,pdf}` — 16:9 **20장**.

| | |
|---|---|
| 누구에게 | 전통시장·골목형상점가·상가 상인회의 **회원 매장 사장님들**(+ 회장·사무국) |
| 읽는 자리 | 1:1 상담이 아니라 **설명회**. 그래서 마지막 장이 상인회에 드리는 요청이다 |
| 구성 | 표지 2 + PART 구분 4 + 본문 14 |

**사장님 덱(15장)과 갈라지는 지점 셋** — 같은 레일인데 읽는 자리가 달라서다:
1. 비교 대상이 개별 가게 광고가 아니라 **회비로 모아 쓴 공동 사업**(공동 전단·상권 축제·배달앱 쿠폰·체험단).
   비교 축은 *돈이 나가는 시점 · 오는 사람 · 혜택이 닿는 범위 · 효과 확인* 넷뿐이고 성과 수치는 전부 뺐다.
2. **사무국이 대신 등록·운영하는 길**(중개 5% + 매장 몫 안의 상인회 몫, 상한 50%·합산 90%).
3. **입점 요청 장** — 설명회 자리 1회 · 희망 매장 명단 · 회원 안내 1회. 그 대가로 유어딜이 등록 대행·사진 정리·사무국 화면.

**일부러 넣지 않은 것**: 기대수익 시나리오(상세판 5장의 월 30/90/150장 표). 단체 자리에서 수익 표를 띄우면 약속으로 읽힌다.

### 🩸 이번에 드러난 것 1 — 셈법에 쓰던 상품이 내려가 있었다

`products.id=2888`(치즈돈가스 25,000 → 16,500)이 **`is_active=0`** 이다. 사장님 덱은 그 숫자를
*"**지금 팔리는** 실제 상품"* 이라고 소개하고 있었으므로 **문장이 거짓이 된 상태**였다. 빌드도 테스트도
초록이고 아무도 신고하지 않는 종류다.

⇒ 라이브에서 지금 팔리는 유일한 실제 매장 이용권 **2915**(홍대돈까스 · 14,500 → 7,500 → 수수료 750 → 입금 6,750)로
교체하고, 값을 **`FACTS.sample*` 한 곳**에 모아 덱들이 같이 쓰게 했다. 상세판의 `CALC` 도 그 값으로.

**다음 세션의 규칙**: 덱을 다시 만들기 전에 그 상품이 **아직 팔리고 있는지부터** 확인할 것.
```sql
SELECT id,name,price,original_price,is_active FROM products
WHERE seller_id IS NOT NULL AND group_buy_status='active'
  AND category IN ('meal_voucher','beauty_voucher','stay_voucher','etc_voucher')
```

### 🩸 이번에 드러난 것 2 — 중개사 몫 송금 게이트가 켜져 있다 (덱 둘은 "켜기 전"이라고 적혀 있다)

```
platform_settings.broker_share_enabled = true        ← 09-19 인계는 OFF 였다
influencer_attributions                 = 0행        ← 그런데 한 건도 적립된 적이 없다
seller_meta.broker_share_pct 가 박힌 매장 = 4곳(전부 10%)
```

**대표 확인이 필요한 것** (내가 임의로 고치지 않았다):
- 이 게이트를 **대표가 켜신 것인지**, STAGING **S-BROKER** 실결제가 통과한 것인지.
- 켠 것이 맞다면 **대행사 덱 §14**(슬라이드 25)의 *"귀사 몫 직접 송금은 **켜기 전**입니다 … 켜기 전까지는
  종전대로 매장과 직접 정산합니다"* 가 **사실과 다르다**. 그 장은 대표 승인본이라 **문구를 안 건드렸고**,
  `addNotes` 에만 10-06 실측을 적어 두었다.
- 사장님 덱 11장의 *"대행사 보수는 … 유어딜 장부에는 나오지 않습니다"* 도 같은 이유로 흔들린다(아래 3 참조).

**새 상인회 덱은 이 사실을 슬라이드가 직접 말한다** — 12장에 *"아직 흐른 적이 없습니다. 이 송금 기능은 켜져
있지만 2026-10-06 기준 실제 적립된 건이 아직 0건입니다"* 를 박아 두었다.

## 6. 안 한 것

- 상인회 전용 화면·기능은 **하나도 만들지 않았다**(문서만). 덱은 지금 있는 기능만 말한다.
- 상권 쿠폰(`district_coupons`)은 **넣지 않았다** — 재단 예산 기반 병렬 엔티티이고 WP2(원장→payout)가
  미완이라 상인회에게 제품으로 약속할 수 없다.
- 상권 단위 묶음 페이지는 **없다**. 덱 9장이 그 사실을 직접 말한다("아직 없는 것도 말씀드립니다").
