## 🩸 이번에 시간 날린 함정 둘 (다음 세션이 또 밟는다)

### 1. PR 을 열어도 Verify 가 안 돌아간다

`verify.yml` 은 `pull_request`(기본 types: opened·synchronize·reopened)인데, **이 세션이 만든 PR 의 `opened`
이벤트는 워크플로를 만들지 않는다**(재귀 방지). 같은 시각 다른 PR 들의 Verify 는 정상이라 큐 문제가 아니었다.

- 증상: 체크런이 `Cloudflare Pages` **하나뿐**이다 → “느린 게 아니라 안 도는 것”
- `workflow_dispatch` 는 **403**(권한 없음). 빈 커밋·close/reopen 은 금지.
- ⇒ **main 을 병합해 푸시**하면 `synchronize` 가 발동한다(진짜 변경이라 규칙 위반도 아니다).
- 브랜치를 지웠다가 다시 만든 뒤 PR 을 여는 흐름(머지 직후 후속 작업)에서 재발한다.

### 2. 내 변경이 **남의 주입 앵커**를 옷긴다

`if (!balance)` → `if (!balance && !awaiting)` 하나와 prop 추가로 **기존 주입 3건**이 “낡은 지도” 로
떨어져 CI 가 빨간불이 됐다. 네 번째(`서버가 제목까지 그린다`)는 **불변식 자체가 폐기**돼 새 경계
(`서버가 가격까지 그린다`)로 **옷겨** 주었다.

⇒ **코드 커밋 전에 `node scripts/check-guard-mutations.mjs --map-only` 를 따로 돌릴 것**(1초).
pre-push 게이트는 전수 스윈을 CI 에 맡기므로 이건 로컬에서 안 걸린다.

### 3. draft 해제가 막힐 수 있다 (이번엔 40분)

`markPullRequestReadyForReview` 는 GraphQL 경유라 MCP·CCR 두 경로 뿐인데, 이날 둘 다 막혔다
(MCP `rate limit exceeded` · CCR `GitHub is temporarily unavailable`). 평범한 REST(읽기·푸시·머지)는 정상이었다.
REST `PATCH {"draft":false}` 는 **무시된다**(응답은 200 인데 draft 가 그대로다 — 성공으로 오독하기 쉬우니 값을 다시 읽을 것).
draft 상태 머지는 405. ⇒ 우회로가 없다. 대표게 “Ready for review 를 눌러 달라” 고 한 줄 요청하는 것이 가장 빠르다.

⚠️ **ms 로 판정하지 말 것** — 프록시 릴레이라 같은 경로가 3.0s ↔ 12.8s 로 흔들린다. 판정은 **순서와 개수**다.

## ① 서버 첫 화면 — 경계를 제목까지 밀었다

09-15 에 히어로에서 멈춘 이유는 제목 **위**에 per-user 블록이 둘 있어서였다. 둘을 치웠다:

1. **`ShareRewardBanner`(딜 보유자에게만)를 가격 아래로.** 이 배너는 서버 조회가 끝나야 뜨는데
   (첫 렌더는 항상 `null`) 제목 위에 있어 **딜 가진 사람에게만 뒤늦게 제목·가격이 밀렸다.**
   서버 렌더와 무관하게 **오늘도 나던 밀림**이라 이건 결함 수정이다. 빈 칸은 `empty:hidden` 으로 접는다.
2. **`?ref=` 추천 배너는 URL 로 결정**되므로, 그 파라미터가 붙은 요청에서만 제목을 접는다
   (`buildDetailFirstScreen(…, url.search)`). 그 경우 09-15 와 byte 동일 = 무회귀.

감싸는 노드에 **`class="gbd"` + 페이지 루트와 같은 배경·글자색**을 줬다. 없으면 (a) `--gbd-*` 가 안 풀려
제목이 기본색이 되고 (b) 바탕이 `--bg`(#F8F7FC) 라 마운트 때 `--surface`(#FFFFFF) 로 **바뀐다**.

### ❌ 주소·가격은 여전히 안 그린다 — 경계를 여기서 끊은 이유

제목 바로 아래 주소 줄에 `· 1.2km`(내 위치 기준 거리)가 **문장 안으로** 들어간다. 그 값은 localStorage
에만 있어 서버가 모르고, 거리 없이 그리면 그 줄이 한 줄 → 두 줄로 **되감길 수 있다.** 그러면 바로 아래
가격이 밀린다. ⇒ 경계는 **"서버가 확실히 아는 마지막 것" = h1**.

> 🧭 서버가 **안 그린** 것이 나중에 채워지는 건 밀림이 아니다 — 위는 한 픽셀도 안 움직인다.
> 그리다 만 것이 나중에 **모양이 바뀌는 것**만 밀림이다. 이 구분이 경계를 정한다.

## ② PC(lg+) — 만들지 않기로 했다 (근거 3개)

1. PC 첫 화면은 세로 스택이 아니라 **2열 그리드**(`lg:grid-cols-[minmax(0,1fr)_360px]`)다. 반쪽만 그리면
   마운트 때 오른쪽 360px 구매박스가 끼어들며 **그린 쪽이 가로로 줄어든다.** 세로 밀림을 없애려다
   가로 밀림을 만드는 셈이다.
2. 그 그리드 **밖**에 있는 유일한 블록 `DetailTitleHeader` 에는 `StarRating` 과 lucide `MapPin` **SVG** 가 있다.
   path 데이터를 워커 문자열로 손으로 옮기는 것은 이 레포가 반복해 당한 **두 벌이 갈리는** 클래스이고,
   path 동일성은 쉬운 기계 검사가 없다.
3. 애초에 전제("데이터는 왔는데 V8 파싱 1.2초")가 **폰 CPU 현상**이다. PC 는 같은 번들을 수 배 빨리 판다.

⚠️ **PC 상세 비중은 실측하지 못했다.** CF 토큰은 읽기 4종뿐이라 Analytics Read 가 없고(CLAUDE.md 가
추가 스코프 요청을 금지), 앱 계측(`/api/analytics/vitals`)에도 기기 차원이 없다. **높은 것으로 드러나면**
1·2 를 푸는 별건으로 다시 올릴 것 — 그때는 그리드 전체(빈 오른쪽 열 포함)와 제목 헤더를 **같이** 그려야 한다.

## ③ JS 다이어트 — 아이콘 봉투를 갈랐다

**번들러 모듈→청크 그래프를 실제로 떠서** 재판정했다(정적 추적은 못 믿는다 — 아래 함정 참조).

```
트리쉐이킹은 멀쩡했다 — lucide 1,534 모듈 중 260개만 남는다
문제는 그 260개가 한 봉투(64.8KB)라 셸 폐쇄(43개)가 전부를 끌고 왔다는 것
```

**⚠️ 규칙을 지우면 될 것 같지만 아니다** — 지워 보니 Rollup 이 256개를 통째로 `app-shell` 에 넣어
총량이 그대로였다(695.0 → 694.0KB). **명시 분할만** 효과가 있다.

함께 고친 것: **`auth/` 버킷을 `RouteGuards` 로 좁혔다.** 폴더 통째로 묶여 있어서 셸이 쓰는
`RouteGuards` 때문에 `KakaoLinkButton`·`SellerPinPrompt`(셀러 프로필 편집 **한 페이지만** 쓴다)가
13.7KB + 아이콘 6개를 달고 첫 페인트에 실려 왔다.

| | 청크 | raw | gzip |
|---|---|---|---|
| before | 17 | 695.0 KB | 211.8 KB |
| after | 17 | **633.1 KB** | **193.1 KB** (−8.8%) |

### 🩸 이번에 내가 밟은 함정 (다음에 비슷한 걸 할 때)

- **아이콘 이름 ≠ 파일 이름.** `AlertCircle`·`Home`·`CheckCircle2` 는 lucide 의 **별칭**이고 구현은
  `circle-alert`·`house`·`circle-check` 에 있다. 별칭 파일만 목록에 넣었더니 구현이 큰 봉투에 남아
  셸이 그 봉투를 **다시** 끌고 왔다 — **빌드는 성공하고 총량만 안 준다**(에러가 안 나는 부류).
  ⇒ 가드가 별칭 체인을 따라간다.
- **정적 import 추적기는 실제 청크 구성을 못 맞힌다.** 내 첫 추적기는 83파일/40아이콘을 냈는데
  실제 폐쇄는 128파일/42아이콘이었다(manualChunks 버킷이 lazy 전용 모듈을 끌어들이기 때문).
  ⇒ 판정은 `generateBundle` 로 뜬 **진짜 그래프**로 할 것.

`app-routes`(admin/seller/supplier 라우트 표)는 `<Routes>` **직계 자식**이라 중첩 라우트로 바꿔야 하고,

## ④ 잔액이 늦게 와서 목록이 밀리던 것

잔액은 마운트 뒤 API 로 온다 → 첫 커밋은 **누구든 `null`** 이고 부품은 그걸 44px 한 줄 바로 그렸다.
응답이 오면 170px 카드로 바뀌며 **아래 이용권 목록 전체가 내려갔다.**

⇒ 로그인 여부는 **동기로 알 수 있다**(`getUserIdSync`). 로그인이면 **숫자만 비운 같은 카드**를 먼저 그리고
(높이 동일 → 밀림 0), 비로그인이면 종전 한 줄 바.

- ⚠️ 빈 자리에 **0 을 적지 않는다** — 모르는 것과 0 은 다르다. 0 을 보여 주면 딜 보유자에게 잠깐
  "잔액 없음" 이라고 말하는 셈이다.
- 조회 실패는 `setDealBalance(b => b ?? 0)` — 2026-06-26 룰(**읽은 값은 0 으로 안 덮는다**)을 지키면서
  **한 번도 못 읽은 경우**에만 종전 실패 동작(한 줄 바)으로 떨어진다. 이게 없으면 숫자 없는 빈 카드가
  영원히 남는다.

### ❌ 목록 표면은 서버가 첫 화면을 안 그린다 (이번에 내린 판단)

per-user chrome 은 풀렸지만, `/vouchers`·홈의 첫 화면은 곧 **상품 그리드**다. 그 카드
(`VoucherCard`/`VoucherRow`/`GroupBuyFeedCard`)는 **잠금표 부품**이고 잠금표가 지키는 것이
이미지 속성(width/height/srcSet/lazy/fetchPriority/dominant_color)과 prefetch 배선이다.
상세 히어로는 배경 이미지 `div` **하나**였지만 그리드는 **N장 × 약 10개 속성**이라, 두 벌이 갈리는
클래스에 정면으로 들어간다.

⇒ 다시 시도한다면 **선행 조건**은 하나다: 카드 마크업을 서버·클라가 **같은 SSOT 로** 만드는 것
(상세 히어로에서 `detailHeroMobileUrl` 이 한 일과 같은 역할).
