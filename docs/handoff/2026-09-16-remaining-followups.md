### ④(잔액 밀림) — 하네스로 로그인 상태를 만들어 쟀다

처음엔 "소비자 로그인 세션이 없어 못 쟀다" 고 적었는데, **필요한 입력 둘은 하네스로 만들 수 있었다**:
`getUserIdSync()` 는 `localStorage.user_id` 만 읽고, 잔액은 `/api/points/balance` 응답 하나다.
⇒ initScript 로 `user_id` 를 심고 그 엔드포인트만 1.5초 늦춰 stub 했다(실제와 같은 순서: 마운트 → 응답 도착).

```
1,612ms  잔액=카드(h=152)  ← 숫자가 오기 전에 **기다리는 카드**가 자리를 잡는다 ✅
1,976ms  잔액=바(h=112)    ← user_id 가 null 이 된 프레임 (아래 ⚠️ — 하네스 아티팩트)
3,293ms  잔액=카드(h=152)  ← stub 응답 도착
```

**핵심 불변식은 확인됐다: 기다리는 카드와 도착한 카드의 높이가 같다(152 → 152).** 잔액 때문에 목록이
내려가지 않는다.

> ⚠️ **중간의 '바' 는 코드가 아니라 내 하네스 탓이다.** 같은 프레임에 `user_id` 가 `9999 → null` 로
> 바뀐다 — 진짜 세션이 없는 가짜 신원을 앱이 정리하는 것이고, 실제 로그인 사용자에겐 안 일어난다.
> (그 순간 `!userId` 분기가 `setDealBalance(0)` → 한 줄 바.) **재려면 그 프레임을 같이 찍어야
> 아티팩트와 결함이 구분된다** — 안 찍었으면 "밀림" 으로 오독했을 것이다(첫 판에 실제로 그럴 뻔했다).

📌 **별개로 눈에 띈 것(이번 범위 밖)**: 카테고리 칩 행이 늦게 로드되며 첫 사진이 **10px 내려간다**

## ① 서버 첫 화면 — 경계를 제목까지 밀었다

09-15 에 히어로에서 멈춘 이유는 제목 **위**에 per-user 블록이 둘 있어서였다. 둘을 치웠다:

1. **`ShareRewardBanner`(딜 보유자에게만)를 가격 아래로.** 이 배너는 서버 조회가 끝나야 뜨는데
   (첫 렌더는 항상 `null`) 제목 위에 있어 **딜 가진 사람에게만 뒤늦게 제목·가격이 밀렸다.**
   서버 렌더와 무관하게 **오늘도 나던 밀림**이라 이건 결함 수정이다. 빈 칸은 `empty:hidden` 으로 접는다.
2. **`?ref=` 추천 배너는 URL 로 결정**되므로, 그 파라미터가 붙은 요청에서만 제목을 접는다
   (`buildDetailFirstScreen(…, url.search)`). 그 경우 09-15 와 byte 동일 = 무회귀.

감싸는 노드에 **`class="gbd"` + 페이지 루트와 같은 배경·글자색**을 줬다. 없으면 (a) `--gbd-*` 가 안 풀려
제목이 기본색이 되고 (b) 바탕이 `--bg`(#F8F7FC) 라 마운트 때 `--surface`(#FFFFFF) 로 **바뀐다**.

### ❌ 주소·가격은 여전히 안 그린다 — 경계를 여기서 끊은 이유

제목 바로 아래 주소 줄에 `· 1.2km`(내 위치 기준 거리)가 **문장 안으로** 들어간다. 그 값은 localStorage
에만 있어 서버가 모르고, 거리 없이 그리면 그 줄이 한 줄 → 두 줄로 **되감길 수 있다.** 그러면 바로 아래
가격이 밀린다. ⇒ 경계는 **"서버가 확실히 아는 마지막 것" = h1**.

> 🧭 서버가 **안 그린** 것이 나중에 채워지는 건 밀림이 아니다 — 위는 한 픽셀도 안 움직인다.
> 그리다 만 것이 나중에 **모양이 바뀌는 것**만 밀림이다. 이 구분이 경계를 정한다.

### 🩸 이번에 내가 밟은 함정 (다음에 비슷한 걸 할 때)

  ⇒ 가드가 별칭 체인을 따라간다.
- **정적 import 추적기는 실제 청크 구성을 못 맞힌다.** 내 첫 추적기는 83파일/40아이콘을 냈는데

  ⇒ 판정은 `generateBundle` 로 뜬 **진짜 그래프**로 할 것.

⇒ 로그인 여부는 **동기로 알 수 있다**(`getUserIdSync`). 로그인이면 **숫자만 비운 같은 카드**를 먼저 그리고

- ⚠️ 빈 자리에 **0 을 적지 않는다** — 모르는 것과 0 은 다르다. 0 을 보여 주면 딜 보유자에게 잠깐
  "잔액 없음" 이라고 말하는 셈이다.
- 조회 실패는 `setDealBalance(b => b ?? 0)` — 2026-06-26 룰(**읽은 값은 0 으로 안 덮는다**)을 지키면서
  **한 번도 못 읽은 경우**에만 종전 실패 동작(한 줄 바)으로 떨어진다. 이게 없으면 숫자 없는 빈 카드가
  영원히 남는다.
