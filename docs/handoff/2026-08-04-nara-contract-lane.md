## 🧪 파라미터를 **추측하지 않고 레인이 측정한다**

원부가 26,445건 롤링이라 날짜 창(`inqryBgnDate`/`inqryEndDate`)이 먹히면 하루 ~3페이지로 끝나고,
안 먹히면 전량 페이징(200행 × 8페이지/회 → 며칠에 한 바퀴)이다. **그 파라미터 지원 여부를 이
환경에서는 확인할 수 없다**(포털 문서 403 · 프록시 차단). 그래서:

1. 창 파라미터로 쏜다 → 게이트웨이가 오류를 내면 **같은 페이지를 파라미터 없이 한 번만** 재시도
2. 판정을 `param_mode` 로 기억하되 **`NARA_PARAM_STATE_VERSION` 으로 잠근다**
   (인허가에서 겪은 *"코드 고쳤는데 DB 의 옛 판정이 이겨 라이브가 안 변함"* 을 반복하지 않으려고)

`apis.data.go.kr` 은 모르는 파라미터를 **조용히 무시**한다(실측: `pageIndex`·`_type` 을 얹어도 200)
→ 최악의 경우에도 *무시된 채 정상 동작*. **다운사이드가 없는 측정**이다.

좋으면 대표께 `ADS_NARA_CONTRACT_ENABLED=true` 요청(일 1회, 23 UTC = **KST 08시**).

## 판단 기록 (다음 세션이 다시 파지 않도록)

- **`시장` 단독을 필터에 안 넣었다** — "시장조사 용역"·"농수산물도매시장 청소용역"이 통째로 들어온다.
  `전통시장`·`시장현대화`처럼 붙은 형태만 받는다.
- **행 수 기본 200** (500 아님) — 계약 1건이 ~1.9KB 라 500행이면 1MB 파싱이고, 무료 플랜에서
  **CPU 로 죽는 자리**다(이 레포가 반복해 겪은 그 죽음).
- **발주기관 지역은 주소와 같은 규칙**(`pickAddrRegion`)을 쓴다 — 소스마다 규칙이 다르면 같은 서울이
  `서울`/`서울특별`로 갈려 어드민 지역 필터가 깨진다.
- **낙찰 API(`getDataSetOpnStdScsbidInfo`)로 안 갔다** — 프로브에서 `resultCode 08 필수값 에러`(날짜
  범위 등 필요)였고, 계약정보가 이미 *수주사 + 발주기관 + 금액 + 계약명*을 전부 준다. 낙찰은 중복이다.

## 🚀 자동화 + 첫 회차 실측 (2026-08-04 저녁, 대표 *"자동으로 데이터 나오게끔 하면 되잖아"*)

수동 1회(어드민 위임) 결과 — **정상 동작 확인**:
```jsonc
"scanned": 1200, "matched": 2, "saved": 2, "upserted": 2,
"total": 29129, "page": 7, "stopped_by": "pages",
"param_mode": "window", "param_v": 1, "diag.error": null
```

읽는 법:
- **`param_mode: "window"` + `total: 29,129`** → 날짜 창 파라미터가 **무시됐다**(예상 시나리오 ①).
  거부가 아니라 무시라 폴백도 안 걸렸다 — 전량 페이징으로 정상 동작 중이다.
- **`stopped_by: "pages"`** → 마감선(20s)이 아니라 **페이지 수**에서 멈췄다 = **시간이 남는다.**
- 수율: 1,200건에 상권 계약 1건(리드 2개). 전체 29,129건이면 **상권 계약 ~24건 · 리드 ~48개** 예상.

### 바꾼 것
1. **게이트 기본 ON**(`!== 'false'` — opt-out). 다른 레인과 다른 이유: 원부를 다 훑는 데 회차가 많이
   필요해 **사람이 버튼을 누르는 방식으로는 영영 못 돈다.** 끄려면 env 에 `false`.
2. **회차당 페이지 8 → 20**(상한 40). 근거는 위 `stopped_by:"pages"` — 시간이 남는데 페이지에서
   끊겼다. 마감선이 백스톱이라 느린 날엔 알아서 일찍 멈추고 **커서는 진행분을 보존**한다.
   → 한 바퀴 25회차 → **8회차**(일 1회면 8일).
