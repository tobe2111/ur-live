# 시드에서 고쳤는데 라이브가 안 고쳐졌다 — 가이드 한정 해동 (2026-08-31)

## 어떻게 발견했나

#1270·#1276 배포 후 **초록불로 끝내지 않고 라이브를 직접 읽었다**(`GET /api/guides/seller`).
운영백서·후기 보너스 등 새 내용은 정상 반영됐는데, **셀러 가이드에 OBS 설정법이 그대로 살아 있었다.**
라이브커머스는 2026년 6월에 영구 중단된 기능이다.

시드 파일에는 분명히 '종료됨'으로 바꿔 놨다. 그런데 라이브가 안 바뀌었다.

## 원인 — 아무도 편집하지 않았는데 얼어 있었다

`guide.routes.ts` 의 보수적 백필:

```
if (firstRun) UPDATE operation_guides SET manually_edited = 1 WHERE section_key != 'auto-reference'
```

`manually_edited` 컬럼이 생기던 날, **그때 존재하던 모든 섹션**을 수동편집으로 간주했다.
당시엔 편집 여부를 알 방법이 없었으니 합리적인 선택이었다 — 하지만 그 결과
**2026-04-27 이전 섹션은 시드 갱신이 영영 안 닿는다.** 아무도 편집하지 않았는데도.

실측(라이브 제목 vs 시드 제목 대조):

| 가이드 | 얼어 있던 섹션 |
|---|---|
| seller | `live-broadcast` (OBS 설정법) · `live-mastery` |
| admin | `daily` (낡은 일일 체크리스트) |
| agency | 없음 |

## 수리 — **키를 명시한 것만** 1회 해동

`syncGuideSeed` 앞에 `UNFREEZE_ONCE` 3키만 `manually_edited = 0` 으로 되돌리고,
`platform_settings.guide_unfreeze_2026_08_31` 마커로 **1회만** 돈다. 이후 관리자가 그 섹션을
편집하면 그 편집이 이긴다. GUIDE_SEED_VERSION 20 → 21.

⚠️ **전체 해동(`POST /:type/reseed`)을 쓰지 않은 이유**: 그건 그 가이드의 **모든** 수동 편집을
초기화한다 — 운영자가 손으로 다듬은 문구까지 날아간다.

## 다음 세션의 첫 액션

배포 후 라이브로 판정한다(초록불은 아무것도 말해 주지 않는다):

```
GET /api/guides/seller  → live-broadcast 제목이 '라이브 방송 운영 — 종료됨' 인가
GET /api/guides/admin   → daily 제목이 '일일·주간 운영 체크리스트' 인가
```

## ⛔ 남아 있는 더 큰 구멍 (이번에 안 고쳤다)

제목 비교로 찾았기 때문에 **제목은 같고 본문만 낡은 pre-백필 섹션**은 여전히 조용히 낡아 있을 수
있다. seller 11개 · admin 17개가 2026-04-27 생성분이다. 본문까지 대조하려면 시드 본문과 라이브
본문을 해시로 비교하는 진단이 필요하다 — 별도 과제.

## 이번에 틀렸던 판단

1. 처음엔 *"관리자가 그 두 섹션을 편집했나 보다"* 로 읽었다. **아니었다** — 백필이 전부를 얼렸다.
   소스를 읽고서야 알았다. 라이브 증상만 보고 원인을 지어내면 안 된다.
2. 셀러 가이드 검증에서 `'2단계 1%'` 를 전체 본문에 grep 해 *"아직 있음"* 으로 읽었다.
   **내가 쓴 정정 안내가 그 문구를 인용**하고 있었다 — #1270 에서 이미 한 번 당한 실수를
   검증 단계에서 그대로 반복했다. 위치를 봐야 한다.
