# 2026-09-08 — 유어쇼츠: 이용권 없는 영상도 홈에 (INNER → LEFT) + 수수료 질문 답변

## 대표 지시 (그대로)
> "응 이용권 정보를 입력하지 않으면 그냥 정보 없이 두는걸로. 근데 만약 이렇게 유어쇼츠로
> 이용권을 구매하게 되면 수수료는 어떻게 되는거지?"

앞선 대화에서 대표가 *"아직 메인 홈페이지에서는 안나오네?"* 라고 물어 라이브를 재 보니
**버그가 아니라 구조**였다 — 등록된 영상 3편이 전부 `product_id = null`, `consent = 0` 이고
공개 쿼리가 `JOIN products`(INNER) + `AND s.consent = 1` 이라 한 건도 안 나간다.
대표가 그중 **이용권 조건만** 풀라고 확정했다. **허락(consent) 게이트는 그대로다.**

## 무엇을 바꿨나

| 자리 | 전 | 후 |
|---|---|---|
| `urshorts.routes.ts` `PUBLIC_SQL` | `JOIN products` | `LEFT JOIN products` |
| 같은 곳 WHERE | `AND p.is_active = 1` | `AND (p.id IS NULL OR p.is_active = 1)` |
| `UrShortsRail` 카드 | 글자 띠 항상 | `hasInfo` 일 때만 (+ 가격 줄은 `pd.price > 0`) |
| `VideosPage` 구매 바 | `{cur && (` | `{cur && cur.product_id ? (` · 매장명 조건부 |
| `shared/urshorts.ts` | `product_id: number` | `number \| null` |

### 🔴 놓치기 쉬운 한 줄
`AND p.is_active = 1` 을 그대로 두면 **LEFT JOIN 이 조용히 INNER 로 되돌아간다**(NULL 비교가
거짓이라 상품 없는 행이 전부 걸러진다). SQL 을 읽으면 고쳐진 것처럼 보이는데 레일은 여전히
비고 에러도 안 난다. 주입 매니페스트에 이 한 줄만 되돌리는 항목을 따로 뒀다.

## 카드가 어떻게 보이나 (실제 렌더로 확인)
- 전부 있음 → 매장 / 상품명 / 정가 / 할인율·판매가 (안 라 그대로)
- 매장·정가 없음 → 그 줄만 사라짐
- **이용권 없음 → 글자 띠 자체가 없다.** 썸네일 + 재생 아이콘 + 재생시간뿐.
  띠를 조건 없이 그리면 빈 검정 그라디언트만 남는데 그건 "정보 없음"이 아니라 결함으로 보인다.

## 💸 대표 질문 답 — 유어쇼츠로 사면 수수료가 어떻게 되나

**유어쇼츠는 유입 경로일 뿐이다. 수수료는 그 매장의 기존 요율 그대로이고, 쇼츠라서 붙거나
빠지는 몫은 0 이다.** 근거(코드·라이브 실측):

1. 카드/구매 바는 `/group-buy/:id` 로 간다 — **추천 코드가 안 붙는다**(`VideosPage.tsx`).
   ⇒ 어필리에이트·소개 커미션 **0**. 영상 올린 사람에게 가는 몫도 지금은 없다.
2. 결제는 이용권 일반 경로 그대로 → 요율은 `getSellerCommissionRate`(SSOT,
   `features/group-buy/api/seller-commission-rate.ts`) 가 정한다. 순서는
   **채널 > 매장별 override > GMV tier > 기본 5%**.
3. 라이브 실측(2026-09-08): `fee_channel_rates_enabled = true` · `commission_rate_default = 5` ·
   활성 이용권 매장은 **id 14 한 곳뿐**이고 `store_channel = 'brokered'`, `commission_rate = 5`
   ⇒ 지금 쇼츠로 팔리면 **5%**.
4. 채널이 `direct`(업주 직접 입점)면 10%. 채널 미지정 매장은 brokered 폴백(기존 매장 무재가격).

⚠️ **그래서 결정할 거리가 하나 생긴다**(대표 판단 — 지금 코드 변경 없음): 남의 영상을 허락받아
쓰는 경우 **그 창작자 몫이 0** 이다. 소개 커미션을 붙이려면 쇼츠 링크에 귀속(추천 코드)을
실어야 하고, 그건 머니 경로라 결재함 + staging 실결제 대상이다. 붙이기 전까지는 "허락"이
곧 무상 사용이라는 점을 제휴 제안에서 정직하게 말해야 한다.

# 후속 (같은 날) — 허락(consent) 게이트 해제

## 대표 지시 (그대로)
> "일단 어드민 대시보드에서 올렸던 유어애즈 영상(링크)는 메인에서 보여지도록 해줘 허락 받은 유무 상관없이"
>
> (내가 창작자 보증 위험을 한 줄 남기자) "어차피 허락을 받지 않은 영상에는 이용권을 붙히지 않을거라 상관없을 것 같아"

**대표 논리가 맞다.** 내가 든 위험("구매 버튼 옆의 남의 영상 = 보증처럼 읽힌다")은 **구매 버튼이 있어야** 성립하는데,
이용권을 안 붙이면 이 PR 의 앞부분 변경으로 **구매 바도, 카드 글자 띠도 안 그려진다.** 썸네일만 남는다.
⇒ 09-07 의 `AND s.consent = 1` 게이트는 이 지시로 **대체**됐다.

## 무엇을 바꿨나
- `PUBLIC_SQL`: `AND s.consent = 1` **삭제**. 홈 노출 조건은 이제 `s.is_active = 1` 하나다.
- `consent` 컬럼·어드민 토글은 **남긴다** — 어떤 영상에 허락을 받아 뒀는지 알아야
  유어애즈 제휴 제안을 보낸다. 노출에서 빠졌을 뿐 **기록으로 산다**.
- 셀러 투고 경로(`sellerUrshortsRoutes.post`)는 **여전히 등록 시 consent 필수** — 자기 영상임을
  스스로 확인하는 자리라 성격이 다르다.
- 어드민 화면 문구 정정: *"확인 안 하면 홈에는 안 나갑니다"* → *"기록용입니다 — 확인 안 해도 홈에는 나갑니다"*.
  그리고 상단 "홈 노출" 카운트에서 `consent`·`product_id` 조건 제거(서버 규칙과 어긋나면 화면이 거짓말을 한다).

## 되돌리는 법
`PUBLIC_SQL` 의 WHERE 에 `AND s.consent = 1` 한 줄 복원. 컬럼·토글·셀러 강제는 그대로 살아 있어
다른 건 손댈 게 없다. 그때 주입 `🎬 허락 게이트가 되살아나…` 가 빨간불이 되므로 함께 판단할 것.

## 가드
- 낡은 주입 `🎬 허락 안 받은 영상이 홈에 나간다 (consent 게이트 제거)` 제거 — 그 불변식이 뒤집혔다.
  ⚠️ **이 항목은 매니페스트에 두 벌 있었다**(앞쪽 1 + 끝쪽 1). 앞쪽만 지우고 `--map-only` 를
  안 돌렸으면 낡은 지도가 남을 뻔했다 — 지도 검사가 잡았다.
- 새 주입 2건, 둘 다 **되돌려-검증 빨간불 확인**:
  ① 허락 게이트가 되살아나 어드민 영상이 홈에서 사라진다
  ② 어드민 화면이 홈 노출 규칙을 거짓으로 말한다(문구만 낡는 종류 — 테스트 말고는 아무도 안 잡는다)
