# 인플루언서 풀 페이지 첫 페인트 — 224KB 를 빼냈다 (2026-08-05)

## 대표 신고
*"대시보드의 인플루언서 페이지 로딩이 너무 느린데?"*

## 실측 (추측 전에 잰 값)

| API | TTFB | 크기 |
|---|---|---|
| `/influencer-pool/stats` | **1.10s** | 8.8KB |
| `/influencer-pool?limit=50` | 0.73s | 86KB |
| **`/influencer-pool/keywords`** | 0.47s | **224KB** |

첫 로딩 **310KB 중 72% 가 키워드**다. 그런데 그걸 쓰는 `KeywordManager` 는 **접힌 `<details>`** 라
열기 전엔 본문도 안 그린다(그 파일 주석이 이미 *"닫혀 있으면 본문 미렌더"* 라고 적고 있다) —
**대부분의 방문에서 224KB 를 받아 파싱만 하고 버렸다.** 서버 SELECT 가 `LIMIT 1000` 이라
비활성 키워드까지 전부 온다.

⚠️ **오진할 뻔한 것**: 처음엔 `setInterval(loadMeta, 10_000)` 을 보고 *"10초마다 224KB"* 로 읽었다.
실제로는 **정비 실행 중에만** 도는 폴링이었다(`maintainRunning` 게이트). 상시 부하가 아니다 —
코드를 끝까지 읽고 정정했다. (그래도 정비 중엔 실제로 10초마다 224KB 였으므로 그쪽도 같이 고쳤다.)

## 처방

- `loadMeta` 를 `loadStats` / `loadKeywords` 로 분리
- **마운트는 통계만** · 키워드는 **패널을 처음 펼칠 때**
- 정비 폴링(10초)도 **통계만** — 안 고치면 보고 있는 내내 같은 비용을 문다
- 키워드 편집 뒤(`onChanged`)엔 둘 다 갱신(분류 통계도 같이 바뀐다)
- 받기 전 요약줄에서 **개수를 숨긴다** — "활성 0" 으로 보이면 *키워드가 사라진 걸로* 읽힌다

⇒ 첫 페인트 네트워크 **310KB → 86KB(−72%)**, API 3콜 → 2콜.

## 남은 것 (안 건드림)

**`/stats` 가 1.10s** 로 가장 느린 단일 호출이다. 40여 개 집계를 51,483행에서 매번 센다.
어드민 인증 경로라 공개 엣지캐시를 못 쓰고(그 미들웨어는 잠금 영역), 짧은 KV 캐시는 무료 쓰기 한도
규칙(`check-kv-delete-budget`)과 얽힌다 → **별건으로 다뤄야 한다.** 이번 변경과 독립이다.

## 다음 세션의 첫 액션

배포 후 브라우저 개발자도구 Network 에서 `/admin/influencer-pool` 첫 로드를 확인:
- `keywords` 요청이 **없어야** 한다(패널을 펼치기 전까지)
- 펼치면 그때 1회 요청 + 요약줄에 개수 표시
⚠️ 이 환경엔 그 화면이 없어 **체감 속도는 라이브에서만 판정된다** — 유닛은 배선만 고정한다.
