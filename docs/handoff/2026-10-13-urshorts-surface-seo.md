## ② 장소 URL — 제가 보고한 것보다 결함이 **셋**이었다

제가 대표께 *"`kko.to` 단축링크가 `sameAs` 에서 빠진다"* 한 가지로 보고했는데, 고치려고 파 보니
같은 자리에 셋이 있었다.

### ⓐ 같은 가게인데 껍데기가 다르면 `sameAs` 가 안 나갔다

라이브를 직접 두드려 **id 공간이 같다는 것을 증명**했다(2026-10-13):

```
place.map.kakao.com/10256701      200 · og:title=달빛한스푼      ← 정본
map.kakao.com/?itemId=10256701    200 · og:title=달빛한스푼      ← 같은 가게
map.kakao.com/link/map/10256701   302 → ?itemId=10256701        ← 같은 id 로 접힌다(하드 증거)
map.kakao.com/link/to/10256701    302 → …rt2=달빛한스푼
map.kakao.com/?itemId=99999999999 200 · og:title 없음            ← 틀린 id 는 이름을 안 만든다
kko.to/{code}                     프록시 CONNECT 403 — **실측 불가**
```

⇒ 판정을 SSOT(`shared/kakao-place-url.ts`)로 옮기고 **id 를 뽑아 정본으로 접는다**.
`detail-ssr-meta.placeSameAs` 는 그 SSOT 에 위임한다(호스트 리터럴이 두 벌이 되지 않게).

🔑 **그리고 `kko.to` 틈의 절반을 네트워크 없이 닫았다** — 처음엔 "리다이렉트를 못 풀어서 못 한다"
로 끝내려 했는데, 코드를 읽어 보니 **카카오 장소 검색으로 고른 매장은 id 를 따로 받아 둔다**
(`b.kakao_place_id` → `seller_meta.kakao_place_id`). 그 id 가 정본 주소의 id 와 같은 공간이라는
증거도 **우리 코드 자신**에 있었다 — **다섯 화면이 이미 손으로** `https://place.map.kakao.com/${id}`
를 조립하고 있었고 사진 스크래퍼도 같은 id 로 그 페이지를 받는다. ⇒ `kakaoPlaceUrlFromId(id)` 를
SSOT 에 두고 **그 다섯 자리를 모았고**(두 벌 드리프트 제거), 등록 경로 둘은
`URL 에서 id → 못 뽑으면 받아 둔 id` 순서로 정본을 저장한다. 순서가 중요하다 — **URL 이 더 최신
입력**이라(사람이 방금 고쳤다) id 를 먼저 쓰면 수정이 조용히 무시된다(주입이 그 방향을 고정).

🔴 **아직 안 닫힌 절반**: 어드민·셀러 폼에 사람이 `kko.to` 를 **직접 붙여넣는** 경로(거기엔 id 가
같이 오지 않는다). 리다이렉트를 풀어야 하는데 **이 환경에서 그 동작을 검증할 수 없다**(프록시가
`kko.to` 에 CONNECT 403). 검증 못 하는 fetch 를 어드민 저장 경로에 넣지 않는다 — 종전과 같이
`sameAs` 부재(손실 0). 다시 하려면 **먼저 `kko.to` 가 어떤 Location 을 주는지 실측**할 것.

🔴 **좌표형 `link/map/{이름},{위도},{경도}` 는 일부러 안 받는다** — 거기엔 장소 id 가 없다.
**틀린 id 로 접는 것은 `sameAs` 가 없는 것보다 나쁘다**(남의 가게를 우리 매장이라고 선언한다).
주입이 그 방향을 고정한다.

### ⓒ 내 시험이 `http://` 를 거부로 적어 뒀다

`placeSameAs` 가 https 만 받았는데, 그건 *내보내는 값*이 https 여야 한다는 요구를 *입력*에까지

**거부 → 정규화로 옮겼고**(내보내는 값은 늘 https 정본), 그 반대 방향을 주입이 지킨다.
