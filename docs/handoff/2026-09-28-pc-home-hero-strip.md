### 🩸 하네스가 낸 숫자 하나는 그대로 믿으면 안 된다
타일 **요청 횟수가 14회**로 나왔다(고유 URL 은 8개). 기대는 8회였다 —
`<img>` 16개 중 둘째 벌은 같은 주소라 브라우저가 한 번만 받아야 한다.
**이건 라이브 결함이 아니라 하네스 아티팩트다**: 이 하네스는 모든 요청을 가로채
Node fetch 로 대신 받아 채우는데(프록시 CA 문제), 가로챈 요청은 브라우저 HTTP 캐시를
제대로 안 탄다. 근거는 응답 자체에 있다 — `immutable` + 1년 TTL + 같은 URL.
⇒ **판정 기준은 "요청 횟수"가 아니라 "고유 URL 수"로 읽을 것.** 8/8 이면 통과다.

## 3. 이번에 틀렸던 판단 (같은 오진 반복 방지)

1. **"오늘 히어로는 96KB"** — 아니다. 직접 재니 **55KB** 다. 원본이 540×720 이라 리사이저가
   1024·2048·3072 어느 폭을 요청해도 **더 못 키운다**. 소스 주석·기존 테스트 주석에 96KB 가
   여러 군데 남아 있는데(2026-08-22 추정치가 굳은 것) 그걸 근거로 계산하지 말 것.
2. **매대 첫 줄을 5열로 알았다** — 시안을 5열로 그려 놓고 `HERO_STRIP_SKIP = 5` 로 적었다.
   진짜는 `md:grid-cols-4`(`GroupBuyFeed`·`HomeSections` 둘 다). 4 로 정정했고, 가드가
   **그 클래스를 소스에서 읽어** 대조한다(상수끼리 비교하면 자기 자신을 기준 삼는 셈이 된다).
3. **가드가 처음에 헛돌았다** — `id <= HERO_STRIP_SKIP` 로 썼더니 그 상수를 0 으로 바꾸는 주입이
   **통과**했다(조건이 저절로 참). 주입 러너가 잡았다. 같은 함정: *검사의 기준이 검사 대상 안에 있으면 안 된다.*
4. **"처음 5장만 받는다"는 선택지가 아니다** — 마퀴는 한 바퀴(34초)에 모든 타일이 화면에 온다.
   가능한 건 "먼저/나중"뿐이고, 진짜 레버는 **장당 KB**(카드 URL 공유 28.5~81.6KB vs 전용 13.3KB)다.

## 5. 머지 직전에 터진 것 — 번들 예산 **93바이트** (해결)

머지하려는데 CI `Verify` 가 빨간불. 원인은 히어로가 아니라 **번들 총량 예산**이었다.

```
main (내 변경 없음)   7,935,284 B   여유 2,927 B   violations 0
내 변경 포함          7,938,304 B   93 B 초과      ← 내 PR 이 마지막 한 방울
```
제 변경분은 **+2,950 B**(띠 컴포넌트 + SSOT)로 정상 크기다. main 에 남은 여유가 2.9 KB 뿐이었다.
⇒ **"base 도 빨간불" 이 아니라 내 PR 의 실패다.** 변명하지 말 것.

### 처방 — 예산을 올리지 않고 **내렸다** (아홉 번 만에 처음)
`scripts/check-bundle-size.mjs` 가 2026-09-24 부터 매 상향마다 요구해 온 것:
*"이 값을 또 올리기 전에 처리 끝난 결재를 `docs/decisions/archive/` 로 옮겨라."*
`AdminDecisionsPage` 가 `import.meta.glob('docs/decisions/*.md', { eager: true })` 로 결재 원문을
번들에 통째로 박기 때문이다. **대표 승인** 받고 실행했다(2026-09-28).

```
7,938,304 → 7,889,277 B (−47.9 KB) · AdminDecisionsPage 173.8 KB → top10 밖
예산 7.57 → 7.53 (헤드룸 6.8 KB) · critical 17청크 195.7/240 · gzip 2.401/2.45
```

### 🩸 여기서 내가 틀릴 뻔했다 — **승인만 보고 세면 안 된다**
대표께 "approved/rejected **20건**" 이라고 보고하고 승인까지 받았는데, 옮기기 직전에 실제로
파싱해 보니 **그중 13건은 `반영 커밋` 이 비어 있었다** = 어드민이 `승인 · 구현 중` 으로 추적하는
**살아 있는 일**. 옮겼으면 대표가 *"승인해 줬는데 어디 갔지"* 를 겪는다.
⇒ 판정 기준을 파일 상태가 아니라 **`parse-decision.ts` 의 `fullyApplied`**(승인 + 반영 커밋에
해시) + `rejected` 로 바꿔 **7건만** 옮겼다. 48.7 KB 로 93 B 를 메우는 데 500배 충분하다.
규칙은 `docs/decisions/archive/README.md` 에 박아 뒀다.

**남은 여지**: 13건이 반영 커밋을 채우는 대로 같은 방법으로 **약 66 KB** 를 더 내릴 수 있다.
그때 예산을 7.47 쪽으로 더 내릴 것(7.47 은 13건이 남아 있을 때의 목표였다 — 지금은 못 닿는다).

## 6. E4 판정 하네스 — 다음에 또 쓸 기법 (결과는 §1)

`scratchpad/hero/live-e4.mjs`. 이 컨테이너 Chromium 은 에이전트 프록시 CA 를 안 믿어서 라이브를
못 열었는데, **TLS 검증을 끄지 않고** 모든 요청을 CA 를 믿는 **Node fetch 로 대신 받아** 브라우저에
채워 넣는 방식으로 풀었다(`context.route('**/*')`). ⚠️ 세션이 끝나면 사라지니 다음 세션은 다시 만들 것.

**머지 전 라이브 기준선(before)** — 하네스가 실제로 동작함을 확인한 값:
```
.ur-hero-band 없음 · width=384 요청 0개 · width=1280 요청 1개
스크린샷: 돈가스 한 조각이 띠 전체를 채움 (= 대표 신고 증상 그대로)
```
**머지 후 실측(after)**: 기대와 전부 일치 — §1 표 참조.

라이브 타일 URL 은 머지 전에 이미 실측해 뒀다 — `cf-resized: internal=ok` · AVIF **12,580 B**
(원본 414,544 B, 33배). 8장 ≈ **101 KB**.
