대표: *"여기 지금 들어있는 사진 비율이나 너무 마음에 안드는데? 이거 그냥 확대해서 올라가버리는거잖아"*
→ ***"2번으로 하고 저 이용권들이 좌우로 자연스럽게 계속 이동하는건?"***
→ *"보통이 낫다. 트래픽은 최대한 이상적으로 하자. 처음 5장만 받는게 가장 이상적인가? 모바일은 필요없어. PC만 있으면 돼."*

시안·근거·표는 `docs/design/pc-home-hero-deal-strip-2026-09.md` 가 SSOT. 여기는 **다음 세션이 이어갈 것**만.

## 1. 다음 세션의 첫 액션 — 배포 후 E4 판정

머지·배포가 끝나면 **PC 하드로드 프레임으로** 판정한다(ms 가 아니라 **개수와 순서**로).

```
urdeal.kr/  (PC 1920, 첫 방문)
 ① 히어로 오른쪽에 타일이 **첫 프레임부터** 있고 마운트 때 안 움직이는가
 ② 실제로 흐르는가 · 커서를 올리면 멈추는가
 ③ 네트워크에 /cdn-cgi/image/width=384,quality=62,...,gravity=auto/ 요청이 **8건**인가
    (16개 <img> 인데 둘째 벌은 같은 URL 이라 8건이어야 한다. 16건이면 캐시가 안 먹은 것)
 ④ 예전 히어로 URL(width=1280,quality=76)이 **0건**인가 (남아 있으면 preload 가 헛돈다)
```
⚠️ 이 컨테이너 브라우저는 라이브 자산을 못 받는다(청크 자가복구가 `chrome-error://` 로 튄다).
로컬 `dist/client` + API 스텁으로 재는 하네스는 `scratchpad/hero/shot-strip.mjs` 에 있다(세션 종료 시 사라짐).

## 3. 이번에 틀렸던 판단 (같은 오진 반복 방지)

1. **"오늘 히어로는 96KB"** — 아니다. 직접 재니 **55KB** 다. 원본이 540×720 이라 리사이저가
   1024·2048·3072 어느 폭을 요청해도 **더 못 키운다**. 소스 주석·기존 테스트 주석에 96KB 가
   여러 군데 남아 있는데(2026-08-22 추정치가 굳은 것) 그걸 근거로 계산하지 말 것.
2. **매대 첫 줄을 5열로 알았다** — 시안을 5열로 그려 놓고 `HERO_STRIP_SKIP = 5` 로 적었다.
   진짜는 `md:grid-cols-4`(`GroupBuyFeed`·`HomeSections` 둘 다). 4 로 정정했고, 가드가
   **그 클래스를 소스에서 읽어** 대조한다(상수끼리 비교하면 자기 자신을 기준 삼는 셈이 된다).
3. **가드가 처음에 헛돌았다** — `id <= HERO_STRIP_SKIP` 로 썼더니 그 상수를 0 으로 바꾸는 주입이
   **통과**했다(조건이 저절로 참). 주입 러너가 잡았다. 같은 함정: *검사의 기준이 검사 대상 안에 있으면 안 된다.*
4. **"처음 5장만 받는다"는 선택지가 아니다** — 마퀴는 한 바퀴(34초)에 모든 타일이 화면에 온다.
   가능한 건 "먼저/나중"뿐이고, 진짜 레버는 **장당 KB**(카드 URL 공유 28.5~81.6KB vs 전용 13.3KB)다.

## 4. 남은 결정 / 대기

- **E4 판정**(위 ①~④) — 이것만 남았다. 통과 전에는 "배포됐다"까지만 말할 것.
- **태블릿(768~1023)** 은 밴드 38%(292px)라 1.5장만 보인다. 대표 지시가 *"PC만 있으면 돼"* 라
  그대로 뒀다. 좁아 보인다는 말이 나오면 그 구간만 타일을 작게 하는 것이 다음 후보.
- **어드민 히어로 배너 0건** 은 그대로다. 띠가 기본이 됐으니 이제 급하지 않다. 다만 배너를 올리면
  띠가 아니라 그 사진 한 장이 뜬다(권장 규격을 2400×440 으로 고쳐 뒀다).
- 직전 작업(#1528 `orders.payment_status`)의 **P16 staging 실결제**는 아직 안 돌았다 —
  `docs/STAGING_CHECKLIST.md` 참조. 그리고 소비자 환불 경로(`order.routes.ts`)를
  `refundOrderFully` 로 위임할지는 **대표 판단 대기**(부분환불 정책과 얽힌다).
