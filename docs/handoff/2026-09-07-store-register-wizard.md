## 그래서 실제로 한 것

### B. 한 화면 한 질문 위저드 (당근 원칙 ①·②)

`StoreRegisterModal` 을 4스텝으로. 종전엔 네 질문이 한 시트에 세로로 쌓이고 아래 버튼은 넷이 다
채워져야 켜졌는데, **무엇이 빠졌는지는 아무 데도 안 적혀 있었다.**

```
[✕]                    1 / 4      ← 진행바 + 카운터
내 매장을 찾아주세요                  ← 질문 하나
카카오맵에서 검색하면 …               ← 왜 묻는지
   …
[     다음     ]  ← 회색이면
지도에서 매장을 선택해주세요   ← 이유를 말한다 (blockReason)
```

- 프리필(`initialPlace`)로 열리면 **1단계를 건너뛴다** — 이용권 위저드가 쓰는 다리 보존.
- **사업자번호는 "(선택 — 지금 안 적어도 등록돼요)"** 로 명시(당근 원칙 ②). 서버는 원래 선택인데
  화면이 안 말해 필수처럼 보였다.

### 🕳️ 막다른 길 셋

| 구멍 | 실측 | 처방 |
|---|---|---|
| **다크에서 입력 글자 실명** | `/store/new` 흰 배경 위 흰 글자 **1.00:1**(브라우저 측정) | 루트에 `force-light-theme` — `index.css` 가 명시한 규칙인데 이 페이지만 빠져 있었다 |
| **이미 등록된 매장** | 서버는 409 에 `seller_id` 까지 주는데 화면은 alert 하나 | 좌석 토큰으로 "내 매장인지" 시험 → 맞으면 그 매장으로, 아니면 정직한 안내 |
| **이유 없는 회색 버튼** | 넷 중 뭐가 빠졌는지 안 알려줌 | 위저드가 구조적으로 해소 + `blockReason` 한 줄 |

**다크 실명은 대표가 2026-09-03 지도 검색창에서 신고한 것과 같은 버그**다. 전역
`.dark input:not(…)`(특이도 **0,5,1**)이 `text-gray-900`(**0,1,0**)을 언제나 이긴다.
하필 매장 유치 퍼널의 **유일한 문**에 있었다.

### ⚠️ 소유권은 자동으로 넘기지 않았다

매장 귀속은 정산이 따라가는 **머니 경로**이고, 진짜 승계(`owner_verified`)는 설계만 있고 코드가
없다(`store-operator-model.md` §5 — 레포 전체 grep **0건**). 대신 **이미 있는 권한 검사를 시험지로**
썼다: 좌석 토큰(`/stores/:id/token`)은 `canOperateStore`(그 파일이 "유일한 방어선" 이라고 못 박은 곳)를
통과해야만 발급된다 ⇒ `enterStoreSeat` 가 성공하면 원래 내 매장이었던 것이다.
**서버 무수정 · 새로 뚫리는 권한 0.**

문구는 **누구 것인지 단정하지 않는다** — 내 매장이어도 승인 대기(pending)면 좌석 토큰이 403 이라
같은 화면으로 온다. "다른 사람이 등록했다" 고 말하면 그 사장님에게 거짓말이 된다.

## 🩸 적대적 재독에서 **내가 만든 새 막다른 길 둘**을 잡았다

막다른 길을 없애러 와서 두 개를 새로 놓을 뻔했다. 둘 다 **화면상 멀쩡해 보인다.**

1. 안내 화면의 [내 매장 목록 보기] → `/seller/stores` 는 **`requireSeller`** 다
   (`seller.routes.tsx:222`). 푸터로 들어온 소비자는 `seller_token` 이 없어 **셀러 로그인으로 튕긴다.**
   ⇒ 좌석이 실제로 있을 때만(`hasSellerSeat`) 보여 준다.
2. "원래 내 매장" 으로 들어간 경우에도 `/store/new` 가 **"매장이 등록됐어요"** 를 띄웠다.
   아무것도 등록되지 않았는데 그렇게 말하면 거짓말이고, 좌석도 이미 잡혀 있어 재발급이 낭비다.
   ⇒ `onDone(sellerId, { existing: true })` 로 문구를 가른다(인자를 안 읽는 기존 호출부 3곳 무영향).
