## v2 (대표 피드백 "내용이 모호하다. 대행사가 매장을 모집하게 하고 싶다")
v1 은 구조 설명이었고 "그래서 내일 어디 가서 뭘 하면 얼마가 남는가"가 없었다. v2 는 순서를 행동으로 바꿨다:
한 장 요약 → 이용권 예시(가격) → 돈 흐름 → **매장 1곳 단위 경제(가정 공개, 차트)** → **사장님 셈법** →
**데려올 매장 체크리스트 6** → **등록 10분 절차** → **설득 대본 + 거절 5 응답** → 인플루언서 5단계 →
주간 루틴 + 화면 6 → 사장님 안심 4 → 유어딜 지원 6 → **8주 파일럿 조건** → 손님 경험 → FAQ·CTA.
새로 확인한 사실: 매장 등록 = 사업자번호·대표자명·개업일 국세청 진위확인 + 카카오맵 장소 연결 + 채널 선택 + 확인 PIN
(`seller-stores.routes.ts`, 사장님 서명 불필요·대행사 계정으로 등록). 정산 = `used` 이용권만 주간(`auto-settlement.ts`).

## v3 (대표 피드백 "Pretendard, 더 세련되게, 실제 모바일 화면을 적재적소에")
- 글꼴 Pretendard(OTF 를 `~/.fonts` 에 두고 렌더). 여백 넓힘(M 0.75), 카드 줄이고 hairline·여백 위주, 제목 자간 −0.6.
- 라이브 모바일 캡처 4장(`scripts/capture-proposal-shots.mjs`, NODE_PATH 로 playwright-core·sharp 를 빌려 실행)을
  폰 프레임으로 1(홈)·3(상세+사용안내)·7(유어샵)·9(상세)·15(4장 전부)에 배치. 유어샵은 cropTop 없이 재캡처.
- 🩸 **틀렸던 것 2건**: ① pptxgenjs `addImage({rounding:true})` 는 둥근 모서리가 아니라 **원형 크롭**이다.
  ② `sizing:{type:'crop', w,h}` 의 w·h 는 **인치**이지 비율이 아니다(1×1 인치로 그려졌다). `cover` 로 교체.
- 5·6 장 구조 정정(대표 지적): 매장 몫 95% 안을 인플루언서 소개비 / 대행사 보수 / 매장 순수취 **세 갈래**로.
- 폰 프레임(대표 *"테두리가 엉망"*): 도형 위에 네모 캡처를 얹던 것을 `phone-frame.mjs`(sharp 합성 PNG: 둥근 화면·베젤·그림자)로 교체.
  시안 4종(`phone-frame-styles.png`)을 보내고 A(minimal)로 빌드. `PHONE_STYLE` 로 교체 가능.
- 셀러 대시보드 화면(대표 *"계정 없어도 들어가서 임의로 내용 만들 수 있지 않아?"* → 맞다): `capture-seller-shots.mjs` 가
  라이브 프론트에 `/api/seller/*` 만 예시 응답으로 끼워 넣어 `/seller/stores·influencers·operating·operators` 4장을 찍었다.
  로그인 0·프로덕션 쓰기 0(클라 가드 `isDashboardTokenUsable` 는 exp 만 본다). 8(매장 관리)·10(인플루언서 찾기 + DB 통계 열)·
  11(3장: 매장 관리/운영 요약/운영자 관리)·12(운영자 관리) 장에 배치, 캡션에 "예시 데이터로 렌더한 실제 화면".
  🩸 stores 페이지 에러 경계: 알림 벨·유입 바인딩 401 throw + `ReviewBonusCard` 가 `[]`.amount 를 읽음 → 엔드포인트별 명시 모킹으로 해결.
  pptx 는 프레임 PNG 를 1200px 로 줄여 7.5MB(줄이기 전 12MB).

## v4 (대표 *"이 PDF 최대한 참고해봐"* — 참고 PDF "유어딜 중개사 파트너 제안" 5장 A4)
참고 PDF 의 골격을 16:9 덱에 옮겼다(17장). 가져온 것: 표지 문장 "매장을 데려오시면 유어딜은 5%만 가져갑니다" + 5%/95%/0원 ·
돈 흐름도(손님→카드사 2.75%→유어딜 5%→매장 95%→귀사 보수) · "흔한 오해/실제" · 규모별 표(10/30/100/300곳, 귀사 3% 예시) ·
객단가 변수(숙박 155,824 = 식사의 4.8배) · 운영자 권한 가능/차단 표 + "제가 통장을 못 건드립니다" · 정직 고지(귀속 미추적 · 초기 상태 · 대표 인용) ·
시작하는 방법 3단계 · 기준일 각주. 단위 경제(5·6장)를 참고 PDF 기준(평균가 32,339원 · 하루 1건 · 보수 3% 예시)으로 통일해 문서 안에서 가정이 하나다.
- **참고 PDF 숫자를 라이브로 재검증**: 활성 338 = demo-deal-* 286 + seller_id 없는 숙박 51 + 실제 매장(홍대돈까스) 1. 식사 평균 32,339(242개)·숙박 155,824(51개) 일치.
- 🩸 **참고 PDF 의 오류 1건을 고쳐 적었다**: "채널은 나중에 어드민에서만 바꿀 수 있다" → 코드는 매장 소유자도 바꿀 수 있다(`seller-stores.routes.ts` `POST /stores/:id/channel`, 소유자 403 가드). 덱은 "매장 주인이나 유어딜만"으로.
- 🩸 **표 객체는 PDF 에서 자간이 벌어진다**: pptxgenjs `addTable` 셀은 UNO 문단 보정이 안 먹어 "10 곳 · 970 만원"으로 렌더 → 텍스트 상자로 교체. `export-pptx-to-pdf.py` 는 표 순회 API(`getRows().getCount()`)로 고쳤다.
- 🩸 **블록 치환 스크립트가 16·17장을 통째로 지웠다**: 뒤에서부터 치환하면서 n=15 의 "다음 마커(16)"가 이미 17로 이름이 바뀌어 있어 끝까지 잘라 냈다. 파일 끝을 확인해 복구. 마커 번호를 바꾸는 치환은 한 번에 조립할 것.
