## 4. 원본에서 **바꾼 것 둘** (그대로 안 가져왔다)

원본 조각을 읽다가 결함 둘을 찾아 이 조각 안에서 고쳤다. 둘 다 라이브에서 지금 당장
터지지는 않지만, 터질 때 **에러 없이 조용히** 틀린다.

### ① 본진을 조회 조건에서 제외 (`m.id != MAIN_MALL`)

원본 `stampOrdersMall` 은 `consumer_path=1 · active=1` 만 걸렀다. 형제 함수
`stampConsumerMall` 은 **본진을 명시로 건너뛰는데**(`if (mid !== MAIN_MALL)`) 이쪽엔 그 조건이 없었다.

라이브 실측(D1): `id=1 유통스타트 consumer_path=0` — **지금은 안 걸린다.** 다만 누가 그 플래그를
켜는 날 **모든 유어딜 주문 카드에 `🏪 유통스타트`(도매 브랜드)가 찍힌다.** 소비자 화면에 도매몰
이름이 뜨는 것은 서비스 분리 위반이다. 조건 한 줄에 드는 값이 0원이라 적어 뒀다.

### ② 한 주문에 두 가게가 섞일 때 승자를 규칙으로

장바구니는 가게를 안 가리므로 한 주문에 두 몰의 상품이 들어갈 수 있다. 원본 SQL 은
`GROUP BY oi.order_id` 하나라 **어느 행이 살아남는지 SQLite 마음**이었다 — 같은 주문이
새로고침할 때마다 다른 가게 이름으로 보일 수 있다.

⇒ `GROUP BY oi.order_id, m.id` + 순수 함수 `pickOrderMall`:
**품목 수가 많은 가게, 같으면 id 가 작은 쪽**(먼저 만들어진 가게 — 임의가 아니라 고정).
원본 PR 도 나중 커밋(`6dc400ca3`)에서 같은 방향으로 고쳤다. 그 커밋의 나머지(서버 신호 승격·
다크 색 파생)는 이 조각 범위 밖이라 안 가져왔고, 결정 로직만 같은 모양으로 맞췄다.

## (b) 입력 22개가 한 번도 안 재지고 있었다 — 그리고 그중 하나는 실제로 안 보였다

`check-dark-contrast` 는 화면을 **실제로 렌더해** 글자/배경 대비를 재는 유일한 가드다. 그런데
**입력을 가진 소비자 화면 6곳이 목록 밖**이었다. 전역 `.dark input`(특이도 0,5,1)이 요소의
`text-gray-900`(0,1,0)을 **언제나** 이기므로, 안 재는 입력은 "괜찮다"가 아니라 **모른다**다.

목록에 넣자마자 **실측 결함 1건**이 나왔다:

```
정산 신청 (/influencer/settlement)
  <p> "현금 송금"   대비 1.07:1   (밝은 표면 위 밝은 글자)
  글자 rgb(255,255,255) / 배경 rgb(248,247,252)
```

원인은 오타가 아니라 **되다 만 팔레트 이행**이다. 선택된 칸이 `bg-blue-50`(다크 짝 없음)로 남아
다크에서도 밝은 판인데, 안의 글자는 `dark:text-white` 로 흰색이 됐다. **바로 옆 칸은 이미
`bg-brand-tint`**(다크에서 `#16243D` 로 뒤집히는 토큰)를 쓰고 있었다 — 같은 토큰으로 통일.

🔬 추측으로 안 고쳤다: 조상 체인의 `backgroundColor` 를 브라우저에서 직접 찍어
`button.bg-blue-50 → rgb(248,247,252)` 를 확인한 뒤 고쳤다.

**⚠️ `/mypage/addresses` 는 이미 목록에 있었는데도 입력 9개가 통째로 안 재지고 있었다** — 폼이
모달 뒤라 닫힌 목록만 쟀다. **경로가 목록에 있다고 그 화면의 입력이 재진 게 아니다.**
⇒ `open` 손잡이(`data-testid="address-add"`) + `open` 이 **배열**(2단 깊이 모달)도 받게.

**못 여는 것은 지우지 않고 사유와 함께 적어 뒀다**(다음 세션이 같은 조사를 처음부터 다시 하지 않게):

(`/api/orders` 스텁 필요) · `SuggestionModal`(카카오 지도 핀이 있어야 함 — 스텁 불가) ·

### 🩸 그리고 **내가 만든 검사가 flake 를 만들었다** (같은 날 발견)

어제 넣은 "경로별 안 그려짐 = 실패"(`r.n < 5`)가 **빌드 직후 실행에서 간헐적으로 빨개졌다**:
