# 2026-08-24 — 은퇴가 레인 하나에만 걸려 있던 것 (유어애즈)

대표 *"이제 영구적이야?"* **3회차** 점검. 앞선 두 번은 제가 갭을 짚었지만, 이번엔 **코드를 직접 확인**해서
답했고 그 과정에서 **제 어제 작업의 누락**을 찾았다.

## 무엇이 반쪽이었나

자동 은퇴(`suppressedSubcats`)를 `collect-webkr` 에**만** 배선했다. 그런데 `collect-company` 도
**같은 웹문서 검색**을 돌려 같은 `source='webkr'` 행을 만든다. 수율 표는 두 레인의 행을 **합쳐서** 세므로:

```
webkr 레인  : 간판 은퇴 → 안 돎
company 레인: 간판 그대로 돎 → 행이 쌓임 → 그 행이 자기 수율 통계를 갱신
⇒ 은퇴시킨 업종이 다른 문으로 들어와 자기 판정 근거를 스스로 만든다
```

⚠️ 어제 커밋 메시지에 *"collect-company 는 의도적으로 손대지 않았다"* 라고 썼는데, 그건 **부기** 얘기였다.
**은퇴까지 안 걸린 건 의도가 아니라 누락**이다. 그 문장이 다음 세션에 "검토된 결정"으로 읽힐 뻔했다.

## 수리 — 레인 전체가 아니라 **웹문서 단계만**

이 레인은 [지역검색 → 카카오 → 웹문서] 를 순차로 돈다. 앞의 둘은 수율 표가 심판하는 대상이 **아니다**
(표는 `source='webkr'` 만 센다). 통째로 막으면 심판한 적 없는 지도 수집이 죽는다.
⇒ `webBlocked` 판정을 웹문서 호출 조건에만 걸었다. `web_suppressed[]` 로 상태줄에 노출.

⚠️ **부기는 남긴다** — 그 키워드는 실제로 돌았다(지도·카카오를 했다). `collect-webkr` 이 부기를 빼는 것과
   다른 이유다: 거기선 아무것도 안 했지만 여기선 했다. **두 레인이 다르게 행동하는 데 이유가 있다.**

## 이번에 틀렸던 판단

1. **가드가 또 헛돌았다(3건 중 1건).** R4("레인 전체를 막지 않는다")를 *"어딘가에 continue 가 있나"* 로
   검사했는데, 주입은 `if (webBlocked) { …; continue }` 형태라 통과했다. → **판정 직후 분기 자체**를 앵커.
   오늘 같은 클래스로 **네 번째**(분모·순서·흘러내림·이번). 규칙으로 굳힌다:
   > 조기 반환/건너뛰기를 검사할 때는 **그 분기 문장을 잡아** `continue|return` 유무를 본다.
   > "파일 어딘가에 있나"는 가드가 아니다.
2. **정규식이 조건 안의 괄호에 걸렸다.** `if \(!webBlocked &&[^)]*\)` 로 썼는데 `(kw.tier ?? 9)` 의
   괄호에서 끊겨 늘 실패했다(빨간불이라 바로 발견). `[^)]*` 대신 `[\s\S]{0,120}?`.

## 다음 세션의 첫 액션

```sql
-- 메인 D1 d9530ba6-…
SELECT value FROM platform_settings WHERE key='ads_company_stats';   -- web_suppressed[] 확인
SELECT value FROM platform_settings WHERE key='ads_webkr_stats';     -- suppressed[] 확인
```
판정: **두 레인 모두에서** '간판 제작'·'현수막 제작'·'판촉물 제작'·'옥외광고'·'인쇄기획'
(전부 `간판·광고물 제작` 업종)이 건너뛰어지는가. 한쪽에만 뜨면 배선이 반쪽이다.
⚠️ 빈 배열이 곧 고장은 아니다 — 그 업종이 그 회차 회전 창에 안 뽑혔거나 탐침 회차(5회마다)일 수 있다.
여러 회차를 봐야 한다.

## 남은 것 (대표에게 보고한 그대로)

- **문턱값 15%/25% 는 여전히 고정 상수다.** 자동화된 것은 *판정*이지 *문턱*이 아니다.
  기저(현재 28%)가 크게 움직이면 재검토 필요. 절대 문턱 ↔ 상대 문턱은 각각 다른 실패 방식이 있어
  (상대로 바꾸면 전체가 나빠졌을 때 아무도 은퇴 안 함) **대표 판단 사항으로 남겼다.**
- **새 업종어 발명은 사람 몫.** 승격은 이미 격자에 있는 것을 넓힐 뿐이다.
