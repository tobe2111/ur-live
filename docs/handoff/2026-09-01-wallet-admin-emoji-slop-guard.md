## 🕳️ 가드가 **두 번째로** 헛돌고 있었다

`check-design-slop` 의 평면 그라디언트 검사는 이렇게 생겨 있었다:

```js
/bg-gradient-to-[a-z]{1,2}\s+from-(\S+?)(?:\s+via-(\S+?))?\s+to-([^\s"'`]+)/g
```

`from-` 다음에 **바로** `to-` 가 와야 매치된다. 그런데 이 레포는 변형을 섞어 쓴다:

```
from-gray-50 dark:from-[#0D0F12] to-white dark:to-[#0D0F12]
             ^^^^^^^^^^^^^^^^^^^ 여기서 매치가 깨진다
```

⇒ **매치 실패 = 0건 = 초록불.** 실제로 `CouponClaimPage` 는 다크 모드에서
`#0D0F12 → #0D0F12`(완전 평면)를 **세 줄** 갖고 있었고 `AboutPage` 도 한 줄 있었다.

🩸 **이 가드는 08-31 에도 같은 이유로 한 번 뚫렸다** — 그때는 인라인
`style={{ background: 'linear-gradient(...)' }}` 표기를 안 봤다. 가드 자신의 주석이
*"같은 클래스의 결함을 한쪽 표기법으로만 찾고 있었던 셈"* 이라고 적어 뒀는데, **한쪽 변형으로만**
찾는 같은 실수를 반복하고 있었다.

**수리**: stop 을 변형 접두사별로 묶어 그룹마다 판정. 투명도 접미사(`/20 → /10`)는 **떼지 않고**
비교한다 — `NotFoundPage` 의 `from-[#6b7280]/20 to-[#6b7280]/10` 은 같은 색의 **진짜 페이드**라
평면이 아니다(첫 시도에서 이걸 오탐으로 잡을 뻔했다).

## 테스트가 가드를 검사한다

`wallet-and-slop.test.ts` 의 4건은 **가드를 실제로 실행한다** — 임시 디렉터리에 합성 `.tsx`
트리를 만들고 `check-design-slop.mjs` 를 돌려 종료 코드를 본다. 양성 2 + 음성 2:

- 변형 stop 이 같은 색이면 **잡는가** (이번에 뚫려 있던 것)
- 붙어 있는 기본 stop 도 **계속 잡는가** (고치면서 원래 능력을 잃지 않았는가)
- 투명도만 다른 페이드는 **통과시키는가** (오탐)
- 진짜 그라디언트는 **통과시키는가**

## 남은 것

`VoucherTicket` 썸네일의 `from-[#F7F8FA] to-[#EFF1F4]`(채널차 6~8, 36px 박스라 사실상 안 보임)은

정해야 하고, 그건 오탐 위험이 있어 대표 판단 없이 넣지 않았다. 다음에 이 자리를 만지게 되면
후보로 올릴 것.
