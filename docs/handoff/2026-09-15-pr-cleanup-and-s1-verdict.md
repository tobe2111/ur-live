### ① 결재 파일에 "구현 안 됐다"고 적었는데 이미 다 돼 있었다

09-14 의 나(같은 세션 계보)가 손바뀜 결재를 기록하면서 **파일 위쪽을 안 읽고** 맨 아래에
*"아직 없음 — 승인은 됐고 구현이 안 됐다"* 를 적었다. 실제로는 09-08·09-09 세션이 전부 만들어
뒀다(`store-ownership-transfer.ts` 103 · `store-handover-guard.ts` 142 4경로 배선 ·
`handover-closeout.ts` 115 · 선행 3건 · 시험 5파일 88건 pass). 문서가 "아직 안 막았다"고 한
마감 payout 취소 구멍조차 `admin-payouts.routes.ts:523-566` 이 이미 `confirm_release` 로 막고 있었다.

🧭 **교훈**: 결재함은 "낡은 지도"가 되면 **가장 비싸다** — 다음 세션이 *있는 것을 다시 구현*한다.
결재 파일에 상태를 적기 전에 **파일이 아니라 코드를 먼저 본다.**

### ② `#1297` 을 "되살린다"고 계획했는데 되살릴 수 없었다

```
git merge-base origin/main origin/claude/commission-budget-procedure  →  (없음)
git diff <추정 base>...branch                                          →  1258 files
```
main 이 스쿼시 머지를 반복해 그 브랜치와 **공통 조상이 없다.** 브랜치 되살리기는 불가능하고,
가치는 ~110줄 엔드포인트 하나뿐이라 **현재 main 위에 다시 구현**했다. 원본과 다른 점:
`platform_revenue_untouched` 를 **판정에서 뺐다** — 2026-09-07 결재 Q4-2 로 07-08 원칙
(*"유어딜 5% 는 어떤 커미션에도 안 쓴다"*)이 폐기돼, 그 줄을 합격선으로 두면 **정상인 주문이
빨간불**로 보고된다. 주입 `🔍폐기된 07-08 원칙이 판정으로 되살아난다` 가 그 방향을 막는다.
