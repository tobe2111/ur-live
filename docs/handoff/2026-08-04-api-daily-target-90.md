# 2026-08-04 — 외부 API 일일 목표 90% (대표 지시 *"유료 api 각각 90%씩은 쓰자"*)

## 0. 먼저 알아야 할 것 — 이건 **늘리는 값이 아니라 멈추는 값**이다

실측(2026-08-04):

```
네이버 오픈API    396 / 25,000   (1.6%)
유튜브 units    3,100 / 10,000   (31%  ← 검색 24×100 + 성과측정 700)
유튜브 검색        24 / 90        (우리 자체 예산의 27%)
카카오 조회       360 / ?         (앱별 쿼터 — 코드가 모른다)
```

**오늘의 병목은 쿼터가 아니다.** 같은 시각 `23:00 KST` 틱 하나에서 네 레인이 CPU 한도로 죽었다
(`collect-commerce` · `collect-storeinfo` · `enrich-company` · `enrich-prospects`, 전부 8.1~8.6초).
서브리퀘스트 학습 상한도 38~60 으로 천장(60)에 붙어 있다.
⇒ **90% 목표를 넣어도 오늘 수집량은 1건도 안 는다.** 그래도 넣는 이유는 유료 전환이다:
천장이 60→900(×15)이 되면 쿼터를 넘겨 429 를 받기 시작하고, **실패 호출도 쿼터를 먹으므로**
회차 후반 작업이 통째로 버려진다. 90% 는 그때 멈춰 주는 브레이크다.

## 1. 무엇을 했나

| API | 전 | 후 |
|---|---|---|
| 네이버 | 카운터만 있고 **게이트 없음** | 22,500(90%) 에서 정지 |
| 유튜브 | 검색 90회 (=90%인데 우연처럼 보임) | `쿼터×90%÷단가` 로 **유도** + 테스트 고정 |
| 카카오 | 게이트 없음 | **그대로**(§3 참조) |

- `naver-api-usage.ts` — `NAVER_DAILY_TARGET_PCT=0.9` · `NAVER_DAILY_TARGET_CALLS=22,500` ·
  `noteNaverCall` 이 이제 **boolean 을 돌려준다**(false=쏘지 마라) · `armNaverDailyAllowance` ·
  `armNaverAndReadSettings`(레인이 원래 하던 설정 읽기에 얹어 **왕복 추가 0** 으로 장전).
- 래퍼 3곳(`fetch-with-err` · `contact-enrich` · `company-collect`)이 반환값을 본다.
- 장전: 인플루언서 레인 + **B2B 레인**. 쿼터는 앱 단위라 한쪽만 무장하면 다른 쪽이 그 위에 얹혀 넘긴다.
- `YT_SEARCH_BUDGET_DEFAULT = floor(10,000 × 0.9 / 100) = 90`. 100 으로 올리면 성과측정(1 unit)
  몫이 0 이 되어 하루 종일 403 (2026-07-27 실사고).

**기본값은 무제한(`allowance = null`)이다.** 무장을 잊은 레인이 *조용히 멈추는* 쪽보다,
*넘겨서 429 로 드러나는* 쪽이 낫다고 판단했다. 그 대가로 장전 한 줄이 사라지면 게이트가 **에러 없이
전면 무효**가 되므로, 그 경로를 주입 검증으로 막았다(아래).

## 3. 남은 것 — 대표 판단이 필요한 두 가지

### ① 카카오 일일 쿼터 숫자
앱별이라 코드가 알 수 없다. **카카오 개발자센터 → 내 애플리케이션 → 쿼터** 에서 로컬 API 일일 한도를
확인해 주시면 그 값의 90% 로 게이트를 넣는다. 지금 실사용 360회/일이라 **어떤 쿼터로도 1% 미만**이고,
게이트를 넣으려면 회차 시작에 읽기가 하나 더 들어 유료 전환 전에는 이득이 없다.

### ② 공개 페이지 크롤 — **쿼터가 아예 없는 축** (더 급하다)
연락처는 오픈API 가 아니라 이걸로 캔다:
```
rss.blog.naver.com/{handle}.xml     · m.blog.naver.com/{handle}  (브라우저 UA)
```
쿼터 0 · 계측 0 · 승인 0. 오늘 naver_blog 4,157건 측정 → **하루 4천~8천 요청**.
네이버 리드가 전체의 78%(39,833/51,345)라 차단당하면 연락처 수집의 주 경로가 멎는다.

🔴 **그런데 차단을 감지할 방법이 지금 없다** — `if (!res.ok) return ''` / `catch { return '' }` 라
429·403 이 "본문 없음"과 구별되지 않는다. 더 나쁜 건 그 0을 `suppressLowRotationYield` 가
**"이 키워드가 나쁘다"로 학습**해 억제한다는 것이다. 네이버가 막았을 뿐인데 멀쩡한 키워드가 영구히 꺼진다.
⇒ **유료 전환 전에** 이 축의 계측 + 별도 상한을 넣어야 한다(다음 세션 최우선).
