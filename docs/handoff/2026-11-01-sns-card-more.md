## 3. 무엇을 했나

### ⓐ 문구 SSOT `shared/sns-account.ts`

`account_type` 은 **이미 저장돼 있었는데** 화면이 안 썼다. 그래서 팔로워를 못 읽었을 때
`읽지 못했어요` 라고만 적었다 — 사장님의 최소 팔로워 조건이 그 숫자로 판정되는데 **사람이 고칠
길을 몰랐다.** 이제 `구독자 수를 숨긴 채널이에요` + `유튜브 스튜디오에서 공개하면 읽을 수 있어요`.

🔴 고칠 수 없는 경우(틱톡 심사 전)엔 **둘째 줄을 안 쓴다**. 빈말을 더하지 않는다.

### ⓑ 사진은 **R2 로 옮긴다** (시안에 없던 판단)

실측: 인스타가 준 사진 주소는 서명돼 있고 **`oe=` 가 4일 뒤 만료**다. 그대로 저장하면 연동
직후엔 보이다가 며칠 뒤 **조용히 사라진다**(사람 눈엔 고장, 로그엔 아무것도 없음).
기존 `rehostImageToR2`(내용 해시 키 — 사진이 그대로면 다시 저장하지 않는다)를 지난다.

🔴 이관 실패는 `null` 을 돌려주고 호출부가 `COALESCE` 로 **예전 사진을 지킨다**. 일시 장애로
멀쩡한 사진을 지우면 ⟳ 를 누를 때마다 사진이 깜빡인다.

### ⓒ 추이 — `user_sns_follower_snapshots`

`follower_count` 는 다시 확인할 때마다 **덮어쓴다.** 비교하려면 지난 값이 따로 남아야 한다.

- 연동·갱신 때 **하루 한 줄**(`INSERT OR IGNORE` + UNIQUE). 같은 날 또 눌러도 **먼저 읽은 값**이
  남는다 — 기준선이 최신으로 밀리면 추이가 언제나 "거의 0" 으로 수렴한다.
- 🔴 **`follower_count` 가 null 인 날은 안 적는다.** 0 으로 적으면 다음 주 추이가 `+9,283` 이 된다.
- 🔒 `external_id` 를 함께 적고 조회도 그걸로 거른다 — 계정을 갈아탄 사람에게 거짓 성장이 찍힌다.
- 기준은 **7일보다 오래된 가장 최근 스냅샷**(60일 안). 문구는 `12일 전보다 ↑ 120` 처럼
  **실제 날수**를 쓴다 — 스냅샷은 사람이 누를 때 쌓여서 "정확히 7일 전" 은 대개 없다.
- 🎨 색을 안 쓴다. 이 팔레트엔 **초록이 없다**(`tailwind.config.js` 가 장식 색조를 잉크로 중화).
- 해제하면 스냅샷도 지운다.

### ⓓ 화면

사진 40px + 로고 17px 배지. **사진이 없거나 죽으면 지금 로고 원으로 떨어진다**(빈 동그라미 금지).
아이디가 계정 링크가 되고, 버튼은 **언제나 제 줄**에 둔다 — 통계와 한 줄에 두면 숫자 길이에 따라
행마다 줄 높이가 갈린다(시안 렌더에서 드러났다).

## 4. 가드

`sns-card-more-2026-11-01.test.ts` **37건** + 주입 **14건**, 그리고 기존 25건까지 **39건 전부 빨간불 확인**.
절반이 반대 방향이다(정보를 더하다 지키던 것을 깨는 쪽).

🕳️ **기존 가드 하나가 낡아서 재조준했다(풀지 않았다)** — `sns-link-card-2026-11-01.test.ts` 의
*"읽지 못했다고 말한다"* 가 문자열 `수를 읽지 못했어요` 를 찾고 있었는데 그 문장이 SSOT 로 옮겨갔다.
불변식은 그대로 두고 **그 함수를 부르는지**를 보게 했다.

🩸 **내 새 단언 넷이 헛돌아 주입이 잡았다** — 전부 "한 자리만 보고 다른 자리를 놓친" 모양이다:
1. `COALESCE` 를 파일 전체에서 **한 번만** 찾아서, 갱신 쪽을 깨도 저장 쪽이 남아 통과했다 → 둘 다 센다.
2. `setDeadPhoto` 를 그냥 찾아서, **선언·초기화**에도 있으니 onError 분기를 통째로 지워도 통과했다.
3. `toContain('part=snippet,statistics')` 가 `...,contentDetails` 를 **통과시켰다**(비용 0 전제가 깨진다).
4. 굵기 검사가 **같은 class 속성 안**만 봐서 안쪽 span 의 `font-bold` 를 놓쳤다 → 굵은 글자 **개수**를 센다.

🩸 그리고 제 단언 하나는 **멀쩡한 코드에 빨간불**을 냈다 — `external_id` 재사용을 막으려다
`followerTrend(..., external_id, ...)` 라는 정당한 사용에 걸렸다. 물어야 할 것은 **공개 타입에
들어 있는가**였다.

## 6. ⚠️ 다음 세션이 알아야 할 것

### 🔴 추이는 지금 구조에서 거의 안 뜬다

스냅샷은 **사람이 연동하거나 ⟳ 를 누를 때만** 쌓인다. 7일 간격으로 두 번 누른 사람에게만 보인다.
실제로 쓰이게 하려면 **하루 한 번 모든 연동을 갱신하는 cron** 이 필요하고, 그건 플랫폼 API 를
사용자 수만큼 호출하는 일이라(토큰 재발급 포함) **별건으로 판단할 문제**다. 이번엔 안 넣었다.

### 키가 들어간 뒤 첫 연동에서 확인할 것

1. 인스타 `media_count`·`profile_picture_url` 이 **우리 앱 토큰으로도** 오는지(§1 ⚠️)
2. 사진이 `/api/media/uploads/sns/h/...` 로 저장되는지(`MEDIA_BUCKET` 바인딩 필요 — 없으면 사진만 생략)
3. **유튜브는 1시간 뒤에 다시** ⟳ — 재발급이 실제로 도는지는 거기서만 드러난다
4. 틱톡은 심사 전까지 팔로워가 **안 온다**(`—` 가 정상). 영상 수·아바타는 올 수 있다

### 안 고친 것

`—` 가 24px 굵게 떠서 글자가 아니라 **선처럼 보인다**(시안에도 그렇게 나왔고 대표가 그 그림을
보고 골랐다). 바꾸려면 "모르는 값에는 큰 숫자 자리를 아예 안 쓴다" 쪽이 맞아 보이는데,
그건 승인받은 그림을 바꾸는 일이라 묻지 않고 하지 않았다.

### 그대로인 것

유어샵 SNS(`users.*_url`, 손입력) ↔ 체험 SNS(`user_sns_links`, OAuth) **상호 참조 0건** ·
어드민에 체험용 콜백 주소 미표시 · 알림톡 7종 SENS 심사 · 신청권 staging 실결제 후 스위치 ·
SNS 키 등록(인스타 `app_id` null · 유튜브·틱톡 env 없음) — **라이브 연동은 여전히 0건**이라
새 필드는 첫 연동부터 채워진다(백필 불필요).
