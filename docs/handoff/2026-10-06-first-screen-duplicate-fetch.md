# 2026-10-06 — 첫 화면이 같은 것을 두 번 받던 것 (전수 수리 + 가드)

> 대표: *"마이 페이지에 로딩 속도? 문제 한번 확인해봐. **내 가게** 이 부분이 가장 늦게 떠."*
> 이어서: *"근본적인 문제를 모두 해결해줘. **다른 페이지들도 그런 경우가 많아.**"*

## 1. 다음 세션의 첫 액션

```bash
npm run build && node scripts/check-duplicate-fetch.mjs   # 소비자 13화면 중복 요청 전수
```
마지막 줄이 `✅ duplicate-fetch: 첫 화면 중복 요청 0` 이면 통과.
`🔴` 가 뜨면 그 화면이 **같은 경로를 두 번** 부른다 — 처방은 §3.

폭포(무엇이 언제 나갔나)를 직접 보려면:
```bash
node scripts/visual-preview.mjs --route=/user/profile --stores=1 --trace-api
# `--slow=250` 을 더하면 실제 서버에 가까운 지연에서 본다(겹침 버그는 즉답 스텁에선 안 보인다)
```

## 2. 무엇이 틀렸나 — 네 자리, 전부 같은 병

| 화면 | 무엇 | 전 → 후 |
|---|---|---|
| 홈 | `/api/banners` 를 자리(hero·inline·wide)마다 | **3회 → 1회** |
| 교환권 | 카테고리 자동선택이 **첫 응답을 버리고** 재요청 | **2회 → 1회** |
| 마이 | `판매 중 N개` 한 줄 때문에 상품 목록 전체를, 좌석 확정 **뒤에** | **직렬 2단 → 1단** |
| 전 화면 | CSRF 토큰을 변경 요청마다 각자 | 지도 **6회 → 1회** |

**넷 다 에러가 안 난다.** 빌드도 테스트도 초록이고 화면도 안 깨진다. 느릴 뿐이라
그 순간을 재 본 사람만 안다 — 사람에게 맡기면 반드시 다시 생긴다.

### ① 홈 배너 — 예열이 한 번도 안 맞고 있었다
자리마다 `?type=hero|inline|wide` 로 따로 불렀다. 그런데 cron 이 데우는 키는
**`/api/banners`(파라미터 없음)** 이고 엣지 캐시 키는 **path+query** 다 ⇒ 셋 다 **다른 키**.
같은 파일(`cache-prewarm.ts`)의 주석이 이미 그 규칙을 적어 뒀는데(*"SSR inject key 와 정확히
일치(path+query)"*) 배너만 어긋나 있었다. 예열 실패는 조용하므로 계속 초록불이었다.
⇒ 활성 배너를 **한 번** 받아(`['banners','all']`) 자리별로 **화면에서** 가른다.
⚠️ `useApiQuery` 는 `select` 를 **queryFn 안에서** 적용하므로 같은 키에 다른 `select` 를 주면
캐시가 서로 덮어쓴다 — **키 하나 + 전체 목록**이라야 안전하다.

### ② 교환권 — 데워 둔 응답을 받아 놓고 버렸다
```
+279ms  /api/products?...sort=price_low          ← SSR 시드·cron 예열과 같은 키
+420ms  /api/vouchers/categories
+491ms  /api/products?...&category=커피%2F음료     ← 첫 결과는 버려진다
```
2026-06-04 에 홈(embedded)에서 *"내용/URL 깜빡임"* 이라 부르며 **이미 없앤 그 현상**이
`/vouchers` 에만 남아 있었다. ⇒ **응답 핸들러의** 자동선택만 제거.
**기능은 안 사라진다** — 바로 위 `localStorage`(1시간) 분기가 **동기로** 자동선택하므로
재방문자는 종전과 똑같이 첫 카테고리가 잡힌 채 열리고 요청도 1회다.
바뀌는 건 **생애 첫 방문**뿐(시드가 이미 그린 '전체'를 가격순으로 본다).

### ③ 마이 내 가게 — 숫자 하나 때문에 목록 전체를, 그것도 2단으로
`work.products` 는 `판매 중 N개` **한 줄**에만 쓰였다. 그 요청은 `my-stores/summary` 가
좌석을 정해 준 **뒤에** 나가므로 직렬 2단이었다(실측 `+368ms → +518ms`).
⇒ 1단계 응답에 `active_products` 를 **이미 돌고 있는 병렬 묶음**으로 얹고(왕복 안 늘어남),
상품 목록은 **달라고 할 때만**(`withProducts`) 받는다.

🔁 **처음엔 `tool === 'vouchers'` 일 때만 켜게 썼다가 재조준했다** — 그 `Tool` 값 자체가
2026-10-01 시트 철거로 사라져 **TS2367** 이 잡았다. 지금 `work.products` 와 `toggleProduct` 는
**소비처가 0 이다**(grep 확인 — `SellerBundlesPage` 의 동명 함수는 자기 로컬 것이다).
그래도 훅의 파라미터와 쓰기 경로는 **남겨 뒀다**: 목록이 필요한 시트가 다시 생기면 `true` 를
넘기면 되고, 쓰기 앞 좌석 확인(`assertSeat`)은 `seller-inline-seat` 가 계속 지킨다.
⚠️ **기본값을 `true` 로 되돌리지 말 것** — 첫 화면 요청이 다시 하나 는다(되돌리면 새 시험이 빨간불).

### ④ CSRF — 쿠키를 세팅하는 건 응답이다
변경 요청(POST/PATCH/PUT/DELETE)마다 쿠키가 없으면 **자기가** 토큰을 받았다. 요청들이 겹친
구간에는 아무도 쿠키를 못 보므로 `readCookie` 가드로는 이 경쟁을 못 막는다 ⇒ **in-flight 공유**.

## 3. 규칙 (CLAUDE.md 방어선 표에 등재)

> 첫 화면(아무것도 안 누른 상태)에서 **같은 경로를 두 번** 부르지 않는다. 쿼리가 달라도 마찬가지다.
> 처방 둘: **한 번 받아 화면에서 가르거나**(홈 배너), **두 번째가 필요 없게 첫 응답에 실어 보낸다**(마이).

## 4. 🩸 이번에 틀렸던 판단

1. **`import('@/lib/api')` 31곳을 병목으로 의심했다.** 폭포에서 160ms 늦게 출발하는 것처럼
   보였기 때문이다. 재 보니 `app-utils` 는 **엔트리가 이미 preload** 하므로 네트워크가 아니었고,
   두 번째 측정에서는 간격이 **10ms**였다(첫 측정이 부하로 흔들린 것). **31곳을 고칠 뻔했다.**
2. **CSRF 수정이 안 먹는데 "고쳤다"고 할 뻔했다.** 소스엔 멀쩡히 보이는데 실측은 **6회 그대로**.
   번들을 뜯어 보니 `let csrfInFlight` 가 인터셉터 콜백 **안**에 들어가 있었다 —
   앵커를 함수 **내부** 주석에 잡았고, **들여쓰기가 0칸이라 눈으로는 안 보였다.**
   ⇒ *"소스에 있다"는 "동작한다"를 말해 주지 않는다.* 시험이 **중괄호 깊이**를 센다.
3. **라이브 API 를 curl 로 재서 앱 시간을 말할 뻔했다.** 아무 DB 작업도 안 하는 401 이
   **0.27~1.8초**로 흔들린다(컨테이너→프록시→CF 경로가 바닥이고 불안정). ⇒ 그 숫자로
   앱 지연을 말하지 말 것. 같은 화면 안의 **상대 순서**는 하네스가 정확히 준다.
4. **첫 시험이 "모든 인터셉터보다 앞"을 요구해 실패했다.** 인터셉터가 둘이라 helper 가
   그 사이에 있는 것이 정상이다 — 진짜 불변식은 *중첩되지 않았는가* 였다.

## 5. 못 한 것 / 가드가 못 보는 것

- **몇 ms 걸리는지는 안 잰다.** 스텁은 즉답이고, 세는 것은 **횟수**다.
- **직렬 2단은 횟수로 안 잡힌다.** 폭포를 사람이 봐야 한다(`--trace-api` 가 시각 + 청크를 찍는다).
  마이에 `my-stores/summary → seller/orders` 2단이 **남아 있다** — 그건 좌석이 정해져야 하는
  진짜 의존성이고 `PendingOrders`(눌러야 할 것)를 그린다.
- 상호작용 뒤(탭·스크롤·시트)의 요청은 범위 밖. 경로 목록이 곧 범위다.
- **`seller-work-seat-2026-09-25` 시험 셋을 재조준했다**(상품 경로를 전제하던 것 → 4번째 인자
  `withProducts: true`). 지우지 않았다 — 좌석 불변식은 그대로 살아 있다. 그 자리에 **동작**
  불변식 하나를 더 박았다: *기본 호출은 주문만 부르고 상품은 안 부르며, 그 회차를 실패로 세지 않는다.*
- 지도 `/api/kakao/place/address` ×5 는 **주소가 전부 달라** 정당하다 — 예외에 사유와 함께 올렸다.
  서버 백필(`ensure-geocode`)이 좌표를 채우면 저절로 0 이 된다.
- **라이브 판정(E4) 미실시** — 배포 후 대표 화면에서 `내 가게`의 `판매 중 N개`가 즉시 뜨는지,
  교환권 첫 진입이 한 번에 뜨는지 눈으로 확인이 필요하다.
