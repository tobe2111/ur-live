# 2026-10-13 · 홈 편성 섹션을 위치로 정렬 (+ 유어샵 관리 페이지 착수)

## 대표 지시
- *"메인에서 위치를 만약 설정하면 맨 위에 … 그 지역에 맞는 이용권이 가장 맨 위에 나와야 … 어드민에서 직접 설정을 하지 않는 한, 그 지역에 가장 가까운 이용권들을 보여줘"*
- 시안(라이브 데이터로 그린 3화면) → *"1,2 섞어서 하면 되겠구만"* = 내 위치(GPS) · 지역만 고름 **둘 다**.
- 같은 메시지 후반: 유어샵 관리 페이지 흐름·정산 화면 개선 + "프로필 편집에서" → "편집" + 아래에서 올라오는 시트.

## 한 것 (홈)
- 서버 `section-rules.nearOrderSql`: 반경 10km 안 = 실매장 먼저 → 가까운 순 / 밖 = 순수 거리순 / 좌표 없음 = 맨 뒤. 수동 섹션 무접촉.
- `/api/sections?near=` (0.02° 격자 재정렬 · L1 키 분리 · 응답 `near`). 위치 없으면 byte-동일.
- 화면 `resolveHomeNear` (GPS=좌표+km / 지역=시도 중심, km 없음) · 소제목 SSOT `nearSubtitle`.
- 쿠키 `ur_loc`(격자) · `ur_loc_n`(라벨) → 워커 SECTIONS 슬롯 + 서버 첫 화면 소제목. 잠금 파일 audit log 기재.
- 가드 `home-near-sections-2026-10-13.test.ts` + 주입 10건(전부 빨간불 확인).

## 틀렸던 판단
- 처음엔 서버 피드의 near 정렬을 그대로 쓰면 된다고 봤는데, 그 정렬은 **데모 후순위가 전 구간**이라 동탄에서 전주(165km)·방배(33km) 실매장이 맨 위가 된다. 실측으로 확인하고 "반경 안에서만 실매장 먼저" 로 바꿨다(시안에 명시해 확정받음).
- 경도 보정 주입이 처음엔 **통과**했다 — 픽스처에 동서/남북 비교 케이스가 없었다. 동쪽 7km vs 북쪽 8km 를 추가해 잡았다.
