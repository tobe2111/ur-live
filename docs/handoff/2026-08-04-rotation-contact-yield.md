# 📝 순환 축에도 연락처 목적함수 — 자동 조율의 나머지 절반 (2026-08-04)

대표: *"머신러닝처럼 계속 자동 조정되게끔 구현해줄래?"*

## 무엇이 빠져 있었나

같은 날 #1055 가 **"몇 명 모았나 → 몇 명 연락 가능한가"** 로 목적함수를 바꿨다. 옳은 방향인데
**닿는 범위가 절반**이었다: 그 감점은 `pickYtKeywords` **점수**에만 걸리고,
네이버/일반 키워드는 **커서 순환**(`buildRotationPools` → `cursor + i`)으로 뽑혀 점수가 아예 없다.

```
실측(2026-08-04, D1 전수 · 측정 완료분 기준 · 기저 26.7%)
  방배동 맛집  측정  46 → 이메일  0  (0.0%)   ← 미측정 358행이 대기 중
  금천 맛집    측정 188 → 이메일 11  (5.9%)
  관악 네일    측정  65 → 이메일  8  (12.3%)
  저수율(<15%) 16개가 측정의 10.7% 를 먹고 산출은 4.1%
```
⇒ **가장 쓸모없는 키워드가 아무 벌점 없이 같은 몫으로 돌고 있었다.**

## ⚠️ 분모가 다르다 — 이게 설계의 핵심이다

`influencer-keyword-yield.ts` 상단이 **네이버에 적용하는 것을 경고**한다:
*"네이버 확보율은 키워드 품질보다 우리 처리 상태에 좌우된다 — 벌주면 백로그를 키워드 탓으로 돌리는 것"*.
**맞는 지적이고, 분모로 해소했다**:

```sql
nb_measured  = COUNT(naver_blog AND perf_checked_at IS NOT NULL)   ← 측정한 것만
nb_contacts  = 그중 이메일 있는 수
```
아직 안 훑은 행은 **분모에도 분자에도 안 들어간다** → 낮게 나올 수가 없다.
증거가 모자라면(`< 40`) 판정 자체를 안 한다. ⇒ 그 반론이 구조적으로 성립하지 않게 된다.

## 왜 "머신러닝"이 아니라 밴딧인가

하는 일은 같다 — **관측 → 몫 조정 → 재관측**. 다만 학습 모델이 아니라 다중 슬롯머신이다:
· 피드백이 느리다(수집 → 측정까지 며칠) → 온라인 학습이 수렴하기 전에 세상이 바뀐다
· 팔이 ~300개뿐이고 특징이 없다 → 모델이 배울 게 "이 키워드가 잘 되나" 하나뿐이다
· **틀렸을 때 조용히 축을 죽인다** → 해석 가능해야 사람이 뒤집을 수 있다
⇒ 관측값 하나로 판정하고 **탐침 회차로 탐색(exploration)을 강제**하는 형태가 이 문제에 맞는 도구다.

| 상수 | 값 | 왜 |
|---|---|---|
| `ROTATION_EVIDENCE_MIN` | 40 | 미만은 판정 안 함 — 없으면 신규 축 차단기가 된다 |
| `ROTATION_OK_RATE` | 0.15 | 기저 26.7% 대비 확실히 낮은 쪽만 |
| `ROTATION_PROBE_EVERY` | 5 | 억제돼도 통과 → **판정이 스스로 뒤집힐 수 있다** |

## 비용 0 으로 얹었다

`recomputeKeywordContactYield` 가 이미 리드 테이블을 훑는다(정비 레인). 거기에 **조건부 집계**로
네이버 두 칸을 더 냈다 — **스캔 추가 0**. 쿼리를 둘로 두면 인덱스 없는 4.9만 행을 두 번 훑는다.

## 🔭 다음 세션의 첫 액션 (라이브 판정)

```bash
# 정비 레인이 recompute 를 돈 뒤(하루 2회), 키워드 테이블에 값이 붙었는지
#   → 그 다음 수집 회차의 last_keywords 에서 저수율 키워드가 **탐침 회차에만** 보이면 작동 중
curl -sS "https://live.ur-team.com/api/admin/ads/influencer-pool/stats" \
  -H "Authorization: Bearer $TOK" -H "User-Agent: $UA" \
  | python3 -c "import sys,json;r=json.load(sys.stdin)['run'];print(r['last_run'], r['last_keywords'])"
```
· 방배동 맛집·금천 맛집이 5회차마다 한 번만 등장 → 억제 작동
· 매 회차 등장 → `nb_measured` 가 안 채워졌거나(정비 레인 미실행) 배선이 안 닿은 것

⚠️ **이 변경이 못 보는 것**: 억제가 *옳은지*. 저수율의 원인이 **우리 추출기 결함**이면 억제는 손해다.
   탐침 회차가 증거를 계속 갱신하지만, 근본 확인은 **저수율 키워드 표본을 사람이 열어 보는 것**뿐이다.
