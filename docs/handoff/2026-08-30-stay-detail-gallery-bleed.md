# 2026-08-30 — 숙소 상세 사진만 여백이 있던 것

대표 스크린샷 + *"숙소 상세페이지의 사진만 여백이 있어. 숙소 이용권 상세페이지들 ui 수정해줘"*

## 원인 — 갤러리가 본문 여백 래퍼 **안**에 있었다

`StayDetailPage` 는 갤러리를 본문과 같은 `px-4 py-5` 래퍼 안에 두고 있었다. 같은
`DetailGallery` 를 쓰는데도 모바일에서 사진만 들여쓰기가 됐다.

라이브 실측 (390px, 갤러리 스크롤러 기준):

| | 공구/이용권 상세 | 숙소 상세 |
|---|---|---|
| 사진 x | **0..390** (풀폭) | **16..374** (358) |
| 상단 | 0 | **20** |
| border-radius | 0 | 0 |

정확히 `px-4`(좌우 16) + `py-5`(상단 20) 이다.

⚠️ **스크린샷만 보고 "둥근 모서리도 다르다" 고 볼 뻔했다** — 재 보니 양쪽 다 `radius 0` 였다.
저해상도 스크린샷에서 여백이 있으면 모서리가 둥글어 보인다. **눈이 아니라 계산값으로 판정할 것.**

## 수리

갤러리 래퍼에 `-mx-4 -mt-5 lg:mx-0 lg:mt-0`. 본문 여백은 그대로 두고 **갤러리만** 빠져나간다.
PC 는 되돌려 좌측 컬럼 안 카드로 유지 + 공구 상세와 같은 `lg:border` 추가.

검증(로컬 빌드에 라이브 API 를 물려 렌더):

```
모바일 360/390/430/767 → 전부 x[0..vw] top=0 ✅ (공구 상세와 동일)
PC 1440 → x[153..895] 폭 742 · radius 16px · border 1px (수리 전 152..896/744/0px)
```

## 🔁 숙소는 상세 개선에서 반복적으로 빠진다

이 파일은 **2026-08-19 에도 같은 이유로** 고쳤다. 그때 대표가 남긴 말이 파일 주석에 그대로 있다:

> *"숙소 이용권은 이용권 상세페이지가 함께 개선이 안됐네. 앞으로는 이런 개선은 다른 카테고리와
> 함께 개선이 되어야 해"*

그 수리는 제목·갤러리 컴포넌트는 맞췄지만 **바깥 여백은 못 맞췄다.** 두 번째 재발이다.
⇒ **이용권/공구 상세를 손대면 숙소도 같은 화면에서 함께 볼 것.** 가드를 그래서 넣었다.

## 이번에 틀렸던 판단

1. **스크린샷으로 "둥근 모서리" 를 오독**할 뻔했다(위 참조). 측정이 바로잡았다.
2. 갤러리 좌표를 재려고 셀렉터를 세 번 갈아엎었다 — `div` 중 "폭 큰 것"으로 고르면 최상위
   컨테이너를 잡고, "화면에 보이는 img" 로 고르면 캐러셀의 다음 슬라이드를 잡는다.
   결국 **`overflowX:auto` + `aspectRatio:1/1`**(DetailGallery 모바일 스크롤러의 고유 서명)로
   확정했다. ⇒ 좌표를 잴 땐 **그 컴포넌트만 가진 계산 스타일**로 앵커할 것.
3. 주석을 길게 달아 파일이 크기 래칫(888줄)을 7줄 넘겼다. rebaseline 대신 **주석을 줄였고**,
   상세 경위는 테스트 docblock 으로 옮겼다(그쪽이 읽히는 자리이기도 하다).
