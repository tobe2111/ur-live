# 2026-10-01 — 이용권 환불 요청이 "배송완료된 주문만"으로 막히던 것 (유어딜 · 소비자)

## 무엇이 문제였나
- 지갑 이용권 카드의 "사용 전이라면 환불 요청" → `POST /api/returns/request` → **400 "배송완료된 주문만 반품 신청이 가능합니다"**.
- 원인: `canRequestReturn`(src/shared/pickup.ts)이 주문을 **배송 / 픽업** 둘로만 판정했다. 이용권은 결제(PAID) 후
  매장 QR 로 소각될 뿐 `DELIVERED` 를 안 거쳐서 배송 게이트에 걸렸다. 2026-08-20 에 버튼을 달 때 서버 판정을 안 고쳤다.

## 수정
- 서버: `returns.routes.ts` 가 `vouchers.order_id` 로 이용권 수(전체/미사용)를 세서 `canRequestReturn({ voucher })` 로 넘긴다.
  이용권 주문 = PAID/DONE + 미사용 1장 이상이면 접수(기간 창 없음 — 판단은 운영자). **접수만 — 돈은 안 움직인다.**
- UI(대표 지시 "빨간 부분 없어도 되지 않을까, 환불요청 버튼만 따로"): 카드의 코드 줄 + 환불 링크 제거.
  환불은 '사용하기' 모달(QRModal)로: 결제 7일 내면 기존 즉시 취소, 그 뒤엔 "환불 요청" 접수 버튼.
- 테스트: pickup-model.test.ts +6.

## 대표 질문 답 — QR 스캔 사용처리 권한(코드 실측)
- `/v/:code` 의 1탭 사용처리 = `use-by-seller`: seller JWT 의 seller_id === 상품 seller_id 일 때만(다른 매장 403) · admin · 그 매장 스캔기기 키.
- 같은 화면 PIN 경로 `/use`: 매장 확인코드(store_verify_pin) 일치 필요, IP 5회/분.
- 손님 셀프 사용 `self-redeem`: 매장 확인코드 일치 필수(scan_only 매장은 차단). 대표가 본 403 은 코드 불일치 = 정상 차단.
