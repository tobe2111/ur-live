# 이용권 관리 — 수정·삭제·정가 (2026-09-14)

대표: *"이용권 관리 맡아서 해줘"*

## 재 본 것 (라이브 D1 실측 — 추측 아님)

셀러가 **소유한** 활성 이용권은 **1건뿐**이다. 나머지는 셀러 화면에 아예 안 뜬다.

```
활성 이용권 337   =  데모 285  +  실제 52
그중 seller_id 있는 것 → 1건   (2888 홍대돈까스, seller_id 14, 16,500 / 정가 25,000 = 34%)
group_buy_tiers 설정된 것 → 0 / 337
```

그 한 곳이 `/seller/group-buy` 에서 할 수 있던 일:

| | 종전 |
|---|---|
| 재발행 · 사장님 링크 복사 · 알림톡 | ✅ |
| **수정** | ❌ 진입점이 `restaurant_phone` **없을 때만** 뜨는 '연락처 등록 →' 배너 안에 있었다. 홍대돈까스는 연락처가 있어 **안 떴다** |
| **삭제** | ❌ 버튼 없음 (서버는 2026-05-15 부터 준비돼 있었다) |
| **정가 수정** | ❌ 서버는 `original_price` 를 검증·저장하는데 **화면이 안 보냈다** |

`/seller/products`(삭제·수정이 있는 목록)는 `SELLER_STORE_ONLY_MODE` 로 nav 에서 빠져 있어 우회로도 없었다.

⇒ "있다" 가 아니라 **"연락처 분기 밖에 있다"** 를 보도록 교체했다.

## 🔒 머니 경로가 아니다 — 근거

`original_price` 는 **표시 전용**이다. 청구액은 판매가와 공구 특가가 정하고, 청구 경로는 정가를
아예 `null` 로 넘긴다 — `worker/utils/gb-order-pricing.ts` 의 `resolveGbPricing(s, list, null, …)`.
그 한 줄을 테스트 ③ 이 고정한다(바뀌면 이 판단의 전제가 무너지므로 빨간불).
삭제도 soft delete 라 **이미 발급된 이용권은 그대로 쓸 수 있다.**

⚠️ `group_buy_tiers` 는 **손대지 않았다.** 2026-05-30 즉시판매 단일가 전환으로 폐기된 구 모델이고
라이브 337건 전부 `null` 이다. 여기에 입력칸을 다는 것은 가격의 두 번째 진실을 만드는 일이다.

## 이번에 틀렸던 판단

1. **"할인율 = `group_buy_tiers`" 라고 대표에게 보고했다 — 틀렸다.** 그건 폐기된 구 모델이고
   할인율은 정가 대 판매가다. 필드 이름만 보고 단정했다.
2. **"이용권 관리에 수정 버튼이 있다" 고 정정했는데 그것도 절반만 맞았다.** 문자열은 있지만
   `restaurant_phone` 이 없을 때만 렌더된다. **조건부 렌더를 grep 으로 판정하지 말 것.**
3. **주입 검증이 내 테스트 셋을 헛돈다고 잡았다** — ① `confirmDialog` 문자열만 봐서 호출을 막아도 통과
   ② 슬라이스 창이 **다음 함수까지 넘쳐** 옆 함수의 같은 패턴에 걸림 ③ `priceDisplay` 가
   **import 줄에 남아** 호출을 통째로 바꿔도 통과. 전부 "이름이 있는가" 를 본 탓이다 — **동작을 볼 것.**
4. **`check-guard-mutations` 는 `STRICT` 가 아니면 실패해도 종료코드 0 이다**(`process.exit(STRICT ? 1 : 0)`).
   rc 로 판정하면 빨간불을 초록으로 읽는다. **`✅`/`❌` 줄을 볼 것.**
5. **주입 앵커가 들여쓰기 때문에 두 곳에 걸렸다** — 22칸 앵커가 26칸 줄의 뒷부분과 부분일치한다.
   앵커에 className 을 붙여 고유화했다.
