**무엇이 문제였나**: `FETCH_TIMEOUT_FLOOR_MS`(1,500ms) 주석은
*"호출부의 마감 가드가 이미 '집을지 말지'를 정하므로, 일단 집은 항목에는 최소한의 기회를 준다"* 를 **전제**한다.
**그 호출부 가드가 없었다** — 루프는 마감을 *이미 지났을 때만* 멈췄다. 그래서 잔여 1~1,499ms 에 집은 항목이
바닥값 1.5s 를 받아 **확정적으로 마감을 넘겨 실패**했다.

실측(08-02 03:00): `tried 9 / measured 6 / failed 3` — **실패 3 = 동시성 3**(워커마다 마지막 1건).
그리고 그 리드는 실패 분기에서 **데이터 없이 `perf_checked_at` 도장**을 받아
22,000 깊이 큐 뒤로 밀리고 `nb_unmeasured` 집계에서도 빠진다 — **측정된 적 없는데 미측정으로 세어지지도 않는다.**

**검증**(npm 403 세션 — 전역 tsc 단독 컴파일 + 실행): 잔여 1~20,000ms **전수 20,000건**에서
"집기로 했으면 타임아웃이 마감을 안 넘는다" 위반 **0건**. 가드를 지우면 위반 **1,499건**(= 옛 동작의 폭).

## 3. 이번에 틀렸던 판단

1. **"측정이 직렬이라 느리다"** — 틀렸다. 이미 워커 풀 `Promise.all` + 건당 RSS/홈 병렬이다.
   `NAVER_CONCURRENCY = 3` 이 하드코딩일 뿐. **코드를 읽기 전에 가설을 말하지 말 것.**
2. **"배분이 병목"** — #943 을 만들 땐 그렇게 판단했는데, 실측 산술이 뒤집었다:
   격차 204/시간 대 측정 4.6/시간. 배분은 회차를 2배 할 뿐 **44배 격차를 못 닫는다.**
   #943 은 여전히 옳지만(드리프트 차단 + 피드백 2배) **백로그 해결책이 아니다.**
3. **`export type { X } from './y'` 가 로컬 스코프에 들어온다고 착각** — 재수출일 뿐이다.
   같은 파일에서 쓰려면 `import type` 을 따로 해야 한다. 스텁 타입체크가 잡았다.
4. **파일 크기 캡을 주석으로 넘겼다** — 595줄(캡 5줄 아래)인 파일에 긴 주석을 넣어 606줄.
