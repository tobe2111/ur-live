# 플랫폼 수수료를 부가세 포함으로 볼까, 별도로 받을까?

상태: approved
등급: C
역할: finance
올린 날: 2026-11-25
기한: 2026-12-01

## 질문
매장 수수료(직접 10% · 중개 5%)에 부가세가 포함된 것인가, 별도로 받는가?

## 근거 (실측)
- 판매자 약관(`src/pages/terms/seller-terms-content.ts`)과 대외 문구 어디에도 수수료 부가세에 대한 말이 없었다.
- 포함으로 보면 유어딜의 실제 수수료 매출은 받은 수수료의 10/11(직접 9.09% · 중개 4.55%). 별도면 수수료가 그대로 공급가액.
- 일반과세 매장은 유어딜이 발행하는 수수료 세금계산서로 그 부가세를 매입세액 공제받는다 → 실부담 그대로. 간이·면세 매장만 공제가 없거나 작다.
- 업계(오픈마켓·배달앱) 수수료는 부가세 별도로 표기하는 것이 일반적이다.

## 선택지
1. 부가세 포함 — 매장 문구 단순 / 유어딜 매출 −9%
2. **부가세 별도** — 업계 표준 / 일반과세 매장 실부담 0 / 약관 변경 고지 필요

## 기본안
2번.

## 롤백
어드민 `platform_settings.fee_vat_exclusive_from = off` → 그 순간부터 부가세를 떼지 않는다(재배포 없음). 이미 뗀 분은 원장 `platform:vat_payable` 에 남아 있어 금액이 그대로 보인다.

## 결정 (대표가 한 말 그대로)
- 2026-11-25 *"1번 부가세 별도로 하자. 그렇게 구현도 해줘."*
- 전권 위임(2026-11-25)에 따라 세션이 구현·사전 안내 발송까지 실행했다.

정리:
| 항목 | 값 |
|---|---|
| 수수료율 | 그대로(직접 10% · 중개 5% — 이 결정은 요율을 바꾸지 않는다. 중개 요율은 별도 결재 `2026-11-25-brokered-fee-margin.md`) |
| 부가세 | 수수료 × 10%, 매장 몫에서 함께 차감 |
| 시작 | **2027-01-01(KST) 이후 사용분**부터 — 약관 "불리한 변경 30일 전 고지" 충족(오늘 기준 37일) |
| 원장 | `platform:vat_payable`(부가세 예수금, 유어딜 수익 아님 · 지급 대상 아님) |
| 사전 안내 | 시작일 전까지 매일, 승인 매장마다 한 번씩 마이 '내 가게' 알림(`fee_vat_notice`) |
| 세금계산서 | 유어딜 → 매장 **정발행**(월합계 · 말일 작성 · 다음 달 10일까지). 발행 사업자 API 연동은 다음 단계 |

⚠️ 남은 것: 발행 사업자(볼타·팝빌·바로빌 등) 선택과 가입 — 대표(사업자 인증서 등록이 본인 확인을 요한다). 그 전까지는 홈택스 직접 발행.
⚠️ 하지 않은 것: 옛 매장용 역발행 코드(`settlement-tax-invoices.ts`)는 그대로 꺼 둔다 — 중개 구조와 방향이 반대.
