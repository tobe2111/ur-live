# 정산 승인을 임계값 아래에서 자동화할까 (원장 무결성 통과 + 건당 상한) — 송금 완료는 사람

상태: open
등급: C
역할: finance
올린 날: 2026-09-07
기한: 2026-09-14

## 질문
`payouts` 의 `pending → approved` 를 "원장 무결성 통과 + 건당 금액 상한 이하 + 셀러 정산계좌 검증됨"이면 자동으로 하고, **`sent`(실제 송금 완료 처리)만 사람이 하는** 규칙을 넣을까?

## 근거 (실측 2026-09-07)
- 정산 흐름: `payouts-generate` cron 이 주간 생성 → 어드민 `PATCH /admin/payouts/:id/approve`(사람) → `sent`(사람). 승인과 송금이 둘 다 사람 버튼이다.
- `ledger-integrity-check` cron 이 이미 매일 원장 무결성을 재고, approve 에 과다지급 가드가 있다(2026-07-01 audit log).
- 지금 payouts 0건. 볼륨 전에 규칙을 꺼진 상태로 넣어 두는 것이 목적. **머니 경로** — 단독 세션 + staging 실결제 + 게이트 기본 OFF.

## 선택지
1. **자동 승인 임계값(게이트 OFF 로 배포)**: 원장 무결성 최근 24h 통과 + 건당 ≤ N원 + 셀러 계좌 검증됨 + 해당 셀러 미해결 분쟁 0 → 자동 `approved`. 초과·미달은 사람 큐. `sent` 는 항상 사람. 게이트 `payout_auto_approve_enabled` + `payout_auto_approve_max_krw`(기본 OFF / 300,000)
2. 안 한다 — 승인·송금 둘 다 사람
3. 송금까지 자동(은행 API) — 지금 단계에선 권하지 않는다(돈이 나가는 스위치는 사람)

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
1. N = 300,000원. 이유: 승인은 "이 숫자가 맞다"의 검증이고 기계가 이미 원장으로 재고 있다. 송금은 "돈을 내보낸다"라 사람 스위치로 남긴다(운영 모델 원칙 4). 켜기 전 staging 에서 주문→원장→payout 생성→자동 승인→sent(사람) 1회 실측.

## 롤백
게이트 OFF(기본값) → 현행과 byte-동일. 자동 승인된 건은 `approved` 상태라 `cancel` 로 되돌릴 수 있다(sent 전).
