# 유어딜 DB(D1)에 한국 근처 읽기 복제본을 켤까요?

상태: approved
등급: C
역할: dev
올린 날: 2026-10-15
기한: 2026-10-22

## 질문
Cloudflare D1 읽기 복제(Read Replication)를 켜고, 손님 화면의 **읽기 전용** 요청만 복제본을 쓰도록 코드를 바꿔도 될까요? (예 / 아니오)

## 근거 (실측)
- 유어딜 DB(`toss-live-commerce-db`, 라이브 본진)는 **미국 동부(ENAM)** 한 곳에만 있고, 읽기 복제는 **꺼져 있다**.
  — CF API `GET /accounts/{acc}/d1/database/d9530ba6-…` 응답 `running_in_region: ENAM`, `read_replication.mode: disabled` (2026-10-15).
- 한국 손님의 요청은 한국 근처 Cloudflare 서버가 받지만, 캐시에 없는 데이터는 질의마다 **미국 동부까지 왕복**한다(추정 ~170ms/회).
- 그 결과의 한 예: 홈 "이런 이용권은 어떠세요?" 섹션 데이터가 캐시가 비면 직렬 17왕복(≈2.9초)이 걸려 첫 화면에서 빠졌다.
  → 같은 날 코드로 17 → 4왕복까지 줄였다(PR #1830). **왕복 수는 줄였지만 왕복 하나의 거리는 그대로**다. 이 결재는 그 거리를 줄인다.
- 실사용 성능 감시(7일 누적): 홈 LCP p75 3,396~4,340ms(기준 2,500ms 초과). 이 중 얼마가 DB 거리 때문인지는 **분리해서 재지 못했다**.
- ⚠️ 이 환경은 미국 서버를 통해 접속해 한국 체감 속도를 직접 잴 수 없다. 170ms 는 추정이다.

## 비용 (확인된 것 / 확인 못 한 것)
- **복제본 자체는 추가 요금이 없다** — Cloudflare 출시 공지: 복제본 생성과 요청 라우팅이 기본 가격에 포함
  ([changelog 2025-04-10](https://developers.cloudflare.com/changelog/2025-04-10-d1-read-replication-beta), [블로그](https://blog.cloudflare.com/fr-fr/d1-read-replication-beta)).
- 요금 기준은 지금과 같다 — **읽은 행 수·쓴 행 수**. 복제본에서 읽어도 한 질의가 읽는 행 수는 같으므로, 같은 트래픽이면 같은 양이 잡힌다.
  ⇒ 9/1 에 닿았던 **무료 일일 읽기 한도(500만 행)는 이 결정으로 늘지도 줄지도 않는다.**
- ⚠️ **확인 못 한 것**: 위 출처는 2025년 **베타** 공지다. 지금도 무료인지·무료 요금제에서도 켜지는지·한국/아시아 근처에 복제본이 생기는지는
  이 환경에서 Cloudflare 문서 원문이 막혀(프록시 403) 확인하지 못했다. **켜기 전에 대시보드 D1 → 설정 화면에서 확인**이 필요하다.

## 어떻게 동작하나 (요약)
- 켜면 Cloudflare 가 전 세계 지역에 **읽기 전용 사본**을 자동으로 만든다. 쓰기는 계속 미국 동부 원본 한 곳으로 간다.
- **켜기만 해서는 아무것도 안 바뀐다** — 코드가 "세션 API"(`env.DB.withSession(...)`)를 써야 복제본으로 간다. 안 쓰면 지금처럼 원본만 쓴다.
  ([공식 문서](https://developers.cloudflare.com/d1/best-practices/read-replication/))
- 사본은 원본보다 **잠깐 늦을 수 있다**. 그래서 결제·정산·환불·재고처럼 방금 쓴 값을 바로 읽어야 하는 경로는 **원본 고정**으로 둔다.

## 선택지
1. **켠다 + 손님 공개 읽기만 복제본** (권장)
   - 대상: 로그인 없이 보는 목록·상세 — 홈 섹션, 이용권 목록·상세, 교환권 목록, 유어샵, 블로그. (지금 서버가 첫 화면용으로 미리 받아 오는 그 요청들)
   - 제외: 결제·정산·환불·재고·딜·주문·어드민·셀러 대시보드 — 전부 원본 그대로(코드 무변경).
   - 장점: 한국 손님의 캐시 빈 요청이 미국 왕복 대신 가까운 사본에서 끝난다. 첫 접속 전반이 빨라진다.
   - 단점: 어드민이 상품을 고친 직후 몇 초간 옛 값이 보일 수 있다(지금도 화면 캐시가 2분이라 체감 차이는 거의 없다). 베타 기능.
   - 머니 접촉: **없음**(머니 경로는 원본 고정으로 명시하고 시험으로 고정한다).
   - 순서: ① 대표가 대시보드에서 켬(Workers & Pages → D1 → toss-live-commerce-db → Settings → Read replication) ② 세션이 코드 PR
     ③ 배포 후 SLO·TTFB 비교. **코드를 먼저 배포해도 무해**하다(꺼져 있으면 원본으로 간다).
2. **그대로 둔다** — 비용·위험 0. 한국 첫 접속은 미국 왕복을 계속 낸다. 캐시를 더 데우는 방식으로만 줄인다(효과는 인기 페이지에 한정).
3. **DB 를 아시아로 옮긴다** — 새 DB 만들어 이전. 쓰기까지 빨라지지만 데이터 이전·다운타임 위험이 크고 되돌리기 어렵다. 권하지 않는다.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
안 1. 추가 요금이 없다고 공지됐고, 머니 경로를 건드리지 않으며, 켜도 코드가 안 쓰면 지금과 같아 단계적으로 갈 수 있다.

## 롤백
대시보드에서 읽기 복제를 끈다(그 즉시 모든 질의가 원본으로 간다). 코드는 그대로 둬도 무해하다.

## 실행 기록
- 2026-10-15 21:4x KST — `PUT /accounts/{acc}/d1/database/d9530ba6-…` `{"read_replication":{"mode":"auto"}}` →
  재조회 `read_replication.mode`: **disabled → auto** (원본 지역 ENAM 그대로). 토큰에 D1 편집 권한이 있었다.
- 끄기: 같은 호출에 `"mode":"disabled"`.
- 판정: 홈 `/api/sections` 응답 헤더 `X-D1-Served`(`replica:<지역>` / `primary:<지역>`) + 다음 날 09:25 KST SLO 회차의 `/` TTFB·LCP.
