# 등록증 OCR 자동 승인 게이트(`ocr_auto_verify_enabled`)를 켤 것인가, 켠다면 어느 문턱으로

상태: approved
등급: C
역할: dev
올린 날: 2026-09-21
기한: 2026-09-28

## 질문
S-OCR-1(대표 실사진 5장) 통과 뒤 `ocr_auto_verify_enabled` 를 켤 것인가 — 켠다면 상호 대조를 ① 완전 일치·포함만(현행) ② 한 글자 차이(`near`)까지 허용 중 어느 쪽으로?

## 근거 (실측)
- 2026-09-21 라이선스 동의 뒤 합성 등록증 3종: 다른 구 → `mismatch`, 흐림 → `unreadable`, 게이트 OFF 12회 → 승인 상태 불변(S-OCR-2·3·4 통과). 출처 `docs/STAGING_CHECKLIST.md` S-OCR.
- 완전 일치 서류의 `match` 비율: 수리 전 0/5 → 재시도·도로명 붙이기(#1508) 배포 뒤 2/4. 나머지는 모델 빈 응답·산문 거절·한 글자 오독(`클로드`→`글로드`).
- 한 글자 오독은 `compareBizName` 이 **의도적으로** 안 봐준다(`korean-address.ts` 머리말: "오타를 교정하지 않는다 — 한 글자 차이를 같다고 우기면 방어가 통째로 무의미"). 2026-09-21 부터 `near` 등급으로 어드민에게 힌트만 준다(판정은 `review`).
- S-OCR-1(실사진 fill ≥ 0.75)은 아직 미측정 — 합성 문서는 폰트·해상도가 실물과 다르다.
- 이 게이트가 켜지면 `seller-profile.routes.ts /business-registration/ocr-verify` 가 `business_registration_status='verified'` 를 자동으로 쓴다(사람 승인 생략). 정산 게이트(`isPayoutEligibleSellerStatus`)는 별개라 돈은 여전히 어드민 매장 승인 뒤에만 나간다.

## 선택지
1. **켜지 않는다(현행)** — OCR 은 어드민 참고 자료. 장점: 위조 통과 위험 0 · 단점: 승인 대기 큐를 사람이 계속 본다. 머니 접촉 없음.
2. **S-OCR-1 통과 뒤 켠다, 문턱은 현행(완전 일치·포함만)** — 장점: 절반 안팎이 자동 승인(실측 2/4) · 단점: 한 글자 오독 서류는 계속 사람 큐. 머니 접촉 없음(정산 게이트 별개).
3. **켜고 `near` 까지 자동 승인** — 장점: 자동 승인 비율 ↑ · 단점: 남의 가게 이름에서 한 글자 바꾼 서류가 통과한다(파일 머리말이 금지한 그 경우). 권하지 않음.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
안 2. S-OCR-1 이 통과하면 켜되 문턱은 현행. 오독분은 사람 큐에 남는 것이 해가 없다.

## 롤백
`platform_settings.ocr_auto_verify_enabled=false` — 어드민 플랫폼 설정 한 줄. 이미 자동 승인된 매장은 어드민에서 개별 반려.

그 안 자체가 *"S-OCR-1(대표 실사진 5장) 통과 뒤"* 를 조건으로 달고 있고, S-OCR-1 은 아직 **미측정**이다
