# 숙소 이용권도 식사 이용권처럼 QR 로 체크인·사용 처리하게 할까요?

상태: open
등급: C
역할: planning
올린 날: 2026-10-25
기한: 2026-11-01

## 질문
숙소(날짜 예약 · 숙박권 둘 다)를 '내 이용권' 지갑의 QR 로 통일하고, 사장님이 QR 을 스캔하면 체크인(또는 숙박권 사용) 처리되게 할까요? — 1 / 2 / 3 중 하나.

## 근거 (실측)
- **지금은 QR 이 없다.** 숙소는 사면 '내 숙소'(`/my-stays`)에 글자 코드(`check_in_code`)만 뜨고 '내 이용권' 지갑엔 안 나온다(`src/pages/MyStaysPage.tsx:129`).
  사장님은 셀러 예약 목록에서 손으로 체크인/사용 처리한다 — 숙박권은 실제 투숙 날짜를 직접 입력(`seller-stays.routes.ts:589` `PATCH /stays/bookings/:id/use-voucher`).
  코드를 대조하는 서버 경로는 **없다**(코드는 알림톡·화면에 표시만).
- 식사 이용권은 [QR 보여주기 → 직원 스캔 → 끝] 이라 두 상품이 다른 절차를 쓴다(대표 *"숙소 이용권도 근데 qr 필요하지 않나?"*).
- **라이브 숙소 46개 전부 날짜 예약(`product_stay_info.sale_mode='date'`), 숙박권 0, 실매장 0(전부 데모), `stay_bookings` 0행** (D1 실측 2026-10-25). ⇒ 오늘 바꿔도 영향받는 실제 예약은 0건이다.
- **💰 사용 처리 = 환불이 끝나는 순간.** 미사용·미만료 숙박권은 셀프 취소 100% 환불이다(`stays-public.routes.ts:1191`). 그래서 스캔으로 사용 처리하는 길을 새로 여는 것은 머니 경로다.
- **🔎 함께 드러난 것(정산 — 확인 필요):** 쇼핑 주문 원장 적립은 이용권 카테고리를 건너뛴다("사용 시점에 원장 기록" 전제 — `order-ledger-credit.ts:57`). `stay_voucher` 도 그 카테고리인데, 숙소 체크인·사용 처리 경로(`seller-stays.routes.ts`)에는 원장 기록이 **없다**. ⇒ 숙소 매출이 자동 정산에 안 잡힐 수 있다. 실예약 0 이라 오늘 손실은 0. finance 가 별도로 판정할 것.

## 선택지
1. **QR 통일 + 정산 배선 한 묶음** — 숙소도 지갑에 QR, 사장님 스캔 → (숙박권이면 투숙 날짜 한 단계) → 체크인/사용 처리 + 그 시점 원장 기록.
   장점: 손님·사장님 절차 하나, 정산 구멍도 같이 닫힘. 단점: 범위가 가장 큼. **머니 접촉 있음**(사용 처리·원장) → 단독 세션 + staging 실결제.
2. **QR 만 통일, 정산은 별건** — 화면·스캔만 바꾸고 원장 기록은 finance 판정 뒤 따로.
   장점: 작게 나간다. 단점: 스캔이 생겨도 정산 구멍은 남는다. 머니 접촉 있음(사용 처리 = 환불 종료).
3. **지금 그대로(코드 표시 + 수동 처리)** — 상세 화면에 "이렇게 써요"(① 숙소에 연락해 날짜 정하기 ② 체크인 때 코드 보여주기 ③ 사장님이 처리)만 추가.
   장점: 머니 접촉 없음. 단점: 두 상품 절차가 계속 다르다.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
안 1. 실예약이 0 인 지금이 통일 비용이 가장 싸고, 정산 구멍은 숙소를 실제로 팔기 시작하면 바로 터지는 자리라 같이 닫는 게 맞다.

## 롤백
스캔 처리 경로를 게이트(`platform_settings` 플래그, 기본 OFF) 뒤에 두고, 끄면 종전 수동 처리만 남는다.
