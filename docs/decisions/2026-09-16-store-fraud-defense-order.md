# 매장 사칭 사기를 어떤 순서로 막을 것인가?

상태: open
등급: C
역할: finance
올린 날: 2026-09-16
기한: 2026-09-23

## 질문

사기꾼이 남의 가게를 자기 매장으로 등록해 이용권을 파는 것을 막는 데,
**(A) 돈이 나가는 출구를 막을 것인가, (B) 매장 정보를 지어낼 수 없게 입구를 바꿀 것인가.**

> 대표: *"리스크는 없어? 사기를 친다던지"* · *"그 전에도 사기꾼이 멋대로 이용권 기껏 유저들에게
> 팔았는데 사장님은 아예 모르는 단계라 난처해질 수 있잖아."* · *"전화보다 더 간단히 하는 법은
> 없을까? 무료로?"* · *"지금 하는게 가장 이상적인 방법인거야?"*

## 근거 (실측 2026-09-16)

### 🩸 먼저 제안한 안(예금주 검증)에 구멍이 있다

세션이 *"예금주 = 사업자등록증 상호 일치"* 를 무료·자동 처방으로 제안했는데, **한 가지 사기만 막는다**:

```
사기꾼이 자기 사업자등록증("김철수 컨설팅")을 올린다 → 매장 이름만 "장수국밥" 이라고 쓴다
  국세청 진위확인  ✅ 통과 (자기 번호)
  예금주 = 상호     ✅ 통과 (자기 상호)
  소비자가 사는 것  "장수국밥 이용권"
```

**남의 등록증을 훔칠 필요조차 없다.** 원인은 `seller-stores.routes.ts` 에 **매장 이름·주소를
사업자등록증과 대조하는 코드가 없다**(실측). 등록자가 매장 정보를 자유 입력하고 등록증은 별개로 검증된다.

### 지금 이미 있는 방어

- 매장은 `status='pending'` 으로 생기고 좌석 토큰은 `active|approved` 만 → **승인 전엔 판매 자체가 불가**
- 사업자등록증 사본 필수 + 국세청 진위확인(`ntsValidateBusiness`)
- 소유권 승계(`/store-claims`)는 **항상 어드민 수동 심사**
- 소스 주석이 이미 경고한다: *"사업자번호는 인터넷에 공개돼 있어서 번호 일치는 증명이 아니다"*

## 선택지

1. **출구 우선**(먼저 제안한 안) — 예금주 검증 · 신규 매장 한도 · 확인 통화.
   장점: 즉시 가능. 단점: **위 구멍으로 뚫린다**. 확인 통화는 사람 손이라 규모가 안 난다.
2. **입구 우선** — ① 사용 시점 정산(가져갈 돈을 0으로) ② 매장 이름·주소 == 사업자등록증 == 예금주를
   한 줄로 묶기 ③ 등록을 **주장(claim)** 으로 바꿔 가진 36만 곳에서 고르게.
   장점: 사기꾼이 셋(상호 도용 + 국세청 통과 + 그 상호로 계좌 개설)을 다 뚫어야 하는데 은행이 막는다.
   사람 심사가 필요 없어진다. 단점: ③은 구현이 크다. 💰 ①이 머니 경로 접촉.
3. **둘 다, 출구부터** — 1을 먼저 넣고 2를 나중에. 단점: 1이 뚫리는 걸 알면서 먼저 넣는 것.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
