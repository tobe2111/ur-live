# 회원 탈퇴 때 남은 딜·안 쓴 이용권·가게를 어떻게 처리할까?

상태: approved
등급: C
역할: planning
올린 날: 2026-10-19
기한: 2026-10-26

## 질문
탈퇴할 때 **돈이 걸린 것**(남은 딜 · 안 쓴 이용권)과 **가게**를 지금처럼 둘지, 아래 기본안(돈·가게가 남아 있으면 탈퇴를 막고 먼저 정리하게)으로 바꿀지 골라 주세요.

## 근거 (실측 — 코드)
지금 탈퇴(`DELETE /api/account/delete` → `src/worker/services/delete-account.service.ts`)가 하는 일:

| 자산 | 지금 처리 | 30일 안에 되살리면 |
|---|---|---|
| 남은 딜 | **즉시 0**(`zeroOutUserPoints`, 원장에 `account_deleted` 기록). 충전으로 산 딜과 무상 딜 구분 없음 | 안 돌아옴 |
| 안 쓴 이용권 | 손대지 않음 — 계정과 함께 잠듦(로그인을 못 하니 매장에서 못 씀) | 돌아옴 |
| 쿠폰 · 찜 · 단골 · 알림 | 즉시 삭제 | 안 돌아옴 |
| 구매 기록 · 리뷰 | 남음(배송 이름·연락처 익명화, 리뷰 이름 '탈퇴회원') | 돌아옴(리뷰 이름은 '탈퇴회원' 그대로) |
| 가게(사장님) | **손대지 않음** — 가게는 별도 신원(`seller-withdraw.routes.ts` 가 따로 있음) | — |

- 복원(`restoreUser`)은 users 한 행만 되살린다.
- 30일 뒤 cron 은 `deleted_accounts`(원본 이메일·카카오 id) 행만 지운다. 이용권은 끝까지 잠든 계정에 묶인다.
- 셀러 탈퇴는 이미 **미사용 이용권 · 미처리 주문 · 미정산 잔액이 있으면 막는다**(같은 파일 머리말). 손님 탈퇴엔 그런 막음이 없다.
- 이번 PR(화면)은 정책을 바꾸지 않았다. 탈퇴 화면이 위 표를 그대로 말하고, 그 사람의 실제 딜 잔액·안 쓴 이용권 장수를 보여 준다.
- ⚠️ 확인 못 한 것: 만료 자동환불 cron(`handleExpiredVoucherRefunds`)이 탈퇴한 계정의 이용권도 환불하는지, 딜 결제분이면 0 으로 만든 잔액에 다시 넣는지.

## 선택지
1. **지금대로** — 화면이 정확히 알려 주니 본인 선택에 맡긴다. 장점: 변경 0. 단점: 충전 딜·결제한 이용권을 모르고 잃을 수 있다(특히 이용권은 30일 뒤 영영 못 쓴다). 머니 접촉 없음.
2. **돈·가게가 남아 있으면 탈퇴를 막는다(셀러 탈퇴와 같은 방식)** — 안 쓴 이용권이 있으면 "먼저 쓰거나 환불 요청", 충전으로 산 딜이 남아 있으면 "환불 요청", 주인인 가게가 있으면 "가게 탈퇴 먼저"를 보여 주고 버튼을 막는다. 무상 딜(선물·보상)은 고지 후 소멸 그대로. 장점: 결제한 돈이 묶이지 않는다, 가게가 주인 없이 남지 않는다. 단점: 탈퇴가 한 단계 길어진다. 머니 접촉: 차단만(돈을 움직이지 않음).
3. **탈퇴할 때 자동으로 환불한다** — 안 쓴 이용권·충전 딜을 탈퇴 순간 카드/계좌로 돌려준다. 장점: 손님이 할 일 없음. 단점: 머니 경로 신규(환불 원장·실패 처리·계좌 수집), 단독 세션 + staging 실결제 필요. 머니 접촉 있음.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
안 2. 셀러 탈퇴가 이미 같은 원칙(돈·손님이 걸려 있으면 못 나간다)을 쓰고 있고, 돈을 움직이지 않아 머니 경로 위험이 없다. 쿠폰·찜·단골 즉시 삭제와 복원 범위(계정 + 기록)는 지금대로 둔다.
