## 질문
"매주 목요일(월~일 사용분)" 약속과 "영업일 10일 보류" 가 함께 설 수 없습니다. (1) 약속 문구를 실제에 맞춘다 (2) 보류를 줄여 약속에 맞춘다 (3) 그대로 둔다 중 무엇으로 할까요?

## 근거 (실측)
- 약속(2026-06-23 · 2026-11-03 대표 확정): 매주 목요일, 지난주 월~일 사용분. 쓰인 곳: `src/shared/partners-facts.ts` `storePayoutDay` · 사장님 정산 화면(`PayoutSheet.tsx` "다음 정산일") · 계좌 화면 · 입점 안내 FAQ · 인스타 DM 응대 문구.
- 보류(2026-09-21 · 09-23 대표 확정 "영업일 10일"): 토스가 카드 대금을 5영업일 뒤에 주므로 우리가 먼저 주지 않는다. 코드는 역일 14일(`payout-hold.ts` · `platform_settings.payout_hold_days`).
- 실제 순서(코드 확인): 사용 순간 매장 받을 돈이 장부에 적힌다 → 사용 뒤 14일이 지난 금액만 **월요일 09:45** 에 지급 대기 건으로 묶인다(`payouts-generate`) → 어드민이 승인·이체.
- 예: 11-04(수) 사용 → 약속대로면 11-12(목) → 실제 대기 건은 11-23(월)에 생긴다. **약속보다 11일 뒤**, 거기에 사람 손 이체가 더 붙는다.
- 사장님 화면은 날짜는 "다음 목요일" 을 보여 주고 금액은 보류가 걸린 장부를 보여 준다(금액은 "기다리는 돈" 으로 나뉘어 있다).
- 라이브 규모(2026-11-25): 지급 대기 1건 15,200원(그 매장은 계좌 미등록). 아직 약속을 어긴 실제 지급은 없다.
- 이 확인은 코드 읽기(조사 에이전트)와 라이브 설정 조회까지다. 실제 지급 주기를 한 번 돌려 본 것은 아니다.

## 선택지
1. **문구를 실제에 맞춘다**: "사용 후 약 2주 뒤 목요일에 정산" 처럼. 장점: 약속과 실제가 일치, 돈 흐름 변경 없음 / 단점: 영업 문구가 덜 매력적 / 머니 접촉 없음(문구·화면 날짜 계산)
2. **보류를 줄인다**: 예) 영업일 5일(토스 입금 직후). 사용 주의 다다음 주 목요일쯤. 장점: 약속에 가까워짐 / 단점: 토스 입금 지연·환불이 겹치면 우리가 먼저 내는 날이 생길 수 있다 / 머니 접촉: `payout_hold_days` 설정
3. 그대로 둔다. 단점: 매장이 늘면 "목요일에 안 들어왔다" 는 문의가 생긴다

## 기본안 (답이 없을 때 권하는 것. 자동 실행되지 않는다)
