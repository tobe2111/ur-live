- 빠르게 하는 쪽(병렬 검사·생성물 분리·푸시 전 검사 셋)은 효과가 컸다. 그런데 **"각 PR 은 통과했는데 합치면 깨지는 것"** 은 줄지 않았다 —
  이건 속도로는 못 고친다. 합친 상태를 검사한 적이 없기 때문이다.
- 원인이 확인된 셋은 전부 **여러 PR 이 같은 여유분을 나눠 쓴** 경우다:
  - 11/9 20시 — `src/worker/index.ts` 줄 수 상한(2672)을 두 PR 이 각자 지키다 합쳐서 1줄 넘김 → **배포가 약 30~40분 멎음**, 수습 PR #2248.
  - 11/9 22시 · 11/10 01시 — 첫 화면 무게 허용치를 두 PR 이 나눠 써 합쳐서 +1.5~1.6KB → 수습 PR #2257 · #2267.
  - 나머지 3번(11/5 둘 · 11/9 12시)은 원인을 따로 확인하지 않았다.
- 수습할 때마다 PR 하나(검사 11분 + 배포 9분)가 더 들고, 그동안 main 은 빨간 채로 다른 세션의 판정을 흐린다.
- 대기열은 "main + 줄 선 PR" 을 **합친 상태로** 검사한 뒤 통과한 순서대로 머지한다 — 위 셋은 머지 전에 걸러진다.
  준비는 이미 돼 있다(`verify.yml` 의 `merge_group` 트리거, 2026-11-03).

## 선택지
1. **옮기고 켠다** — 합친 결과로 main 이 빨개지는 일이 머지 전에 걸러진다. 세션이 main 을 손으로 합칠 일도 준다.
   대표가 할 일(약 15분): ① github.com 에서 무료 조직 만들기 ② 저장소 Settings → Transfer
   ③ Cloudflare Pages(`ur-live`·`ur-wholesale`·`ur-ads`) Git 연결 다시 잇기 ④ Claude GitHub 앱을 조직에 설치
   ⑤ main 규칙에 "Require merge queue" 켜기. 옛 주소는 GitHub 이 자동으로 넘겨 준다. 머니 접촉 없음.
   단점: ③을 놓치면 배포가 멈춘다 — 옮긴 직후 배포 한 번을 세션이 확인한다.
2. **"최신이어야 머지" 만 켠다**(옮기지 않음, 지금 저장소에서 바로 가능) — 합친 상태 검사는 생기지만,
   머지가 하나 들어갈 때마다 **다른 열린 PR 전부가 main 을 다시 합쳐 11분씩 다시 돈다**. 세션이 여럿 동시에 도는
   이 레포에선 취소율이 다시 오른다(11/3 이전 상태로).
3. **지금처럼 둔다** — 주 4~6번 main 빨강 + 수습 PR 을 계속 낸다.
