# 유어샵 진열 카드를 누를 때 화면 전체를 다시 불러오는 것을 앱 안 이동으로 바꿀까요?

상태: approved
등급: C
역할: dev
올린 날: 2026-10-15
기한: 2026-10-22

## 질문
유어샵(`/u/:handle`)에서 이용권을 누르면 지금은 페이지 전체를 새로 불러옵니다(약 2초, 로딩 화면이 뜸). 소개 클릭 기록을 지키면서 앱 안 이동으로 바꿔도 될까요? (예 / 아니오)

## 근거 (실측)
- 2026-10-15 라이브 측정(아이폰 13 에뮬): 유어샵 진열 카드 탭 → `window.location.replace('/u/:handle/p/:id')` → 서버가 클릭을 기록하고 상세로 302 → **전체 새로고침 약 2.1초, 그동안 유어딜 로딩 화면**.
- 같은 날 홈 카드 → 상세는 **87ms**(미리받기 적중, 로더 0프레임). 지도 카드는 이번 PR #1830 으로 같은 수준이 됐다.
- 이 경로가 느린 이유는 코드가 아니라 **설계**다: 클릭 기록(소개 커미션 귀속)을 서버 리다이렉트 한 번에 맡겨 두었기 때문.
- 정정(같은 날 코드 확인): 숙소 핀이 `/pass/:id?aff=` 로 가도 귀속은 걸린다 — 전체 새로고침이라 앱 시작 시 `App.tsx` 가 `?aff=` 를 전역으로 잡는다. 앱 안 이동으로 바꾸면 그 전역 포착이 안 돌므로 **카드에서 직접 저장해야 한다**(안 1 의 ①).

## 선택지
1. **앱 안 이동 — 귀속은 지금과 같은 함수로, 클릭 집계만 비콘** (2026-10-15 코드 확인 후 권장안)
   - 확인한 사실: 커미션은 **클릭 기록(`pin_click_logs`)이 아니라 결제 때 실어 보내는 소개 값**으로 정해진다.
     클릭 기록은 유어샵 통계(클릭 수)에만 쓰인다. 지금의 서버 경유는 그 소개 값을 `?aff=` 로 붙여 주는 역할뿐이다.
   - 방법: 카드를 누르는 순간 ① 하드로드 때 앱이 하는 것과 **같은 함수**(`captureInflowRef` + 소개 값 저장 SSOT
     `affiliate-ref-store`)로 소개 값을 저장 ② 클릭 기록은 `navigator.sendBeacon` 으로 서버에 보냄
     ③ 상세로 앱 안 이동(미리받기 적용). 바깥에 공유된 `/u/:handle/p/:id` 링크(카톡·SNS)는 **지금처럼 서버 경유 유지**.
   - 장점: 약 2.1초 → 홈 카드 수준(0.1초대). 소개 값 저장이 종류와 무관하게 한 곳에서 일어나 **숙소도 정확히 `/stays` 로**
     가면서 귀속된다(지금은 숙소를 `/pass` 로 보내야만 귀속이 걸린다).
   - 단점: 비콘이 유실되면 **클릭 수 통계가 1 모자란다**(커미션에는 영향 없음). **머니 접촉 있음**(소개 귀속 경로를 옮긴다)
     → staging 에서 유어샵 카드 → 결제 1건으로 커미션 적립 확인 필요.
2. **그대로 둔다** — 유어샵에서 들어오는 손님만 매번 2초 로딩.
3. **서버 경유 유지 + 로딩만 줄이기** — 리다이렉트 응답을 가볍게 해도 전체 새로고침 자체(앱 다시 부팅)가 남아 1초대 아래로는 못 간다.
