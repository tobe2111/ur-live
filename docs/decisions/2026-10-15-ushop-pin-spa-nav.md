# 유어샵 진열 카드를 누를 때 화면 전체를 다시 불러오는 것을 앱 안 이동으로 바꿀까요?

상태: open
등급: C
역할: dev
올린 날: 2026-10-15
기한: 2026-10-22

## 질문
유어샵(`/u/:handle`)에서 이용권을 누르면 지금은 페이지 전체를 새로 불러옵니다(약 2초, 로딩 화면이 뜸). 소개 클릭 기록을 지키면서 앱 안 이동으로 바꿔도 될까요? (예 / 아니오)

## 근거 (실측)
- 2026-10-15 라이브 측정(아이폰 13 에뮬): 유어샵 진열 카드 탭 → `window.location.replace('/u/:handle/p/:id')` → 서버가 클릭을 기록하고 상세로 302 → **전체 새로고침 약 2.1초, 그동안 유어딜 로딩 화면**.
- 같은 날 홈 카드 → 상세는 **87ms**(미리받기 적중, 로더 0프레임). 지도 카드는 이번 PR #1830 으로 같은 수준이 됐다.
- 이 경로가 느린 이유는 코드가 아니라 **설계**다: 클릭 기록(소개 커미션 귀속)을 서버 리다이렉트 한 번에 맡겨 두었기 때문.
- 별건: 숙소 진열 카드는 `/pass/:id?aff=` 로 가는데 숙소 상세(`StayDetailPage`)는 `?aff=` 를 읽지 않는다 — 그 경로는 지금도 귀속이 안 될 수 있다(미검증).

## 선택지
1. **앱 안 이동 + 클릭 기록은 비동기로** — 누르면 바로 상세로 가고(미리받기 적용, 0.1초대), 같은 순간 `navigator.sendBeacon` 으로 클릭을 기록한다. 장점: 유어샵에서 이용권까지가 홈과 같은 속도. 단점: 비콘이 유실되면 그 클릭의 소개 귀속이 빠질 수 있다(브라우저가 거의 보장하지만 100%는 아님). **머니 접촉 있음**(소개 커미션 귀속 경로).
2. **그대로 둔다** — 귀속은 지금처럼 서버가 확실히 기록. 단점: 유어샵에서 들어오는 손님만 매번 2초 로딩.
3. **절충** — 앱 안 이동으로 가되 귀속 값(`aff`)을 URL 에 실어 결제 시 서버가 다시 확인한다(기존 `?ref=` 24시간 저장과 같은 방식). 클릭 로그만 비동기. 단점: 손볼 곳이 1보다 많다.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
안 3. 속도는 안 1과 같고, 귀속은 결제 시점에 서버가 다시 확인하므로 비콘 유실이 커미션에 닿지 않는다.

## 롤백
유어샵 카드의 이동을 다시 `window.location.replace('/u/:handle/p/:id')` 한 줄로 되돌린다.
