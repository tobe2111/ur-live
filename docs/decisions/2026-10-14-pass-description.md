# 이용권 상세 310건의 검색 설명 — 화면 쪽 절반을 서버와 같은 함수로 모을까요?

## 질문
`/pass/:id` 의 **화면 쪽 설명**(`GroupBuyDetailPage.tsx` 의 `<SEO description>`, 잠금표 파일)을
서버가 쓰는 설명 생성기와 **같은 SSOT** 로 교체해도 될까요?

## 근거 (실측)
- 같은 `/pass/:id` 가 **설명을 두 벌** 낸다. `react-helmet` 이 서버 메타를 덮으므로
  **JS 를 렌더하는 Googlebot 이 받는 쪽은 화면 버전**이고, 네이버·카톡·AI 봇은 서버 버전을 받는다.
- 서버(이 PR 로 수리됨): `⭐4.7 서울 서초구 · 달빛한스푼 닭도리탕 31,000원 (정가 35,000원) 11% 할인 …`
- 화면(현행): `🎉 0% 할인! 달빛한스푼 닭도리탕 공동구매 - 0명 함께 구매 중, 31,000원`
  (실제 문자열의 `-` 자리는 줄표다)
- 화면 버전의 문제 셋 (전부 실측):
  - **줄표**: #79 가 **서버만** 고쳤다. 화면 쪽은 `src/pages/*.tsx` 라 anti-slop 가드 범위 밖.
  - **`0명 함께 구매 중`**: `group_buy_current` 중앙값 **0** · 샘플 60건 중 **59건(98%)이 0명**.
  - **`🎉 N% 할인!` 이 안 뜬다**: 뿌리인 선언 컬럼이 **45/45건 0**(서버와 같은 원인 — #85).
- 즉 **구글이 보는 쪽이 세 가지로 더 나쁘다**.
- 접촉은 `description` prop **1곳**이고 잠긴 항목(`__SSR_INITIAL_DETAIL__` 즉시 소비 ·
  CountdownRing · polling · below-fold lazy)은 전부 byte-불변.

## 선택지
1. 승인 — 화면 설명을 서버와 같은 SSOT 로. 두 벌이 사라진다 / 잠금표 파일 1줄 접촉 / 머니 접촉 없음
2. #35 와 함께 결정 — 제목·설명이 SERP 에서 함께 읽히므로 한 번에 본다 / 그때까지 구글은 현행을 본다 / 머니 접촉 없음
3. 반대 — 두 벌 유지 / 구글이 계속 `0명 함께 구매 중` 과 줄표를 본다 / 머니 접촉 없음
