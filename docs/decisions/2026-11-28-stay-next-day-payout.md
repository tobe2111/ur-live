# 숙소만 "체크인 다음 날 정산"으로 바꿀까요?

상태: open
등급: C
역할: finance
올린 날: 2026-11-28
기한: 2026-12-12

## 질문
숙소 이용권은 정산 보류 기준을 "체크인 후 14일"에서 "토스가 우리에게 입금한 뒤(결제일 + 약 5영업일) + 체크인 다음 날" 로 바꿔, 대부분의 숙소 예약을 체크인 다음 날 정산할까요?

## 근거 (실측)
- 숙소 사장님(플레이가비): 숙소는 보통 체크인 다음 날 정산받는다 — 매주 목요일은 늦다.
- 지금 실제 흐름(코드): 체크인 = 장부 적립 → 역일 14일 보류(`payout-hold.ts`) → 월요일 지급 대기 → 어드민 이체. **체크인 후 약 2~3주.**
- 보류의 목적은 "토스가 우리에게 주기 전에 먼저 주지 않기"(2026-09-21 대표 확정). 토스 카드 대금은 **결제일 기준 약 5영업일 뒤** 입금.
- 숙소는 대개 체크인 며칠~몇 주 전에 결제한다 → 체크인 무렵엔 이미 우리 통장에 있다. 지금 규칙은 결제일이 아니라 적립일(체크인)부터 14일을 세서 **이미 받은 돈을 2주 더 묶는다.**
- 2026-12-17 부터 직접 송금(결재 `2026-11-25-direct-payout-after-dec17`) — 송금은 은행 이체 API 계약 전까지 사람 손.

## 선택지
1. **숙소만 결제일 기준 보류 + 매일 정산** — 지급 가능일 = max(체크인 다음 날, 결제일 + 7일). 대부분 체크인 다음 날. 장점: 숙소 업계 관행과 같음 / 단점: 매일 이체 손이 간다(은행 API 전엔), 체크인 뒤 카드 취소·차지백은 먼저 낸 돈이 된다. 머니 접촉: 있음.
2. **숙소만 결제일 기준 보류 + 주 2회(월·목) 정산** — 체크인 후 길어야 3~4일. 이체 손은 주 2번. 머니 접촉: 있음.
3. **전 매장 공통으로 결제일 기준 보류로 바꾸고 주 1회 유지** — 이용권 전체가 빨라지지만 숙소 "다음 날" 은 안 됨.
4. 그대로 둔다 — 결재 `2026-11-25-store-payout-thursday-vs-hold` 에서 문구만 사실에 맞춘다.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
