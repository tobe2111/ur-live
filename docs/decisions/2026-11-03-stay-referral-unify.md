# 숙소 소개 적립을 이용권과 같은 방식(사장님이 정한 딜 N% 약정)으로 합치고, 숙소 상세에 '팔아보기'를 붙일까요?

상태: open
등급: C
역할: dev
올린 날: 2026-11-03
기한: 2026-11-10

## 질문
숙소 예약의 소개 적립을 옛 숙소 전용 방식에서 이용권과 같은 "딜 N% 약정" 방식으로 바꾸고, 그 위에 숙소 상세의 '이 이용권 팔기' 줄을 붙이는 작업을 **별도 세션 + staging 테스트 결제**로 진행해도 될까요? 그리고 그 작업에서 결제 잠금 파일(`payment.routes.ts`) 수정을 허가하실까요?

## 근거 (실측 2026-11-03, D1 읽기)
- 숙소 상품 **102개**(판매 중 20) · 전부 `seller_id` 없음(사장님 계정 0) · 예약 `stay_bookings` **0건**
- 숙소 옛 소개 할인(`product_stay_info.referral_enabled=1`) **0곳** · 숙소를 담은 유어샵 핀 **1개**
- 활성 딜 N% 약정(`seller_influencer_deals`) 전체 **1건**
- ⇒ 지금 바꿔도 **실제 손님·사장님 돈에 닿는 행이 0** 이다. 숙소 사장님이 들어오기 전이 가장 싼 시점.

## 지금 두 방식이 어떻게 다른가 (코드)
| | 이용권 | 숙소(2026-05-18 방식) |
|---|---|---|
| 링크 꼬리표 | `?aff=` | `?ref=` |
| 누가 % 를 정하나 | 사장님이 소개자별로(`seller_influencer_deals`) | 객실 설정에 하나(`influencer_commission_pct`) + 손님 할인(`influencer_discount_pct`) |
| 적립 시점 | 결제 확정 | 결제 확정(`payment.routes.ts` 약 608줄 — **잠금 파일**) |
| 상세의 '팔아보기' | 있음(`SellThisCard`) | 없음 |
- 유어샵에 담긴 숙소를 누르면 `?aff=` 가 붙은 채 숙소 상세로 간다(2026-11-03 A 에서 고침). 숙소 상세는 아직 `?aff=` 를 **읽지 않는다** — 그래서 지금은 담기 → 판매 적립이 숙소에서 끊겨 있다.

## 선택지
1. **이용권 방식으로 통일** — 숙소 상세가 `?aff=` 를 읽고, 예약 생성 시 `findActiveDealPct` 로 % 를 판정해 같은 적립 원장에 남긴다. 옛 객실별 소개 필드는 입력 화면에서 내리고 데이터는 둔다. 그 뒤 `SellThisCard` 를 숙소 상세에 붙인다. 장점: 사장님·소개자에게 규칙이 하나 / 단점: 결제 확정 경로 수정(잠금 파일) / **머니 접촉: 있음(적립)**
2. **옛 숙소 방식 유지 + 팔아보기만** — 팔아보기 줄이 숙소에선 옛 % 를 보여 준다. 장점: 결제 경로 무수정 / 단점: 규칙 두 개가 계속 남고, 담기(`?aff`) 적립은 계속 끊김 / 머니 접촉: 적음
3. **보류** — 숙소 사장님이 실제로 들어올 때 한다.
