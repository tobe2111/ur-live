# 점주가 다른 가맹점끼리도 이용권을 쓰게 하고, 정산은 쓴 지점으로 받게 할까?

상태: open
등급: C
역할: planning
올린 날: 2026-10-18
기한: 2026-10-25

## 질문
같은 브랜드에서 **점주가 다른 지점**이 서로의 이용권을 받아 주고, 그 매출을 **쓴 지점**이 정산받게 할지 — 그리고 그때의 세 가지 규칙(아래 ①②③)을 무엇으로 할지.

## 근거 (실측)
- 1·2단계는 PR #1897 로 구현했다: 이용권마다 스위치, **같은 주인 지점만** 받는다, 정산은 판 지점 그대로(돈 이동 0).
- 정산 구조(코드 실측): 이용권 대금은 살 때 `platform:escrow` 에 들어가고(`payout-account.ts` `purchaseCreditAccount`),
  **사용하는 순간** `recordVoucherUsedLedger` 가 escrow 에서 꺼내 `merchant:<지점>` · `platform:revenue` 로 나눈다(`ledger.ts`).
  ⇒ "쓴 지점으로 정산" 은 사용 순간의 받는 매장(`merchant_id`)을 판 지점 → **쓴 지점**으로 바꾸는 것이다. 결제 코드는 안 바뀐다.
- 판매 순간에 이미 **판 지점** 계정에서 빠지는 비용이 있다: 소개비(`influencer_commission`, 판 지점 receivable 차감 — 라이브 약정 1건) ·
  중개사 몫(`creditBrokerShare`, 게이트 OFF). 정산을 쓴 지점으로 옮기면 이 비용은 판 지점에 남고 매출은 쓴 지점으로 간다.
- 수수료율은 받는 매장의 채널로 정해진다(`channelPlatformRate(merchant_id)` — 직접 10% / 중개 5%).

## 선택지
**① 받는 지점의 동의**
1. 받는 지점 주인이 "다른 점주 이용권 받기" 를 따로 켠 지점만 받는다 — 남이 정한 가격·구성으로 손님을 받게 되므로 그 점주가 고른다. **(권장)**
2. 같은 브랜드면 자동으로 받는다 — 간단하지만 점주가 모르는 이용권이 들어온다.

**② 판매할 때 이미 나간 비용(소개비·중개사 몫)이 붙은 이용권**
1. 그런 이용권은 같은 주인 지점에서만 쓰고, 다른 점주 지점에서는 받지 않는다 — 원장 되돌리기 코드가 필요 없다. 지금 해당 약정은 1건이다. **(권장)**
2. 받되 비용은 판 지점이 그대로 진다 — 판 지점은 비용만 내고 매출이 없는 경우가 생긴다.
3. 받고 비용도 쓴 지점으로 옮긴다 — 원장 역분개가 필요해서 가장 복잡하다.

**③ 수수료율**
1. 쓴 지점의 채널 요율 — 정산 받는 곳의 계약을 따른다. **(권장 · 코드상 자연스러운 쪽)**
2. 판 지점의 채널 요율.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
①-1 · ②-1 · ③-1. 점주 동의를 받고, 되돌리기 코드 없이 시작할 수 있는 조합이다.

## 진행 방식 (머니 경로)
- 구현은 **게이트 기본 OFF**(`platform_settings.brand_cross_owner_redeem_enabled`)로 넣는다. 꺼져 있으면 1·2단계와 동작이 같다.
- 켜기 전에 **단독 세션 + staging 실결제**를 한다: 판 지점 A(점주 1)에서 구매하고 B(점주 2)에서 사용한다. 원장에서 `merchant:B` 로 들어가는지, 수수료가 B 의 채널인지, 사용 전 환불 시 escrow 가 되돌아가는지 확인한다.
- 게이트 ON 은 대표가 켠다.

## 롤백
게이트 OFF(`brand_cross_owner_redeem_enabled=false`) — 즉시 1·2단계 동작으로 돌아간다. 이미 쓴 이용권의 원장은 그대로 둔다.
