# AI 비서 검색 창구를 켜고, 에이전트 대신 결제는 설계만 남겨 둘까요?

상태: approved
등급: C
역할: dev
올린 날: 2026-10-19
기한: 2026-10-26

## 질문
① 읽기 전용 AI 비서 검색 창구(`agent_search_enabled`)를 켤지, ② "AI 비서가 손님 대신 결제" 까지 설계를 시작할지 — 두 가지를 각각 예/아니오로 답해 주세요.

## 근거 (실측)
- 대표 *"남은 3가지도 다 해줘"* 의 ② "AI 비서 구매 창구". 결제와 연결되므로 이전 보고에서 **등급 C**(승인 전 실행 금지)로 올렸다.
- 지금 AI 봇은 공개 상품 API(`/api/products`·`/api/group-buy/*`)에서 **403** 이다 — 가격표 벌크 수확을 막으려고 일부러 막아 둔 것(`bot-detection.ts` `scrapeProtection`, 2026-10-11·10-12 기록). HTML 상세와 `/llms.txt` 는 읽을 수 있다.
- 그래서 "방배동 할인 식사권 있어?" 같은 질문에 AI 비서가 **우리 이용권을 직접 찾아 줄 통로가 없다.**
- 이번에 만든 것(코드는 들어가 있고 **꺼져 있다**): `GET /api/agent/search?q=&region=&category=`
  - 검색어나 지역이 있어야 답한다(없으면 400, 전체 목록을 안 준다). 한 번에 최대 10건.
  - **데모 이용권 제외**(실제 가게 이름을 쓰지만 진짜 거래가 아니다). 승인 매장만.
  - 응답은 이름·가게·지역·가격·할인율·**우리 상세 주소** + 사용법 한 줄. 결제는 사람이 그 주소에서 한다.
  - 게이트가 꺼져 있으면 404. 결제·주문·원장 코드 무접촉.
- ⚠️ 켜도 지금은 결과가 거의 없다. 실제 입점 매장이 2곳 안팎(2026-10-12 실측)이고 나머지는 데모라 빠진다. 매장이 늘어날 때 바로 쓰이게 준비해 둔 것이다.

## 선택지
1. **① 켬, ② 보류** — 찾기만 연다. 결제는 지금처럼 우리 상세에서 사람이 한다. 머니 접촉 없음. 단점: 좁지만 공개 API 를 AI 에게 하나 여는 것(최대 10건, 검색어 필수, 5분 캐시라 벌크 수확은 어렵다).
2. **① 켬, ② 설계 시작** — 에이전트 결제는 OAuth 동의 화면, 손님 확인 단계, 토스 결제(잠금 파일) 연결이 필요하다. 머니 경로라 단독 세션 + staging 실결제 + 대표 승인. 지금 실제 매장 수로는 쓸 사람이 거의 없다.
3. **둘 다 보류** — 코드는 꺼진 채로 둔다. 손해 없음.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
안 1. 찾기만 열어도 "AI 비서가 우리를 찾아 준다" 는 효과는 대부분 나고, 결제는 지금 흐름 그대로라 위험이 없다. 결제 대행은 매장이 늘어난 뒤에 다시 판단.

## 롤백
`/admin/platform-settings` 에서 `agent_search_enabled` 를 `false` 로(즉시 404). 코드 제거는 `publicUtilityRoutes.route('/api/agent', …)` 한 줄.

## 결정 (대표가 한 말 그대로)
2026-10-20 대표: *"질문 1번. 통로 열어줘. 질문 2번은 유어딜 안에서 가능하다는거야?"*
- ① **켬** — 2026-10-20 20시대(KST) `agent_search_enabled = true` 저장(어드민 설정 API). 라이브 확인: `?region=서초구` → 200 · 1건(달빛한스푼, `/pass/2919`) · 검색어·지역 없으면 400 · 데모 0건(원본 DB 대조 — 나온 상품 둘 다 승인 매장 실상품) · OAI-SearchBot·ChatGPT-User·Claude-SearchBot·PerplexityBot UA 전부 200.
- ② **보류** — 대표 질문(유어딜 안에서 되는 것인지)에 답한 뒤, 같은 날 대표: *"2번 너가 원래 하려는거 해줘"* → 기본안(안 1) 그대로 **보류 확정**. AI 비서가 대신 결제하는 설계는 시작하지 않는다(머니 경로 — 다시 올릴 때는 새 결재).
- ② **진행으로 변경** — 같은 날 대표: *"4번도 일단은 하자. 가장 이상적으로."* → 이상적인 형태를 **"AI 가 고르고, 사람이 확인해 결제"** 로 정했다.
  AI 가 혼자 카드로 결제하는 것(빌링키·결제마다 손님 확인 없음)은 하지 않는다 — 국내 카드 결제의 본인 인증을 건너뛰고, AI 가 잘못 알아들은
  주문을 되돌릴 길이 환불뿐이며, 잠긴 결제 경로(토스 V2)를 새로 여는 일이라서다. 대신 `GET /api/agent/checkout?id=&qty=` 가 금액과 결제 링크를
  주고, 손님이 링크를 열면 구매 창이 그 수량으로 열려 있다. 결제는 손님이 누르고 금액·한도는 서버가 다시 잰다 ⇒ **머니 경로 무접촉.**
  게이트 `agent_checkout_enabled`(기본 꺼짐) — 배포 뒤 S-AGENT-5·6 확인하고 켠다.
