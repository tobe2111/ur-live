# 한국 방문자가 서울이 아닌 홍콩·도쿄·미국 서버로 접속되는 문제를 요금제 변경으로 풀 것인가

상태: rejected
등급: C
역할: dev
올린 날: 2026-10-20
기한: 2026-10-27

## 질문
Cloudflare 요금제를 올려(또는 한국 경로 옵션을 사서) 한국 방문자가 서울 데이터센터로 접속하게 할지, 지금처럼 둘지 정해 주세요.

## 근거 (실측)
- 대표 신고: "카카오 브라우저도 그렇고 처음 열 때는 항상 로딩이 좀 긴 것 같네?"
- 실사용 표본(한국에서 온 요청만 받도록 거른 10-15 이후, `/api/analytics/summary` 의 `TTFB:colo:*`):
  응답한 데이터센터가 **HKG(홍콩) 22 · NRT(도쿄) 8 · LAX·PDX·SEA(미국 서부) 8** — **ICN(서울) 0건**.
- 첫 방문은 연결을 새로 맺어야 해서 왕복이 여러 번 든다(DNS·TCP·TLS). 서버까지 왕복이 서울 ~5ms ↔ 홍콩·도쿄 ~40~60ms ↔ 미국 ~150ms.
  실사용 연결 시간(CONN, 홈 첫 방문) 10-20 **1,520ms** · 10-18 451ms · 10-19 300ms.
- 우리 서버 처리 자체는 60~95ms(`Server-Timing: total`) — 남은 시간은 거의 전부 **거리**다. 코드로 줄일 수 있는 몫은 이미 줄였다
  (서버 첫 화면 · CSS 먼저 · 사진 미리받기 · Early Hints 켜짐 · HTTP/3 켜짐 `alt-svc: h3`).
- ⚠️ 표본이 하루 수 건이라 비율은 거칠다. 그러나 **서울 0건**은 10-15~10-20 엿새 내내 같다.

## 선택지
1. **지금처럼 둔다** — 비용 0. 첫 방문 연결 0.3~1.5초가 계속 붙는다(재방문은 연결 재사용으로 짧다). 머니 접촉 없음.
2. **Cloudflare 요금제 상향 후 한국 경로 확인** — 한국 통신사 경로는 요금제·계약에 따라 서울 데이터센터 사용 여부가 달라진다.
   올리기 전에 Cloudflare 영업에 "urdeal.kr 의 한국 트래픽이 ICN 으로 가는가"를 서면으로 확인해야 한다(보장이 아니면 돈만 쓴다).
   유료 전환이라 결재 대상. 머니 접촉: 회사 비용 지출(결제 경로 아님).
3. **한국 CDN 앞단 추가**(국내 CDN 이 HTML·정적 파일을 받고 Cloudflare 를 원본으로) — 구조 변경이 커서 별도 설계 필요. 지금은 권하지 않는다.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
1번 유지 + **2번 문의만 먼저**: 비용을 쓰기 전에 Cloudflare 에 한국 경로를 확인받는다(문의는 대표 계정만 가능).

## 롤백
2번은 요금제를 되돌리면 끝(코드 변경 없음).

## 결정 (대표가 한 말 그대로)
"서버 접속 관련으로는 안할거야." (2026-10-26) → 안 1(지금처럼 둔다). 요금제 상향·한국 CDN 추가 모두 하지 않는다.
