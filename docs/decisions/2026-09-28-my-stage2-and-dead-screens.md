> 세어 본 곳이 "진입점 0" 이라 죽은 것으로 분류했는데, 진입점이 0 인 이유가 *은퇴했기 때문*이었다.

### 남은 둘 (2026-09-28 라이브 D1 실측)

| | 줄 | 라이브 상태 | 판정 |
|---|---:|---|---|
| `/seller/consignment` | 249 | **테이블 `consignment_partnerships` 이 라이브 DB 에 없다** | 🔴 **깨져 있다** |
| `/seller/youtube-growth` | 336 | 테이블 있음 · **주문 0건 · 매출 0원** | 🟡 팔린 적 없음 |

```sql
SELECT name FROM sqlite_master WHERE type='table'
  AND name IN ('consignment_partnerships','youtube_growth_requests','products','sellers');
-- → products, sellers, youtube_growth_requests   ← consignment_partnerships 없음

SELECT COUNT(*) n, COALESCE(SUM(price),0) won FROM youtube_growth_requests;  -- → 0, 0
```

**`consignment` 가 왜 깨졌나**: 마이그레이션 `0236_consignment_partnerships.sql` 은 레포에 있는데
**D1 마이그레이션이 CI 에서 안 돈다**(`TECHNICAL_DEBT.md` 의 알려진 부채). `repair-schema` 에도
이 테이블이 없다. ⇒ 페이지를 열면 API 일곱 개가 전부 `no such table` 로 죽는다.
**진입점이 없어서 아무도 신고하지 않았을 뿐이다.**

**`youtube-growth` 는 성격이 다르다**: 결제가 붙은 유료 기능이다 —
`100명 20,000원 / 500명 45,000 / 1,000명 95,000 / 5,000명 450,000 / 10,000명 850,000` (Toss).
코드는 멀쩡한데 **들어갈 문이 자기 성공 페이지밖에 없다.** 팔 생각이면 문을 내야 하고, 팔 생각이
없으면 결제가 붙은 화면을 방치하면 안 된다(누가 주소를 알면 결제가 된다).

### 선택지

1. **`consignment` 은 은퇴 · `youtube-growth` 는 전체 도구에 노출** — 깨진 건 치우고 파는 건 문을 낸다
2. **둘 다 은퇴** — 라우트만 리다이렉트로 남기고 화면 제거(`/my-store` 와 같은 방식)
3. **`consignment` 을 살린다** — `repair-schema` 에 테이블을 넣고 진입점을 만든다 (⚠️ **위탁 정산은
   머니 경로**다 — 단독 세션 + staging 실결제가 붙는다)
4. **안 함** — 지금 상태 유지(깨진 화면이 그대로 남는다)

## ④ PC 우측 2열 분할 · 손님 구역 회색 띠

### 근거 (실측 — 왜 미뤘나)

```
.ur-account-pc : max-width 1200 · padding 0 2rem(64) · 좌 내비 216 · gap 32
⇒ 우측 칸 = 1200 − 64 − 216 − 32 = 888px
⇒ 2열로 쪼개면 한 칸이 428px = 폰 폭
```

칸 안의 블록 **여덟 개가 저마다 `ur-content-medium`** 을 들고 있고, CSS 가 칸 안에서 그걸 무력화하는
구조다. 2열로 가려면 그 여덟의 패딩 규약을 동시에 바꿔야 한다.

**내 판단: 지금 폭에서는 할 값어치가 없다.** 428px 짜리 칸에 숫자 넷 격자를 넣으면 폰보다 좁아진다.
폭을 1200 보다 넓히는 길이 있지만 유어샵도 1200 이라 **두 화면이 갈린다.**

**손님 구역 회색 띠**도 같이 보류했다 — 손님 구역은 `isPc` 삼항으로 갈려서 띠가 중간에 끊긴다.
**끊긴 띠는 없는 것보다 나쁘다.** 그리고 이름 E(제목이 붙은 구역이 파는 쪽) 덕분에 지금도 구분은 된다.

### 선택지

1. **안 함** — 지금 구조에서는 얻는 것보다 잃는 것이 크다
2. **폭을 넓혀서 진행** — 마이·유어샵 둘 다 1200 → 더 넓게(두 화면 동시 변경)
3. **손님 띠만** — 2열 없이 띠만(끊김 문제를 먼저 풀어야 한다)
