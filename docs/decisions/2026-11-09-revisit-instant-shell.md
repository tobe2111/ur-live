## 근거 (실측)

  ⇒ 검은 화면은 **우리 서버의 첫 글자가 도착하기 전**이라 서버·코드로는 더 못 줄인다. 무료 연결 설정(HTTP/3·0-RTT·Early Hints)은 전부 켜져 있고, 첫 화면 앞 바이트도 14KB 안으로 줄였다(#2230).

- 2026-04-27 사고: `vite-plugin-pwa` 의 `navigateFallback` 이 `/auth/kakao/start?redirect=…` 를 가로채 카카오 로그인 전면 차단 → Killer SW 배포로 복구. 그 뒤 CLAUDE.md 에 **"Service Worker / PWA 라이브러리 절대 금지"**. 재도입 조건 4개가 `docs/INCIDENTS.md` 에 적혀 있다(redirect follow · `/auth|/oauth|/api` denylist · e2e 카카오 로그인 · 단독 PR + 1주 안정).

## 선택지
1. **바탕색만** — 첫 글자 전 브라우저 기본 검정 대신 우리 바탕색이 보이게(`theme-color` 는 이미 있음 · 재방문부터 적용). 위험 0 · 머니 접촉 없음. 검은 화면 **길이는 그대로**.
2. **단계식(권장)** — ① 오늘 안 1 ② 시험 주소(`*.pages.dev` 프리뷰 또는 `staging`)에서 **좁은 SW** 를 만든다:
   - 저장 대상: **문서 요청(navigate)만**, 그것도 `/`·`/vouchers`·`/stays`·`/pass/:id`·`/u/:handle` 등 서버 첫 화면이 있는 **소비자 경로만**(허용 목록).
   - **절대 안 건드림**(denylist, 코드가 아니라 상수 파일 하나): `/auth/*` `/oauth/*` `/api/*` `/sync/*` `/checkout*` `/pay*` `/payment*` `/toss*` `/admin*` `/seller*` `/agency*` `/store/*` · 쿼리에 `code=`·`state=`·`paymentKey=`·`orderId=` 가 있는 요청 · `redirect:'follow'` 명시.
   - 동작: 저장본이 있으면 **즉시 보여 주고**(검은 화면 0초) 같은 요청을 네트워크로 받아 **다음 방문용으로 갈아끼움**(stale-while-revalidate). 화면이 켜진 뒤 `/api/*` 는 지금처럼 네트워크.
   - 안전장치: ② `platform_settings` 킬스위치(어드민에서 끄면 다음 로드에 Killer 로 자기 해제) ③ 가드 — denylist 상수를 깨뜨리는 주입(`/auth/kakao/start?redirect=` 를 가로채면 빨간불) ④ e2e: 카카오 로그인 시작→콜백, 토스 결제 성공 URL 복귀, `/u/me` 리다이렉트, 어드민 로그인.
   - 배포: 단독 PR → 프리뷰에서 ④ 전부 통과 → 라이브 → **1주 관찰**(CLAUDE.md 재도입 조건 그대로). 실패 조건 하나라도 뜨면 킬스위치.
   - 머니 접촉: **간접 있음**(결제 복귀 URL 을 denylist 가 지켜야 한다) ⇒ 단독 세션 + staging 실결제 1건.
3. **안 하기** — 검은 화면은 거리 문제로 남긴다. 서울 연결은 유료 선택(아마존 CDN·Cloudflare 기업) 결재로.
