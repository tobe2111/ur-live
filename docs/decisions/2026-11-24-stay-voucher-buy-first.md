## 방향 (대표가 이미 정한 것)
2026-11-24 세션 제안 — *"기본은 '먼저 사고 나중에 예약', 달력을 직접 관리하는 사장님만 '날짜 지정 판매'"* →
대표 ***"그래 그렇게 하자"***. 이 문서는 그 방향을 실제로 켜기 전에 정할 **세부 규칙**만 묻는다.

## 근거 (실측 · 코드)
- **두 방식 모두 코드에 이미 있다.** `stay_bookings.sale_mode` = `date`(손님이 체크인·아웃을 골라 결제) / `voucher`(평일권·주말권을 먼저 사고 날짜는 따로) / `both`.
  손님 화면(`StayDetailPage` · `StayBookingModals` · `StayCheckout` · `MyStaysPage`)은 두 방식을 다 그린다.
- **그런데 사장님이 고를 수 없다.** 등록 위저드가 숙박을 만들 때 항상 `sale_mode: 'date'` 로 저장한다
  (`src/features/seller/api/seller-stays.routes.ts:139`). 화면에 판매 방식 선택 칸이 없다.
- **라이브 숙박 예약 0건.** 판매 중 숙박 20곳은 전부 `seller_id` 가 없다(시범 데이터). 즉 두 방식 모두 실결제로 돌아 본 적이 없다.
- **날짜 방식의 위험** — 작은 숙소는 같은 방을 다른 예약 앱에도 올린다. 유어딜 달력과 자동으로 맞춰지지 않아 **같은 방 이중 판매** 위험이 있다. 먼저 사는 방식은 달력 재고를 쓰지 않아 이 위험이 없다.
- **먼저 사는 방식의 현재 규칙(코드):**
  - 미사용 + 유효기간 안 → 손님 셀프 취소 **100% 환불** (`stays-public.routes.ts` 취소 분기, 2026-06-12)
  - 유효기간: 사장님이 정하면 그 값, 안 정하면 **무기한** (상한 12개월 — `shared/voucher-validity`, 2026-08-22 대표 "180일 강제 기본값 폐지")
  - 만료 30·7·1일 전 손님 알림 (`stay-voucher-expire` cron)
  - 사장님이 [사용 처리] (`seller-stays.routes.ts` voucher 사용 처리)
  - ⚠️ **만료 후 미사용 = 환불 0원.** 반면 식사 등 일반 이용권은 만료 미사용분을 자동 환불한다(`auto-settlement` 만료 환불). 숙박권만 다르다.
  - 날짜 잡는 방법은 코드에 없다 — 알림 문구가 "매장 연락 권장" 뿐이다.

## 선택지 (번호마다 하나씩)

**Q1. 판매 방식 선택을 어디에 두나**
1. 등록 위저드 숙박 단계에 [먼저 판매(기본) / 날짜 지정 / 둘 다] 선택 추가 — 기존 숙박(시범 20곳)은 그대로 `date`. 머니 접촉: 없음(결제 경로는 이미 있는 것)
2. 어드민만 바꿀 수 있게 — 사장님 부담 0, 대신 매번 우리가 손댄다

**Q2. 손님이 날짜를 잡는 방법**
1. 구매 후 화면에 **매장 전화·문자 버튼 + 이용권 코드** 를 크게 보여 준다(새 기능 최소). 사장님이 받으면 [사용 처리]
2. 앱 안에서 "날짜 요청 → 사장님 수락" 흐름을 새로 만든다 — 손님 경험은 낫지만 개발 큼, 사장님이 앱을 봐야 한다

**Q3. 유효기간**
1. 등록 때 **필수 입력**(예: 3·6·12개월 중 선택, 상한 12개월 유지) — 무기한 판매는 막는다
2. 지금처럼 선택 입력(미입력 = 무기한)

**Q4. 만료됐는데 못 쓴 숙박권**
1. 일반 이용권과 **같게 자동 환불** — 식사 이용권과 규칙이 하나가 된다. 머니 접촉: **있음(환불)** → staging 실결제 필요
2. 지금처럼 0원 — 대신 구매 화면에 "만료 후 환불 불가" 를 크게 표시

**Q5. 사용 불가 날짜(연휴·성수기)**
1. 우선 **안내 문구 칸**(사장님이 "12/24~25, 설 연휴 불가" 처럼 적는다) — 구매 전 화면에 노출
2. 날짜를 골라 막는 달력 기능을 새로 만든다

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
**Q1-1 · Q2-1 · Q3-1 · Q4-1 · Q5-1.** 사장님 일이 가장 적고, 손님이 날짜를 못 잡아도 돈을 잃지 않는 조합이다.
켜기 전 순서: 등록 화면 수정 → staging 에서 시험 결제(구매 → 사장님 사용 처리 → 셀프 취소 환불 → 만료 환불) → 대표 확인 → 켜기.

## 롤백
등록 화면의 판매 방식 선택을 숨기면 종전(`date` 고정)으로 돌아간다. 이미 팔린 숙박권은 종전 규칙(미사용 셀프 취소 100% 환불)이 그대로 적용된다.
