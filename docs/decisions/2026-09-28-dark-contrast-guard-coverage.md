# 다크 대비 가드가 콘텐츠 화면을 안 보고 있습니다 — 언제 고칠까요

## 질문
가드가 빈 껍데기만 재고 초록불을 내는 것을 1·2·3 중 어떻게 할까요?

## 근거 (실측 2026-09-28)
`scripts/check-dark-contrast.mjs` 는 *"53개 경로 실제 렌더 측정, 텍스트 1,998개, 0건"* 으로 초록이다.
그런데 **경로별 측정 개수**를 뽑으면:

| 경로 | 측정된 텍스트 | 실제 화면에 있는 글자 |
|---|---|---|
| 유어샵(모바일) | **8개** | 카드 6장 × 5줄 + 헤더 ≈ 50+ |
| 교환권 | 14개 | 상품 목록 전체 |
| 홈(모바일) | 23개 | 카드 피드 전체 |

상품 API 를 시드하지 않아 목록이 안 그려지는데, 헤더 몇 줄이 바닥값 `EMPTY_FLOOR = 5` 를 넘겨
**"검사됨" 으로 집계**된다. 바닥값이 5인 이유는 그 주석에 있다 —
*"빈 상태 화면(주문 0건 등)도 헤더·안내문 몇 줄은 그린다"*.
즉 **"원래 빈 화면"과 "콘텐츠를 못 불러온 화면"을 구분하지 못한다.**

증거: 유어샵 다크의 취소선 정가를 직접 쟀다 — `rgb(85,83,79)` on `rgb(29,31,41)` = **2.14:1**
(가드 기준 3.0 미만, 보이는 상태, opacity 1). 가드는 이것을 **0건**이라고 보고한다.

**✅ 배포 뒤 라이브로 재확인(2026-09-28 13:25 KST, iPhone 13 뷰포트 · `urdeal.kr/u/jiwon1228`)**:
실데이터가 있는 그 화면에서 같은 방식으로 세니 글자가 **60개**였다. 가드는 같은 경로에서 **8개**를 재고
통과시킨다 — 즉 화면의 **87%가 검사 밖**이다. 위 표의 추정이 실측으로 확인됐다.

🩸 **정정 — 위 "곁가지" 에 제가 사실을 틀리게 적었습니다.** 취소선 정가 색을 *"대표가 8차 시안으로
승인한 것이라 임의로 못 바꾼다"* 고 썼는데, 디자인 SSOT(`ticket-completion-reference-2026-09.md`)를
다시 확인하니 **취소선 색 규정이 없습니다**(브랜드·바탕·표면·`--sale` 만 정해져 있습니다).
승인된 시안이 아니라 공용 부품 `DealRow` 의 구현 선택이었습니다. 그리고 이번 리뉴얼로 유어샵이
그 부품으로 옮겨 오면서 이 화면에서는 **5.04 → 2.14 로 후퇴**한 상태였습니다(종전 카드는
`text-gray-500 dark:text-gray-400`). 제가 만든 후퇴라 **등급 B 로 보고 후 먼저 고쳤습니다** —
`text-gray-300 dark:text-gray-600` → `text-gray-400 dark:text-gray-500`(라이트 1.50→**3.65** ·
다크 2.14→**3.10**). 가드 `deal-row-strike-contrast-2026-09-28.test.ts` 가 색 이름이 아니라
INK hex 를 읽어 대비를 계산해 고정합니다.
⇒ **그래서 아래 선택지에서 색 항목은 빠졌습니다. 남은 질문은 가드 커버리지 하나입니다.**

왜 지금 다 못 고치나: 고치려면 콘텐츠 경로에 상품 픽스처를 시드해야 하고, 그러면 지금까지 검사 밖이던
영역이 한꺼번에 드러난다. 몇 건일지 모르고 **다른 화면 수정까지 유어샵 작업으로 끌고 오는 것**이 된다.

## 선택지
1. 별건으로 가드부터 고친다 — 픽스처를 시드해 53개 경로가 진짜로 검사되게 만들고, 거기서 나오는 목록을 대표에게 보고한 뒤 정리 순서를 정한다. 머니 접촉 없음.
2. 가드를 고치고 나오는 결함까지 그 자리에서 전부 정리한다 — 몇 건일지 모르고 여러 화면의 색이 한 번에 바뀐다. 머니 접촉 없음.
3. 지금은 둔다 — 기록만 남기고 나중에. 그동안 콘텐츠 화면의 다크 가독성은 계속 검사 밖이다. 머니 접촉 없음.
