# 12월 17일부터 토스 지급대행 없이 유어딜이 직접 계좌로 보내는 길로 갈까요?

상태: approved
등급: C
역할: finance
올린 날: 2026-11-25
기한: 2026-12-10

## 질문
개정 전자금융거래법 시행일(2026-12-17)부터는 매장 대금·중개사 몫·에이전시 몫·소개비를 **토스 지급대행 없이 유어딜 통장에서 직접** 보내는 쪽으로 정하고, 그 전에 법무 확인 한 번을 받을까요?

## 근거 (실측 · 2차 자료)
- 대표 2026-11-25: *"2번은 계좌로도 일단 보내지면 좋겠는데 토스 지급대행이 걸리는구나"* + 지급대행 관련 조사 글 공유(아래 요지).
- **개정 내용(2차 자료로 확인, 법제처 원문은 이 환경에서 열리지 않음)**:
  - 공포 2025-12-16 · PG 관련 규정 시행 **2026-12-17**.
  - PG(전자지급결제대행) 정의에서 *"통신판매중개 등 다른 업무를 영위하는 과정에서 부수적으로 대가를 수수하고 정산을 대행하는 경우"* 를 **명시적으로 제외**(법률신문 · Lexology 게재 조문).
  - 김앤장: 통신판매중개를 하며 부수적으로 대금을 정산하는 e-커머스는 *"더 이상 전자금융거래법의 적용을 받지 않을 것으로 보입니다"*.
  - 정산자금 외부관리(60% → 80% → 100%)·자본금 요건은 **PG업자**에게 붙는 의무다.
- ⚠️ **이 레포의 기존 전제와 다르다**: `docs/design/pg-cost-and-settlement-legal-2026.md` §4(2026-07-12)와 결재 `2026-11-03-settlement-structure.md` 근거는
  *"12-17 이후 PG업 등록 + 정산자금 100% 예치 대상"* 이라고 적었다. 위 제외 조항을 반영하지 않은 판단이다(외부관리 의무는 PG 에게 붙는다).
- **12월 16일까지는 그대로 위험 구간**: 금융위 법령해석(2024, `fsc.go.kr/no010102/82523`) — 통신판매중개업자가 결제대금 정산에 관여하면 PG 등록 대상.
  지금 매장 정산도 유어딜 통장을 거친다(`settlement-schedule.ts` · 어드민 이체 파일) — 새 송금(중개사·에이전시 몫)을 시행일 전에 켜면 같은 위험이 넓어진다.
- 남는 실무: 세무(유어딜 매출은 수수료만 · 받은 대금은 예수금으로 분리) · 매장 매출 누락 관리 · 계좌 확인 · 대량 이체. 다른 법(대규모유통업법 개정 — 대형 온라인 중개업자 정산기한·대금 별도관리)의 적용 규모에 우리가 드는지 법무 확인 필요.
- 현재 스위치: `broker_share_enabled=false` · `agency_share_payout_enabled` 없음(OFF) · `toss_payouts_enabled`(토스 지급대행 게이트) OFF.

## 선택지
1. **12-17부터 직접 송금**(지급대행 안 씀) — 지금 매장에 하는 어드민 이체 파일 방식에 중개사·에이전시 몫·소개비를 얹는다. 시행일 전 법무 확인 1회 + staging 실결제(S-BROKER · S-AGENCYSHARE) 뒤 스위치 ON. 장점: 지급대행 요금 0 / 단점: 송금·세무 실무를 우리가 진다. 머니 접촉: 있음.
2. 토스 지급대행 유지(11-03 결정 그대로) — 요금은 들지만 돈이 우리 통장을 안 거친다. 머니 접촉: 있음.
3. 지금 바로 직접 송금 시작 — 12-16 까지는 미등록 PG 위험(3년 이하 징역 또는 2천만 원 이하 벌금 조항). 권하지 않는다.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
1. 12-17 이후엔 지급대행이 법적 필수가 아니게 되므로 요금을 아낄 수 있다. 다만 원문 조문 확인과 "부수적" 해석은 법무에 한 번 묻는다.

## 롤백
스위치 OFF(`broker_share_enabled` · `agency_share_payout_enabled`) — 장부 적립은 남고 송금만 멈춘다.

  - 법무 확인 2가지(부수적 정산 해당 여부 · 대규모유통업법 규모 기준)는 그대로 권한다 — 대표가 받는다.
  - 새 송금 스위치(`broker_share_enabled` · `agency_share_payout_enabled`)는 12-17 이후 staging 실결제(S-BROKER · S-AGENCYSHARE) 뒤 켠다(결재 C 그대로).
