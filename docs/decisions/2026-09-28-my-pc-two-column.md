# 마이 PC 우측 칸을 2열로 쪼갤까

상태: approved
등급: C
역할: design
올린 날: 2026-09-28
기한: 2026-10-05

## 질문

마이 PC 의 우측 칸을 2열로 쪼개고 손님 구역에도 회색 띠를 넣을까, 지금 구조를 유지할까?

## 근거 (실측 — `src/index.css` · 하네스 렌더)

```
.ur-account-pc : max-width 1200 · padding 0 2rem(64) · 좌 내비 216 · gap 32
⇒ 우측 칸 = 1200 − 64 − 216 − 32 = 888px
⇒ 2열로 쪼개면 한 칸 = 428px  (= 폰 폭 430 과 거의 같다)
```

- 428px 칸에 지금의 **숫자 넷 격자**(딜·이용권·교환권·쿠폰)를 넣으면 **폰보다 좁아진다**
- 칸 안의 블록 **여덟 개가 저마다 `ur-content-medium`** 을 들고 있고, CSS 가 칸 안에서 그걸
  무력화하는 구조다 ⇒ 2열로 가려면 여덟의 패딩 규약을 동시에 바꿔야 한다
- 폭을 1200 보다 넓히는 길이 있지만 **유어샵도 1200** 이라(`.ur-ushop-pc`) 두 화면이 갈린다
- **손님 구역 회색 띠**: 손님 구역은 `isPc` 삼항으로 갈려 띠가 중간에 끊긴다 —
  **끊긴 띠는 없는 것보다 나쁘다.** 그리고 대표 확정 "이름 E"(제목이 붙은 구역이 파는 쪽) 덕분에
  띠 없이도 구분은 이미 된다

## 선택지

1. 안 함 — 지금 폭에서는 얻는 것보다 잃는 것이 크다. 머니 접촉 없음
2. 폭을 넓혀서 진행 — 마이·유어샵 둘 다 1200 → 더 넓게(두 화면 동시 변경). 머니 접촉 없음
3. 손님 띠만 — 2열 없이 띠만 넣는다(끊김 문제를 먼저 풀어야 한다). 머니 접촉 없음

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)

1. 888px 를 둘로 쪼개면 한 칸이 폰보다 좁아진다 — 근거가 없다.

## 롤백

해당 없음(안 함). 진행한 경우 그리드 규칙과 블록 패딩 규약 환원.

## 결정 (대표가 한 말 그대로)

> **"모두 가장 이상적으로 순서대로"**

⚠️ 순서 목록 전체에 대한 답이고, 이 항목의 기본안은 **"안 함"** 이었다.
⇒ **아무것도 바꾸지 않았다.** 888px 를 둘로 쪼개면 한 칸이 428px — 폰(430)보다 좁아진다.
"더 이상적으로" 가 이 화면에서 뜻하는 것은 2열이 아니라 **그대로 두는 것**이다.

🔎 다시 올릴 만한 조건은 하나다: **폭을 넓히기로 정할 때**(선택지 2).
그건 마이만의 일이 아니라 유어샵(`.ur-ushop-pc` 도 1200)과 **함께** 정해야 한다 —
한쪽만 넓히면 두 화면이 갈린다.
