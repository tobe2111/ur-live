# 소개 수수료를 기본 '딜'로 주고, 사업자 정보를 넣은 사람만 현금으로 정산할까요?

상태: open
등급: C
역할: finance
올린 날: 2026-11-02
기한: 2026-11-16

## 질문
소개 수수료(매장이 그 인플루언서에게 정한 %)의 기본 수령 방식을 **딜**로 바꾸고, 딜 지급을 자동화하며, **사업자등록번호 + 계좌**를 넣은
사람만 현금으로 정산하는 안(아래 1번)으로 갈까요?

## 근거 (실측 · 코드)
- 대표 제안(2026-11-02): *"딜 N%로 적립을 하고 사업자등록증 혹은 사업자등록번호와 계좌번호를 입력 시, 정산해주는건 어때? 근데 이거 어떻게
  자동화하지? 세금은 어떻게 처리하고?"* · *"토스 지급대행은 너무 비싸서 일단 보류야."*
- 지금 받는 돈은 **매장이 사람마다 정한 수수료 %** 하나뿐이다(`worker/utils/influencer-deal.ts` `findActiveDealPct`). 플랫폼 2% 어필리에이트는
  2026-08-22 종료(`affiliate_program_enabled` 행 부재).
- 소개 인정: 링크로 들어온 뒤 **24시간**, 마지막 링크 기준(`utils/affiliate-ref-store.ts`).
- 확정 시점: 손님이 이용권을 **사용**하거나 전부 만료·환불된 뒤(`worker/utils/payout-use-gate.ts`, 2026-09-16 대표 확정).
- 수령 방식: `influencer_balances.payout_method` = `'cash'`(기본) | `'deal'` — 소개자가 `/influencer/settlement` 에서 고른다.
- 지급: **자동 아님.** 매월 1일 cron(`worker/cron/influencer-payout.ts`)은 지급 대기 알림만 만든다. 딜은 1원부터, 현금은 10만 원부터.
  실제 지급은 어드민 `/admin/influencer-payouts` [송금 처리]를 사람이 누른다. 현금 이체도 사람이 한다.
- 원천징수: 지금 코드는 *사업자번호가 있거나 사업소득 → 3.3% · 기타소득 → 8.8% · 신고 정보 없음 → 0%*(`shared/influencer-payout-math.ts` `resolveWithholdingRate`).
  🔴 **세법 확인 필요** — 사업자등록이 있는 사람에게 주는 대가는 보통 원천징수 대상이 아니고 상대가 세금계산서를 발행한다.
- 세금계산서 API: 홈택스는 발행 API가 **없다**(국세청 공개 API는 사업자 진위·상태 조회뿐). 자동화는 인증 대행사(팝빌·바로빌·볼타 등) 건당 유료
  — 예: 볼타 역발행 1건 200원(자사 공개가). 역발행은 상대 사업자의 '승인'이 있어야 끝난다.

## 선택지
1. **기본 딜 + 사업자만 현금(월 1회 수동)** — 딜 지급은 사용 확인 즉시 **자동**(우리 장부라 비용 0) · 사업자등록번호는 국세청 무료 API로 자동 확인 ·
   현금 송금과 세금계산서는 월 1회 사람이 처리(대상 목록은 자동 생성). 머니 접촉: **있음**(지급 경로·기본값 변경).
2. **지금 그대로** — 소개자가 딜/현금을 고르고, 둘 다 어드민이 버튼으로 지급. 머니 접촉 없음. 단점: 사람 손이 계속 든다.
3. **1번 + 세금계산서 API(건당 ~200원)** — 사업자 정산 건수가 늘면. 머니 접촉: 있음 + 외부 유료 계약.

## 기본안 (답이 없을 때 권하는 것 — 자동 실행되지 않는다)
2번 유지. 1번은 **세무사 확인 두 가지**가 먼저다 — ① 사업자 소개자에게 원천징수 없이 세금계산서로 처리하는 것이 맞는지(부가세 포함/별도 포함)
② 비사업자 개인에게 **딜**로 주는 수수료가 소득 신고 대상인지. 확인되면 1번을 단독 세션 + staging 실결제로 진행.

## 롤백
1번 진행 시: 기본값(`payout_method`)을 `'cash'` 로 되돌리고 자동 딜 지급 스위치를 끈다(게이트 OFF).
