## 질문

## 근거 (실측)
- 최근 3일(10/31 21시 ~ 11/3 21시 KST) PR 검사 300회 중 **125회(42%)가 취소** — 평균 42분 돈 뒤, 합계 약 87시간.
  그중 31회는 **main 을 합치느라** 다시 올린 것이다(GitHub API `actions/workflows/verify.yml/runs`).
- 11/2 하루에 main 이 **세 번** 빨개졌다 — 각 PR 은 자기 검사를 통과했는데, **합친 결과**가 검사된 적이 없었다
  (GitHub 은 지금 "최신이어야 머지" 를 요구하지 않는다: 규칙 `23392011` 의 `strict_required_status_checks_policy: false`).
- 머지 대기열은 바로 그 두 가지를 없앤다 — "main + 줄 선 PR" 을 합친 상태로 검사하고 통과한 순서대로 머지한다.
- 그런데 이 저장소는 **개인 계정 소유**(`owner.type = User`)라 대기열을 켤 수 없다. 대기열은 조직 소유 저장소 기능이다.
- 준비는 끝냈다: `verify.yml` 에 `merge_group` 트리거를 넣어 두었다(2026-11-03 PR) — 조직으로 옮기고 켜기만 하면 된다.

## 선택지
1. **옮기고 켠다** — 세션이 main 을 합치는 일 0 · 합친 결과로 main 이 빨개지는 일 0. 대표가 할 일(약 15분):
   ① github.com 에서 무료 조직 만들기 ② 저장소 Settings → Transfer ③ Cloudflare Pages(`ur-live`·`ur-wholesale`·`ur-ads`)의 Git 연결을 새 주소로 다시 잇기
   ④ Claude GitHub 앱을 조직에 설치 ⑤ main 규칙에 "Require merge queue" 켜기. 옛 주소(`tobe2111/ur-live`)는 GitHub 이 자동으로 넘겨 준다.
   머니 접촉 없음. 단점: ③을 놓치면 배포가 멈춘다(옮긴 직후 배포 한 번을 확인해야 한다).
