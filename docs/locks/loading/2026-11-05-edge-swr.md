# [UNLOCK_LOADING] 2026-11-05 — 공개 캐시 만료 직후 즉시 응답(SWR)

- 파일: `src/worker/middleware/edge-cache.ts` (잠금 항목 `useKv:false` 기본 · `CDN-Cache-Control` 분리 — **둘 다 불변**)
- 대표: *"잠금파일도 모두 허가해줄게"*(2026-11-04) · *"더 최적화. 무료 수준에서 대기업 수준으로"*(2026-11-05)
- 왜: Cache API 는 `stale-while-revalidate` 를 안 지킨다 — 만료되면 없는 것이라 **만료 뒤 첫 손님**이 D1(미국 동부) 왕복을
  전부 기다렸다. 손님이 적은 콜로일수록 거의 매번이 "만료 뒤 첫 손님" 이다.
- 무엇: 이미 있던 24시간 예비 사본(stale-if-error)에 저장 시각(`X-Ur-Stored-At`)을 붙이고, 신선 캐시가 없을 때 그 사본이
  **엣지 수명(ttl×3) + min(ttl, 60초)** 안이면 즉시 `*-SWR` 로 내고, 뒤에서 같은 주소를 `x-ur-revalidate: 1` 로 다시 받아 채운다.
  isolate 안 동시 갱신은 1번. 창 밖이면 종전대로.
- 최대 낡음: 종전 엣지 수명 + 최대 60초. 브라우저에는 `max-age ≤ 15` 로 짧게.
- 보안: 갱신 헤더는 캐시 **조회만** 건너뛴다 — 쿼리 하나 붙여 캐시를 피하는 것과 같아 새 우회가 아니다.
- 시험: `edge-swr-2026-11-05`(5) · `stale-if-error-2026-11-04`(오래된 사본으로 조정). 주입: 창 판정을 항상 false → 빨간불.
- ⚠️ 못 보는 것: Pages 에서 자기 주소 fetch 가 워커로 다시 들어오는지(SSR self-fetch 가 같은 수법) — 라이브 `X-Cache-Status: public-SWR` 로 판정.
