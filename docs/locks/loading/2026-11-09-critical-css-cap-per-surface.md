# [UNLOCK_LOADING] 2026-11-09 — 첫 화면 CSS 상한을 전체판 70KB → **표면별 40KB** 로 (대표 승인 "내 결정이 필요한 것들 가장 이상적으로 진행")

## 왜
종전 상한은 **전체판**(모든 첫 화면 폐쇄의 합) 하나에 70,000B. 첫 화면이 14개가 되자 69,8xxB 로 상한에 닿아 **새 첫 화면(PC 상세 등)을 더할 수 없는** 상태가 됐다.
그런데 손님 HTML 에 실제로 실리는 것은 **표면 하나의 CSS**(20~38KB)이고, 전체판은 표면 항목이 빠졌을 때의 폴백뿐이다(2026-11-08 표면별 분리 뒤).
상한이 지키려던 것("한 화면에 CSS 를 너무 많이 인라인하지 않는다")은 표면 상한이 더 정확히 지킨다.

## 바뀐 것
- `CRITICAL_SURFACE_MAX_BYTES = 40_000` — 표면 하나의 하드 상한. **생성기가 빌드에서 강제**(넘으면 빌드 실패). 지금 최대는 지도 38,0xx · 상세(PC 포함) 35,9xx.
- `CRITICAL_CSS_MAX_BYTES = 160_000` — 전체판의 정신 건강 상한(어떤 모듈이 앱 CSS 를 통째로 끌고 오는 사고만 잡는다). 현재 70,6xx.
- 토큰판(2,263B)은 별도(로더-먼저 표면 전용).
