# 로딩 최적화 잠금 — 변경 기록 (2026-11-01 ~ , 기록마다 파일 하나)

**새 `[UNLOCK_LOADING]` / `[LOADING_ADDITIVE]` 기록은 이 폴더에 파일 하나로 쓴다.** 이름은 `<YYYY-MM-DD>-<슬러그>.md`
(예: `2026-11-02-vouchers-header-trim.md`). 슬러그는 영문 소문자·숫자·하이픈.

- ❌ `../loading-audit-log.md` 에 추가하지 말 것 — 그 파일은 **동결**됐다(항목 수가 늘거나 줄면 CI 빨간불).
- 🔎 찾을 때는 옛것·새것을 함께: `grep -rn '<파일명>' docs/locks/`
- 📌 잠금 규칙·잠긴 항목 표는 `CLAUDE.md` 의 `## 🔒 로딩 최적화 잠금` 절에 있다.

## 왜 파일 하나씩인가

예전 규칙은 *"큰 파일 맨 위에 한 줄 추가"* 였다. 그러면 잠금 파일을 건드리는 **모든 세션이 같은
줄을 고친다** — 내용상 무관한 작업끼리도 머지마다 충돌했고, 풀어서 다시 올리면 Verify 가 처음부터
돌았다(2026-11-01 한 PR 이 하루에 두 번 · 최근 Verify 100회 중 36회 취소). `docs/CURRENT_WORK.md` 가
2026-07-29 에 같은 병을 같은 처방(세션마다 파일 하나)으로 고쳤고, 그 뒤 그 충돌은 사라졌다.

## 한 건에 적을 것 (옛 기록과 같은 내용)

- 날짜 · 태그(`[UNLOCK_LOADING]` / `[LOADING_ADDITIVE]`) · 바꾼 잠금 파일

- 무엇을 왜 — 실측 근거
- **불변으로 지킨 잠금 항목**

- E4 판정 방법 · 롤백
