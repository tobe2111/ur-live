# flip 前 리스크 전수조사 — 5문 감사 기록 (2026-07-10)

> 대표 질문 5건(전금법·이용권 약관·자가구매·백업·카카오 장애)에 대한 read-only 코드 감사 결과 박제. **①·②는 법무 검토 입력값**(코드 사실만 — 법적 판단 아님), **③은 8월 flip 의 선행 차단 조건**(`flip-ui-checklist-2026-08.md` §0). 상세 근거 file:line 은 각 절 참조.

## ① 딜 포인트 — 전금법(선불전자지급수단) 검토 입력값

**코드 사실** (법무에 이대로 전달):
- 사용처 = **다수 독립 매장 + 제3자(KT알파) 교환권** → 단일가맹점 면제 논거 없음 (points.routes.ts:660, kt-alpha-auto-send.ts).
- **딜→현금 출금이 일반 유저에게 상시 오픈**: 최소 1만딜, 유상분 한도, 8.8% 원천징수, 어드민 승인 (points.routes.ts:1117-1193). 커미션 적립은 유상 버킷 = 현금화 가능 (point-buckets.ts:11).
- 한도: 1회 20만원 패키지 화이트리스트 + rate limit 뿐 — **보유/일/월 한도 미구현**.
- **발행잔액(SUM(user_points.balance))·연간 충전총액 집계 쿼리 부재** — 등록 기준 모니터링 불가 상태. ✅ 2026-07-11 AP-2로 어드민 모니터링 카드 구현. **등록면제 기준(공식 확인 2026-07-12): 발행잔액 30억원 미만 AND 연간 총발행액 500억원 미만**(전금법 개정 시행 2024-09-15, 초과 시 충전금 100% 별도관리). 상세·소스: `pg-cost-and-settlement-legal-2026.md` §3.
- 유상/무상 버킷 SSOT 구현됨(point-buckets.ts) · 무상 우선 차감 · 무상 출금 불가.
- **상충 발견**: 충전 UI "환불 불가"(PointsChargePage.tsx:288) ↔ 약관 제12조 "유상 잔액 환급 가능"(consumer-terms-content.ts:107) + **환급 실행 엔드포인트 부재** + 탈퇴 시 전액 소멸 코드(point-ledger.ts:187) vs 약관 정합 확인 필요.

**코드 후속 후보**: 발행잔액/연간 집계 어드민 쿼리 · 보유/월 한도(값은 법무 결론 따라) · UI-약관 문구 정합.

## ② 미사용 이용권 — 표준약관 정합 입력값

**구현이 표준약관보다 유리한 구조** (뼈대 건강):
- 유효기간: 구매 시 확정(셀러 지정, 기본 +90일), 구매 전후 표시, D-30/7/3/1 통지 cron.
- **만료 시 신청 불요 100% 자동 환불, 원결제수단 환원**(딜→딜, 카드→토스 취소+실패 재시도 큐) = 낙전 0 (auto-settlement.ts:169-296).
- 미사용분 = `platform:escrow` 예치, 매장 정산은 **사용 시점**만(주간) — 에스크로 명확.
- 셀프 환불 = 7일 청약철회 전액(group-buy-voucher.routes.ts:412-556). 7일~만료 공백 구간은 만료 자동환불로 커버.

**고칠 것**:
1. 고지 모순 3건 — QRModal.tsx:323 "자동 소멸돼요"(실제=자동 환불) · GroupBuyTermsPage.tsx:41 "딜 포인트로 환불"(카드건=카드 환불) · :47 "즉시 환불 가능"(실제=7일 제한). → 문구 수정(비-머니, 즉시 가능).
2. **숙소(stay) 이용권만 만료 자동환불 부재**(stay-voucher-expire 는 알림만) — 정책 비대칭. 환불 배선은 머니 경로 → 8월 격리.
3. '신유형 상품권' 명칭·90% 조항이 소비자 문서에 없음(코드 주석에만) — 약관 법무 검토 시 함께.

## ③ 자가구매/공모 — **flip 선행 차단 조건 (상세는 checklist §0)**

있는 방어: 동일 계정 자기추천 차단(C1/C2/C3 공구) · T+7 hold · 환불 역전 · 인출 어드민 승인+사업자+유상 한정 · [INV-CB] 예산캡.
**구멍 4개 (flip 전 필수)**:
1. **매장 공모 콤보**: `use-by-seller`(QR)가 실거래 증빙 없이 매장 임의 + 사용 순간 affiliate holding **즉시 확정**(group-buy-voucher.routes.ts:184-191) → hold 무력화. 사용-확정 T+N 유예 또는 이상치 감지+확정 보류 필요.
2. **부계정 무방비**: self 체크 전부 같은 user_id 만. IP 캡 1곳(referrer+IP 24h 3건). referrer 는 클라이언트 임의 지정(order.routes.ts:509, affiliate.routes.ts:64). referrer 단위 일/월 캡·기기 지문·그래프 점검 부재.
3. **영입 인플 본인 구매 미차단 2축**: `recordIntroductionCommissionShare`(20% share, ledger.ts:356+) + `creditInfluencerStoreIntroCommission`(1.5% — **주석은 "self-매장 skip" 이라 쓰였으나 코드에 구매자==인플 체크 없음**, influencer-store-intro-commission.ts:81-85).
4. **커미션 레일 이상 탐지 0**: anomaly-detect cron 은 후원+가입 IP 만. 커미션/이용권 사용 패턴·자동 동결 전무. + granted 역전은 MAX(0) clamp 라 소진분 회수 불가(회수 부채 기록도 없음 — 유저 커미션엔 settlement_clawbacks 상당물 부재).
