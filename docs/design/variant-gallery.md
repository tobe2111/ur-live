# 🎨 시안 갤러리 `/design/variants`

> 2026-09-15 대표 지시: *"각 페이지마다 이렇게 지금 UI들이 공통적으로 잡혀있는데 어떻게 다른 디자인
> 시안들로 더 받을 수 있을까?"* → *"시안 라우트 만들어줘."*

**구조가 다른 여러 안을 같은 데이터로 나란히 놓고 고르는 화면.** 내부 전용(링크 0 · robots 차단 · noindex).

## 왜 필요했나 — 기존 두 방법의 한계

| 방법 | 되는 것 | 안 되는 것 |
|---|---|---|
| 글로 설명 + 알파벳 선택("안 B 로 하자") | 색·여백·문구 | **레이아웃** — 글로는 판단이 안 된다 |
| `scripts/visual-preview.mjs --css` | 실제 컴포넌트를 렌더 | **구조** — CSS 만 바꾼다 |
| **시안 갤러리** | 구조가 다른 안을 나란히, 데이터 상태까지 | 예쁜지 여부(그건 대표가 고른다) |

## 쓰는 법

```
https://urdeal.kr/design/variants                     기본(첫 세트, 첫 안, 폰 430)
  ?set=seller-analytics   어느 화면
  &v=b                    어느 안        ("안 b 로 하자" 의 그 b)
  &data=empty             데이터 상태     ← 🔑 이 도구의 핵심
  &w=phone|tablet|pc      폭
  &side=1                 나란히 보기
```

🔑 **데이터 스위치가 핵심이다.** 대표가 불편해한 화면은 대부분 **숫자가 0일 때** 무너진다
(`/seller/analytics` 가 정확히 그랬다 — 0 이 다섯 개, 그 앞뒤로 컨트롤 12개). 데이터가 있을 때만
보면 그 문제를 못 본다. 그래서 모든 시안은 `장사됨 ↔ 비어 있음` 두 상태로 그려진다.

## 새 시안 세트 추가 (파일 하나 + 등록 두 줄)

1. `src/pages/design-variants/sets/<이름>.tsx` — `VariantSet` default export
2. `registry.ts` 의 `SET_LOADERS` 에 한 줄, `SET_INDEX` 에 한 줄
   (lazy 라 목록 화면이 **불러오기 전에** 이름을 알아야 해서 두 곳이다. 가드가 키 일치를 고정한다.)

**규칙 넷** — `design-variants-2026-09-15.test.ts` 가 전부 강제한다:
- 안이 **둘 이상**이고 그중 하나는 **"지금"**(기준선이 없으면 좋아졌는지 알 수 없다)
- 세트마다 `problem`(대표가 무엇을 불편해했나), 안마다 `note`(무엇을 다르게 했나)
- **API 호출 0** — 가짜 데이터로만 그린다(이 화면은 무엇도 망가뜨릴 수 없어야 한다)
- **lazy** — 소비자 첫 페인트 영향 0
