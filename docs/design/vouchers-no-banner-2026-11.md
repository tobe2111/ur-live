## 1. 지금 무엇이 문제인가 (라이브 실측 2026-11-01, iPhone 390×844)

브라우저로 `urdeal.kr/vouchers` 를 열어 **박스를 재서** 얻은 값이다.

| 블록 | y | 높이 |
|---|---|---|
| 배너 히어로(잉크 `#16181C`, 유달이 + "딜, 이렇게 모아요") | 0 | **196** |
| 잔액 카드(배너에 28 걸침) | 168 | 56 |
| 카테고리 밑줄 탭 | **216** | 44 |
| 브랜드 로고 줄 | 272 | 76 |
| 섹션 제목 `커피/음료 교환권 20+` + 정렬 | 385 | 44 |
| **첫 상품 타일** | **432** | |

- **첫 화면(844)의 절반이 상품 앞에 있다.** 그중 196px 가 "딜 모으는 법" 안내다. 교환권을 사러 들어온 사람에게 첫 화면의 23%가 그 광고다.
- 거르는 장치가 **두 줄**이다(카테고리 탭 + 브랜드 로고 줄, 합쳐 120px).
- 섹션 제목 `커피/음료 교환권` 은 **바로 위 탭이 이미 하는 말**이다.

## 2. 시안 네 개 (전부 배너 제거 + 흰 바탕)

첫 상품 y 는 **캔버스에서 실제로 잰 값**이다(라벨을 손으로 적지 않고 렌더 후 실측값으로 덮어썼다). 기준 폰의 재현값 422 는 라이브 432 와 10px 차이이고, 비교는 같은 자 안에서 한 것이다.

| 안 | 머리 | 첫 상품 y | 성격 |
|---|---|---|---|
| 지금 | 배너 196 | 422 | 기준 |
| **A** 한 줄 머리 | 잔액 + 검색·보관함 한 줄(56) | **230** | 최소 변경. 지금 구조를 그대로 두고 머리만 교체 |
| **B** 탭이 머리 | 없음(카테고리 탭이 맨 위) | **139** | 가장 압축. 잔액은 브랜드 줄 앞 알약 |
| **C** 브랜드가 머리 | 검색창 + 큰 브랜드 줄 | **256** | "교환권은 브랜드로 찾는다"는 판단 |
| **D** 2열 큰 타일 | A안과 같음 | **200** | 3열 → 2열. 사진·상품명이 커진다 |

### 각 안이 잃는 것

- **A** 잃는 게 가장 적다. 대신 얻는 것도 가장 적다(여전히 거르는 줄이 두 개).
- **B** 잔액이 알약으로 작아진다. 검색·보관함이 탭 줄 오른쪽에 붙어 탭 스크롤 폭이 줄어든다(카테고리가 9개라 4개쯤 보인다).
- **C** 카테고리가 브랜드보다 아래로 내려간다. 브랜드가 없는 카테고리(기타상품권 등)에서는 머리가 비어 보인다.
- **D** 한 화면에 보이는 상품이 9개에서 4개로 준다. 사진이 큰 대신 훑는 속도가 느려진다.

## 3. 흰 배경을 전 화면에 적용할 때의 대가 (실측)

`--bg: #F8F7FC → #FFFFFF` 를 주입해 **실제 코드로** 렌더한 A/B (`assets/white-bg-ab-2026-11-01.png`).

- **유어샵**: 차이 거의 없다. 2026-09-30 에 이미 한 톤(`bg-surface`)으로 간 화면이라 그렇다.
- **마이**: 흰 안내 카드가 **바탕에 녹는다.** 카드 색 `--surface: #FFFFFF` 와 바탕이 **같은 값**이 되어 둘을 가르는 것이 `--lift`(잉크 6% 그림자) 하나뿐이다.

지금은 바탕과 카드가 `#F8F7FC ↔ #FFFFFF` 로 **밝기 차 + 그림자** 둘이 갈라 주는데, 흰 배경에서는 **밝기 차가 0**이 된다.

### 그래서 같이 정해야 하는 것

1. **그림자를 진하게** `--lift` 를 6% → 10~12%. 한 줄 변경이고 전 화면에 즉시 먹는다. 대신 그림자가 보이기 시작하면 "떠 있는" 느낌이 세진다.
2. **hairline 테두리** 카드에 `--rule`(잉크 8%) 한 줄. 또렷하지만 2026-09-02 에 정한 "카드 테두리 0" 을 되돌리는 것이다.
3. **판을 없앤다** 마이·지갑도 유어샵처럼 평면 목록으로. 가장 일관되지만 범위가 가장 크다.

## 4. 측정하며 틀렸던 것 (다음 세션 주의)

- **컨테이너에서 교환권 사진이 하나도 안 뜬다**(26장 중 21장 깨짐). 결함이 아니라 **측정 한계**다. `bizimg.giftishow.com` 이 이 컨테이너에서 connection reset 이고(우리 R2 `media.ur-team.com` 은 200), 라이브 교환권 100건은 **전부 giftishow 직링크**다(2026-10-31 `RAW_ONLY_IMAGE_HOSTS` 결정). 대표 폰에서는 뜬다. **"사진이 안 보인다"를 UI 결함으로 보고하지 말 것.**
- `scripts/visual-preview.mjs --route=/vouchers` 는 **목록이 0건**으로 렌더된다(그 경로 시드가 없다). 그래서 이 시안은 캔버스로 그렸고, 상품명·가격·대표색은 라이브 API 에서 받은 실제 값이다.
- 레포 `node_modules` 를 설치하면 전역 chromium 과 버전이 어긋난다. `executablePath: '/opt/pw-browsers/chromium-1243/chrome-linux64/chrome'` 를 주면 된다.

### 🔑 처방 1 은 토큰 한 줄이라 전 화면에 한 번에 먹는다

`shadow-lift` 는 **139파일 248건**이고 전부 `--lift` 를 읽는다. 그래서 값만 올리면 카드도, **떠 있는 면**
(모달·시트·드롭다운·토스트·캐러셀 화살표·지도 오버레이·차트 툴팁)도 같이 진해진다 — 흰 배경에서는
그쪽도 경계가 약해졌으므로 **같은 방향이 맞다.**

⚠️ 만약 평면(처방 3)으로 갔다면 `--lift: none` 은 쓸 수 없었다. 그러면 떠 있는 면이 흰 배경에서
**통째로 사라진다**(2026-09-29 가 명시한 경계) — 카드만 골라 평면화해야 했고 그게 248건을 가르는 일이다.
처방 1 은 그 문제가 없다.
