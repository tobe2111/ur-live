# ✅ 릴리즈 체크리스트 — 공구 운영자 SaaS "완성" 정의

> **대표 지시 2026-07-29**: *"목표는 파일럿 없이도 실제 운영자가 오늘 쓸 수 있는 상태.
> '코드가 다 됐다'가 아니라 **'운영자가 가입하고, 상품을 올리고, 소비자가 사고, 픽업하고,
> 정산받는 전 과정이 막힘 없이 돈다'**가 완료다."*
>
> **이 문서는 1단계 산출물 — 코드 변경 0.** 대표 승인 후 2단계(세션 순서대로 연속 실행).
>
> 🔴 **"완료"라는 단어의 사용 조건**: 아래 전 항목 green **+ 대표가 실계정으로
> 운영자 가입 → 상품 등록 → 구매 → 픽업 → 정산 확인을 직접 1회 완주.**
> 그 전에는 어떤 세션도 "완료"라고 쓰지 않는다.

---

## 0. 판정 규칙 — 이 문서의 사용법

각 항목은 **"된다/안 된다"가 아니라 "완료 판정을 누가 어떻게 하는가"**를 적는다.
판정자는 셋뿐이다:

| 판정자 | 무엇을 판정하나 | 증거 |
|---|---|---|
| 🤖 **세션(자동)** | 코드가 규칙을 지키는가 | vitest / 가드 스크립트 / tsc — **CI green 이 증거** |
| 👤 **대표(수동)** | 실제로 돈이 맞게 흐르고 화면이 도는가 | 실계정 왕복 · 어드민 화면 숫자 · staging 실결제 |
| 🏛 **외부** | 법적으로 써도 되는가 | 법무 회신 · 기획자 산출물 |

> **🤖 만으로 green 인 항목은 없다.** 자동 판정은 "틀리지 않았다"만 말하고
> "된다"는 말하지 못한다. 여정 단계는 전부 👤 왕복이 최종 판정이다.

### 1.1 🔴 X1 이 지금 실행 가능한지부터 확인해야 한다

`docs/STAGING_CHECKLIST.md` 는 2026-07-05 신설 이후 **12개 항목(S1~S4·P1~P8) 전부 `⬜ 미검증`**이다.
**staging 으로 게이트를 닫은 전례가 0건**이라는 뜻이고, 이 계획 전체가 그 메커니즘에 걸려 있다.

또 레포 안에 **모순된 서술**이 있다:

| 근거 | 말하는 것 |
|---|---|
| `scripts/deploy-staging.sh` + `npm run deploy:staging` | staging 프로젝트 `ur-live-staging` **있음** |
| `.github/workflows/prod-smoke.yml:4` 주석 | *"staging 이 없어…"* |

⇒ **세션 ② 착수 전에 대표가 확인해야 할 3가지** (이게 X1 의 실제 선행조건):

1. `ur-live-staging` Pages 프로젝트가 **실제로 존재하는가**
2. 거기에 **별도 D1** 이 붙어 있는가 (프로덕션 D1 을 공유하면 실결제 테스트가 라이브 데이터를 오염시킨다)
3. **Toss 테스트 키**가 staging env 에 있는가 (없으면 "실결제"가 성립하지 않는다)

> 셋 중 하나라도 아니면 X1 은 *"검증을 못 한다"*가 아니라 ***"검증 환경부터 만들어야 한다"***가 되고,
> 그건 **별도 작업 항목**으로 이 체크리스트 앞에 붙는다. 지금 상태로는 판정 불가 — **먼저 확인.**

#### ⚠️ PR 프리뷰 배포를 staging 으로 착각하지 말 것

PR 마다 Cloudflare Pages **프리뷰 배포**가 자동으로 뜬다(예: `<hash>.ur-wholesale.pages.dev` ·
브랜치 프리뷰 URL). 화면은 도니까 staging 처럼 보이지만 **실결제 검증엔 못 쓴다** —
Pages 프리뷰는 별도 preview 바인딩을 명시하지 않으면 **프로덕션 D1 을 그대로 붙는다.**
프리뷰에서 실결제하면 **라이브 주문·원장·재고에 진짜로 쓴다.**

⇒ §1.1 의 확인 2번(별도 D1)이 *"있으면 좋은 것"*이 아니라 **필수 조건**인 이유다.
확인 전에는 프리뷰 URL 에서 결제 버튼을 누르지 말 것.


### 1.2 ✅ X9 — cron 트리거·바인딩 **판정 완료** (2026-07-29, 두 소스 교차확인)

**소스 ①** CF API 직접 조회(읽기 토큰) · **소스 ②** 어드민 하트비트. **둘이 일치한다.**

| 코드의 cron 식 | CF API 등록 | 하트비트 | 결론 |
|---|---|---|---|
| `*/5 * * * *` | ✅ 등록 | 9건 기록 | 🟢 정상 |
| `0 18 * * *` | ✅ 등록 | (18시 미도래) | 🟢 **정산 성숙·원장 정합은 돈다** |
| `0 19 * * *` | ✅ 등록 | (19시 미도래) | 🟢 대사·인플루언서 지급 돈다 |
| `*/2` · `0 * * * *` · `0 3` · `0 9` · `0 0` · `0 20 * * 0` · **`0 0 * * 1`** | ❌ **미등록** | 0건 | 🔴 **안 돈다** |

> 09:00 UTC 경과 후 재조회 — `0 9 * * *` 블록 작업이 **하나도 안 나타났다**(소비자 하트비트 9건 전부 `*/5`).
> CF API 가 말한 "미등록"을 **런타임이 독립적으로 확인**했다.

**🔴 치명 3건**: `0 0 * * 1`(**`payouts-generate` 주간 지급 — 돈이 안 나간다**) ·
`0 20 * * 0`(**`d1-backup` — 못 되돌리는 축**) · `0 * * * *`(환불 재시도·자가복구·**감시자 자신**).

**🔴 더 큰 것 — 캐리어 바인딩이 5개뿐**: cron 은 `ur-live` **Worker** 에서 도는데 바인딩이
`DB`·`FRONTEND_URL`·`LIVE_STREAM`·`RATE_LIMITER`·`SCRAPER_URL` 뿐이다(Pages 는 env 63개).
⇒ **DB 만 쓰는 작업만 정상**이고 `TOSS_SECRET_KEY`·`CACHE_KV`·`ALIGO_*`·`VAPID_*`·`KT_ALPHA_*` 가 필요한
작업은 전부 무력화. **트리거만 켜면 절반만 고치는 것이다.**

**⚠️ 앞선 가설 정정**: *"일간 블록도 안 돈다"* 는 **틀렸다**(`0 18`·`0 19` 는 등록돼 있다).
하트비트에 없던 건 추적 시작(03:42Z)이 늦어서였다 — **"판정 불가"로 남겨둔 판단이 맞았다.**

수습 순서·Plan B: [cron-trigger-remediation.md](./cron-trigger-remediation.md) §F
