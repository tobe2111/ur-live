# 🧭 기획 브리프 — 공구 운영자 SaaS (P0)

> **이 문서의 쓰임**: 기획자에게 넘기는 **유일한 진입 문서**. 다른 설계 문서는 전부 엔지니어 향(가드·래칫·
> 롤백 절차가 절반)이라 그대로 주면 구조를 되묻는 데 시간이 샌다. 여기서 **구조는 답으로 주고, 과제만 연다.**
>
> 작성 근거: 2026-07-29 대표 지시 — "기획자 첫 산출물 3건 승인. 순서와 경계를 붙인다."

---

## 0. 무엇을 만드는가 (3분)

**공구 운영자에게 "자기 이름의 공동구매 판"을 통째로 내주는 SaaS.**

- 운영자는 신청하면 자기 몰(`urdeal.kr/{몰}` 또는 자기 도메인)을 갖는다
- 그 판에 자기 상품을 올리고, 공구(마감·특가)를 연다
- 소비자는 **카드로 즉시 결제**하고 **매장에서 픽업**한다
  > 🔒 **P0 는 픽업 전용이다**〔대표 확정 2026-07-29〕. **배송은 P0 범위 밖** — 이후 항목이다.
  > 화면·문구·정책을 배송 전제로 쓰지 말 것(배송비·주소·송장 개념이 들어오면 P0 가 늘어난다).
- 유어딜은 거래액의 **5%**를 가져간다. 나머지는 운영자 몫

기존 **도매몰(유통스타트)은 접는다.** 몰 껍데기(멀티테넌시·브랜딩·컨텍스트 해석)만 물려받고,
B2B 판매 화면은 물려받지 않는다 → §3 제약 참조.

## 1. 구조 요약 — 되묻지 않도록

### 등장인물

| 이름 | 정체 | 돈 |
|---|---|---|
| **소비자** | 유어딜 회원(또는 비로그인 방문자) | 카드로 결제 |
| **운영자** | 몰 주인. 시스템상 **merchant** | 결제액 − 5% − (인플루언서 몫) |
| **유어딜** | 플랫폼 | **결제액의 5%** — 고정 |
| 인플루언서 | 소개해서 판 사람(선택) | 운영자 몫에서 나눠 받음 |

### 돈이 흐르는 순서

```
소비자 카드 결제
   → 유어딜이 잠시 보관(escrow)
   → 소비자가 상품을 받거나 사용
   → 유어딜 5% 떼고 운영자에게 지급
```

**5%는 소비자가 더 내는 돈이 아니다.** 소비자가 낸 금액 안에서 유어딜 몫으로 먼저 떼는 구조다.
(예: 7,000원 결제 → 유어딜 350원, 운영자 6,650원. 정가 10,000원이어도 **실제 결제액 기준**)

### 몰 = 테넌트

몰 하나는 데이터 한 줄이다. 몰마다 이름·로고·색상·카테고리·도메인을 따로 갖는다.
**소비자는 자기가 들어온 몰의 상품만 본다.** 몰끼리, 그리고 유어딜 본진과 서로 안 섞인다.

## 2. 과제 3건 — 순서와 경계

> 🔴 **순서는 대표 확정이다.** 1번이 개발(세션 ③-a)을 직접 막고 있고, 2번은 법무 리드타임이 있어
> 착수는 즉시다. 3번은 정책이 이미 정해져 있어 문안만 남았다.

### 과제 1 — 몰 브랜딩 기본값 〔최우선〕

**왜 최우선인가**: 소비자 몰 화면(세션 ③-a)이 이 값 없이는 못 그려진다. 화면이 몰마다 달라지는
지점이 여기라서, 기본값이 정해져야 "브랜딩 안 넣은 몰은 어떻게 보이는가"가 결정된다.

**정해야 하는 것**
- 운영자가 아무것도 설정하지 않았을 때 몰이 **어떻게 보이는가** (이름·로고 자리·색)
- 운영자가 설정할 수 있는 항목의 **범위** — 어디까지 열고 어디부터 잠그는가
- 유어딜 브랜드가 **어디에 얼마나 남는가** (완전 화이트라벨인가, "powered by 유어딜"인가)
- 몰 이름의 **제약** (길이·금칙어·중복 처리)

**경계**
- 🔴 서비스 자체의 **브랜드명은 이 과제가 아니다.** (§9 열림 유지 — 대표 결정 사항)
- 화면 레이아웃을 새로 그리지 말 것. 기존 소비자 공구 화면에 **브랜딩만 얹는다**(§3 제약)

---

### 과제 2 — 미수령 청약철회 제한 고지 문구 〔즉시 착수, 법무 초안까지〕

**왜 지금**: 법무 확인에 리드타임이 있다. 문안이 늦으면 픽업 공구 전체가 늦어진다.

**경계 (대표 확정)**
- 기획자 산출물은 **법무에 보낼 초안까지**다
- **최종 문구는 법무 확인 후 확정**. 그 전까지 코드에는 **임시 표기**로 둔다
- 정책값(아래 2갈래) 자체는 이미 있다. 기획자는 **정책을 바꾸는 게 아니라 고지 문안을 쓴다**

**정책 2갈래 — 입력값이지 과제가 아니다**

| 보관구분 | 정책 |
|---|---|
| 냉장 · 냉동 | 픽업 마감 후 **환불 불가** |
| 실온 | **유예 3일** 후 부분 환불(매장 원가 보전분 차감) |

- 상품 등록 시 매장이 보관구분을 선택 → **소비자 결제 화면에 명시**해야 한다(청약철회 제한의 법적 고지 요건)
- 정책값은 상수가 아니라 설정이다. 법무 확인 후 바뀔 수 있다

**써야 하는 것**
- 결제 **전** 고지 문구 (소비자가 동의하는 시점의 문안)
- 마감 **후** 안내 문구 (미수령이 확정됐을 때 소비자가 보는 문안)
- 상품 등록 화면에서 **운영자가 보는** 설명 (자기가 무엇을 선택하는지 알게)

---

### 과제 3 — 운영자향 수수료 안내 문구

**🔒 정책은 대표가 이미 정했다 — 재논의 대상 아님**

> **소비자에게 수수료 비노출.** 5%는 소비자가 아니라 운영자(merchant)에게서 나가는 돈이라
> 소비자 화면에 노출할 실익이 없다. (대표 확정 2026-07-29)

따라서 과제는 *"소비자 표시 문구"가 아니라* **운영자향 안내 문구**로 좁힌다.

**써야 하는 것**
- 운영자가 **신청할 때** 보는 수수료 안내 (얼마를, 언제, 무엇에서 떼는가)
- 운영자 **정산 화면**의 표기 (결제액 / 수수료 / 실지급액이 어떻게 보이는가)
- 인플루언서 몫이 있을 때 **운영자 몫이 어디서 줄어드는지** 오해 없게 쓰는 법
  (유어딜 5%는 그대로고, 인플루언서 몫은 **운영자 몫에서** 나간다)

**경계**
- 🔴 **모드 B 수수료율**은 이 과제가 아니다 — 아직 열려 있다(§9). 여기서 다루는 건 **5% 구조의 설명**뿐

## 3. 제약 — 어기면 산출물을 못 쓴다

### 명칭 (SSOT — 사용자에게 보이는 모든 문구)

| 쓴다 | 쓰지 않는다 |
|---|---|
| **유저** / **사업자 유저** | 큐레이터, 크리에이터, 인플루언서(사람 지칭), 판매자, 셀러(사람) |
| **이용권** (매장에서 쓰는 권종) | 식사권, 공구권 |
| **교환권** (기프티콘) | — |
| **동네딜** (지역 딜 목록) | — |
| **셀러 대시보드** (도구 이름으로만) | — |

"셀러"는 **도구 이름**에서만 살아 있다(셀러 대시보드). 사람을 가리킬 땐 쓰지 않는다.

### 화면 — 새로 그리지 말 것 / 물려받지 말 것

| | 대상 |
|---|---|
| 🟢 **물려받는다** | 몰 인프라(브랜딩·색상·로고·카테고리·도메인·배너·게시판) |
| 🟢 **물려받는다** | 소비자 공구 화면(공구 목록·공구 상세) — 여기에 **몰 스코프 + 브랜딩만** 얹는다 |
| 🔴 **포크 금지** | 도매 B2B 판매 화면 전부(카탈로그·대시보드·체크아웃·장바구니·예치금) |

**B2B 화면을 못 쓰는 이유** — 세 층이 뼈대에 얽혀 있다:

| 층 | B2B 현행 | 운영자 몰에 필요한 것 |
|---|---|---|
| 가격 | 등급별 공급가 + 마진 | 소비자 단일가 / 공구가 |
| 인증 | 로그인 여부로 **가격이 갈린다** | **비로그인 소비자**도 그냥 본다 |
| 결제 | 예치금 차감 | **카드 즉시결제** |

### 결제 방침 (대표 확정)

- 신규 운영자 몰은 **예치금 무접촉**. 충전·잔액·차감 개념이 화면에 등장하지 않는다
- 소비자 결제는 **유어딜 카드 즉시결제만**
- 예치금 기반 멤버십(`wholesale/plus`)은 운영자 몰에 **노출 금지**

## 5. 산출물이 어디로 가나

| 과제 | 받는 즉시 반영되는 곳 |
|---|---|
| 1. 몰 브랜딩 기본값 | 세션 ③-a(소비자 몰 화면) **착수 조건** — 이게 오면 바로 시작 |
| 2. 미수령 고지 문구 | 법무 송부 → 확인 후 결제 화면 문구 확정. 그 전엔 **임시 표기**로 코드 진행 |
| 3. 운영자향 수수료 문구 | 세션 ③-b(3분 등록 폼) · 운영자 정산 화면 |

**개발과 병렬로 진행한다.** 코드 쪽 차단 관계(staging 실결제 · 예치금 숫자)는 그대로이고,
그건 대표가 처리한다 — 기획 3건은 그 게이트와 무관하게 돈다.

## 6. 대표 확정 사항 (재논의 대상 아님)

- 운영자 = 소비자 셀러 + `mall_id` 스탬프 방향
- 운영자 = **merchant**, 유어딜 5% 불변 (새 요율 로직 만들지 않는다)
- 신규 몰 **예치금 무접촉** · 소비자 결제는 카드 즉시결제만
- **소비자에게 수수료 비노출** 〔2026-07-29〕
- 도매몰(유통스타트) 폐기
- 메디스타트 — ⏳ **폐기 방침이되 확정은 활동 조회 후**〔2026-07-29 정정〕
  > 이 세션은 **활동 조회를 하지 않았다.** 앞서 "메디스타트 폐기"로 단정해 적었던 것을 되돌린다.
  > 조회는 이 환경에서 **구조적으로 불가**하다 — 도매 API 는 도매 배포(`utongstart.com`)에만 있고
  > 그 호스트가 프록시 차단(000)이며, D1 직접 조회용 CF 토큰은 죽어 있다(`code 1000`).
  > **확인 주체·방법**: 대표가 `utongstart.com` 도매 어드민에서 **몰 2의 상품·주문·회원 수**를 확인.
  > 전부 0이면 그때 "폐기 확정"으로 갱신한다. 기획 산출물은 이 항목에 의존하지 않는다.
- P0 최소 세트 = **소비자 몰 화면 + 3분 등록 폼**. 운영자 신청/대시보드는 파일럿 동안 어드민이 수동 처리
- B2B 판매 화면 **포크 금지**
- **운영자 문의 = 파일럿 동안 대표 연락처**〔2026-07-29〕. 운영자가 늘면 카카오 채널로 승격.
  **티켓 화면은 만들지 않는다** — 기획 산출물에 문의 화면을 넣지 말 것

## 7. 아직 열려 있는 것 (기획자가 채우지 않는다)

- **서비스 브랜드명** — 사입 성격이 드러나는 이름 권장. "유어몰" 보류
- **모드 B 수수료율** — 모드 A 실측 후 결정
- **법무 문구 최종본** — 법무 확인 전 확정 금지 (초안까지가 기획 범위)
