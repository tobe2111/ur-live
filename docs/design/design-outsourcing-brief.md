# 🎨 디자인 의뢰서 — 유어딜 운영자 몰 파일럿

> **이 문서 하나만 읽고 작업할 수 있게** 쓴 의뢰서입니다. 코드나 서비스에 대한 사전 지식이 없어도 됩니다.
> 작성 2026-08-02.

---

## 1. 이 서비스가 무엇인가

**동네 가게 사장님이 "공동구매"를 열고, 손님이 그 링크로 들어와 사고, 정해진 날 가게에 와서 받아가는 서비스**입니다.

- 택배가 없습니다. **손님이 가게에 직접 찾으러 옵니다**(픽업).
- 사장님은 자기 링크(`urdeal.kr/{가게이름}`)를 **카톡 단톡방에 뿌립니다.** 그게 유일한 유입 경로입니다.
- 결제는 저희(유어딜)가 처리하고, 사장님은 주문 목록을 화면에서 봅니다.

지금 **기능은 다 만들어져 있고 디자인만 안 입혀져 있습니다.** 개발자가 기능 검증용으로 회색 박스만 놓은 상태입니다.

### 이 파일럿의 성공 기준 (디자인 판단의 기준선)

> **2주 안에 사장님이 ① 공동구매를 2번 이상 열고 ② 주문을 엑셀·카톡이 아니라 이 화면에서만 관리한다.**

②가 진짜 기준입니다. **사장님이 화면을 어려워해서 엑셀로 돌아가면 실패**입니다.
그래서 디자인 목표는 "예쁘게"보다 **"사장님이 안 도망가게"** 입니다.

---

## 2. 두 명의 사용자

| | **사장님 (운영자)** | **손님 (소비자)** |
|---|---|---|
| 누구 | 동네 반찬가게·베이커리·정육점 사장. 40~60대 흔함 | 그 가게 단골. 카톡 단톡방 멤버 |
| 기기 | **휴대폰, 한 손, 가게 카운터에서 서서** | 휴대폰 |
| 디지털 숙련도 | 낮음. 엑셀·카톡으로 주문 받던 사람 | 보통. 쿠팡·배민은 씀 |
| 이 사람이 겁먹는 순간 | 입력칸이 많을 때, 뭘 잘못했는지 모를 때 | "이거 택배 오나요?" 가 헷갈릴 때 |

---

## 3. 전체 흐름

```
[사장님]  휴대폰으로 공구 등록 (화면 B)
              ↓  링크 복사
          카톡 단톡방에 뿌림
              ↓
[손님]    urdeal.kr/{가게이름} 도착 (화면 A)  ←── 손님이 보는 유일한 매장 화면
              ↓  상품 탭
          상품 상세 → 결제  (※ 기존 화면, 이번 범위 아님)
              ↓
[사장님]  주문 목록에서 확인 (화면 C)
              ↓
          정해진 날 손님이 가게에 와서 받아감
              ↓
[사장님]  문제 생기면 반품 처리 (화면 D)
```

## 4. 화면별 의뢰 내용

### 🥇 화면 A — 손님이 보는 가게 홈 `urdeal.kr/{가게이름}`

**가장 중요합니다.** 손님이 카톡 링크를 눌러 도착하는 **첫 화면이자 유일한 매장 화면**입니다.
여기서 안 사면 뒤가 없습니다. 모바일 세로가 기본입니다.

**지금 화면에 있는 것 (전부)**

| 영역 | 내용 |
|---|---|
| 상단 | 가게 로고(없으면 가게 이름 첫 글자를 색 사각형에), 가게 이름, 한 줄 소개 |
| 상단 | 🔒 `결제는 유어딜이 안전하게 처리합니다` — 처음 보는 가게라 손님이 불안해합니다 |
| 목록 | 상품 카드 격자 (모바일 2열 / 태블릿 3열 / PC 4열) |
| 카드 | ① 정사각 상품 사진 ② 사진 위 왼쪽 `⏰ 2일 남음` ③ 사진 위 오른쪽 `3개 남음`(10개 이하일 때만) ④ 상품명(2줄까지) ⑤ `30%` + `7,000원` + ~~10,000원~~ ⑥ `📦 8월 10일 픽업` + `냉장·냉동` 배지 |
| 목록 하단 | 보관 안내 문구 (예: *"냉장·냉동 상품입니다. 픽업일에 찾아가지 않으면 환불이 어려울 수 있습니다."*) |
| 맨 아래 | `powered by 유어딜` (작게) |
| 상품 없을 때 | *"진행 중인 공동구매가 없습니다."* |

**꼭 지켜야 할 것**

- 🔴 **카드에서 제일 먼저 읽혀야 하는 것은 "언제 마감"과 "얼마"** 입니다. 공동구매는 마감이 있어서 급합니다.
- 🔴 **"📦 픽업" 표시가 눈에 띄어야 합니다.** 이게 안 보이면 *"택배 언제 와요?"* 문의가 사장님에게 쏟아집니다. 저희가 가장 걱정하는 문의입니다.
- 보관 안내는 **목록 아래에 한 번만** 나옵니다. 카드마다 반복하면 마감·가격이 묻힙니다.
- `powered by 유어딜` 은 **클릭되지 않는 글자**입니다. 링크로 만들지 마세요(의도적입니다 — 손님을 저희 사이트로 데려가지 않습니다).

---

### 🥇 화면 B — 사장님의 "빠른 공구 등록" (휴대폰)

**성공 기준 ①의 무대입니다.** 사장님이 가게 카운터에서 **서서, 한 손으로, 3분 안에** 끝내야 합니다.

**지금 화면에 있는 것 (위에서 아래로)**

1. 제목 `빠른 공구 등록` / 부제 `사진·가격·마감만 정하면 바로 열립니다.`
2. **사진** — 업로드 1장
3. **상품명** — 예시 문구 `예: 수제 사과잼 250g`
4. **정가 / 공구가** — 좌우 2칸. 숫자 키패드가 바로 뜹니다
5. 가격 피드백 — 잘못: `공구가는 정가보다 낮아야 합니다.` / 맞음: `30% 할인으로 열립니다.`
6. **마감** — **`3일` `7일` `14일` 버튼 3개** (달력 없음)
7. **픽업일 (선택)** — 날짜 선택
8. **보관구분 (선택)** — `실온` `냉장·냉동` 버튼 2개. 고르면 아래에 *"소비자 안내: …"* 로 손님에게 나갈 문구를 미리 보여줍니다
9. 오류 상자 (있을 때만)
10. **하단 고정 버튼** — `공구 열기`

**꼭 지켜야 할 것**

- 🔴 **입력칸과 버튼은 높이 56px**입니다. 손가락으로 눌러야 합니다. 줄이지 마세요.
- 🔴 **마감에 달력을 넣지 마세요.** 버튼 3개인 건 빠뜨린 게 아니라 **일부러 뺀 것**입니다 — 달력은 한 손으로 가장 괴로운 위젯입니다.
- 🔴 **제출 버튼은 화면 하단에 고정**입니다. 스크롤해서 찾게 하지 마세요.
- **필수(사진·상품명·가격·마감)와 선택(픽업일·보관구분)이 눈에 구분**되면 좋겠습니다. 지금은 선택 항목에 회색 `(선택)` 만 붙어 있습니다.
- 오류가 났을 때 **뭘 고쳐야 하는지** 바로 보여야 합니다. 사장님은 "저장 실패"만 보면 포기합니다.

---

### 🥈 화면 C — 사장님의 주문 목록 `/seller/orders`

**성공 기준 ②의 무대입니다.** 여기가 엑셀보다 편해야 사장님이 안 돌아갑니다.

이 화면은 **이미 만들어져 오래 쓰이던 화면**이라 뼈대가 있습니다. **재설계가 아니라 정돈**을 부탁드립니다.
사장님이 하는 일은 단순합니다 — *"오늘 픽업하러 올 사람이 누구고 뭘 가져가나"* 를 훑는 것.

---

### 🥉 화면 D — 사장님의 반품 요청 목록 `/seller/returns`

**지금 있는 것**: 제목 `반품 요청` / 안내 *"내 상품에 들어온 반품 요청입니다. 환불 실행은 관리자가 처리합니다."* /
목록 카드(주문번호, 고객명, 금액, 날짜, 사유, 상태 배지) / `승인` `거절` 버튼 / 빈 상태 / 오류 상태.

- 🔴 **환불(돈) 버튼은 일부러 없습니다.** 넣지 마세요. 사장님은 승인·거절만 하고, 실제 환불은 관리자가 합니다.
- **"요청 0건"과 "목록을 못 불러옴"은 다른 화면**이어야 합니다. 지금 그렇게 나눠져 있습니다.

---

### 🏅 화면 E, F — 나중에 (급하지 않음)

- **문의 카드** (사장님 홈 안 작은 카드): *"문제가 있으면 알려주세요"* + 카카오 오픈채팅 링크. ⚠️ **연락처가 등록 안 되면 이 카드는 아예 안 그려집니다** — "빈 상태" 디자인이 필요 없습니다.
- **환불 금액 입력** (관리자 전용): 손님에게 안 보입니다.

## 5. 브랜드 & 기술 제약

### 5.1 브랜드 색

| 용도 | 색 |
|---|---|
| 주 버튼 / 강조 | **`#E0526B`** (로즈) — 눌렀을 때 `#C43D55` |
| 옅은 로즈 배경 | `#FBEDF0` (다크모드에선 `#3A2530`) |
| 로고 워드마크 | 소문자 `urdeal` + 로즈 원 마침표 (Poppins 800) |

지금 화면들은 **브랜드 색을 하나도 안 쓰고 회색·검정만** 씁니다. 그게 이번 의뢰의 핵심입니다.

### 5.2 🔴 다크모드 — 화면마다 규칙이 반대입니다

| 화면 | 규칙 |
|---|---|
| **손님 화면**(화면 A) | **라이트/다크 둘 다** 필요합니다. 손님이 폰 설정으로 바꿉니다 |
| **사장님·관리자 화면**(화면 B·C·D·E·F) | **라이트 한 벌만.** 다크는 **만들지 마세요** — 시스템이 거부합니다 |

헷갈리기 쉬운 부분이라 다시 적습니다: **손님 화면만 두 벌, 사장님 화면은 한 벌.**

### 5.3 화면 크기

- **모바일 세로가 기본**입니다 (360px · 430px 기준으로 그려주세요)
- **PC에서도 손님 화면은 폭 430px 짜리 "폰 모양 액자" 안에 들어갑니다.** 넓게 펼쳐지지 않습니다.
  (사장님 대시보드는 PC에서 넓게 씁니다)

### 5.4 개발이 지켜야 해서 미리 알려드리는 것

시안에 반영해 주시면 좋고, 아니어도 개발이 맞춥니다. **다만 이걸 어기는 시안은 구현이 안 됩니다:**

- 입력창 글자색을 **밝은 회색/흰색으로 지정하지 마세요** — 배경이 흰색이라 안 보이게 됩니다
- 화면 높이를 꽉 채우는 레이아웃에서 **하단 고정 버튼이 잘리지 않게** 해주세요(모바일 브라우저 주소창 때문에 실제로 자주 잘립니다)
- 이미지는 **정사각(1:1)** 기준입니다

| 반품 화면에 **환불 버튼** 넣기 | 사장님 권한이 아닙니다 |

## 8. ⚠️ 지금 화면 스크린샷이 없는 이유

현재 화면 캡처를 함께 드리는 게 최선이지만, **이 문서를 만드는 환경에서는 캡처를 뽑을 수 없었습니다** —
사장님 화면은 로그인이 필요하고, 손님 가게 홈은 아직 파일럿 가게가 개설되지 않아 열리지 않습니다.

그래서 §4 에 **화면에 있는 요소를 하나도 빠짐없이, 실제 문구 그대로** 적었습니다.
캡처가 필요하시면 요청해 주세요 — 저희가 뽑아 이 문서에 붙이겠습니다.

## 9. 시안 전달 방법

이미지 파일 + 간단한 설명을 주시면 저희가 `docs/design/` 에 보관합니다.
채팅으로만 주고받으면 다음 작업자가 못 보므로, **파일로** 주시면 감사하겠습니다.
