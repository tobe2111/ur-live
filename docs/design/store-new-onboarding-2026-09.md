## 1. 대표 신고

> *"https://urdeal.kr/store/new 페이지가 불친절해. 처음 등록 시 페이지인데
> 매장 이용권 판매 등록하기 라던지, 그런 내용이 있어야 할 것 같은데?"*

## 2. 실측 — 페이지가 없다

`StoreClaimPage.tsx` 는 **82줄**이고 그중 화면은 두 줄이다.

```tsx
<div className="force-light-theme min-h-[100dvh] bg-gray-50">
  <SEO ... />
  <StoreRegisterModal dismissOnBackdrop={false} onClose={goBack} onDone={...} />
</div>
```

그 모달은 `fixed inset-0 bg-black/40` 오버레이 + `sm:max-w-lg`(512px) 카드이고,
첫 화면은 **바로 1단계 "내 매장을 찾아주세요" + 카카오맵 검색창**이다.

⇒ 이 주소에 도착한 사장님이 받는 정보는 **0**이다. 무엇을 등록하는 곳인지, 등록하면
무엇을 할 수 있는지, 돈이 드는지, 몇 분 걸리는지 **어디에도 안 적혀 있다.**
이 파일의 머리말도 그걸 의도로 적어 두었다 — *"이 페이지는 화면이 아니라 **주소**가 목적"*.
맞는 설계였지만, 그 주소가 **소비자 화면 어디서나 도달하는 유일한 입구**가 되면서
"주소만 있고 화면이 없는" 상태가 결함이 됐다.

### 🩸 그리고 2026-09-21 에 내가 이걸 키웠다

같은 날 PC 액자 해제 B 묶음(PR #1525)에 `/store/new` 를 넣었다. 그 전에는 430px 액자
안이라 512px 모달이 **폭을 꽉 채워** 앱 화면처럼 보였다. 액자를 벗기자 같은 모달이
**1440px 어두운 빈 들판 한가운데 뜬 작은 카드**가 됐다.

⚠️ **그렇다고 액자로 되돌리는 것은 답이 아니다** — 해제 자체는 대표 승인 사항이고,
B 묶음의 근거(*"사장님 화면의 좌우가 전부 소비자 앱 설치 QR"*)는 그대로 유효하다.
빈 공간이 생긴 게 문제가 아니라 **그 공간에 놓을 것을 아직 안 만든 것**이 문제다.
아래 안 B 가 정확히 그 자리를 쓴다.

## 3. 시안 3안

| 안 | 무엇이 바뀌나 | 값 | 대가 |
|---|---|---|---|
| **A 제목 한 줄** | 검은 오버레이를 걷고 제목 + 한 문단 + 사실 3개(0원 / 4단계 / 사진 1장)를 카드 위에 얹는다 | 가장 작은 변경. 폰에서 즉시 좋아진다 | PC 는 여전히 가운데 한 칸만 쓴다 |
| **B PC 2단** ✅ **확정·구현** | 폰은 A 와 거의 같고, PC 에서 **좌 설명 / 우 등록 카드**로 편다 | 09-21 에 생긴 빈 1440px 을 실제로 쓰는 **유일한** 안 | 레이아웃 두 벌을 유지해야 한다 |
| **C 먼저 보여주기** | 첫 화면이 폼이 아니라 *"내 가게가 손님에게 이렇게 보입니다"* 카드 한 장 + 버튼 하나 | 가장 친절하다. 이용권이 뭔지 **보여준다** | **버튼을 한 번 더 누른다.** 이미 등록하러 온 사람에겐 단계가 늘어 이탈이 는다 |

**추천: B.** 이유 셋 —
① 문제의 절반이 PC 폭이라 A 는 절반만 고친다.
② C 의 "한 단계 더"는 이 퍼널에서 비싸다. `/store/new` 로 오는 사람은 이미 **등록 의사가
   있어서** 온 사람이고(푸터·소개 페이지·카톡 링크), 설득이 아니라 안내가 필요하다.
③ B 의 폰 화면은 A 와 사실상 같으므로 **A 를 먼저 하고 B 로 확장하는 순서**도 가능하다.

⚠️ C 를 버릴 이유는 없다. C 의 "손님 화면 미리보기"는 **`/partners` 랜딩**에 있어야 할
물건이지 등록 폼 앞이 아니다(거기는 아직 설득이 필요한 자리다).

## 4. 시안에 쓴 사실 — 전부 코드 대조 완료

| 문구 | 근거 |
|---|---|
| 4단계 | `StoreRegisterModal.tsx` `STEPS` 배열 4개 |
| 카카오맵 검색 → 주소·전화번호 자동 | 1단계 `hint` |
| 담당자 전화번호는 승인·문의·정산 확인용 | 2단계 `hint` |
| 내 가게 / 중개·대행사 선택 | 3단계 |
| 사업자등록증 사진, 사람이 직접 확인 | 4단계 `hint` |
| 등록 후 이용권을 올린다 | `onDone` 토스트 |
| 소개 코드를 받는다 | 3단계 본문 *"사장님께 드릴 코드가 생겨요"* |
| 손님이 미리 사고 매장에서 쓴다 | CLAUDE.md 명칭 SSOT "이용권" |

🔴 **일부러 숫자를 안 쓴 것 하나** — 수수료율. CLAUDE.md 는 채널별 요율
(직접 10% / 중개 5%, `fee_channel_rates_enabled`)을 적고 있지만 **라이브 실측을 안 했다.**
시안은 *"등록은 무료입니다. 팔릴 때만 수수료가 나갑니다"* 로 **요율 없이** 썼다 —
이건 요율이 무엇이든 참이다. 구현 때 숫자를 넣으려면 `platform_settings` 실측이 선행이다.

## 5. 구현 시 주의 (다음 세션)

1. **`force-light-theme` 를 루트에서 떼지 말 것.** 2026-09-07 에 다크모드 입력 글자가
   1.09:1 로 안 보이던 것을 이걸로 고쳤다(`StoreClaimPage.tsx` 머리말).
2. **`dismissOnBackdrop={false}` 유지.** 2026-09-07 대표 신고 *"흰 섹션 바깥쪽을 클릭하니까
   페이지가 꺼져"* 의 수리다. 오버레이를 걷을 때 이 계약이 같이 사라지지 않게 할 것.
3. **모달을 페이지로 바꿀 때 `StoreRegisterModal` 을 포크하지 말 것.** 같은 부품이
   `MyStoresPanel`(셀러 대시보드 안)에서도 열린다 — 두 벌이 되면 4단계 문구가 갈린다.
   `variant="page"` 처럼 **오버레이·가운데정렬만 끄는 prop** 하나가 맞다.
4. `/store/find`(내 가게 찾기)도 같은 클래스다. 이번에 손대지 않았지만 **같은 처방**이 필요하다.

## 6. 이 문서가 못 보는 것

실제 픽셀. `/store/new` 는 `ProtectedRoute` 라 **익명으로는 라이브를 못 연다** —
위 실측은 소스 대조이고, 시안은 캔버스 렌더다. 구현 후 판정은 **로그인 상태의 브라우저**에서
1440px / 390px 두 폭으로 해야 한다.

## 7. 구현 (2026-09-23, 대표 *"안 B로 하자"*)

`StoreRegisterModal` 에 `variant: 'overlay' | 'page'` 를 더하고(**포크하지 않았다** — 달라지는 것은
바깥 틀·패널 **클래스 두 줄**뿐이고 4단계 문구·검증·업로드는 byte-동일), `StoreClaimPage` 를
[좌 설명 / 우 등록 카드] 2단으로 다시 썼다. 폰은 같은 마크업이 세로로 쌓인다.

### 🩸 렌더해 보고서야 잡은 것 둘 — 소스만 봤으면 둘 다 놓쳤다

1. **폰에서 카드 아래 24px 이 하단 네비 밑으로 잘렸다.** 페이지를 `h-[100dvh]` 로 잡았는데
   `main` 이 이미 `padding-bottom:56px` 로 그 자리를 예약하고 있었다(고정 네비 57px, top 787).
   ⇒ 페이지는 높이를 정하지 않고(`min-h`), **카드가 자기 `max-h` 로 바운드**한다. 바운드는 남겨야
   한다 — 없으면 1단계 `KakaoMapPicker fill` 이 `flex-1 min-h-0` 사슬에서 높이를 못 받아 **0px 로 접힌다**.
2. **✕ 가 두 개였다**(페이지 하나 + 카드 1단계 하나, 둘 다 같은 `goBack`). page 변형은 1단계 ✕ 를
   안 그리고 빈 `span` 으로 자리만 지킨다(`justify-between` 이라 `1 / 4` 가 안 밀린다).

### 🕳️ 가드에서 드러난 것 (값진 부분)

- **내 주석이 기존 가드에 구멍을 냈다.** `store-claim-2026-09-07.test.ts` ③ 은 `read(PAGE)`(주석 포함)로
  `dismissOnBackdrop={false}` 를 찾았는데, 내가 페이지 주석에 *"이 한 줄을 남겨 둔다"* 고 **설명을 적자**
  prop 을 통째로 지워도 초록이 떴다. 주입 러너가 잡았다. **설명을 잘 적을수록 가드가 헐거워지는 구조**였다
  → `stripComments` 로 수정. 이 레포가 반복해 온 "주석에만 남아도 통과" 클래스다.
- 같은 파일 ① 은 `light-island` 가 **리터럴 `className="…"`** 안에 있기를 요구했는데, 패널 클래스를
  변수로 옮기자 빨간불이 났다. **방어가 사라진 게 아니라 자리를 옮긴 것**이라 판정을
  *"리터럴 속성인가"* → *"그 문자열이 실제로 className 에 닿는가"* 로 재조준했다(패널은 이제 넷).
- **기존 주입 3건의 앵커가 낡았다**(변수화·들여쓰기 변경). 낡은 앵커는 조용히 아무것도 주입하지 않는다.
  재조준하면서 하나는 **부분일치로 2곳**에 걸려(409 패널의 같은 문자열, 들여쓰기만 다름) 줄바꿈까지 앵커에 넣었다.
- 내 새 테스트도 한 번 헛돌 뻔했다 — `/\bh-\[100dvh\]/` 가 **`min-h-[100dvh]` 까지 잡아**
  정답에 빨간불을 냈다(`-h` 앞에서도 단어 경계가 성립한다).
- 🩸 **CI 가 잡은 것 하나 — 내가 로컬에서 못 잡았다.** page 패널을 `rounded-2xl shadow-lift` 로 썼는데
  `StoreRegisterModal` 은 `src/components/seller/**` 라 **셀러 D3 래칫**
  (`seller-d3-2026-09-15.test.ts` "옛 패턴 0")의 대상이다 — 그 래칫이 `rounded-2xl` 과
  `bg-white rounded-xl shadow` 를 금지한다. ⇒ overlay 가지가 이미 쓰던 **같은 토큰**
  `rounded-[var(--dash-radius,16px)]` 으로 통일했다(셀러/어드민 8px · 그 밖 16px).
  **같은 부품이 두 반경을 갖고 있던 것 자체가 드리프트**였으니 결과적으로 더 맞다.

  🧭 **왜 못 찾았나 — 오늘 세 번째로 같은 클래스다.** 바꾼 파일을 읽는 테스트를
  `grep -rln 'StoreRegisterModal' src/tests/` 로 찾았는데, 이 래칫은 **파일 이름을 안 쓴다** —
  `git ls-files ':(glob)src/components/seller/**/*.tsx'` 로 **경로 글롭**을 훑는다.
  이름으로 grep 하면 구조적으로 안 걸린다.
  ⇒ **바꾼 파일이 어느 글롭 밑에 있는지도 보라**: `grep -rln 'git ls-files' src/tests/` (현재 7개).

## 8. 형제 화면 `/store/find` 도 같은 모양으로 (2026-09-24, 대표 *"나머지는 다 해줘"*)

§5-4 가 *"같은 클래스다. 이번에 손대지 않았지만 같은 처방이 필요하다"* 고 적어 둔 그 자리다.

**`/store/find`(`StoreOwnerClaimPage`, 287줄)는 `/store/new` 만큼 나쁘지는 않았다** — 헤더도
설명 문단도 이미 있었고 검은 오버레이도 없었다. 문제는 하나: 2026-09-21 에 PC 액자를 벗겼는데
(`pc-fullbleed.ts` 의 `/store/find`) 페이지가 `max-w-lg`(512px) 한 칸이라 **열린 폭을 안 썼다.**

**수정(안 B 와 같은 모양)**: `max-w-[1180px]` + `lg:grid-cols-[minmax(0,1fr)_460px]` —
왼쪽은 무엇을 하는 곳인지(제목 + 기존 문단 + 진행 단계 3 + 사실 3), 오른쪽은 찾기·신청·내역 그대로.
**폰은 한 줄도 안 늘렸다**(단계·사실은 `hidden lg:*`) — 09-23 에 배운 것: 폰에 설명을 다 펴면
정작 입력 칸이 첫 화면에서 사라진다. 제목은 **한 층에만** 둔다(폰=sticky 헤더 / PC=h1, 헤더는 `lg:hidden`),
그 대가로 PC 뒤로가기를 왼쪽 칸이 맡는다.
