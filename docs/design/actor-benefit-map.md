# 행위자·베네핏 한 장 지도 — "지금 살아 있는 것"만 (2026-09-07)

> 대표(2026-09-07): *"이 서비스를 창업한 나조차도 지금 구조가 헷갈리는 경우도 많아. 특히 인플루언서, 매장,
> 중개사 간의 역할이 분명하지 않고, 각각에게 베네핏을 어떻게 줄 것인지 등 말이야."*

헷갈리는 이유는 구조가 복잡해서가 아니라 **결정이 시간순으로 쌓여 취소선과 "확정 아님" 이 한 표에 섞여
있어서**다(`urdeal-platform-model.md` §2·§5 가 그 상태다). 이 문서는 **취소된 것은 싣지 않는다.**
한 행이 곧 하나의 사실이고, 사실의 출처는 코드와 `platform_settings` 실측이다. 문서와 코드가 다르면 코드가 진실이고
지도는 기획(`planning`) 역할이 고친다. **대표가 값을 바꾸고 싶으면 `docs/decisions/` 로 결정한다.**

라이브 실측(2026-09-07, D1 읽기): 승인 매장 **1**(중개 채널) · 운영 위임 **1** · 인플루언서 딜 **0** · 영입 매장 **0** ·
최근 30일 주문 **0** · 활성 이용권 2,600(데모 286). ⇒ 아래는 전부 **설계값**이고 아직 돈이 흐른 적이 없다.

## 2. 돈 한 건이 흐르는 그림 (이용권 10,000원, 직접 입점, 인플루언서 추천 경유)

```
소비자 10,000 ─ Toss ─▶ 유어딜
                          ├─ 매장 정산   9,000  (10% 뺀 값)  ← 여기서 매장이 딜 제안 %(예 5% = 500)를 인플루언서에게 낸다
                          ├─ 인플루언서 영입 2% = 200  (이 매장을 영입했다면 · 유어딜 몫 1,000 에서 나감)
                          └─ 유어딜     1,000 − 200 − PG(≈275) = 525
```
중개 경유 매장이면 유어딜 500 − PG 275 = **225** 이고 영입 2% 는 **안 나간다**(직접 입점 한정). 이 숫자가 2026-08-31 결정의 근거다.

## 4. 이 지도를 낡지 않게 하는 방법
- 값(%·기간)은 어드민 `platform_settings` 가 진실. 지도엔 실측일을 적는다. 구조(행위자·축)가 바뀌면 같은 커밋에서 이 표와 `urdeal-platform-model.md` §2 를 고친다(`check-platform-model-sync` 경고 대상).
- `finance` 루틴이 매일 §1 의 설정값을 재고, `planning` 루틴이 주 1회 §3 의 어긋남 목록을 갱신한다.
