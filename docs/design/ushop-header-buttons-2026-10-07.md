# 🔵 유어샵 헤더 공유·관리 버튼 (2026-10-07 대표 확정 **안 C · 위계**)

## 무엇이었나

대표가 유어샵(`/u/:handle`) 헤더 스크린샷을 보내며: *"여기 관리, 공유 버튼이 촌스럽네.."*
시안 셋을 받고 **"C안으로 하는게 맞는 것 같은데?"**.

## 왜 촌스러웠나 (390px 렌더 실측)

이름 줄 오른쪽 버튼 묶음 한 줄 안에 **모양 2종 · 높이 2종**이 섞여 있었다.

| | 모양 | 높이 | 테두리 |
|---|---|---|---|
| SNS(유튜브·인스타·틱톡) | 원 | 36px | 없음 |
| 공유 · 관리 | 알약 | 31px | `border-rule-strong` |

게다가 **공유와 관리가 같은 무게**였다. 2026-09-28 c2 가 *"주인/방문자 차이는 버튼 한 자리"* 라고
못 박은 그 자리가 `관리` 인데, 눈으로는 한 자리가 아니었다 (`공유` 는 누구에게나 보인다).

## 시안 셋

| 안 | 무엇을 바꾸나 | 대가 |
|---|---|---|
| A 한 덩어리 | 넷을 알약 하나에 넣고 사이를 hairline. 테두리 1개 · 높이 1개 | 조용해서 `관리` 가 눈에 덜 띈다 |
| B 아이콘만 | 글자 0, 모양 1종(36px 원) | 연필이 '관리'인지 처음 온 주인은 모른다 |
| **C ✅ 위계** | 공유는 SNS 와 **같은 모양**으로 내리고 `관리`만 유일한 채운 버튼 | 390px 에서 가게 이름 칸이 좁아진다 |

## 구현

```
[유튜브 36원] [인스타 36원] [공유 36원]  [✎ 관리]   ← 채운 면은 여기 하나뿐
```

- `iconBtnCls` — SNS 세 링크와 **공유가 같은 상수**를 쓴다. 문자열을 다시 적는 순간 갈린다.
- `manageBtnCls` — `bg-brand text-white` · h-9 · px-3 · 15px bold. 손으로 검정을 적지 않으므로
  주 버튼 색 규칙을 그대로 지킨다.
- 연필은 **유어딜 세트의 신규 `EditIcon`** 이다 — 편집은 *뜻* 아이콘이라 lucide 를 쓰면 안 되는데
  세트에 없었다(24 그리드 · 획 1.6 · `filled` 변형).

## ⚠️ 이 결정이 뒤집는 것

2026-09-28 c2 의 한 조항 *"헤더에 블루 면을 두지 않는다"*. 그 처방이 만든 결과가 위 표의
"모양 2종"이었고, 대표가 세 시안을 보고 C 를 골랐다. 🎫 규칙 ②(강조색 하나)는 그대로다 —
불변식이 **"블루 면 0" → "채운 면은 정확히 하나이고 그것이 `관리`"** 로 옮겨갔을 뿐이고,
헤더의 유일한 색 면이 주인 전용 자리가 되므로 c2 의 의도는 오히려 또렷해진다.
가드(`ushop-a3-p1.test.ts`)도 지우지 않고 그 말로 재조준했다.

## 이 변경이 **못** 하는 것

- 가게 이름이 길고 SNS 가 셋인 주인 화면에서는 이름 칸이 좁아져 **두 줄**이 된다.
  2026-09-30 이 `line-clamp-2` 로 그 경우를 **이미 허용**해 둔 상태라 잘림은 아니지만,
  C 를 고른 대가가 이것이라는 점은 시안 단계에서 대표에게 그대로 알렸다.
- jsdom 은 레이아웃이 없어 그 폭을 단위시험으로 못 잰다 — 브라우저 렌더가 판정한다.
