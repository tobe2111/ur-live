## 0. 재정의 (대표 원문 기준)

**셀러 대시보드 = 매장업주 혹은 중개자가 유어딜(이용권)을 관리하는 대시보드.**
핵심 플로우: **매장 등록 → 이용권 등록 → 인플루언서 제안** (+ 판매·사용·정산).
에이전시 대시보드는 일몰(#1179) — 두 주체 모두 셀러 대시보드를 쓴다.
매장 등록 시 **"내 가게 직접" vs "중개 업체가 관리"** 를 선택한다.

## 1. 💰 수수료 최종 구조 (대표: "이게 최종이야") ✅

| 채널 | 유어딜 수수료 | 근거 |
|---|---|---|
| **매장 직접** (`store_channel='direct'`) | **10%** | 업주가 직접 등록·운영 |
| **중개사 경유** (`store_channel='brokered'`) | **5%** | 중개 업체가 영업·관리(중개 마진은 매장↔중개사 간 계약) |

- 구현: `fee-resolver.ts` `platformPctDirect`(10, `fee_platform_pct_3p_direct`) + `FeeContext.storeChannel` — 테스트 5건 박제.
- **채널 미지정(기존 매장) = 5% 폴백** — 기존 매장을 조용히 재가격하지 않는다. 백필은 대표 확인 후.
- ⚠️ **정산 실적용은 fee-resolver authoritative 전환(FEE_RESOLVER_ENABLED)과 함께** — 현재 리졸버는 그림자.
  실수령 **표시**(등록 폼 카드·fee-context API)는 즉시 이 규칙을 쓴다(표시·정산 SSOT 동일 함수).

## 2. 매장 등록·관리 ✅(v1)

- ✅ `/seller/stores` **매장 관리**: 목록(소유/위임 배지) · **추가** · **삭제**(소유자=영업종료 soft, 운영자=목록 이탈) · **위임**(→ /seller/operators)
- ✅ 추가 플로우: **카카오맵 검색**(`/api/kakao/place/search`) → 선택 → **채널 선택(직접 10%/중개 5%)** → **국세청 사업자 확인**(`nts-business-verify` SSOT — 진위확인/휴폐업조회) → 등록.
  검증 통과 시 **즉시 승인**("그냥 매장 등록하면 돼"), 실패/키미설정 시 pending(어드민 검토).
- ✅ 소유 모델: `sellers.linked_user_id` 는 UNIQUE(1인 1행) → 추가 매장은 linked 없이 생성 + `seller_operators`(직접=owner/중개=operator). 중개 등록 매장은 owner 공석 = **대리 등록** — 실제 사장님 승계는 3단계(사업자번호 대조).
- ✅ **국세청 키는 라이브에 이미 등록돼 있다** (2026-08-22 CF API 실측: Pages env `NTS_API_KEY` 존재 — 코드가 `PUBLIC_DATA_SERVICE_KEY` 부재 시 이 키로 폴백). 키 값의 유효성은 배포 후 매장 등록 1건으로 판정.
- ⏳ 네이버 지도 검색 병행(대표 언급 "네이버 지도로나") — 카카오 우선 구현, 네이버는 후속.

## 3. 이용권 등록 ✅(부분) / ⏳(리뉴얼)

- ✅ **AI 자동입력(OCR 메뉴판) 블록 제거** (대표: "빼줘").
- ✅ **판매 1건당 실수령가 카드 상시 표시** — 판매가 − 플랫폼 수수료(채널별 5/10%) − 인플루언서 소개비(%) = 실수령. 서버 `/api/seller/fee-context`(loadFeeRates SSOT) 사용 — 표시와 정산이 같은 값을 읽는다.
- ⏳ **등록 페이지 전체 리뉴얼은 대표와 상의하며 진행** (대표 명시 — 임의 진행 금지).

## 4. 인플루언서 협업 (탐색 → 제안 → 공구 → 성과 → 정산)

### 4.1 탐색 ✅(v1) — `/seller/influencers`
- 유어애즈 DB(ADS_DB `ad_influencer_leads`, 43k+) 읽기 전용: 핸들·카테고리·팔로워·게시물·평균조회·평균댓글 (크리에이터 탐색 UI 참고). 필터: 카테고리/팔로워 밴드/정렬/검색.
- 🔒 **연락처(email/DM) 무반환** — SELECT 목록에서 원천 배제. 중개자 비공개는 대표 명시. 직접 매장의 연락처 열람 판매는 과금 배선과 함께 별도 결정.
- 제외: `opted_out=1`(수신거부) · `is_brand=1`(브랜드 계정).

### 4.2 제안 ✅(v1) — 유어딜 대행 발송 모델
- 조건: **판매 커미션 %** · **상품 무상/유상 제공** · **진행 매체**(인스타·유튜브·틱톡·블로그·네이버클립 복수) · 기간 · 제안문(20자+, 유어딜 소개 문구를 덧붙여 발송).
- 저장: `influencer_outreach_requests`(메인 DB, repair-schema 등록) → **어드민 벨** → 유어딜이 이메일/DM 발송.
- **컨택 1명당 과금**: ⏸️ 단가는 **대표 고민 중**(2026-08-22) — 확정 전까지 기본 0=미청구 유지. 단가 `platform_settings.influencer_contact_fee_krw`(기본 0=미청구) — 견적을 접수 시점에 **표시·기록**(quoted_fee_krw). ⚠️ **실제 청구 배선은 머니 경로 — 단독 세션 + 결제 게이트로 별도**.
- ⏳ 어드민 발송 큐 화면(`/admin/influencer-outreach`) — 알림 링크는 걸어 둠, 화면은 후속.

### 4.3 공구 진행·성과 ⏳ (기존 자산 위에)
- **이미 있는 것**: 핀 어필리에이트(추천 링크, 2%) · `seller_influencer_deals`(우대 커미션 proposed/accept) · `products.referral_commission_rate`(딜별 소개비 override) · GB 엔진 설계(gb_mode) · owner-funding promo 스위치.
- **성과 페이지(인플루언서용)**: `/u/me/earnings` 확장이 정도(定道) — 브랜드커넥트 "판매 실적" UI(요약 스탯 + 시계열 + 상세 내역) 참고.
- **집계 기준 (대표 확정)**: **최종 실적 = 이용권 "사용"** (환불 가능성 때문). 구매 수치는 보조 지표로 병기.
  → 현행 원장과 정합: 이용권 매출 원장 기록이 이미 **사용 시점**이다(`/:code/use`). 커미션 성숙(T+7)도 동일 사상.
  ⏳ 인플루언서별 링크(기존 affiliate_ref 재사용) + 성과 대시보드에 [구매 n건 / 사용 확정 n건] 병기.

### 4.4 정산 모델 — ✅ **대표 승인 (2026-08-22 "정산 모델은 승인할게")**

> 승인된 내용: 아래 **원천 분배** — 소비자 결제액을 유어딜이 받아, 유어딜 수수료·인플루언서 커미션을 떼고
> 나머지를 매장에 지급한다. 매장→인플루언서 직접 결제는 하지 않는다.
> ⚠️ **배선은 머니 경로** — 단독 세션 + staging 실결제 검증 후 별도 PR (이 문서 §9-2).
브랜드커넥트는 **제휴비를 브랜드가 직접 결제**(판매 종료 후 크리에이터 정산액 + 서비스 이용료를 카드/계좌로). 유어딜은 **돈이 이미 플랫폼을 지나간다**(소비자가 유어딜에서 결제) — 그래서 더 단순한 모델이 가능하다:

> **권장: 원천 분배(소스 스플릿)** — 소비자 결제액에서 [플랫폼 5/10%] · [인플루언서 커미션 X%] 를 떼고
> 나머지를 매장에 정산. 매장이 따로 결제할 일이 없고(미수 리스크 0), 인플루언서는 **사용 확정 + T+7 성숙 + 원천징수(3.3%)** 후 지급 — 전부 기존 원장·payout 레일 재사용.
> 브랜드커넥트식 "매장 직접 결제"는 후불 미수 리스크와 결제 UX 를 추가로 만든다 — 우리 구조에선 불리.
> 남는 별도 결제는 ① 인플루언서 컨택비(선불 소액) ② 상품 유상 제공분(매장↔인플 직접) 뿐.

## 5. 환불 ✅(접수) / 정책(제안)

- ✅ **유저 환불 요청**: 내 이용권(미사용)에 "사용 전이라면 환불 요청" — `POST /api/returns/request`(픽업 접수 자격은 기왕 열려 있었음) → 셀러 `/seller/returns`(**환불 요청**으로 개칭) + 어드민 처리. **돈은 어드민 환불 실행에서만 움직인다**(현행 유지).
- **환불 조건 제안 (대표 질문 "어떤 조건일 때?")**:
  1. **미사용 + 유효기간 내 = 전액 환불** (전자상거래법 §17 청약철회 7일과 무관하게, 미사용 이용권은 기간 내 전액이 업계 표준 — 소비자 신뢰가 확보 비용보다 싸다)
  2. **유효기간 경과 미사용 = 90% 환불**(공정위 소비자분쟁해결기준의 상품권 기준 준용)
     — ✅ **유효기간 정책 확정 (2026-08-22 대표)**: "매장이 설정하면 있고, 설정 안 하면 유효기간 없음(무기한)".
     발급 경로 4곳의 강제 기본값(이용권 90일·체험권 90일·숙박권 180일) 전부 폐지 — 미설정 = expires_at NULL
     (사용 검증·표시·알림톡 모두 NULL 지원 확인). 무기한 이용권은 조건 2가 적용될 일이 없다.
  3. **사용(부분 포함) = 환불 불가**, 매장 귀책(폐업·서비스 불이행)은 전액 + 유어딜 중재
  4. 인플루언서 커미션은 **사용 확정 기준**이라 환불과 자연 정합(미사용 환불 = 커미션 발생 전)
- ⏳ 위 정책의 자동판정(1·2 자동 승인) — 지금은 전건 운영자 검토.

## 6. 유어애즈 DB 판매 ⏳ (정책 골격)
- 셀러 대시보드에서 DB **열람은 무료**(연락처 없음) — 리드는 미끼, 수익은 **컨택 대행**.
- 컨택(제안 발송) = 1명당 과금(§4.2). 연락처 **직접 판매는 하지 않는 것을 권장** — opt-in 없는 개인정보 제3자 제공은 법적 리스크(대행 발송은 유어딜↔인플루언서 관계라 안전).

## 7. 운영성 결정 ✅
- **멀티 로그인**: 셀러 시트를 단일세션 강제에서 제외 — 여러 브라우저/여러 명 동시 사용 + 401 폭풍 해소. 토큰 30일.
- **명칭**: 미니샵→**링크샵 설정** · 반품 요청→**환불 요청** · (에이전시 잔재) 매장 영업→**매장 관리**.
- **컴팩트**: 대시보드 매출 목표 카드 제거 · 여백 축소(space-y-6→3, p-8→4).
- **라이브 잔재**: streams 호출 제거 · 가이드 부제 교체. ⏳ 알림톡(브랜드 메시지) 템플릿 문구 전수 재작성 — 콘텐츠 감사 별도.
- **버그**: support-contact 경로 정합 · PIN 저장 seller_meta 이전(sellers 100컬럼 한도로 500) · 운영 가이드/알림 401 은 멀티세션 수리로 해소 예상(배포 후 판정).
