## 1. 지금 카드가 보여 주는 것

아이디 · 플랫폼 · 연동 배지 · 팔로워 수(24px) · 신선도 · 다시 확인 · 해제.
저장은 돼 있는데 화면이 안 쓰는 값이 넷 있다.

## 2. 무엇이 실제로 가능한가 (2026-11-01 실측)

| | 무엇 | 비용 |
|---|---|---|
| 이미 저장 중 | `profile_url` · `account_type` · `token_expires_at` · `display_name` | 0 |
| 인스타그램 | `media_count` · `profile_picture_url` | 요청 필드에 낱말 추가 |
| 유튜브 | `thumbnails` · `videoCount` · `viewCount` | **0** (이미 받아 놓고 버린다) |
| 틱톡 | `avatar_url` · `video_count` · `likes_count` · `is_verified` | 요청 필드에 낱말 추가 |
| 안 됨 | 참여율 · 평균 조회수 | 인스타 `manage_insights` = Meta 심사 별도 |
| 안 됨 | 팔로워 추이 | 지금은 덮어쓴다. 스냅샷 테이블 필요 |

**인스타는 짐작이 아니라 물어봤다.** 연동 계정에 직접 조회해 셋이 다 왔다:

```
username urdeal_official · name 유어딜 · account_type BUSINESS
followers_count 9283 · media_count 13 · profile_picture_url ✓
```

⚠️ 단 그 토큰은 이 세션에 붙은 연동 계정의 것이지 **우리 앱(`instagram_business_basic`)이 받은
토큰이 아니다.** 두 필드가 그 권한에 속하는 것은 맞지만, 최종 확인은 우리 앱으로 첫 연동한 뒤다.

**유튜브가 가장 눈여겨볼 자리다.** `fetchProfile` 이 `part=snippet,statistics` 로 이미 받아 놓고
`subscriberCount` 하나만 쓰고 나머지를 버린다. 영상 수와 채널 사진은 **지금 응답 안에 들어 있다.**

## 3. 시안 넷

| 안 | 더하는 것 | DB | 서버 호출 | 새 심사 |
|---|---|---|---|---|
| **A** | 계정 링크 · 계정 종류 · 못 읽은 이유 | 0 | 0 | 0 |
| **B-1** | A + 사진(로고 자리 대체) + 게시물 수 | 컬럼 2 | 필드 추가 | 0 |
| **B-2** | A + 게시물 수 (사진 없음) | 컬럼 1 | 필드 추가 | 0 |
| **C** | B + 팔로워 추이 | 컬럼 2 + 스냅샷 테이블 | 필드 추가 | 0 |

### 안 A가 실제로 고치는 것

팔로워를 못 읽었을 때 지금은 `—` 옆에 "읽지 못했어요" 라고만 적는다. **왜** 못 읽었는지는
`account_type` 에 이미 저장돼 있다(`hidden_subscribers` · 비즈니스 계정 아님 · 틱톡 심사 전).
사장님의 팔로워 조건이 이 숫자로 판정되므로, 빈 칸의 이유를 모르면 사람이 고칠 길이 없다.

### 안 B의 갈림길 — 사진이 로고 원을 대체하는가

지금 원은 **두 가지 일**을 한다: 플랫폼이 무엇인가(글리프) + 연동됐는가(파란 원 ↔ 회색 원).
사진을 그 자리에 넣으면 둘째가 사라지고 연동 여부는 배지 하나가 맡는다.

- **B-1** 사진 40px + 로고 17px 배지. 다른 서비스 연동 화면이 대개 이 방식.
- **B-2** 로고 원 유지. 상태 표시가 그대로지만 덜 개인적이다.

어느 쪽이든 **사진이 없거나 못 받으면 지금 로고 원으로 떨어진다**(빈 동그라미를 남기지 않는다).

### 안 C의 대가

`user_sns_follower_snapshots` 가 필요하고 **데이터가 쌓여야 보인다.** 라이브 연동이 0건이라
첫 연동부터 모아도 처음 한두 주는 `추이는 다음 주부터` 가 뜬다(시안의 둘째 카드).

🎨 그리고 **이 팔레트에는 초록이 없다** — `tailwind.config.js` 가 장식 색조(green·emerald …)를
전부 잉크로 중화한다. 증감은 색이 아니라 화살표로만 말한다.

## 4. 지킬 것

1. **블록마다 카드를 씌우지 않는다.** 이미 `SNS 연동` 카드 안이고 신청 시트 안이다(2026-10-12 교훈).
2. **못 읽은 숫자를 0으로 위장하지 않는다.** 모르는 것과 0은 다르다.
3. **로고는 단색.** 플랫폼 공식 색을 쓰면 그 줄에서 가장 먼저 읽히는 것이 남의 브랜드가 된다.
4. **굵은 글자는 덩어리마다 하나.** 팔로워가 주인공이므로 게시물 수는 13px 중간 굵기(굵기 체계 ⑨ —
   12·13px 의 700+ 는 금지).
5. **블록 사이는 hairline 하나**(규칙 ⑦ 평면 목록).

## 5. 구현할 때 풀 것 (시안에서 드러난 것)

- 🔁 **둘째 줄 줄바꿈이 행마다 갈린다.** `flex-wrap justify-between` 이라 숫자가 짧은 행은
  [팔로워 · 버튼]이 한 줄, 긴 행은 두 줄이 된다. 지금도 그런데 **게시물 수를 더하면 더 자주** 난다.
  같은 목록에서 행마다 다르면 눈에 띈다 → 액션 줄을 항상 제 줄에 두거나 통계를 한 묶음으로 고정.
- `—` 가 24px 굵게 떠서 글자가 아니라 선처럼 보인다(지금도 그렇다).

## 6. 안 할 것

참여율 · 평균 조회수. 인스타는 `manage_insights` 가 Meta 심사 별도이고 틱톡도 추가 권한이라
**대표 몫의 심사 작업이 늘어난다.** 지금 막힌 것은 SNS 키 등록이지 심사가 아니다.

## 7. 확정 — **안 C** (2026-11-01 대표)

> *"안 C로 하고 추이는 다음 주부터는 굳이 안넣어도 돼."*

사진은 **B-1**(로고 자리를 대체하고 로고는 배지로). 추이는 기준 스냅샷이 쌓인 **뒤에만** 뜨고,
없을 때는 `추이는 다음 주부터` 같은 **자리표시자를 두지 않는다** — 그 자리가 그냥 비어 있다.

### 구현된 것

| | 어디 |
|---|---|
| 계정 링크 · 계정 종류 · 못 읽은 이유 | `shared/sns-account.ts` (문구 SSOT) |
| 사진 · 게시물 수 | `fetchProfile` 세 플랫폼 + `user_sns_links` 컬럼 2개 |
| 추이 | `user_sns_follower_snapshots` + `recordFollowerSnapshot` · `followerTrend` |

**§5 에서 예고한 줄바꿈 문제는 고쳤다** — 버튼을 언제나 제 줄에 둔다(숫자 길이에 따라 행마다
줄 높이가 갈리던 것). `—` 가 24px 로 떠서 선처럼 보이는 것은 **그대로 뒀다**(시안에도 그렇게
나왔고 대표가 그 그림을 보고 골랐다).

### 구현하며 바뀐 판단 하나 — 사진은 **R2 로 옮긴다**

시안에는 "사진 주소를 저장한다" 고만 적었는데, 실측해 보니 인스타가 준 주소는 서명돼 있고
**`oe=` 가 4일 뒤 만료**다(틱톡 `avatar_url` 도 임시, 유튜브 `yt3.ggpht.com` 만 안 변한다).
그대로 저장하면 연동 직후엔 보이다가 며칠 뒤 **조용히 사라진다.** 기존 `rehostImageToR2`
(내용 해시 키)를 지나게 해서 영구 주소로 만든다. 실패하면 `COALESCE` 로 예전 사진을 지킨다.

## 8. 먼저 올라온 시안에만 있던 둘 — 안 했다

`#2073` 의 안 C 에는 있고 대표가 고른 안 C 에는 없어서 **구현하지 않았다**. 둘 다 새 조회 0 이다.

| | 왜 안 했나 |
|---|---|
| **총 조회수**(유튜브 `statistics.viewCount`) | 대표가 본 그림에 없었다. 유튜브에만 있어서 **인스타·틱톡 줄은 그 칸이 빈다**(안 C 의 "비는 칸이 안 생긴다" 와 어긋난다). |
| **토큰 만료 안내**(`token_expires_at`) | 대표가 본 그림에 없었다. 그리고 2026-11-01 제자리 갱신(#2072) 이후 **만료가 가까우면 ⟳ 가 알아서 재발급**하므로, 사람에게 미리 알릴 일이 줄었다. |

넣을 거면 **대표 확정이 먼저다**(그림을 보고 고른 것과 달라진다).

## 9. `repair-schema` 는 필요 없었다 — 실측

`#2073` §A3-6 이 *"세 컬럼은 `repair-schema` 에 **함께** 등록해야 라이브에서 산다"* 고 적었는데,
확인해 보니 **이 경우엔 아니다.** 새 컬럼은 `SEEDING_TABLES_SQL` 의 `ALTER TABLE … ADD COLUMN` 으로
자가치유하고, 그 `ensureSeedingTables(DB)` 를 **읽는 쪽과 쓰는 쪽이 둘 다 먼저 부른다**:

- `GET /api/seeding/me` → `ensureSeedingTables` **다음에** `listSnsLinks`(새 컬럼 SELECT)
- `GET /api/sns-link/:platform/callback` → `ensureSeedingTables` **다음에** `saveSnsLink`(새 컬럼 INSERT)

⚠️ 그래서 **그 두 자리에서 ensure 를 떼면** SELECT 가 던지고 `.catch(() => ({ results: [] }))` 가
삼켜서 **연동 목록이 통째로 사라진다**(에러 없이). 떼지 말 것.

## A3. 지켜야 하는 것 (어느 안을 고르든)

1. 🔴 **못 읽은 값은 `0` 이 아니라 `—`** 다. 무상 체험 자격을 이 숫자로 판정하므로 0 으로 적으면 **판정이 거짓말을 한다**.
2. 🔴 **없는 칸을 빈 채로 두지 않는다** — 틱톡은 안 B·C 에서도 팔로워 한 칸이다(심사 전엔 나머지가 안 온다).
3. 🔴 **넣을 자리는 `fetchProfile()` 한 곳**이다. 연동(코드 교환)과 다시 확인이 **같은 조회**를 쓰므로,
   두 벌로 적으면 *연동했을 때와 다시 확인했을 때 숫자가 갈리는데 에러가 안 난다*.
4. 🔴 **블록마다 카드를 씌우지 않는다** — 이 목록은 이미 카드 **안**이다(*카드 안에 카드*).
5. 프로필 사진은 `cfImage()` 경유 + `cfImageOnError` 배선(깨진 이미지 아이콘 금지 — 가드가 센다).
   호스트가 `SUPPORTED_HOSTS`/`CDN_CGI_VERIFIED` 밖이면 **실측 후** 목록에 추가할 것(`cdninstagram.com`·`yt3.ggpht.com`·`tiktokcdn.com`).
6. 새 컬럼이 필요하면 `user_sns_links` 는 사이드테이블 대상이 아니다(products·sellers 예산제와 무관) —
   다만 `profile_image`·`media_count`·`view_count` 세 컬럼은 `repair-schema` 에 **함께** 등록해야 라이브에서 산다.
