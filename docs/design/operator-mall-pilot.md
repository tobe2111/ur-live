## 2. 화면 5개 모두 **이미 있는 화면의 재디자인**이다

새로 만들 화면은 없다. 다섯 자리 전부 기능이 완성돼 있고 의뢰서 표현대로 *"디자인만 안 입혀져 있다"*.
특히 **화면 B 는 시안과 구조가 이미 같다** — `SellerQuickGbPage` 가 사진·상품명·정가/공구가·가격
피드백·마감 3버튼·픽업일(선택)·보관구분(선택)·하단 고정 제출을 그 순서로 갖고 있고, 입력 높이도
`h-14`(=56px)로 의뢰서 §5.4 를 이미 지킨다.

⇒ 이번 작업은 **배선이 아니라 표면**이다. 시안이 바꾸는 것은 주로 아래 4가지다.

| 시안이 더한 것 | 현재 |
|---|---|
| 필수(사진·상품명·가격·마감) / 선택(픽업일·보관구분) **두 카드로 분리** | 한 줄로 이어짐 + 회색 `(선택)` 라벨만 |
| 마감 버튼 아래 **`8월 9일 (일) 밤 11시 59분에 마감돼요`** 실제 날짜 환산 | 없음 (며칠인지만 보임) |
| 오류를 **상단 요약 상자**로 — `2가지만 고치면 바로 열려요` + 항목 나열 | 하단 단문 + 필드별 문장 |
| 보관구분 미리보기를 **옅은 로즈 면**으로 승격 | 회색 작은 글씨 한 줄 |

## 3. 채팅에서 결정된 것 (원본 채팅은 소실됨 — 여기가 유일한 기록)

### 3.1 주색: **2e — 차콜 버튼 + 유어딜 로즈** 〔대표 확정〕

후보 5안(2a 로즈 현행 / 2b 차콜+주황 / 2c 딥그린 / 2d 딥오렌지 / **2e 차콜+로즈**) 중 2e.

**문제 정의**: 로즈를 *주 버튼에도* 쓰고 *마감 경고에도* 쓰니 **"급하다"가 버튼에 묻혔다.**
공동구매는 마감이 전부인데 그 신호가 약해진다.

**해법**: 버튼만 차콜로 내리면 로즈가 "급함" 전용으로 풀린다. **브랜드 색은 그대로**라 의뢰서 §5.1 승인 불필요.

| 역할 | 색 |
|---|---|
| 주 버튼 | `#1A1719` (누를 때 `#000000`) |
| 마감 배지 · 할인율 · 재고 · 안전결제 스트립 · 가게 로고 | `#E0526B` |
| 옅은 로즈 | `#FBEDF0` / 다크 `#3A2530` |

> 사진 위 배지가 **맞바뀌었다** — 마감이 로즈, 재고가 검정 반투명.
> 의뢰서가 *"제일 먼저 읽혀야 한다"* 고 한 것이 마감이라서다.

### 3.2 테두리 규칙 — **"테두리는 입력칸에만. 버튼은 면으로 만든다."**

대표 지적(*"버튼이나 테두리 같은 것의 유무가 AI 티를 가른다"*)에서 나온 규칙.

- 흰 배경 + 1.5px 회색 테두리 보조 버튼 → **회색 면 채움, 테두리 없음**
- 마감 3/7/14일·보관구분 미선택 상태도 테두리 박스 → **회색 면** (세그먼트 컨트롤처럼 읽힘)
- 남은 테두리는 입력칸뿐: **1px `#DFD9DC`**, 포커스만 **1.5px `#1A1719`**

### 3.3 말투 — **~어요체 통일**

다이클로를 따라 빈 상태·오류 문구는 **마침표를 뺀다** (`진행 중인 공동구매가 없어요`).

**그대로 둔 것 2가지**: 반품 사유(손님이 직접 쓴 글) · 재사용 요소 패널의 규칙 메모(개발자용 문서).

> 🔴 **주의 — 아래 3개는 말투만의 문제가 아니다.** §5 참조.

### 3.4 이모지 → 얇은 선 아이콘

⏰📦🔒 를 같은 뜻의 SVG 선 아이콘으로 교체. 안드로이드·iOS에서 이모지 모양이 달라져 대기업 서비스처럼 안 보이는 것이 이유. **되돌릴 수 있다**고 디자이너가 명시.

### 3.5 추가분 판단 2건 — 디자이너 답변

| 의뢰서가 물은 것 | 시안의 답 |
|---|---|
| `최대 210딜 적립` — 지울지 작게 둘지 | **`구매 확정 시 210원 적립`** 으로 바꿔 부가세 줄 옆에 작게. *딜*은 손님이 모르는 단위라 지우고, 금액으로 쓰면 설명 없이 읽힌다. 실제로 적립되니 아주 지우는 건 과하다 |
| `배송·교환·반품` 아코디언 제목 | **`교환·반품·환불 안내`** 로 제목만 변경. 안쪽 법정 고지 문구는 **그대로 두는 전제**. 제목에서 배송을 빼야 화면 어디에도 택배를 암시하는 낱말이 안 남는다 |

### 3.6 픽업 안내를 가격 바로 아래 로즈 면으로 (A-2 핵심)

추가분 §"4번이 이 화면의 핵심"에 대한 답:
머리에 `가게에 직접 찾으러 오는 상품이에요` 로즈 채움 띠 + 받는 날 **17px/800** (옵션·수량보다 크게) + 하단 고정 바에도 `1개 · 8월 10일 픽업` 재노출.

## 5. 🔴 구현 전 확인이 필요한 것

> ✅ **5.1·5.3 은 판정 완료** (2026-08-02). 5.2 는 그대로 열려 있다 — §6 참조.

### 5.1 몰 대표 색 vs 시안의 로즈 고정 — **판정: 의뢰서가 틀렸다**

🔴 **의뢰서 §5.1("주 버튼·강조 = 로즈 `#E0526B`")은 무효다.** 그걸 쓴 세션이 코드를 안 보고 썼다.
`src/shared/mall/branding.ts` 에 2026-07-29 대표 확정이 있다 — `MALL_COLOR_LIGHT = '#2E7D5B'`,
*"유어딜 본진(로즈 `#E0526B`)과 **구분**되되 결제 신뢰를 주는 톤"*.

**⇒ 의뢰서와 코드가 어긋나면 코드에 박힌 대표 확정이 우선이다.**

적용한 역할 분리:

| 역할 | 색 | 근거 |
|---|---|---|
| 몰 정체성(로고 아바타·안전결제 띠) | `mall.colorLight` / `colorDark` | 운영자가 고른 값 |
| 급함(마감·잔여) | 기능 red | 브랜드색이 아니라 **기능 신호**. `tailwind.config.js` 가 이미 *"유일 예외 = red(에러/마감임박)"* 로 규정 |
| 주 버튼·본문·가격 | 잉크 뉴트럴 / 차콜 | 어떤 상품 사진 위에서도 안 죽는다(시안의 2e 논리 그대로) |

🔴 **다크에서는 운영자 색을 안 쓴다.** `resolveMallBranding`(`branding.ts:89`)이
`colorDark: color ? MALL_COLOR_DARK : MALL_COLOR_DARK` — 삼항 양쪽이 같아 **운영자 지정과 무관하게
항상 `#5FBF95`** 를 돌린다(임의 파생이 AA 를 깰까 봐 P0 보류). **A·A-2 다크를 운영자 색으로 그리면
실물과 다르다.**

> 📌 화면 A-2 의 픽업 블록은 **몰 색도 안 쓴다.** `ReceiveMethodNotice.tsx` 가 판정을
> *"몰이 아니라 픽업 데이터"* 로 하고 본진 픽업 상품도 같은 블록을 쓴다고 명시했기 때문이다.
> 거기서 `mall.colorLight` 를 물면 그 파일이 금지한 몰 결합이 생긴다 → 잉크 채움으로 해결.

### 5.1-b 🔴 코드 가드가 필요하다 (디자인으로 못 막는다)

운영자가 고른 색의 **대비 검사가 코드에 없다.** 옅은 색을 고르면 아바타 이니셜·안전결제 띠의
**흰 글자가 안 보인다.** 파일럿은 몰 1개라 안 터지지만 몰이 늘면 터진다.

⇒ `validateMallSlug`/`validateMallName` 옆에 **`validateMallColor`(WCAG AA 대비)** 가 저장 시점에
필요하다. `branding.ts` 주석이 *"대비는 취향이 아니라 규격"* 이라고 이미 선언해 놓고 검사는 없다.

### 5.1-c 몰 대표 색 vs 시안의 로즈 고정 (원본 기록)

의뢰서 §5.1 은 브랜드 색을 로즈 `#E0526B` 로 고정했고 시안은 그대로 따랐다.
그런데 코드에는 **몰마다 운영자가 고르는 대표 색**이 이미 있다:

```
src/shared/mall/branding.ts
  MALL_COLOR_LIGHT = '#2E7D5B'   // 기본 딥그린
  MALL_COLOR_DARK  = '#5FBF95'
  // 주석: "유어딜 본진(로즈 #E0526B)과 구분되되 결제 신뢰를 주는 톤"
```

`MallHomePage` 는 가게 로고 아바타에 `mall.colorLight` 를 쓴다. 시안은 그 자리를 **로즈로 칠했다.**

**제안** — 시안의 *논리*(로즈를 버튼에서 빼서 "급함" 전용으로)를 지키면 둘이 양립한다:

| 자리 | 색 |
|---|---|
| 몰 정체성(로고 아바타, 픽업 안내 블록 헤더) | `mall.colorLight` / `colorDark` — **운영자 색** |
| 급함 신호(마감 배지·할인율·재고) | 로즈 고정 — `MallHomePage` 가 이미 `rose-600` 으로 그렇게 하고 있다 |
| 주 버튼 | 차콜 `#1A1719` — 시안대로 |

⇒ **파일럿 몰이 1개면 차이가 안 보이고, 몰이 늘면 이 분리가 반드시 필요해진다.**

### 5.2 법무 대기 문구를 말투 통일에 휩쓸지 말 것

§3.3 의 ~어요체 통일 대상에서 **아래 3개는 빼야 한다.** 법무 회신(체크리스트 X4c) 대기 중이고, 인계 문서도 *"환불·반품 고지 문구를 조용히 바꾸지 않았다"* 고 명시했다.

| 상수 | 현재 값 | 위치 |
|---|---|---|
| `STORAGE_NOTICE.cold` | `냉장·냉동 상품입니다. 픽업일에 찾아가지 않으면 환불이 어려울 수 있습니다.` | `src/shared/pickup.ts` |
| `STORAGE_NOTICE.room` | `실온 보관 상품입니다. …보관 기간 이후 처리 기준이 적용됩니다.` | `src/shared/pickup.ts` |
| `PAYMENT_TRUST_NOTE` | `결제는 유어딜이 안전하게 처리합니다` | `src/shared/mall/branding.ts` |

시안은 이 셋을 각각 `…환불이 어려울 수 있어요` / `…가게에서 받아가세요` / `결제는 유어딜이 안전하게 처리해요` 로 바꿔 그렸다.

> ⚠️ `PAYMENT_TRUST_NOTE` 는 말투 외에 **내용 이슈**가 하나 더 있다 — `branding.ts` 주석이
> *"운영자도 직접 환불을 실행할 수 있어 '환불은 유어딜이 처리'가 사실과 어긋날 수 있다"* 고
> 적어 뒀다. 말투만 고치면 그 문제는 그대로 남는다.
