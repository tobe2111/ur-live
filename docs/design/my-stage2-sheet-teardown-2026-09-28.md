# 2단계 시안 — 손수 시트 일곱을 철거할까 (2026-09-28)

> 대표: *"1번은 시안이 필요하겠는데?"* — 결재 `2026-09-28-my-stage2-sheet-teardown.md` 의 시안이다.
> 손으로 그리지 않았다. **지금 코드가 실제로 그리는 화면**을 폰 폭(430px)으로 렌더해 판정했다
> (`scripts/visual-preview.mjs`, 2026-09-28 에 좌석 시드·클릭을 붙여 처음 가능해졌다).

## 1. 무엇을 정하는가

마이의 판매 도구 중 일곱은 **폰 전용으로 손수 만든 시트**다(1,362줄). 같은 일을 하는
**대시보드 화면이 따로** 있고, 지금은 `COVERED_BY_SHEET` 표가 대시보드 주소를 손수 시트로
돌려보내 "문은 둘이어도 도착지는 하나" 를 지킨다.

| 손수 시트 | 줄 | 같은 일의 대시보드 |
|---|---:|---|
| `OrdersSheet` | 269 | `SellerOrdersPage` (596) |
| `WithdrawSheet` | 263 | `SellerSettlementsPage` (332) |
| `PartnersSheet` | 207 | `SellerInfluencerDealsPage` (480) |
| `VoucherSheet` | 175 | `SellerGroupBuyPage` (147) |
| `StoreSheet` | 168 | `/seller/store` |
| `MessagesSheet` | 152 | `SellerAlimtalkPage` (372) |
| `AnalyticsSheet` | 128 | `SellerAnalyticsPage` (288) |
| **1,362** | | |

소스 주석이 철거 조건을 이미 박아 놨다:

> *"손수 시트가 존재하는 이유는 **대시보드 화면이 폰에서 나쁘기 때문**이다. UI 정리로 그 화면들이
> 폰에서 좋아지면 이 표와 시트 일곱은 내려와야 한다."*

**⇒ 그러니 이 시안이 답할 질문은 하나다: 대시보드 화면이 폰에서 쓸 만한가.**

## 2. 🔴 측정 결과 — 전제가 아직 안 선다

### 2-a. 대시보드 화면을 **시트 안에서** 열면 깨진다

전체 도구에서 대시보드 화면을 골라 시트로 여는 경로(`ToolPageSheet`)를 실제로 눌러 봤다:

| 도구 | 시트 안 | 같은 화면 단독(`/seller/...`) |
|---|---|---|
| 셀러 등급 | 🔴 **에러 화면** | ✅ 정상 |
| 매장 관리 | 🔴 **에러 화면** | ✅ 정상 |
| 사업자 정보 | 🔴 **에러 화면** | ✅ 정상 |

**셋 중 셋이 시트 안에서만 깨진다.** 같은 데이터·같은 빌드인데 단독으로 열면 멀쩡하다
⇒ 데이터가 아니라 **시트 경로**의 문제다.

> ⚠️ **원인은 이 하네스에서 판정할 수 없다.** `ErrorBoundary` 가 `import.meta.env.DEV` 일 때만
> 로그를 남기는데 하네스는 프로덕션 빌드를 서빙한다. 콘솔에 남은 것은 전부 외부 차단 잡음이었다
> (진짜 예외 0건 — 바운더리가 잡아 버려서 `pageerror` 로도 안 올라온다).
> ⚠️ **실기기 확인이 필요하다** — 하네스 고유 문제일 가능성을 완전히 배제하지는 못했다.

🕳️ **그리고 이걸 아무도 못 잡고 있었다.** 이 경로를 지키는 시험
(`seller-all-in-my-2026-09-26.test.ts` 등)은 전부 **텍스트 가드**라 "배선이 있는가" 만 본다 —
**렌더되는가는 안 본다.** 그래서 *"66/68 라우트가 시트에서 열린다"* 는 기록이 초록인 채로 남아 있었다.

### 2-b. 설령 고쳐도 — 대시보드 화면은 시트에 그대로 못 들어간다

단독 렌더(430px)에서 본 것:

| | 손수 시트(`OrdersSheet`) | 대시보드(`/seller/orders`) |
|---|---|---|
| 머리 | 제목 한 줄 + 닫기 | `내 매장` / `내 매장` **제목 중복** |
| 그 아래 | 바로 필터 칩 | **카카오 연동 배너 ~215px** |
| 탭 | 1단(전체·확인 대기·준비 중·취소·환불) | **2단**(주문·환불요청·리뷰관리 → 처리대기·준비중·완료·전체) |
| 바닥 | 환불하기 | 셀러 하단 탭바 5개 |
| 기능 | 주문 + 환불 | 주문 + 환불 + **리뷰 관리** |

⇒ 대시보드 쪽이 **기능은 더 많고 군더더기도 더 많다**. 철거하려면 시트 안에서
①제목 중복 ②카카오 배너 ③하단 탭바를 걷어내야 하고, 그건 `ToolPageSheet` 의 임베드 컨텍스트가
할 일이다. **지금은 그 앞 단계(렌더 자체)에서 막혀 있다.**

## 3. 권고 — **철거하지 않는다. 먼저 시트를 고친다.**

순서:

1. **시트 렌더 깨짐 원인 규명** — 실기기/스테이징에서 `전체 도구 → 셀러 등급` 을 열어 본다.
   하네스 고유 문제면 여기서 끝나고, 아니면 이게 가장 급한 결함이다
   (마이에서 여는 도구 상당수가 지금 안 열린다는 뜻이므로)
2. **렌더 시험 신설** — 텍스트 가드는 이 클래스를 원리상 못 본다.
   `ToolPageSheet` 가 실제로 렌더되는지 보는 시험이 있어야 같은 일이 또 안 조용히 지나간다
3. **그 다음에** 시트 안 chrome(제목 중복·카카오 배너·하단 탭바) 정리
4. **그 다음에** 일곱을 하나씩 철거 — 한 번에 1,362줄을 지우지 않는다.
   가장 단순한 `AnalyticsSheet`(128줄)부터 하나 내려 보고, 폰에서 나빠지지 않으면 다음

> 🧭 **왜 "지금 철거" 가 아닌가**: 철거는 되돌리기 쉬운 일이 아니다. 그리고 일곱 중 둘
> (`WithdrawSheet`·`SettlementsSheet`)은 **출금·정산 화면**이라, 폰에서 나빠지면 눈에 보이는 것이 돈이다.

## 4. 이 시안이 **못 본 것** (과신 금지)

- 시트 안 크래시의 **원인** — 프로덕션 빌드라 바운더리 로그가 없다
- **실데이터** — 하네스는 모든 API 에 빈 응답을 준다. 주문 100건이 쌓인 화면은 여기서 안 보인다
- `/seller/settlements` 는 **단독으로도** 에러 화면이었는데, 같은 이유로 원인 판정 불가
- 일곱 중 나머지(`알림·가이드` 등)는 클릭이 안 걸려 **미측정**
