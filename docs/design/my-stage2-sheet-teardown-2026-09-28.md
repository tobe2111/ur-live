## 2. 🔴 측정 결과 — 전제가 아직 안 선다

### 2-a. 대시보드 화면을 **시트 안에서** 열면 깨진다

전체 도구에서 대시보드 화면을 골라 시트로 여는 경로(`ToolPageSheet`)를 실제로 눌러 봤다:

| 도구 | 시트 안 (측정 당시) | 단독(`/seller/...`) | 🔧 수리 후 |
|---|---|---|---|
| 셀러 등급 | 🔴 **에러 화면** | ✅ 정상 | ✅ 정상 |
| 매장 관리 | 🔴 **에러 화면** | ✅ 정상 | ✅ 정상 |
| 사업자 정보 | 🔴 **에러 화면** | ✅ 정상 | ✅ 정상 |

**셋 중 셋이 시트 안에서만 깨졌다.** 같은 데이터·같은 빌드인데 단독으로 열면 멀쩡하다
⇒ 데이터가 아니라 **시트 경로**의 문제다. 같은 날 고쳤다(아래 §3).

### 🔴 원인 **둘**. 하나가 아니었다 — `ToolPageSheet` 는 한 번도 동작한 적이 없다.

```
Error: You cannot render a <Router> inside another <Router>.
       You should never have more than one in your app.
```

앱은 `BrowserRouter` 로 감싸여 있는데(`App.tsx:1072`) `ToolPageSheet` 가 그 **안에**
`MemoryRouter` 를 또 넣는다(`ToolPageSheet.tsx:92`). react-router v6 은 중첩 라우터를 금지한다 —
**여는 즉시 throw** 다. 특정 화면 탓이 아니라 **어느 주소로 열어도 같다**.

#### 왜 브라우저에서는 원인이 안 보였나
프로덕션 빌드는 `drop_console: true`(`vite.config.ts:429`)라 콘솔이 통째로 지워지고,
react-router 도 프로덕션에선 invariant **메시지를 지운다** — 화면엔 `Error` 만 남는다.
`ErrorBoundary` 의 로그도 `import.meta.env.DEV` 게이트라 안 찍힌다(게이트를 강제로 열어도
`drop_console` 이 지워 버린다 — 실제로 그 순서로 두 번 헛짚었다).
**jsdom(vitest)은 개발 빌드라 메시지가 살아 있다** — 그래서 렌더 시험이 진단까지 해냈다.

가드: `src/tests/unit/tool-page-sheet-renders-2026-09-28.test.tsx` (수리 후 **뒤집었다** —
이제 "열려도 안 터진다" 를 고정한다).

🕳️ **그리고 이걸 아무도 못 잡고 있었다.** 이 경로를 지키는 시험
(`seller-all-in-my-2026-09-26.test.ts` 등)은 전부 **텍스트 가드**라 "배선이 있는가" 만 본다 —
**렌더되는가는 안 본다.** 그래서 *"66/68 라우트가 시트에서 열린다"* 는 기록이 초록인 채로 남아 있었다.

### 🔴 원인 ② — 고쳐 놓고도 **전체 도구로 튕겨 돌아왔다**(히스토리 칸)

중첩 라우터를 고치자 시트가 열렸는데, 브라우저에서 눌러 보니 여전히 *아무 일도 안 일어나는 것처럼*
보였다. 실제로는 도구 시트가 한 프레임 떴다가 **스스로 닫혔다.**

`Sheet` 는 열릴 때 히스토리에 한 칸 쌓고(안드로이드 뒤로가기 = 닫기), X·배경·Escape 로 닫힐 때
그 칸을 `history.back()` 으로 도로 뺀다. 한 시트만 보면 완벽한 규약인데, 마이는 시트를 **갈아 끼운다**:

```
A(전체 도구) 정리 → history.back()     ← A 가 쌓아 둔 칸을 빼려는 것
B(도구)      설치 → pushState
…popstate 도착 → B 가 "뒤로가기" 로 읽고 닫는다   ← A 가 빼려던 칸을 B 가 뒤집어썼다
```

🔬 **실측으로 확정**: 같은 빌드에서 `history.back()` 한 줄만 임시로 빼자 셀러 등급 화면이 시트 안에
그대로 떴다. ⇒ 규약을 **"칸은 시트마다가 아니라 열려 있는 동안 하나"** 로 바꿨다
(`sheet-history.ts` — 판정은 순수 모듈, `pushState`/`back()` 은 `Sheet.tsx`).

🧭 **교훈**: 첫 번째 원인을 찾았다고 거기서 멈추면 안 된다. 증상이 같아도 원인은 여러 겹일 수 있고,
**브라우저에서 다시 눌러 보는 것** 말고 그걸 알아낼 방법이 없었다(둘 다 에러가 0이다).

### 2-b. 설령 고쳐도 — 대시보드 화면은 시트에 그대로 못 들어간다

단독 렌더(430px)에서 본 것:

| | 손수 시트(`OrdersSheet`) | 대시보드(`/seller/orders`) |
|---|---|---|
| 머리 | 제목 한 줄 + 닫기 | `내 매장` / `내 매장` **제목 중복** |
| 그 아래 | 바로 필터 칩 | **카카오 연동 배너 ~215px** |
| 탭 | 1단(전체·확인 대기·준비 중·취소·환불) | **2단**(주문·환불요청·리뷰관리 → 처리대기·준비중·완료·전체) |
| 바닥 | 환불하기 | 셀러 하단 탭바 5개 |
| 기능 | 주문 + 환불 | 주문 + 환불 + **리뷰 관리** |

⇒ 대시보드 쪽이 **기능은 더 많고 군더더기도 더 많다**. 철거하려면 시트 안에서
①제목 중복 ②카카오 배너 ③하단 탭바를 걷어내야 하고, 그건 `ToolPageSheet` 의 임베드 컨텍스트가
할 일이다. **지금은 그 앞 단계(렌더 자체)에서 막혀 있다.**

## 4. 이 시안이 **못 본 것** (과신 금지)

- ~~시트 안 크래시의 원인~~ — 규명됐다(위 ①②)
- **시트 안 chrome** — 사업자 정보의 탭 줄(`사업자 정보 / 정산 계좌 / 사업자등록증 검…`)이
  430px 에서 **셋째 탭이 잘린다**. 열리는 것과 폰에서 쓸 만한 것은 다른 일이다(§3-5)

- 일곱 중 나머지(`알림·가이드` 등)는 클릭이 안 걸려 **미측정**

### ⚠️ 이 측정이 못 보는 것

### B — `--seller-work` + `--trace-api` 로 쟀다 — 🟡 **절반 됐다. 돈 화면이 아직 안 열린다**

대표 *"코드 수정 해줘. 남은 것들 다 해줘"* ⇒ 1차가 헛돈 원인을 고치고 다시 쟀다.

### 왜 1차가 헛돌았는지 (확정)

하네스의 **catch-all 이 `{ data: [] }`** 를 돌려줘서 일곱이 전부 빈 목록으로 떴다.
새로 넣은 **`--trace-api`** 가 그걸 한 줄로 보여 준다 — 정산 화면 하나가 `/api/*` 를
**18곳** 부르는데 하네스가 목하던 건 셋뿐이었다.

### 고친 것 (도구만 — 제품 코드 무접촉)

| | |
|---|---|
| `--seller-work[=empty]` | 주문·정산·출금·정산옵션·대시보드 통계 시드. **응답 모양은 라우트에서 읽어 맞췄다**(추측 아님). 긴 매장명·`null` 운송장·일곱 자리 금액 등 **폰에서 깨지는 값**을 일부러 넣었다 |
| `--trace-api` | 화면이 부른 `/api/*` 와 **스텁이 뭘 돌려줬는지** 출력. 프로덕션 빌드는 `drop_console` 이라 이게 없으면 "오류 화면이다" 까지만 알 수 있다 |
| `--phone-audit` 판정 | **빈 화면·오류 화면이면 🟢 가 아니라 🟡 "판정 보류"**. 1차의 거짓 초록이 재현 검증에서 실제로 🟡 로 바뀌는 것을 확인했다 |

### 🔴 `/seller/settlements` — 아직 못 쟀고, **라이브 결함이라고 단정하지 않는다**

- 하네스에서 **ErrorBoundary** 로 떨어진다. **시드 모양과 무관**하다(`[]`·`{}`·빈 시드 전부 같은 오류).
- 결재문이 남긴 질문에는 답이 나왔다: **`useApiQuery` 는 `throwOnError`/suspense 가 없다** ⇒
  **목록 API 하나가 실패해도 화면 전체가 날아가지 않는다.** 즉 이건 쿼리 실패가 아니라 **렌더 예외**다.
- 더 좁히려면 **셀러 실세션** 또는 **dev 빌드**(콘솔이 살아 있는)가 필요하다 — 이 세션의 도구로는 여기까지다.
- ⚠️ 그래서 *"정산 화면이 라이브에서 깨진다"* 고 말하지 않는다. 하네스가 `success:true` + 가짜 본문을
  주는 경로를 타서 생긴 것일 수 있다(라이브라면 401 로 로그인 이동).
