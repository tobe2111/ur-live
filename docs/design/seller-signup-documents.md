## 시안 셋 (전부 확정 디자인 시스템 안 — 브랜드 블루 면 · 카드 테두리 0 · 이모지 0 · 티켓 밴드)

### 안 1 — 한 화면에 전부
서류 2장 + 계좌를 가입 화면으로 끌어올린다. 대표 말씀 그대로.
- 얻는 것: 한 번에 다 내면 심사가 바로 시작된다.
- 대가: 첫 화면이 길어진다(필수 5 + 서류 2 + 계좌 1). 이탈이 늘 수 있다.
- ⚠️ **당근 모델과 방향이 반대다** — 첫 화면에서 서류를 요구하는 것은 "들여보내고 안에서 고치게 한다"의 반대.

### 안 2 — 다 보이되, 지금 낼 것만 (**세션 추천**)
필수 5개만 펼치고, 영업신고증·정산계좌·이용권 등록을 **"승인까지 남은 것 N"** 으로
**이름까지 보여 주되** 첨부를 강제하지 않는다.
- 대표 요구("다 떠야 한다")를 만족한다 — 이름이 다 나온다.
- 같은 날 확정한 **당근 모델**(`switch-to-seller` 가 대기·반려도 통과)과 이어진다.
- 대가: 사장님이 '남은 것' 을 안 채울 수 있다 ⇒ 대시보드 배너(`SellerApprovalBanner`)가 계속 센다.

### 들어간 것
- **안 2**: '승인까지 남은 것'(등록증·영업신고증·정산계좌)이 가입 화면에 **이름으로** 뜬다.
  ⚠️ 첨부는 강제하지 않는다 — 당근 모델과 어긋난다. 제출 게이트는 필수 5칸 그대로.
- **시각 C**: 라벨 10.5px / 값 17px bold → **글자 굵기만으로** 진행이 읽힌다.
  상자 제거 → 행 구분선 + 포커스 시 브랜드 바. 입력 `min-h-[34px]`(라벨 16 + 34 = 50px 탭 영역).
- **3단계 사다리 제거**(정보 입력 → 심사 → 판매 시작) · **티켓 제거**(가입 폼 한정 — 결과 화면의 티켓은 유지).
- **주소 = 카카오 장소 검색**(`AddressPickerField` → `KakaoMapPicker`, lazy).
- `(선택)` 라벨 제거 — **두 곳 다**(Field 라벨 + `BusinessCertUpload` 자기 라벨 `hideLabel`).
- locale 6종 갱신 + 죽은 사다리 키 8개 제거.

### 🔴 주소 자동입력 — 국세청 API 로는 불가능하다 (실측)
`nts-business-verify.ts` 의 `/validate` 는 **진위(`valid`)와 휴·폐업(`status`)만** 준다.
상호도 주소도 없다. "사업자번호 넣으면 주소가 채워진다" 는 이 API 로는 못 만든다.
⇒ 주소의 출처는 **카카오 장소 검색**, 상호·대표자는 **등록증 OCR**(오늘 라이브)이 맡는다.

## ✅ 2026-09-16 (2차) — ④ 제출 전 확인 · ⑤ 등록증 자동 채움 구현

대표 *"이 5장 거의 우리도 같게 하게끔 참고해"* 의 나머지 중 **④⑤ 를 붙였다.**

### ⑤ 등록증 사진 → 위 칸 자동 채움
`ocrDocument`(이미 라이브)를 **가입 앞문 쪽으로 돌렸다.** 사장님은 등록증을 손에 든 채로
아홉 칸을 옮겨 적고 있었다 — 읽을 수 있는 걸 사람에게 시키고 있었다.

**왜 새 라우트를 안 만들었나 (설계상 제일 중요한 판단)**
`/api/upload/business-cert` 에 **바이트가 이미 있다.** 그래서 opt-in 필드(`ocr=1`) 하나만 얹었다.
URL 을 받아 서버가 대신 fetch 하는 라우트였다면 문이 **셋** 열린다:
1. **SSRF** — 임의 주소를 우리가 대신 부른다
2. **남의 등록증 읽기** — 키만 넘기면 내용이 나온다(32자 랜덤이라 추측은 어렵지만 문을 열 이유가 없다)
3. **추론 비용 남용** — 새 라우트마다 한도를 다시 걸어야 한다
⇒ 같은 요청 안에서 끝내면 셋 다 안 생긴다. 한도도 이미 있다(`biz-cert-upload` 10회/10분 per-IP).

**결재 §안전 레일 그대로** — 추출만 한다. 승인·반려·DB 쓰기 0. 주입 ④ 가 그 선을 지킨다.

| 규칙 | 왜 |
|---|---|
| **빈 칸에만** 채운다 | 덮으면 모델이 잘못 읽는 순간 사장님이 고친 걸 되돌린다. 아무도 모른다 |
| 손대면 '사진에서' 딱지가 **떨어진다** | 안 그러면 사장님이 직접 친 칸에도 확인 요청이 붙어 의미가 없어진다 |
| 못 읽어도 **아무 말 안 한다** | "읽기 실패" 라고 하면 사장님이 사진을 다시 찍는다. 손으로 치면 되는 일이다 |
| AI 바인딩 없으면 조용히 건너뛴다 | Pages preview 엔 바인딩이 없다. 프리뷰가 추론 비용을 안 태우는 건 이득이다 |
| `onRead` 를 준 호출부만 `ocr=1` | 도매·제조 가입은 요청이 종전과 byte-동일 → 비용 0 |

### ④ 제출 전 확인 (`ReviewSheet`)
별도 페이지가 아니라 **시트**다. 이 가입은 한 스크롤이고 대표가 *"복잡해서도 안되긴 하는데"* 로
선을 그었다 — 라우트를 더 만들면 뒤로가기·새로고침·진행 복원이 전부 새 문제가 된다.

**이 시트가 실제로 막는 것**: OCR 이 잘못 읽은 값을 그대로 보내는 것. 사진에서 채운 칸은
사장님이 **한 번도 안 읽었을 수 있고**, 보내기 직전에 글자로 보여 주는 자리가 여기뿐이다.
사진에서 채운 칸이 0 이면 그 얘기를 꺼내지 않는다(안 한 일을 했다고 하면 안 된다).

### 🩸 렌더 실측이 또 잡았다 (코드만 봐서는 못 봤다)
1. **등록증 칸이 채워 줄 세 칸 *밑*에 있었다.** 사장님이 세 칸을 손으로 다 친 **뒤에야**
   *"사진을 올리면 채워 드려요"* 를 읽는다 — 자동 채움이 아무 일도 안 하는 배치였다.
   ⇒ 카드 **맨 위**로. 참고 시안도 같은 순서다(③ 서류 먼저 → ⑤ 확인).
2. 업로드 버튼에 `📄` 이모지 — 🎫 규칙 ⑥ 위반. lucide `ImagePlus` 로.
3. 시트가 "사진에서 채운 값이 섞여 있어요" 를 **항상** 말했다(하나도 안 읽었을 때도).
4. `사업자등록증 · 아직` 행과 '제출 뒤에 남는 것' 이 **같은 말을 두 번** 했다.

⚠️ **①②③ 은 여전히 남았다** — 핀 드래그 역지오코딩(②) · 등록증/영업신고증 `0/2` 슬롯(③).
③ 은 영업신고증을 가입 payload 로 받아 `seller_meta.food_permit_url` 에 넣는 서버 변경이 붙고,
그건 **당근 모델**(문 앞에서 서류를 요구하지 않는다)과 어떻게 맞출지부터 정해야 한다.
