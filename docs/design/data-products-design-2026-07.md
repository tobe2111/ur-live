## 0. 현재 가진 원천 데이터 (상품 재료)

| 테이블 | 핵심 필드 | 상품 기여 |
|---|---|---|
| `inflow_clicks` | `anon_id, ref_id(인플루언서 users.id), campaign, landing_path, user_id(로그인 후), created_at` | 유입(클릭)·인플루언서 귀속 |
| `voucher_visits` | `voucher_id, user_id, seller_id(매장), product_id, amount, path, created_at` | 방문(오프라인 사용)·매장·금액 |
| `orders` (+`order_items`) | `user_id, seller_id, total_amount, created_at, product` | 결제·GMV |
| `vouchers` | `user_id, product_id, status, used_at` | 발급→사용 전환 |
| `influencer_attributions` | `influencer_id, order_id, seller_id, commission_amount, status` | 인플루언서→매출 귀속(커미션) |
| `district_coupons`/`district_stores`/`district_campaigns` | `user_id, redeemed_store_id, redeemed_at` / `seller_id, district` / 캠페인 | 상권 캠페인 사용(정밀) |
| `product_regions` | `product_id, region_si/gu/dong, region_dong_code, lat, lng` | **매장→상권(동) 매핑** (이미 존재) |
| `user_regions` | `user_id, region_si/gu/dong, dong_code, source` | **유저→거주 상권 매핑** (이미 존재) |
| `products` | `category, restaurant_name, restaurant_lat/lng, seller_id` | 업종·좌표 |
| `sellers` | `seller_type(influencer 등), business_*` | 인플루언서/매장 구분 |
| `voucher_redemptions` | `voucher_id, used_lat/lng(≈1km 격자로 하향됨)` | 사용 위치(상권 단위) |

**완결 고리**: `inflow_clicks.ref_id → user_id → orders/voucher_visits(seller_id) → 재방문` 이 한 `user_id`로 조인됨(데이터 감사 1·2단계 결과).

## 1. 상품별 매핑 + Gap 분석

### 상품 ① 인플루언서별 전환 리포트 (가장 빠름)
> "이 인플루언서 링크로 들어온 사람이 얼마나 가입·구매·방문·재방문했나" + GMV/ROI.

**지금 데이터로 되는 것 (funnel, ref_id별 집계)**
- 클릭수 = `inflow_clicks` count by `ref_id`
- 가입 전환 = `inflow_clicks.user_id IS NOT NULL` 비율
- 구매 전환·GMV = 그 user_id들의 `orders`(amount 합)
- 방문 전환 = `voucher_visits` join (오프라인 실사용 — **경쟁사 못 주는 차별점**)
- 재방문 = 같은 user의 visit 2회+ (간격/횟수)
- 커미션/정산 = `influencer_attributions`

**Gap (더 필요한 것)**
- 🔴 **노출/도달(reach·impressions)**: 우리는 *클릭*만 있음. "노출 대비 전환율(CVR from reach)"·CPM은 인플루언서 플랫폼(YouTube/Insta) 조회수 데이터 필요 → **외부 연동**(YouTube Data API는 일부 보유 — ads 발굴). 없으면 "클릭→전환"까지만(그래도 판매 가능).
- 🟡 **인플루언서 프로필 enrich**: `ref_id`=users.id뿐. 팔로워 수·플랫폼·니치(업종 적합도)가 있어야 리포트가 "값진" 문서가 됨. `sellers.seller_type='influencer'` + YouTube 발굴 데이터로 일부 보강 가능.
- 🟡 **오가닉 언급 미포집**: 링크(`?ref=`) 경유만 잡힘. 링크 없는 자연 유입은 귀속 불가(구조적 한계 — 명시).
- 🟢 위치·재방문·GMV는 **현재 데이터로 충분**.

**차별화 포인트**: 온라인 광고 리포트는 클릭/구매까지지만, 우리는 **오프라인 매장 방문·재방문까지** 연결 → "이 인플루언서가 실제 매장 손님을 만들었다"는 증명. 이게 코어 셀링포인트.

### 상품 ② 상권 소비 리포트 (중간)
> "이 상권(동/구)에서 무엇이·누구에게·얼마나 소비되나" — 매장/건물주/프랜차이즈/에이전시 대상.

**지금 데이터로 되는 것**
- 매장→상권 매핑 = `product_regions.region_dong_code`(존재) → `voucher_visits.seller_id` 를 상권으로 집계
- 상권별 소비: 카테고리 믹스(products.category), 금액 분포, 시간대(created_at), 방문 빈도/재방문율
- 캠페인 상권은 `district_coupons`(정밀 user·store·time)로 더 촘촘

**Gap**
- 🔴 **인구통계(연령/성별)**: `users`에 birth/gender **미저장**(카카오 기본 동의 scope = email·nickname·image만; birthday/birthyear/gender는 별도 추가동의 flow에만). → "누가 소비하나(20대 여성 등)" 세그먼트가 **현재 불가**. **선결: 카카오 age_range/gender 추가 동의 수집**(법무·동의 후) 또는 구매행동 기반 추정.
- 🟡 **매장→상권 매핑 완결성**: `product_regions`가 모든 매장에 채워져 있어야(현재 일부만일 수 있음) 전 상권 커버. 백필 필요.
- 🟡 **대표성/시장점유**: 우리 데이터=우리 플랫폼 거래만. 상권 "전체 소비"가 아니라 "유어딜 내 소비". 리포트에 **표본 성격 명시** 필요(또는 외부 상권 통계와 병기).
- 🟢 위치는 이미 상권(동) 단위 — 법적으로도 안전, 리포트 목적에 적합.
- `user_regions`(거주 상권) 존재 → "이 상권 소비자의 거주지 분포"(유입 반경) 도 가능 = 강력.

### 상품 ③ 매장-인플루언서 매칭 (가장 어려움)
> "이 매장(업종·상권)에는 어떤 인플루언서가 실제 전환을 낸다" 추천.

**지금 데이터로 되는 것(행동 기반 매칭 — 가장 강한 신호)**
- 인플루언서 X가 유입시킨 user들이 **실제로 어느 업종/상권 매장에서** 구매·방문했나 = `inflow_clicks → user_id → voucher_visits(seller→category/region)`
- → "X의 청중은 카페·강남 전환이 강함" 같은 프로파일을 **선언(declared)이 아니라 실측(behavioral)** 으로 산출. 이게 경쟁 우위.

**Gap**
- 🔴 **볼륨/희소성(sparsity)**: 매칭엔 (인플루언서 × 업종/상권) 셀마다 전환 표본이 충분해야 함. 초기엔 인플루언서·매장·전환 모두 적어 행렬이 텅 빔 → **가장 오래 걸리는 이유**.
- 🟡 **콜드스타트**: 이력 없는 신규 인플루언서/매장은 행동 데이터 0 → 프로필(팔로워·니치) 기반 폴백 필요(①의 enrich gap과 동일).
- 🟡 **매장 수요측(demand)**: 매장이 원하는 타깃/예산/캠페인 목표 미수집 → 추천을 "매장 니즈"에 맞추려면 매장 선호 입력 UI 필요(에이전시 이미 일부 역할).
- **의존**: ①(인플루언서 프로파일)+②(상권/업종 집계)의 상위 조합 → 둘이 성숙해야 가능.

## 2. 상품별 필요 데이터량 (신뢰성 기준)

> 비율(전환율·재방문율) 추정의 안정성 기준. 러프 가이드(정확한 CI는 구현 시 계산).

**공통 원칙**: 비율 추정은 분모(표본) 크기에 좌우. 대략:
- n≥30: 방향성(directional) — 내부 참고용
- n≥100: 판매 가능(sellable) — ±10%p 내외
- n≥1,000: 세그먼트 분해(연령/시간대별) 가능(premium)

| 상품 | 최소(MVP) | 판매가능 | 프리미엄(세그먼트) |
|---|---|---|---|
| ① 인플루언서 리포트 | 인플루언서당 **클릭 100+ / 전환 30+** | 클릭 500+ / 전환 100+ | 전환 300+ (시간대·업종별 분해) |
| ② 상권 리포트 | 상권당 **매장 5+ / 거래 100+/월** | 매장 10+ / 거래 300+/월 | 거래 1,000+/월 (연령×카테고리, 단 인구통계 gap 해소 후) |
| ③ 매칭 | (인플 10+ × 매장 20+)에 **교차전환 셀당 5+** | 셀당 20+ , 전체 수백 전환 | 수천 교차전환(안정 랭킹) |

**k-익명성(재식별 방지·법무 연계)**: 어떤 집계 셀도 **n<5면 표시 억제(suppress)** — 리포트의 표준 규칙으로 고정(개인 식별 방지 + 상품 신뢰성 동시 충족).

**방배 관점**: ①은 파일럿 인플루언서 소수로도 **수 주 내** MVP 도달 가능. ②는 방배 상권 1~2개 집중이면 수 주~1개월. ③은 **수개월**(볼륨 축적) 필요.

## 3. 동의·법무 선결 항목 (법무 의뢰서용 체크리스트)

> 데이터로 리포트를 **파는(제3자에게 제공)** 순간 = 개인(행동)정보의 처리·제공. 아래를 법무에 의뢰.

**A. 개인정보 수집·이용 (개인정보보호법 §15)**
- [ ] 처리방침에 **행동데이터(클릭·방문·구매) 수집 및 통계·분석 목적** 명시
- [ ] `inflow_clicks.anon_id`(쿠키/로컬 UUID) = 온라인 식별자 → 처리방침·쿠키 고지 대상 여부 확인

**B. 상품화(제3자 제공) 경로 — 핵심 판단**
- [ ] **가명정보 특례(§28-2) 활용 가능 여부**: 통계작성·과학적연구 목적의 가명정보는 **정보주체 동의 없이 처리·제공 가능**. → 리포트를 **가명·집계(개인 식별 불가)** 로만 제공하면 이 경로가 현실적. (개별 제3자 제공 동의는 비현실적)
- [ ] **재식별 금지 준수**: 가명정보 결합·소량 셀 노출로 재식별 방지 → **n<5 셀 억제** 규칙을 계약·기술로 보장
- [ ] 리포트가 "개인정보"인지 "비개인정보(집계)"인지 법적 판정 — **집계면 규제 대폭 완화**

**C. 위치정보 (위치정보법)**
- [ ] `voucher_visits` + `product_regions`로 "누가 어느 상권에서 소비" = 개인위치정보 해당 여부. 우리는 **≈1km 상권 격자**로 하향(감사 1단계) → 완화 요소. 그래도 **위치기반 상품 판매 시 위치정보사업 신고 필요성** 확인 필요
- [ ] `voucher_redemptions` 정밀 GPS(현재 격자 하향)·개인 단위 위치 결합 판정

**D. 인구통계 수집(②·프리미엄 전제)**
- [ ] 카카오 **age_range/gender 추가 동의** 수집 시 동의문구·목적 → 처리방침 반영
- [ ] 민감정보 아님 확인(연령대·성별은 일반 개인정보)

**E. 인플루언서/매장 대상 리포트 계약**
- [ ] 제공 리포트에 **개인 식별정보 불포함**(집계만) 계약 명시
- [ ] 인플루언서 본인 성과(자기 링크 전환) 제공 시 — 제3자의 개인정보 포함 없으면 문제 적음

**의뢰 우선순위**: **B(가명정보 특례) + C(위치정보 적용범위)** 가 상품화의 관문. 이 둘이 풀리면 ①은 거의 바로 판매 가능.

## 4. 구현 난이도·순서 초안

| 순서 | 상품 | 난이도 | 기존 데이터로? | 선결 |
|---|---|---|---|---|
| **1** | ① 인플루언서 전환 리포트 | 낮음(집계 SQL) | **거의 됨** — funnel(clicks→user→order→visit→repeat) by ref_id | 법무 B, 인플루언서 프로필 enrich(선택) |
| **2** | ② 상권 소비 리포트 | 중 | 됨(매장→상권 매핑 존재) | `product_regions` 백필 완결, **인구통계 gap**(프리미엄만), 법무 B·C |
| **3** | ③ 매장-인플루언서 매칭 | 높음(볼륨+알고리즘) | 부분(행동 매칭) | 볼륨 축적, ①②성숙, 콜드스타트 프로필 |

**권장 로드맵**
1. **먼저 ①** — 방배 파일럿 인플루언서 대상 "내 링크 성과(오프라인 방문 포함)" 리포트. 가장 빨리 팔리고(인플루언서가 자기 증명서로 원함), 재료 이미 있음. 집계 뷰 + n<5 억제 + 가명화만.
2. **다음 ②** — 방배 상권 집중 소비 리포트(매장/에이전시 대상). 매핑 백필 + 집계. 인구통계는 동의 수집 후 프리미엄으로.
3. **마지막 ③** — 데이터 축적 후 매칭 엔진(행동 기반 스코어 + 콜드스타트 폴백).

**공통 인프라(구현 시)**: 원천 이벤트는 이미 D1에 append됨 → 상품 레이어는 **읽기 전용 집계 뷰/배치**(원장·라이브 경로 무접촉) + 가명화 export + n<5 억제. 실시간 불필요(주간/월간 배치로 충분).

**무엇이 구현됐나 (읽기 전용·게이트 OFF·어드민 전용)**
