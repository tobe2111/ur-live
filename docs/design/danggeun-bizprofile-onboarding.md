## 1. 당근이 실제로 하는 것 (시안 순서대로)

| # | 화면 | 핵심 |
|---|---|---|
| 01 | 비즈프로필 이름 | **한 화면 = 한 질문.** 0/30 카운터, TIP 박스로 작성 기준 안내 |
| 02 | 업종 | 검색 + **검색 제안 칩**(카페/디저트·일반·식품판매…). "사업자등록증 [종목]으로 검색" 팁 |
| 03 | 주소 | 주소 검색 + 상세주소, **"주소가 없어요" 체크박스**(무점포 사업자 수용) |
| 04 | **이 업체가 맞나요?** | 입력값으로 **기존 업체를 찾아 보여 주고** [이 업체 관리하기] / [신규 업체로 등록하기] |
| 05 | 사업자등록증 제출 | 사진 0/2. **개업일·대표자명 타이핑 없음** |
| 06 | 프로필 사진 | "고객은 사진이 있는 프로필을 더 신뢰해요" — 이유를 말해 준다 |
| 07 | 사진 등록 | 0/20 + **결과 미리보기**(비즈프로필 사진 탭이 이렇게 보인다) |
| 08 | 소개글 **(선택)** | 미리보기 카드 + 예시 문장 |
| 09 | 전화번호 **(선택)** | **안심번호 지원** 링크 — 개인번호 노출 걱정을 그 자리에서 해소 |
| 10 | 관리자 홈 | 기본정보 채우기 **미션 0/5 → 3,000원** · 업종 추천 도구(포장주문·예약·**공동구매**) · 관리 도구 12개 그리드 · 최근 7일 통계 · 소식/후기 |

### 뽑아낼 원칙 6가지

1. **한 화면 한 질문 + 진행바.** 폼이 아니라 대화다. 이탈 지점이 보이고, 되돌아가기가 싸다.
2. **필수/선택을 제목에 대놓고 적는다.** `소개글을 작성해주세요 (선택)`. 사장님이 "이거 안 쓰면 못 넘어가나?"를 고민하지 않는다.
3. **기존 업체를 찾아 준다 = 클레임 프레이밍.** "등록하세요"가 아니라 **"이 업체가 맞나요? 관리를 시작할 수 있어요"**. 이미 존재하는 내 가게를 되찾는 느낌이라 심리적 진입장벽이 훨씬 낮다.
4. **서류로 대체 — 타이핑을 없앤다.** 개업일·대표자명을 묻지 않고 사업자등록증 사진으로 받는다.
5. **매 단계 결과 미리보기.** 지금 넣는 값이 고객에게 어떻게 보이는지 그 화면에서 보여 준다.
6. **완료가 끝이 아니라 시작.** 관리자 홈이 **미션(0/5, 보상 3,000원)** 으로 다음 행동을 지정한다. 빈 대시보드를 던지지 않는다.

## 2. 우리와의 간극 — 대표가 말한 "간극"의 정체

당근은 **소비자 앱 안에 사장님 세계가 들어 있다.** 동네지도에서 보던 그 가게를,
같은 앱에서 "내 가게예요" 하고 가져간다. 앱을 갈아타지 않는다.

우리는 지금 **두 개의 사이트처럼** 동작한다:

| | 당근 | 유어딜 (현재) |
|---|---|---|
| 사장님 진입 | 소비자 앱 안 → 비즈프로필 만들기 | 소비자(`urdeal.kr`) ↔ 셀러(`/seller`)가 **서로 다른 세계** |
| 내 가게 발견 | **지도의 그 업체를 클레임** | 셀러 대시보드에 들어가야 비로소 카카오맵 검색 |
| 등록 UX | 9단계 한 질문씩 | **모달 한 장에 4단계 압축** |
| 인증 | 사업자등록증 사진 | 번호+대표자명+**개업일 타이핑** |
| 등록 직후 | 미션 0/5 + 추천 도구 | 게이트 해제 → **빈 대시보드** |

⚠️ **핵심 갭은 "등록 폼"이 아니라 "발견"이다.** 우리 소비자 지도에는 카카오맵에서 온
매장이 이미 떠 있다. 그런데 그 화면 어디에도 *"사장님이신가요?"* 가 없다 — 사장님이
자기 가게를 보고 있어도 클레임할 방법이 그 자리에 없다.

## 3. 구현 방향 — **판정 갱신 (2026-09-07)**

> 🩸 **이 절의 원래 제안 A·D 는 대표가 이미 반려했다.** 아래 표기가 없어서 2026-09-07 세션이
> A 를 "미구현"으로 읽고 그대로 구현할 뻔했다(코드에서 반려 주석을 찾아 멈췄다).
> **문서가 낡으면 다음 세션을 반대 방향으로 이끈다** — 이 레포가 반복해 밟은 함정이다.

### ~~A. 소비자 표면에 클레임 진입점~~ ❌ **대표 반려 (2026-08-26, 재차)**
근거는 코드에 박제돼 있다 — `src/pages/restaurant-map/SuggestionModal.tsx:6-10`:
> *회색 핀이든 컬러 핀이든 어차피 카카오맵 데이터라, 사장님이 자기 가게를 찾으려고 이 지도를 뒤질
> 이유가 없다 — 우연히 자기 핀을 눌러야만 발견된다. 이 모달을 여는 사람은 사실상 전부 **손님**이라
> 사장님 CTA 는 그들에겐 노이즈다. 매장 등록의 상시 문은 `/store/new` 다. **프리필의 이득도 작다.***

대표의 대안이 이미 구현돼 있다: **`/store/new`(`StoreClaimPage`) = 상시 문 하나**, 마이·푸터·
하단바 ➕·블로그·입점 랜딩에서 진입. 그래서 §2 의 *"핵심 갭은 발견"* 진단도 **폐기**다.
⇒ 지도·상세에 사장님 CTA 를 다시 넣지 말 것. 넣으려면 위 반려를 뒤집는 새 근거가 필요하다.

### B. 등록을 한 화면 한 질문으로 ✅ **구현 (2026-09-07)**
`StoreRegisterModal` 을 4스텝 위저드로 — 진행바 + `1 / 4` + 단계별 [다음].
프리필(`initialPlace`)로 열리면 1단계를 건너뛴다(이용권 위저드가 쓰는 다리 보존).

### C. 개업일 타이핑 제거 → 사업자등록증 사진 ✅ **부분 구현 · OCR 은 대표 대기**
타이핑 제거와 사진 첨부는 2026-08-26 에 됐다. **OCR 자동판독만 미동작** —
`POST /api/seller/business-registration/ocr-verify` 는 `env.AI` 가 없으면 조용히 skip 하는데
`wrangler.toml` 에 `[[ai]]` 바인딩이 **없다**(실측). 대표가 대시보드에서 추가해야 켜진다.

### ~~D. 등록 직후 = 미션 체크리스트~~ ❌ **대표 결정과 충돌 (2026-06-04)**
대표가 *"대시보드 간소화"* 로 시작 가이드(온보딩 체크리스트)를 빼라고 했고
(`SellerPage.tsx:365` 주석), `SellerOnboardingChecklist.tsx` 는 지금 **렌더 0인 죽은 파일**이다.
빈 대시보드 문제는 다른 방식으로 이미 해결됐다 — `MyStoresPanel` 이 **STEP 1 게이트**가 되어
매장 등록 전에는 아래 전부가 잠기고 다음 할 일을 지정한다(2026-08-24 대표 AB테스트).
⇒ 미션 체크리스트를 되살리려면 그 두 결정을 함께 뒤집어야 한다.

## 3-b. 그 대신 막은 구멍 셋 (2026-09-07)

문서가 말한 "발견"은 갭이 아니었지만, **그 문 안쪽에 막다른 길 셋이 있었다.**

| 구멍 | 증상 | 왜 아무도 몰랐나 |
|---|---|---|
| **다크모드 입력 실명** | `/store/new` 에서 사업자번호·전화번호가 **흰 배경 위 흰 글자**(브라우저 실측 **1.00:1**) | 에러도 경고도 없다. 라이트로 보면 멀쩡하다. `index.css` 가 *"대시보드 밖 라이트 페이지는 `force-light-theme` 을 붙일 것"* 이라고 써 뒀는데 이 페이지만 빠져 있었다 |
| **이미 등록된 매장** | 409 `STORE_EXISTS` 에 서버가 `seller_id` 까지 실어 주는데 화면은 alert 하나 띄우고 끝 | 자기 매장을 다른 계정으로 등록해 둔 사장님은 거기서 **조용히 포기**한다 |
| **이유 없는 회색 버튼** | 넷 중 하나만 빠져도 [매장 등록]이 회색인데 무엇이 빠졌는지 안 알려줌 | 토스 결제에서 한 번 고친 "구조적으로 잠기는 버튼"과 같은 클래스. 위저드가 이걸 구조적으로 없앤다 |

⚠️ **소유권 자동 이전은 하지 않았다.** 매장 귀속은 정산이 따라가는 **머니 경로**이고 진짜 승계
(`owner_verified`)는 설계만 있고 코드가 없다(`store-operator-model.md` §5, 레포 전체 grep 0건).
대신 **이미 있는 권한 검사를 시험지로 썼다** — 좌석 토큰(`/stores/:id/token`)은 `canOperateStore`
를 통과해야만 발급되므로, 그게 성공하면 원래 내 매장이었던 것이다. 서버 무수정, 새 권한 0.

🩸 **적대적 재독에서 내가 만든 새 막다른 길 둘을 잡았다** — ① 좌석 없는 소비자에게
`/seller/stores`(requireSeller)를 권해 셀러 로그인으로 튕길 뻔했고 ② 아무것도 등록 안 했는데
"매장이 등록됐어요" 라고 말할 뻔했다. 둘 다 화면상 멀쩡해 보인다. 가드 + 주입 매니페스트로 고정.

## 4. 우리가 **따라 하지 않을 것**

- **현금 미션 보상(3,000원)** — 2026-05-22 대표 방침(가짜 보너스 금지)과 충돌.
- **안심번호** — 별도 인프라(가상번호 중계)가 필요. 담당자 번호를 소비자에게 노출하지 않는 것으로 대체(2026-08-26 구현 완료).
- **업종 자유 검색** — 우리 카테고리는 이용권 4종(식사·미용·숙소·기타) SSOT라 자유 입력을 받으면 분류가 깨진다. 칩 선택만.
