# PC 홈 히어로 — 흐르는 이용권 띠 (2026-09-28 대표 확정, 시안 ②)

> 대표: *"여기 지금 들어있는 사진 비율이나 너무 마음에 안드는데? 이거 그냥 확대해서 올라가버리는거잖아,,
> 디자인 변경이 필요하다 어떻게 하는게 좋을지 제안들을 줘봐"* (히어로 우측 사진을 빨간 상자로 표시한 스크린샷)
> → *"렌더해서 모두 스크린샷으로 시안들 보여줘볼래?"*
> → ***"2번으로 하고 저 이용권들이 좌우로 자연스럽게 계속 이동하는건? 이해했을까?"*** ← 확정
> → *"보통이 낫다. 트래픽은 최대한 이상적으로 하자. 처음 5장만 받는게 가장 이상적인가? 모바일은 필요없어.
> PC만 있으면 돼. 속도는 보통."*

## 1. 진짜 원인 — 크롭 설정이 아니라 **틀과 내용의 불일치** (실측)

| 무엇 | 값 |
|---|---|
| 히어로 사진 틀 (PC 1920) | **1037 × 190 = 5.46 : 1** |
| 그 자리에 들어간 라이브 사진 (id 2915 홍대 돈가스) | **540 × 720 (세로 3:4)** → 세로의 **14%** 만 보인다 |
| 우리 사진 70장의 비율 (2026-08-31 실측) | 세로 37% · 정사각 21% · 4:3 23% · 3:2 11% · 16:9 7% — **중앙값 정확히 1:1** |
| `banners` 의 히어로 배너 | **0건** → 늘 카탈로그 썸네일이 배너 자리에 들어간다 |
| 어드민 권장 규격 | `2400 × 800`(3:1) — **틀과 안 맞아** 지켜 올려도 세로 45%가 잘린다 |

⇒ "더 좋은 한 장을 고르는" 문제가 아니다. 5.46:1 에 맞는 사진이 우리 카탈로그에 사실상 없다.

## 2. 확정안 — 4:3 타일이 오른쪽에서 왼쪽으로 흐른다

```
┌──────────────────────────────────────────────────────────────────────┐
│  사서 바로 쓰는 동네 이용권          ░░┌────┐ ┌────┐ ┌────┐ ┌────┐░░ │
│  예약도 대기도 없이. 식사, 미용…      ░│22% │ │25% │ │19% │ │22% │░ │ ← 계속 왼쪽으로
│  [📍 남산동 ⌄][◎] [지도에서 딜 찾기] ░░└────┘ └────┘ └────┘ └────┘░░ │
└──────────────────────────────────────────────────────────────────────┘
        색면(--home-field)                양끝은 mask 로 색면에 녹인다
```

- 타일 **189 × 142**(4:3), 간격 10px, 반경 12, 하단에 `[할인율 파랑][판매가]` 캡션.
- 밴드: `w-[38%] lg:w-[46%] max-w-[900px]`, 오른쪽 기준은 **아래 매대와 같은 자**
  (`right-[calc(max(0px,(100vw-1440px)/2)+2rem)]`).
- 속도 **보통 = 47 px/초**(시안의 55초 / 2,587px). 장수가 달라져도 속도는 같다 — 지속시간을 거리에서 구한다.
- 커서를 올리면 멈춘다(`:hover`/`:focus-within`). `prefers-reduced-motion` 이면 정지한 매대로 남는다.
- **아래 매대 첫 줄과 겹치지 않는 딜**만 돈다(첫 줄은 `md:grid-cols-4`).

### 왜 ②였나 (기각한 안)
| 안 | 내용 | 결과 |
|---|---|---|
| ① | 사진을 4:3 한 장으로 줄이고 `gravity=auto` | 같은 딜이 바로 아래 카드와 **중복** — 렌더해 보니 사진 두 장이 40px 간격으로 붙었다 |
| ② | 이용권 타일 여러 장 | **확정**(+ 대표 요청으로 마퀴) |
| ③ | 사진 없이 타이포 + 색면 | 렌더 결과 허전하지 않았다(내 예측이 틀렸다). 다만 히어로가 파는 것을 안 보여 준다 |

## 3. 트래픽 — 대표 질문 *"처음 5장만 받는게 가장 이상적인가?"* 에 대한 답

**앞 몇 장을 먼저 받는지는 맞는 방향이지만 가장 큰 레버가 아니다.** 실측(띠에 들어갈 딜 8개):

| 방식 | 합계 | 장당 |
|---|---|---|
| 아래 매대 카드와 URL 공유 (width=400, DPR1) | 228 KB | 28.5 KB |
| 아래 매대 카드와 URL 공유 (width=800, DPR2) | 652 KB | 81.6 KB |
| 전용 420×315 q72 | 150 KB | 18.7 KB |
| **전용 384×288 q62 ← 채택** | **106 KB** | **13.3 KB** |
| (참고) 오늘의 히어로 사진 한 장 | 55 KB | — |

- **카드와 URL 을 공유하면 공짜처럼 보이지만 아니다.** 스크롤해 내려가는 사람에겐 이득이지만
  안 내려가는 사람에겐 2~6배를 물린다. 손익분기는 **DPR1 방문자의 54% · DPR2 의 84%** 가
  첫 줄 아래로 내려가야 한다.
- **마퀴는 한 바퀴(약 34초) 안에 모든 타일이 화면에 온다** — "5장만 받는다"는 선택지가 아니고
  "5장을 먼저, 나머지는 늦게"만 가능하다.
- 첫 화면에 실제로 보이는 건 밴드 폭(최대 900px)에 **4.5장 ≈ 60KB** — 오늘 히어로 한 장(55KB)과 비슷하다.
- 둘째 벌(루프용 복제)은 **같은 URL** 이라 캐시 적중 — `<img>` 16개인데 다운로드는 8개.

🩸 **정정**: 이 세션 초반에 "오늘 히어로가 ~96KB" 라고 말했는데, 직접 재니 **55KB** 다
(원본이 540×720 이라 리사이저가 1024·2048·3072 어느 폭을 요청해도 더 못 키운다).

## 4. 현재 vs 시안

| | 현재(2026-09-27까지) | 확정안 |
|---|---|---|
| 우측 미디어 | 딜 사진 **한 장**을 5.46:1 로 늘려 자름 | 4:3 타일 **8장**이 흐른다 |
| 크롭 | `object-cover` 가운데 | 리사이저 `fit=cover&gravity=auto`(피사체 추적) |
| 클릭 | 사진 전체가 링크 1개 | 타일마다 그 딜로 |
| 파는 것을 보여 주나 | 사진 한 장(무엇인지 안 적힘) | 매장·할인율·가격이 타일마다 |
| 첫 화면 바이트 | 55 KB | ~60 KB (전체 106 KB) |
| 어드민 배너 | 있으면 이긴다 | **그대로 이긴다**(띠는 기본값일 뿐) |

## 6. 남은 것 / 결정 대기

- **태블릿(768~1023)** 은 밴드가 38%(292px)라 1.5장만 보인다. 대표 지시가 *"PC만 있으면 돼"* 라
  그대로 두되, 좁아 보이면 그 구간만 타일을 작게 하는 것이 다음 후보.
- **모바일(<768)** 은 종전대로 미디어 없음(색면 + 카피).
- 어드민 히어로 배너가 0건인 상태는 그대로다 — 띠가 기본이므로 이제 급하지 않다.
