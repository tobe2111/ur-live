시안은 **배포된 번들을 라이브 데이터로 실제 렌더한 스크린샷** 옆에 제안 화면을 같은 폭·같은 사진·같은

## 안 B 가 무엇인가

> 안 A(중복만 걷기) + **숙소에 하단 구매 바와 리뷰를 신설**하고, 두 상세가 같은 순서를 따른다.
> 사진 → 이름·가격 → 살 조건 → 소개 → 위치 → 이용 안내 → 리뷰.

안 A 와 안 C 를 고르지 않은 이유: A 로는 **숙소에서 가격이 한 번도 안 보이는 것**과 **리뷰 30개가
안 뜨는 것**이 안 고쳐진다(둘 다 취향이 아니라 결함이다). C 는 사는 화면으로는 빠르지만 처음 보는
매장을 판단할 재료가 뒤로 밀린다.

## ✅ 구현 완료 (2026-09-14)

### 시안에서 **바꾼 것 하나** — 리뷰 0건 처리

시안은 *"공구 리뷰 0건이면 섹션을 안 그림"* 이었다. 착수 전에 재 보니 **부작용이 있었다**:
`ProductReviews` 는 0건일 때도 '리뷰 작성하기' 를 그리고, 대안 경로인 주문 상세의 작성 버튼은
**배송완료 상태에서만** 열린다(이용권·숙소는 배송이 없다). 섹션을 통째로 숨기면 **구매자가 리뷰를
쓸 자리가 사라진다.**

⇒ 상단 탭에서 '리뷰' 만 빼고(0건일 때) 섹션과 작성 진입은 남겼다. 주입 매니페스트가 이 결정을 고정한다
(섹션을 조건부로 감싸면 빨간불).

같은 이유로 숙소 **만실**도 목록을 대체하지 않고 카드를 목록 **위에** 얹었다 — 대체하면 그 숙소에
어떤 객실이 있는지조차 볼 수 없다.
