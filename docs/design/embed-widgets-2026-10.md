→ 시안 넷(배너·이용권 위젯·떠 있는 버튼·유어샵) →
*"HTML 임베드를 여러개 만들어줘. 1개만 선택하진 않을거야. 일단 에이전시 홈페이지에 넣을 것. 인플루언서의 홈페이지에 넣을 것(자신의 유어샵 페이지에 있는 이용권들 보이게.) 또 있을까?"*

## 만든 것

| 위젯 | 주소 | 누가 어디에 | 무엇이 보이나 |
|---|---|---|---|
| 유어샵 | `/embed/u/:handle` | 인플루언서·유저 블로그·개인 홈페이지 | 담은 이용권(유어샵 진열 순서) + 내 가게 이용권 |
| 에이전시 | `/embed/agency/:id` | 에이전시 회사 홈페이지 | 맡아 운영하는 매장 이용권(다른 에이전시 담당분 제외) |

| 이용권 하나 | `/embed/pass/:id` | 블로그 글 속 카드 | 이용권 한 장 + 구매하기 |

## 🤝 제휴사 입점 위젯 (2026-10-31 2차)

대표: *"추가로 제휴사들이 우리 유어딜 서비스를 파는 위젯이 필요해. 다른 제휴사들이 유어딜 에이전시를 하긴 할테지만 자신들의 사이트에서 유어딜 서비스를 파는거지."*
→ 확인 질문에 **"사장님께 입점 영업" · "소개 + 가입 버튼"** 확정.

흐름: 제휴사 사이트 위젯 → `/store/partner/:agencyId` → (로그인) → 내 매장 고르기 · 없으면 `/store/new` 등록 후 **자동으로 되돌아옴** → [운영 요청] → 그 제휴사 콘솔 '맡은 매장' 에 **대기(pending)** → 수락하면 운영 시작.
- 공개 주소라 **바로 운영을 열지 않는다**(초대 링크와 다른 점) — 아무나 아무 매장을 남의 에이전시에 떠넘길 수 없게.
- 위젯 문구에 요율 숫자 없음(어드민 값이 바뀌면 남의 사이트에 박힌 숫자가 거짓말이 된다).
- API: `GET /api/store-agency-invite/partner/:id` · `POST /api/store-agency-invite/partner-request`(소비자 세션 · 주인만 · CSRF).

### 🎫 디자인 확정 — 시안 A (2026-10-31)
대표: *"제휴사 관련 내용 별로다. 너무 투박하고 우리 서비스의 아이덴티티를 나타내야지 차별점과. 체험단에 지치셨나요? 이런거"* → 시안 A/B/C 중 **A**.
유어딜 이용권 모양(파란 띠 + 절취선 + 본문). 머리 "체험단에 지치셨나요?" · 체험단(음식은 공짜로 · 후기만 남고 · 매출은 0원) ↔ 유어딜 이용권(손님이 선결제 · QR로 바로 사용 · 팔린 만큼 정산) · [유어딜 입점 신청] · 가입비·월 이용료 0원. 높이 400(320px 폭까지 맞춤).

## 설계

- **서버가 그리는 HTML, 스크립트 0**: 남의 사이트 iframe 마다 앱 번들을 받지 않게. CSP nonce 를 위젯 문서가 알 수 없어 스크립트는 어차피 막힌다.
- **높이 고정**: 카드는 가로로 넘기는 한 줄(330px), 한 장 카드는 172px. 붙이는 쪽이 높이를 미리 안다.
- **노출 조건은 소비자 피드와 같다**: 승인 매장 · 도매 원본 제외 · 판매 중 · 이용권 카테고리 · 데모 맨 뒤.
- **유어샵 핀은 서버 리다이렉트로** → 소개 값(?aff=)·클릭 기록이 카톡 공유 링크와 똑같이 잡힌다.
- 링크마다 `utm_source=embed&utm_medium=<종류>` — 위젯별 유입을 센다.
- 엣지 캐시 5분(엣지 15분), robots 차단 + noindex.
