## 0. 왜 이 모델인가 — 병목의 실체 (2026-09-07 실측)

대표가 "수기로 하나하나 컨트롤"하게 된 원인은 실행력 부족이 아니다. 실측:

| 항목 | 실측 | 의미 |
|---|---|---|
| 워커 cron | 62개 파일 | 기계 실행은 충분하다 |
| 결정론 가드 | `scripts/check-*` 126개 · 불변식 100 | 기계가 지키는 것도 충분하다 |
| 역할 정의 | `.claude/agents/` **0개** | 모든 세션이 같은 범용 세션. 매번 대표가 레일·범위를 지정한다 |
| "대표 판단" 대기 | handoff 문서 **98건**에 산재 | 결정할 것이 문서·PR·Notion 에 흩어져 있어 대표가 찾아다닌다 |
| 반복 루틴 | 9개 중 반복 1개, 그 1개(System health check)는 **매일 실패** | 자동 운영 루틴이 사실상 0 |
| 완료 보고 | "완료" 뒤에 미완성·에러가 남아 있던 사례 다수(대표 지적) | 완료의 정의가 사람마다 달랐다 |

⇒ 고칠 것은 셋이다. **① 역할을 파일로 고정 ② 결정을 한 곳으로 모음 ③ "완료"를 증거 등급으로 정의.**

## 1. 원칙 5개 (위반 시 가드가 막는다)

1. **완료는 주장이 아니라 증거다.** "완료" 라는 말은 §4 의 **증거 등급 4(라이브 판정) 이상**에서만 쓴다.
   등급 3 이하는 "구현됨 · 검증됨 · 배포됨" 으로만 말한다. 보고 첫 줄에 `[E1~E5]` 등급을 반드시 적는다.
2. **결정은 한 곳에서 한다.** 대표가 판단할 것은 `docs/decisions/<날짜>-<슬러그>.md` 로만 올린다.
   handoff 본문·PR 코멘트·채팅에 "대표 판단 필요" 라고만 적고 끝내는 것을 금지한다.
3. **역할은 파일이다.** 세션이 어떤 역할로 일하는지는 `.claude/agents/<역할>.md` 의 프론트매터가 정한다.
   허용 도구·금지 레일·읽을 SSOT·보고 형식이 거기 있다. 채팅에서 "너는 CFO 야" 라고 부여하지 않는다.
4. **머니 경로와 대외 발송은 사람 스위치다.** 에이전트는 숫자를 재고 이상을 판정해 올린다.
   결제·정산·요율·환불·게이트 ON·이메일/알림톡/소셜 발송은 **대표가 켠다**(§2 등급 C).
5. **룰은 가드로 환원한다.** 이 문서의 규칙 중 레포에서 관측 가능한 것은 전부 테스트가 지킨다.
   못 지키는 범위는 테스트 주석에 적는다(과신 방지).

세 등급뿐이다. 애매하면 **한 등급 위**로 올린다.

| 등급 | 뜻 | 대표 개입 |
|---|---|---|
| **A 자율** | 하고 나서 handoff 에 기록 | 없음 |
| **B 보고 후 진행** | 세 줄(레일·머니 접촉·롤백) 보고하고 **기다리지 않고** 진행 | 사후 열람 |

| 행위 | 등급 | 비고 |
|---|---|---|
| 버그 수정 · 가드 추가 · 테스트 · 문서 · 리팩토링(동작 불변) | A | 잠금표(Toss·로딩) 파일은 예외 → C |

| 서버 로직 변경(비머니) · cron 주기/게이트 조정(비머니) | B | |
| 서비스 경계 교차 변경(도매↔유어딜↔공구 서비스↔유어애즈) | B | CLAUDE.md 세 줄 보고 룰 그대로 |
| 결제·정산·요율·환불·원장·커미션 코드 | **C** | + 단독 세션 + staging 실결제 |
| 게이트/플래그 ON(`platform_settings`·env·feature-flags) | **C** | OFF 로 되돌리는 것은 B |
| 이메일·알림톡·소셜·블로그 **발행** | **C** | 초안 생성은 A(draft-first 룰) |
| 외부 서비스 유료 전환 · 한도 상향 · 결제수단 | **C** | |
| 삭제·purge·데이터 일괄 수정(D1 UPDATE) | **C** | 읽기는 A |
| 잠금표(Toss V2 · 로딩) 파일 수정 | **C** | 기존 `[UNLOCK]` 절차 그대로 |

실행되지 않는다**. 기본안은 대표가 "기본안대로" 한 마디로 승인할 수 있게 하기 위한 것이지, 무응답을
승인으로 읽으라는 뜻이 아니다.

## 4. 완료 판정 기준 — 증거 등급 E1~E5

대표가 지적한 "완성됐다고 했는데 문제가 숨어 있던" 사고의 공통점은 **등급 2~3 에서 '완료' 라고 말한 것**이다.

| 등급 | 이름 | 증거(보고에 첨부할 것) | 이 단어를 써도 됨 |
|---|---|---|---|
| **E1** | 작성됨 | diff 존재 | "작성했다" |
| **E2** | 검증됨 | `tsc 0` · 해당 vitest pass · 관련 가드 GREEN · **되돌려-검증(주입) 빨강 확인** | "검증됐다" |
| **E3** | 머지·배포됨 | PR 머지 해시 + `main.yml` 성공 + 배포 산출물 도달(청크 해시 변화 등) | "배포됐다" |
| **E4** | 라이브 판정됨 | 라이브에서 **그 변경이 의도한 효과**를 실측(curl 응답·D1 행·브라우저 하네스·하트비트 `rr`) | **"완료"** |
| **E5** | 사용자 판정됨 | 대표 또는 실제 사용자가 화면/결과를 확인 | "확정" |

규칙:
- **E2 없이 E3 로 가지 않는다**(CI 가 대신 해 주지 않는다 — 가드 주입 검증이 40분 걸려도 기다린다).
- **E3 에서 멈추면 "완료" 가 아니다.** 배포 후 라이브 판정(E4)을 같은 세션이 하거나, 못 하면 `send_later`
  로 자기 체크인을 걸어 두고 handoff 에 "E4 대기 · 판정 명령" 을 적는다.
- **머니 경로는 E4 가 staging 실결제다.** 실결제 없이 "완료" 금지.
- **E4 판정은 "에러가 안 났다" 가 아니라 "의도한 효과가 났다"** 다. 이 레포의 사고 대부분은 에러 없이
  조용히 틀려 있었다(soft-404 · 캐시 컬럼 드리프트 · 헛도는 가드).
- 보고 형식(고정): 첫 줄 `[E4] 홈 카드 다음 사진 미리받기 — 라이브 최악 5.0s → 1.8s (하네스 실측)`.
  등급 미기재 보고는 ceo-office 가 반려한다.

## 5. 결재함 프로토콜 — `docs/decisions/`

- 파일 하나 = 결정 하나. `docs/decisions/<YYYY-MM-DD>-<slug>.md`. 템플릿 `docs/decisions/_template.md`.
- 필수 필드: `상태(open/approved/rejected/expired)` · `등급(C)` · `역할` · `질문(한 문장)` · `근거(실측 수치)` ·
  `선택지` · `기본안` · `기한` · `롤백` · `결정(대표가 한 말 그대로)` · `반영 커밋`.
- `ceo-office` 루틴이 매일 open 항목을 KST 로 요약해 대표에게 올린다(푸시 + Notion 미러가 연결된 세션이면 Notion).
- 대표가 답하면 **그 답을 한 말 그대로** `결정` 필드에 옮기고 상태를 바꾼다(요약·의역 금지 — 이 레포는 의역된
  결정이 다음 세션을 반대로 이끈 사례가 있다).
- 승인된 항목은 실행 세션이 `반영 커밋` 을 채운다. 채워지지 않은 approved 는 ceo-office 가 매일 다시 올린다.
- `CURRENT_WORK.md` 처럼 **공유 파일에 append 하지 않는다**(충돌 원인). 파일 단위라 세션 간 충돌 0.

규칙: 루틴은 **판정과 초안**까지다. §2 의 C 는 절대 루틴이 실행하지 않는다. "변화 없음" 이면 대표에게
보고하지 않고 handoff 한 줄만 남긴다(소음 0). 루틴 프롬프트는 이 문서와 역할 파일을 **먼저 읽으라**로 시작한다.

기존 "System health check"(2026-04 생성, MCP 미연결, 매일 실패)는 위 표로 **대체**한다. ⚠️ 그 루틴은 `http_api` 로 만들어져
에이전트가 끌 수 없다(실측 거부) — **대표가 Routines UI 에서 끈다.** 루틴 6개는 커넥터 0 으로 생성됐으므로(세션이 넘길 권한 없음)
PR 생성·Notion 미러는 대표가 Routines UI 에서 GitHub·Notion 을 붙인 뒤부터 자동이다. 붙이기 전에도 판정(git·curl·D1·어드민 API)은 돈다.

## 8. 이 모델이 스스로 못 막는 것 (정직하게)

- 에이전트가 **E4 라고 적고 실제로는 E2 인 경우**. 가드는 등급이 적혔는지만 본다. 대표가 handoff 의
  E4 근거(수치·명령)를 한 번씩 찔러 보는 것이 유일한 방어다 → ceo-office 가 브리핑에 근거 줄을 그대로 싣는다.
