## 🔴 1차 시안의 전제가 실측에서 무너졌다

1차는 *"다섯 칸(사업자번호·대표자명·개업일·가게명·연락처)은 **국세청 자동 승인**에 필요하니 그대로 두고
블록만 줄인다"* 였다. 라이브 D1 을 직접 조회하니 그 전제가 사실이 아니었다.

```
sellers 4행 (approved 2 · pending 2)
  representative_name  비어 있음 4/4
  business_start_date  비어 있음 4/4
  nts_verified_at      NULL     4/4
  nts_verify_result    NULL     4/4
```

⇒ **국세청 자동 승인은 한 번도 성사된 적이 없다.** 그리고 재검증 라우트
(`internal-admin-tools.routes.ts:1049`)는 그 두 칸이 비면 `대표자명 / 개업일 누락 — 재검증 불가` 로
되돌아온다. 즉 **지키려던 두 칸이 실제로는 아무 일도 하고 있지 않았다.**

⚠️ `NTS_API_KEY` 설정 여부는 확정 못 했다(`/api/version` 의 시크릿 목록은 큐레이션된 고정 목록이고,
`Env` 타입에도 선언이 없어 `c.env as {NTS_API_KEY?}` 캐스팅으로 읽는다). **다만 그건 상관없다** —
전제 필드가 비어 있어 키가 있든 없든 호출 조건 자체가 성립하지 않는다.

## 3-1. 🔁 정정 — OCR 은 지금 **된다** (2026-09-21 재측정)

대표 질문 *"OCR은 지금 안되는거야?"* 에 답하려고 같은 서류로 다시 쟀다. **위 표는 낡았다.**
그 세 건은 **09:01·09:45 KST** 측정인데, 그 뒤 같은 날 오전에 수리가 셋 들어왔다:

| 시각(KST) | 커밋 | 무엇 |
|---|---|---|
| 09:24 | `a014de2` | 빈 응답 1회 재시도 + 도로명 숫자 띄어쓰기 흡수 |
| 10:13 | `eebeb2c` | 문자열로 감싼 JSON 응답 파싱 |
| **11:17** | **`3d575e7` (#1491)** | **가입 전 OCR 통로 신설** — `POST /api/upload/business-cert` 에 `ocr=1` opt-in |
| 11:47 | `532945e` (#1511) | 상호 한 글자 오독 `near` 등급 + 등록번호 칸의 개업일 되돌리기 |

**재측정(같은 서류, 3회 연속)**: `fill 0 / 0.75 / 0` → **1.0 · 1.0 · 1.0**

> 🔴 **그리고 이 "3회 연속" 도 오판이었다 (같은 날 12:4x KST, 4회 더 재고 정정).**
> 같은 서류·같은 엔드포인트로 4회를 더 돌리니 **회차마다 결과가 다르다**:
> `match`(완벽) 1 · `review`(상호 `[테스트] 글로드분식` 오독) 1 · **`unreadable`(아무것도 못 읽음) 2**.
> ⇒ **절반은 아예 못 읽는다.** 오전의 "3회 연속 1.0" 은 운이 좋았던 구간을 잘라 본 것이다.
> 이 레포가 반복해 당한 *"관측 창이 주기보다 짧으면 단정하지 말 것"* 을 내가 또 밟았다.

| 칸 | 결과 |
|---|---|
| 사업자번호 | `9999999991` ✅ |
| 개업일 | `20240302` ✅ |
| 대표자 | `김테스트` ✅ |
| 상호 | `글로드분식` (원본 `클로드분식`) — **한 글자 오독** |

⇒ **읽히기만 하면 세 칸은 정확하다.** 문제는 정확도가 아니라 **재현성**이다 — 절반은 빈손으로 돌아온다.
가입 화면은 못 읽으면 **아무 말도 안 하고 조용히 넘어가므로**(의도된 동작) 깨지지는 않는다.
사장님 입장에서는 "사진을 올렸는데 어떤 날은 채워지고 어떤 날은 안 채워진다" 로 보인다.

⚠️ **여전히 실사진 실측은 0회다.** 위는 합성 등록증(글자가 또렷한 렌더 문서)이다.

🩸 **교훈**: 어제 측정한 결과를 오늘 사실로 말하면 안 된다. 이 레포는 세션이 여러 개 동시에 돌고,
그중 하나가 내가 "못 한다" 고 적어 둔 바로 그것을 만들고 있었다.

## 5. ✅ 구현 (안 B — 2026-09-21 대표 확정 *"응 안 B로 하는데"*)

### 무엇이 달라졌나
사장님이 카카오맵에서 가게를 고르면 **[가게명]·[매장 주소] 두 칸이 사라지고 카드 한 장이 된다.**
남는 칸은 담당자 연락처(알림톡 수신)와 매장 종류 칩, 매장 소개(선택)뿐이다.
사업자 정보 3칸은 **등록증 사진이 채운다**(#1491, §3-1) ⇒ **손으로 치는 건 연락처 하나.**

### 지킨 것
- **탈출구 상시** — 지도에 없는 가게(신규 개업·무점포)는 카드가 안 뜨고 종전 칸이 그대로 남는다. 모드 전환 버튼 없음.
- **담당자 휴대폰을 가게 대표번호로 덮지 않는다** — 덮으면 주문·정산 알림톡이 유선번호로 간다.
- **매장 종류 칩은 골라도 남는다** — 카카오 업종 매핑은 추측이다. 맞으면 이미 선택돼 있고, 틀리면 한 번 누르면 된다.
- **fail-soft** — 메타 저장이 실패해도 가입은 성공한다(프로필 수정에서 채울 수 있다).
- **머니 경로 무접촉** — 요율을 가르는 `store_channel` 은 종전 `stampSignupStoreChannel`(언제나 `direct`) 그대로.

### 덤으로 닫힌 것
`kakao_place_id` 가 가입 문에서도 남으므로, 매장 등록 문(`/store/new`)의 **중복 검사**
(`seller_meta.kakao_place_id` 역조회 → `STORE_EXISTS`)가 같은 가게를 알아본다.
종전엔 가입 문으로 들어온 매장이 그 검사에 **보이지 않아** 같은 가게가 두 번 등록될 수 있었다.

### 가드
`src/tests/unit/seller-signup-store-pick-2026-09-21.test.tsx` **19건**
