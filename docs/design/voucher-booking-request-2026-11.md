# 예약이 필요한 이용권 — 예약 요청 → 매장 한 번 누르기 (2026-11-04 대표 확정 시안)

시안(디자인 캔버스): https://claude.ai/artifact/QiE7JRE9CpZHFtsh2kcKcS — 탭 **"전체 흐름 (한 장)"**(12화면, 라이트·다크) ·
**"예약이 필요한 이용권"**(화면별). 서비스: **유어딜(소비자 이용권)**.

## 왜
미용·마사지·레슨·PT·숙소처럼 예약이 필요한 이용권은 지금 첫 이용권 화면에 예약 설정이 없다(미용을 골라도 '바로 사용'으로 등록).
사장님은 이미 네이버 예약·전화·야놀자 등으로 예약을 받고 있어 **유어딜이 빈자리를 실시간으로 알 길이 없다**(공개 연동 없음).
그래서 "자리를 약속하지 않고, 매장이 확인해 확정"하는 구조로 간다. 기존 `시간 예약`(슬롯) 기능은 설정 매장 0곳(11-03 실측).

## 대표 확정 (2026-11-04, 말 그대로)
- 업종을 5가지로 나누면 복잡 → 사장님에겐 **"손님이 오기 전에 예약이 필요한가요? 예/아니요 + 같은 시간 몇 명"** 한 줄. 업종은 기본값만 고른다. 숙박은 날짜·객실.
- *"직원(운영자)이 운영할 수도 있잖아"* → 알림톡은 **사장님·직원이 각자 적은 휴대폰 번호**로. 먼저 누른 사람이 처리.
- *"답 기한은 영업시간 기준"* → **영업시간 기준 2시간**(*"시간은 2시간 안으로 하자"*). 넘으면 재알림.
- 당일 예약: 손님은 **매장이 답할 수 있는 시간(2시간) 뒤**의 시간만 고른다. 마감 직전 요청이면 다음 영업일로 넘어간다. 급하면 '매장에 전화'.
- *"직원권한에선 판매 잠깐 멈춤 권한도 줘"* → 직원: 예약 처리·사용처리·판매 멈춤 가능 / 매출·정산·가격·등록은 사장님만.
- *"예약을 못하는 경우 이용권으로 남는걸로 하고 고객이 환불 요청을 하면 환불"* → **자동 환불 없음**.
- *"날짜는 달력처럼"* · *"숙소라면 또 다르잖아"* → 미용은 월 달력 + 시간 3개까지, 숙소는 체크인~체크아웃 띠 + 객실 + 인원.
- 마지막 검토 *"나머지는 다 좋아"*: 사는 화면에서 날짜·시간을 같이 골라 **결제 = 예약 요청**("날짜는 나중에 정할게요" 허용) ·
  예약 필요 시 **영업시간**(카카오맵 값 미리 채움) 확인 · 달력은 쉬는 날 + **유어딜 확정 예약으로 찬 시간**을 막는다.
- *"알림 받을 사람은 선택이긴 하지만 넣긴 해야지"* → 판매 준비 흐름 8번에 두되 **선택**(나중에 할게요). *"축하 화면 두번 나오는 것도 나쁘지 않은데"* → 등록 완료·올림 완료 둘 다 유지.

## 흐름
사장님: ①가게 찾기 → ②등록 → ③등록 완료 → ④첫 이용권(사진 + 예약 필요? + 영업시간) → ⑤올림 완료 → ⑥사업자등록증 → ⑦정산 계좌 → ⑧알림 받을 사람(선택)
손님: ⑨날짜·시간(숙소: 기간·객실) 고르며 결제 → ⑩사장님·직원 카톡 → ⑪먼저 누른 사람이 확정 → ⑫예약 확정(QR + 전날 알림)
